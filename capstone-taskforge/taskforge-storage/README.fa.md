# کریت `taskforge-storage`

دو تا پیاده‌سازی از Traitِ `JobStore` مربوط به کریتِ `taskforge-core`:

- **`InMemoryJobStore`** — بدون هیچ وابستگیِ بیرونی، استفاده‌شده تو کلِ مجموعه‌تست‌های این ورک‌اسپیس. ماژولِ تستِ خودش هم ثابت می‌کنه که قراردادِ همروندی‌ای (concurrency contract) رو که هر پیاده‌سازیِ `JobStore` باید بهش پایبند باشه رعایت می‌کنه: متدِ `claim_next` هیچ‌وقت اجازه نمی‌ده دو تا فراخواننده‌ی همزمان یه جابِ یکسان رو مالِ خودشون کنن.
- **`PostgresJobStore`** — پیاده‌سازیِ واقعی، از طریقِ `sqlx`. مایگریشن‌ها تو پوشه‌ی `/migrations` قرار دارن و موقعِ فراخوانیِ `PostgresJobStore::connect` به طور اتوماتیک اجرا می‌شن.

## چرا تک‌تکِ کوئری‌ها از `sqlx::query`/`query_as` استفاده می‌کنن و هرگز از `!query!` / `!query_as` استفاده نمی‌کنن

ماکروهای `!query!`/`query_as` میاد کوئریِ SQL تو رو تو **زمانِ کامپایل با یه دیتابیسِ زنده** (یا یه کشِ آفلاینِ ثبت‌شده تو `.sqlx`) چک و اعتبارسنجی می‌کنه. این ویژگی تو پروژه‌های معمولی واقعاً عالی و قشنگه — اما معنیش واسه این مخزنِ آموزشی این بود که دستورِ `cargo build --workspace` واسه کُلِ این ریپوزیتوری فِیل می‌شد مگه اینکه موقع بیلد گرفتن یه Postgres زنده رو سیستمِ تک‌تکِ یادگیرنده‌ها همیشه در دسترس می‌بود. که خب اینجا اصلاً قابل قبول نیست. به خاطر همین این کریت همه‌جا از APIهایی که تو زمانِ اجرا چک می‌شن (`...(...)sqlx::query(...).bind` و `...<sqlx::query_as::<_, JobRow`) استفاده می‌کنه — یعنی اشتباهاتِ SQL به جای ارورهای زمان کامپایل، به شکلِ ارورهای زمان اجرا خودشون رو نشون می‌دن (که با تست‌ها مچشون گرفته می‌شه)، که اینم همون بده‌بستانِ ماست. ساختارِ `JobRow` تو فایل `row.rs` (با ماکروی `sqlx::FromRow`) بازم مپینگِ تایپ‌شده و امنِ ستون‌ها رو بهت می‌ده — اون derive فقط ستون‌ها رو تو زمان اجرا به فیلدها مپ می‌کنه، و تو زمان کامپایل کلاً دست به دیتابیس نمی‌زنه.

## ران کردن تست‌ها

```sh
cargo test -p taskforge-storage
```

این دستور همه چیز رو اجرا می‌کنه **بجز** تستِ `postgres::tests::enqueue_and_claim_round_trip` که علامتِ `#[ignore]` خورده چون به یه Postgres واقعی نیاز داره. واسه ران کردن واقعیش:

```sh
# از مسیر capstone-taskforge/
docker compose up -d postgres
DATABASE_URL=postgres://taskforge:***@localhost:5432/taskforge \
  cargo test -p taskforge-storage -- --ignored
```

(داکر نداری؟ هر Postgres محلیِ دیگه‌ای هم جواب میده — فقط متغیرِ `DATABASE_URL` رو ست کن روش؛ متدِ `PostgresJobStore::connect` خودش مایگریشن‌های تو پوشه‌ی `/migrations` رو برات ران می‌کنه. این قضیه موقع توسعه واقعاً روی یه سرویسِ ساده و محلیِ `postgresql` تست و تایید شد، نه فقط داکر — یه رول و دیتابیسِ `taskforge`/`taskforge` دستی ساخته شد و تستِ ignore شده روش پاس شد، بدون اینکه کانتینری تو کار باشه.)
