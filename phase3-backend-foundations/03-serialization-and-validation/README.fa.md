# ماژول ۳ — سریال‌سازی و اعتبارسنجی

استخراج‌کننده‌ی `Json<T>` تو `axum` (ماژول ۲) از قبل بدنه‌ی درخواست‌ها رو برات پارس می‌کنه. این ماژول یه لایه عمیق‌تر می‌ره تو *چطور*: ماکروها و attributeهایِ derive تویِ `serde`، پاسِ اعتبارسنجیِ جدا و صریحی که `validator` روش اضافه می‌کنه، و دو چیزی که هر API واقعی بالاخره لازمش می‌شه: یه قراردادِ ماشین‌خوان برایِ شکلش، و یه برنامه برایِ عوض‌کردنِ اون شکل بدونِ خراب‌کردنِ هر مصرف‌کننده‌ی موجود.

۱. [۰۱ — عمقِ serde](01-serde-depth/README.fa.md)
   — `rename_all`، `flatten`، `skip_serializing_if`، یه پیاده‌سازیِ دستیِ `Serialize`، و enumهایِ `untagged`: همون attributeهایی که APIهایِ واقعی واقعاً بهشون نیاز پیدا می‌کنن، عمداً کاملاً جدا از HTTP نگه داشته شده.
۲. [۰۲ — اعتبارسنجی](02-validation/README.fa.md)
   — قوانینِ سطحِ فیلدِ `#[derive(Validate)]` و `ValidationErrors`، رویِ همون structهایی که درسِ قبلی ساخت.
۳. [۰۳ — قراردادهایِ API و OpenAPI](03-api-contracts-and-openapi/README.fa.md)
   — ساختنِ یه سندِ OpenAPIِ واقعی از رویِ نوع‌هایِ خودت با `utoipa`، به‌جایِ دستی‌نوشتنِ یکی که بی‌سروصدا از هماهنگی می‌افته.
۴. [۰۴ — نسخه‌بندیِ API و تکاملش](04-api-versioning-and-evolution/README.fa.md)
   — چه‌چیزی واقعاً یه مصرف‌کننده رو می‌شکنه، و استراتژی‌هایِ واقعی — URL، هدر، فقط-اضافه‌کردن — برایِ عوض‌کردنِ یه API بدونِ شکستنش.

ماژول ۵ دقیقاً همین‌جا رو دوباره برمی‌داره: structهایی مثلِ `CreateAnime`/`UpdateAnime` که تو ماژول ۲ دیدی، قوانینِ واقعیِ `validator` می‌گیرن، و بعد واقعاً پرسیست می‌شن.
