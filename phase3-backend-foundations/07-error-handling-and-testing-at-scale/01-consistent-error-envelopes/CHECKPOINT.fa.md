# ایست بازرسی

1. `thiserror::Error` و `IntoResponse` هرکدام دقیقاً چه مسئله‌ای را حل می‌کنند؟ چرا `Display` برای ساخت پاسخ HTTP کافی نیست؟ برای `tonic` چه مرز دیگری لازم داری؟
2. یک bug واقعی در frontend مثال بزن که `code` پایدار جلویش را می‌گیرد، اما APIِ فقط-`message` نه. چرا وعدهٔ «متن ۴۰۴ همیشه همین است» قرارداد خوبی نیست؟
3. نبودن `WidgetStoreError` جدا چه مزیت و چه بهایی دارد؟ چه زمانی error domain جدا می‌سازی و چه زمانی فقط تشریفات است؟
4. تستِ شکل مشترک error چه regressionی را می‌گیرد که تست جداگانهٔ ۴۰۰ و ۴۰۴ ممکن است نگیرد؟
5. برای خطای نام تکراری و `409 Conflict`، کدام بخش‌های `src/lib.rs` را تغییر می‌دهی و کدام بخش دست‌نخورده می‌ماند؟
6. چرا `From<ValidationErrors>` پیش از join کردن messageها آن‌ها را `.sort()` می‌کند؟ بدون آن، flake چه شکلی خواهد داشت؟
