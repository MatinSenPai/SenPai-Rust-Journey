# ماژول ۴ — دیتابیس PostgreSQL و `sqlx`

تک‌تک درس‌هایی که تا قبل از این کار کردی، واسه ذخیره‌سازی از یه ساختارِ `<...Mutex<HashMap>` که داخل حافظه (in-memory) قرار داشت استفاده می‌کردن — که خب یه روش درست و سریعه، اما دقیقاً تو همون ثانیه‌ای که اجرایِ پروسه (process) متوقف بشه کلاً از بین می‌ره. این ماژول قراره اونو با یه دیتابیسِ Postgresِ واقعی جایگزین کنه، اونم از طریق کریتِ `sqlx`، که یه ابزارِ کمکیِ غیرهمگام (async) برای SQL هست که بررسی‌هاش تو زمان کامپایل (compile-time-optional) انجام می‌شه (اینجا خبری از یه ORM کامل و سنگین مثل جنگو نیست — تو کدهای واقعیِ SQL رو با دست خودت می‌نویسی، و `sqlx` فقط دیتایِ اونا رو برات تو متغیرهایی که نوعشون امن و مشخصه (type-safe) می‌ذاره و درمیاره).

**پیش‌نیازها:** تو به یه دیتابیسِ Postgres محلی (local) نیاز داری که بشه از طریق یه رشته‌ی اتصال (connection string) بهش وصل شد. محیط تمرینیِ (sandbox) فعلیِ تو از قبل Postgres 16 روش نصبه؛ اگه روشن نیست با دستورِ `sudo service postgresql start` روشنش کن (با `sudo service postgresql status` می‌تونی چکش کنی). تک‌تک درس‌های اینجا به عنوان پیش‌فرض از آدرس `postgres://taskforge:***@localhost:5432/taskforge` به عنوان متغیرِ `DATABASE_URL`شون استفاده می‌کنن — یعنی دقیقاً همون نام‌کاربری/دیتابیسی که کریتِ `taskforge-storage` تو پروژه‌ی نهاییِ دوره قراره ازش استفاده کنه، که اینجا یه بار ساخته می‌شه و همه‌جا از همون استفاده می‌شه تا مجبور نباشی واسه هر درس دوباره دیتابیس بسازی. اگه هنوز این یوزر رو تو سیستمت نداری، این دستور رو بزن: `sudo -u postgres psql -c "CREATE ROLE taskforge LOGIN PASSWORD 'taskforge' CREATEDB;" && sudo -u postgres createdb -O taskforge taskforge`.

هر تستی که برای کار کردن به یه دیتابیس زنده (live database) نیاز داشته باشه، با صفتِ `[ignore]#` علامت‌گذاری شده تا تو اجرای عادی نادیده گرفته بشه (واسه اینکه بدونی چرا کلاً تو این مخزن (repo) این رویه وجود داره برو به این آدرس `phase4-backend-advanced/03-background-jobs-and-message-queues/01-postgres-skip-locked-toy-queue/`) — یعنی اگه فقط دستورِ `cargo test` رو به تنهایی بزنی، همیشه بدونِ نیاز به هیچ زیرساخت اضافه‌ای کلاً پاس می‌شه؛ اما اگه دستورِ `cargo test -- --ignored` رو بزنی (در حالی که متغیرِ `DATABASE_URL` از قبل تو محیط ذخیره شده (exported) باشه)، تست‌ها واقعاً دیتابیسِ Postgres رو درگیر می‌کنن و تست می‌گیرن.
