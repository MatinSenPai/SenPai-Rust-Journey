# ۱.۱.۳ — انواعِ مرکب و واکافت

## در یک نگاه

بعد از این درس می‌توانی:

- یک تاپل و یک آرایه بسازی، و بگویی هرکدام برای چه کاری‌اند.
- بگویی چرا `(u32, f64)` و `(f64, u32)` دو نوعِ متفاوت‌اند، و چرا `[i32; 4]` با `[i32; 5]` فرق دارد.
- یک مقدارِ مرکب را با نوشتنِ شکلش باز کنی، به‌جای اینکه فیلدهایش را یکی‌یکی بیرون بکشی.
- بگویی وقتی از آخرِ یک آرایه رد می‌شوی چه اتفاقی می‌افتد — و چرا این پنیک، برخلافِ سرریز، در release هم سرِ جایش است.

**زمان:** حدود ۴۵ دقیقه · **پیش‌نیاز:** [۱.۱.۲ — انواعِ اسکالر و سرریز](../02-scalar-types-and-overflow/README.fa.md)

---

## چرا اهمیت دارد

تا اینجا هر متغیری که ساخته‌ای یک چیز بوده: یک عدد، یک `bool`. ولی داده‌های واقعی این‌طوری نیستند. یک نمونه‌ی سنسور یعنی زمان *و* دما *و* رطوبت — سه عدد که با هم معنا دارند و جدا از هم تقریباً بی‌معنا هستند.

در پایتون این را بدونِ فکر کردن حل می‌کنی:

```python
sample = (1700000000, 21.5, 48.0)
timestamp, celsius, humidity = sample
```

و در پایتون آن `sample` می‌تواند بعداً چهار عنصر داشته باشد، یا اولین عنصرش یک رشته بشود، و هیچ‌کس تا لحظه‌ی انفجار خبردار نمی‌شود.

در Rust همان دو خط را می‌نویسی — نحوش تقریباً یکی است — ولی **تعدادِ عناصر و نوعِ هرکدام بخشی از نوعِ آن مقدار است.** یعنی تابعی که یک نمونه‌ی سه‌تایی می‌خواهد، هرگز یک نمونه‌ی دوتایی نمی‌گیرد، و کسی که فردا یک فیلد اضافه کند، *همه‌ی* جاهایی را که باید عوض شوند به‌صورتِ خطای کامپایل تحویل می‌گیرد.

و یک چیزِ دوم که در پایتون اصلاً وجود ندارد: **آرایه‌ی Rust رشد نمی‌کند.** طولش از قبل معلوم است و همان می‌ماند. اولش محدودکننده به‌نظر می‌رسد؛ ولی همان محدودیت است که به کامپایلر اجازه می‌دهد آرایه را روی پشته بگذارد و از تخصیصِ حافظه‌ی پویا کلاً صرف‌نظر کند. لیستِ رشدکننده هم داری — اسمش `Vec` است و [۱.۱.۶](../06-vec-and-string-basics/README.fa.md) درباره‌ی همان است.

## مفهوم

Rust دو راهِ داخلی برای چسباندنِ چند مقدار به هم دارد، و تفاوتشان یک جمله است:

| | تعداد | نوع‌ها | مثال |
|---|---|---|---|
| **تاپل** | ثابت | می‌توانند فرق کنند | `(1700000000, 21.5, true)` |
| **آرایه** | ثابت | همه یکی | `[12, 7, 19, 3, 14]` |

هر دو اندازه‌ی ثابت دارند. تفاوت این است که تاپل چیزهای *متفاوت* را کنار هم می‌گذارد و آرایه چیزهای *هم‌جنس* را.

### تاپل

نوعِ تاپل دقیقاً به همان شکلی نوشته می‌شود که مقدارش ساخته می‌شود:

```rust
let sample: (u32, f64, bool) = (1_700_000_000, 21.5, true);
```

به فیلدها با شماره‌ی جایگاه می‌رسی، و شماره‌ها از صفر شروع می‌شوند:

```rust
println!("timestamp: {}", sample.0);
println!("celsius:   {}", sample.1);
println!("verified:  {}", sample.2);
```

```text
timestamp: 1700000000
celsius:   21.5
verified:  true
```

نقطه‌ای که راحت از دست می‌رود: **جایگاه بخشی از نوع است.**

```rust
let pair: (u32, f64) = (3, 1.5);
let flipped: (f64, u32) = (1.5, 3);
```

این‌ها «دو عدد» نیستند؛ دو نوعِ کاملاً متفاوت‌اند. تابعی که `(u32, f64)` می‌خواهد، `(f64, u32)` را قبول نمی‌کند. اگر عادت داری در پایتون تاپل‌ها را جابه‌جا رد و بدل کنی، این همان جایی است که Rust سختگیر می‌شود — و همان جایی که یک کلاسِ کاملِ باگ را از زندگی‌ات حذف می‌کند.

تاپل‌ها تو در تو می‌شوند و دسترسی هم زنجیر می‌شود:

```rust
let reading = ((10, 20), true);
println!("nested .0.1: {}", reading.0.1);
```

```text
nested .0.1: 20
```

دو حالتِ خاص که بهتر است همین حالا ببینی:

```rust
let single = (7,);      // تاپلِ یک‌عنصری — کامای آخر لازم است
let nothing: () = ();   // تاپلِ صفرعنصری
```

```text
single:    (7,)
unit:      ()
```

بدونِ آن کامای آخر، `(7)` فقط عددِ ۷ داخلِ پرانتز است. و آن `()` خالی اسمِ خودش را دارد: **نوعِ یکه** (unit). این همان چیزی است که تابعی که چیزی برنمی‌گرداند، در واقع برمی‌گرداند. الان زیاد به کارت نمی‌آید؛ ولی وقتی در [۱.۶.۳](../../06-absence-and-failure/03-result-and-question-mark/README.fa.md) با `Result<(), Error>` روبه‌رو شوی — یعنی «موفق شد و چیزی برای گفتن ندارد» — می‌خواهی بدانی این از کجا آمد.

### مهم‌ترین کاربردِ تاپل

**برگرداندنِ بیش از یک مقدار از یک تابع.**

```rust
fn divide(total: u32, per_box: u32) -> (u32, u32) {
    (total / per_box, total % per_box)
}
```

```text
47 in 6s:  7 boxes, 5 left over
```

در زبانی مثلِ C برای همین کار یا باید یک `struct` تعریف می‌کردی یا یک اشاره‌گرِ خروجی پاس می‌دادی. اینجا فقط جفتش را برمی‌گردانی. این پرکاربردترین دلیلی است که در کدِ واقعی تاپل می‌بینی.

### آرایه

```rust
let readings: [i32; 5] = [12, 7, 19, 3, 14];
```

نوع را «این نوع، این‌قدر تا» بخوان. و **آن عدد بخشی از نوع است** — دقیقاً به همان معنایی که در تاپل جایگاه بخشی از نوع بود:

```rust
let four: [i32; 4] = [1, 2, 3, 4];
let five: [i32; 5] = [1, 2, 3, 4, 5];
// let same: [i32; 4] = five;   // ← E0308
```

اگر می‌خواهی یک مقدار را چند بار تکرار کنی، نحوِ کوتاهش این است:

```rust
let zeroed = [0_u8; 8];
```

```text
zeroed:    [0, 0, 0, 0, 0, 0, 0, 0]
```

طول را با `.len()` می‌گیری و به عناصر با اندیس می‌رسی — باز هم از صفر:

```rust
println!("length:    {}", readings.len());
println!("first:     {}", readings[0]);
println!("last:      {}", readings[readings.len() - 1]);
```

```text
length:    5
first:     12
last:      14
```

> عادت کن آخرین عنصر را `readings[readings.len() - 1]` بنویسی نه `readings[4]`. اینجا هر دو درست‌اند چون طول در نوع نوشته شده. ولی همین کد وقتی به `Vec` تبدیل شود، `[4]` می‌شود پنیکی که منتظرِ یک ورودیِ کوتاه نشسته.

### هر اندیس بررسی می‌شود

اینجا Rust کاری می‌کند که C نمی‌کند. در C خواندنِ `readings[5]` از یک آرایه‌ی پنج‌تایی هر چیزی که آن‌طرف در حافظه بوده را به تو می‌دهد — بی‌سروصدا، و اگر بنویسی، همان‌جا شروعِ یک آسیب‌پذیریِ امنیتی است. در Rust برنامه می‌ایستد.

و دو زمانِ مختلف برای ایستادن هست.

**اگر کامپایلر بتواند خودش حساب کند، اصلاً کامپایل نمی‌شود:**

```text
error: this operation will panic at runtime
 --> out-of-bounds.rs:3:20
  |
3 |     println!("{}", readings[5]);
  |                    ^^^^^^^^^^^ index out of bounds: the length is 5 but the index is 5
  |
  = note: `#[deny(unconditional_panic)]` on by default
```

**اگر اندیس فقط در زمانِ اجرا معلوم شود، برنامه پنیک می‌کند:**

```text
length:  5
safely:  None

thread 'main' (12124) panicked at examples\04-out-of-bounds.rs:20:29:
index out of bounds: the len is 5 but the index is 5
```

**و حالا تفاوتِ مهم با درسِ قبل.** در [۱.۱.۲](../02-scalar-types-and-overflow/README.fa.md) دیدی که پنیکِ سرریز در release ناپدید می‌شود. این یکی نمی‌شود:

```text
=== release ===
length:  5
safely:  None

thread 'main' (24804) panicked at examples\04-out-of-bounds.rs:20:29:
index out of bounds: the len is 5 but the index is 5
```

عینِ همان. **بررسیِ مرزها یک بهینه‌سازی نیست که بشود خاموشش کرد؛ بخشی از تعریفِ زبان است.** بله، هزینه دارد — یک مقایسه به‌ازای هر دسترسی — و Rust با کمالِ میل آن هزینه را می‌دهد، چون چیزی که می‌خرد این است که یک اندیسِ غلط هرگز به حافظه‌ی همسایه نرسد. (کامپایلر در بسیاری از حلقه‌ها می‌تواند ثابت کند بررسی لازم نیست و حذفش می‌کند؛ ولی این تصمیمِ اوست، نه تو.)

اگر نمی‌خواهی برنامه بایستد، نپرس — **درخواست کن**:

```rust
println!("get(2):    {:?}", readings.get(2));
println!("get(99):   {:?}", readings.get(99));
```

```text
get(2):    Some(19)
get(99):   None
```

`.get()` به‌جای پنیک، یک `Option` می‌دهد: `Some(مقدار)` یا `None`. همان چیزی که در `checked_add` دیدی. درسِ کاملش [۱.۶.۱](../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) است.

### واکافت — نوشتنِ شکل به‌جای بیرون کشیدنِ فیلدها

این قلبِ درس است.

```rust
let (timestamp, celsius, verified) = sample;
```

سمتِ چپِ `=` سه دستورِ جدا نیست. **یک الگو است که شکلش با شکلِ مقدار یکی است**، و اسم‌های داخلش پر می‌شوند. اگر پایتون بلدی این را قبلاً دیده‌ای. تفاوتش این است که در Rust کامپایلر بررسی می‌کند شکل بخواند — تعداد و نوع، همان لحظه.

`_` یعنی «اینجا یک فیلد هست و برایش اسم نمی‌خواهم»:

```rust
let (_, only_celsius, _) = sample;
```

```text
only:      21.5
```

دقت کن که `_` تو را از شمردن معاف نمی‌کند. الگو همچنان باید کلِ شکل را پوشش بدهد؛ آن دو `_` حرفشان این است که «سه فیلد، و می‌دانمش».

آرایه‌ها هم به همان شکل باز می‌شوند و تعدادش بررسی می‌شود:

```rust
let corners = [1, 2, 3, 4];
let [top_left, top_right, bottom_left, bottom_right] = corners;
```

الگوها تا هر عمقی که مقدار دارد تو در تو می‌شوند:

```rust
let route = ((35.7, 51.4), (32.6, 51.7));
let ((from_lat, from_lon), (to_lat, to_lon)) = route;
```

```text
from:      35.7, 51.4
to:        32.6, 51.7
```

و چون سمتِ راست کاملاً ارزیابی می‌شود و بعد چیزی بسته می‌شود، جابه‌جا کردنِ دو متغیر به متغیرِ کمکی احتیاج ندارد:

```rust
let mut a = 1;
let mut b = 2;
(a, b) = (b, a);
```

```text
before:    a=1 b=2
after:     a=2 b=1
```

> **این را جدی بگیر:** الگوها یک ویژگیِ کوچکِ `let` نیستند. همین ماشین است که پشتِ `match`، پشتِ `if let`، پشتِ آرگومان‌های تابع و پشتِ باز کردنِ `Option` و `Result` کار می‌کند. هر بار در ادامه‌ی این دوره الگو می‌بینی، دقیقاً همین قاعده است با یک شکلِ پیچیده‌تر.

### کدام را کِی برداری

| وضعیت | بردار |
|---|---|
| دو سه مقدار که کوتاه‌مدت با هم سفر می‌کنند | تاپل |
| برگرداندنِ چند مقدار از یک تابع | تاپل |
| چند مقدارِ هم‌نوع با تعدادِ از پیش معلوم | آرایه |
| فهرستی که رشد می‌کند | `Vec` — [۱.۱.۶](../06-vec-and-string-basics/README.fa.md) |
| هر چیزی که فیلدهایش اسم می‌خواهند | `struct` — [۱.۵.۱](../../05-your-own-types/01-structs-and-methods/README.fa.md) |

آخرین سطر مهم‌ترین است. تاپل تا سه فیلد قابلِ تحمل است. از آن به بعد `thing.3` معما می‌شود و باید اسم بگذاری.

## خطاهایی که خواهی دید

### `E0308` — الگو سه فیلد می‌خواست، تو دوتا نوشتی

```text
error[E0308]: mismatched types
 --> examples\05-wrong-arity.rs:9:9
  |
9 |     let (timestamp, celsius) = sample;
  |         ^^^^^^^^^^^^^^^^^^^^   ------ this expression has type `(u32, f64, bool)`
  |         |
  |         expected a tuple with 3 elements, found one with 2 elements
  |
  = note: expected tuple `(u32, f64, bool)`
             found tuple `(_, _)`
```

**کامپایلر به چه اعتراض دارد:** الگوی تو دو جایگاه دارد و مقدار سه فیلد. Rust خودش تصمیم نمی‌گیرد کدام را دور بریزد.

**راه‌حل:** اسمِ سوم را بنویس، یا اگر لازمش نداری `_` بگذار: `let (timestamp, celsius, _) = sample;`

**چرا این راه‌حل است:** آن `_` نیتِ تو را می‌نویسد. تفاوتش با فراموش کردن این است که شش ماهِ بعد کسی که کد را می‌خواند می‌داند فیلدِ سوم هست و عمداً استفاده نشده — و مهم‌تر، اگر فردا فیلدِ چهارمی اضافه شود، همین‌جا خطا می‌گیری و مجبور می‌شوی نگاهش کنی.

### `E0527` — همان چیز، برای آرایه

```text
error[E0527]: pattern requires 3 elements but array has 4
  --> examples\05-wrong-arity.rs:14:9
   |
14 |     let [a, b, c] = corners;
   |         ^^^^^^^^^ expected 4 elements
```

**کامپایلر به چه اعتراض دارد:** همان مشکل، ولی چون آرایه است کدِ خطای اختصاصیِ خودش را دارد.

**راه‌حل:** یا هر چهار جایگاه را بنویس، یا اگر فقط چند تای اول را می‌خواهی، بقیه را با `..` نادیده بگیر: `let [a, b, ..] = corners;`

### `E0308` — طولِ آرایه با هم نمی‌خواند

```text
error[E0308]: mismatched types
 --> array-lengths.rs:3:26
  |
3 |     let same: [i32; 4] = five;
  |               --------   ^^^^ expected an array with a size of 4, found one with a size of 5
  |               |
  |               expected due to this
  |
help: consider specifying the actual array length
  |
3 -     let same: [i32; 4] = five;
3 +     let same: [i32; 5] = five;
  |
```

**کامپایلر به چه اعتراض دارد:** `[i32; 4]` و `[i32; 5]` دو نوعِ متفاوت‌اند. هیچ تبدیلی بینشان نیست، چون هیچ تبدیلی معنا نمی‌دهد.

**راه‌حل:** طولِ درست را بنویس — یا اگر واقعاً می‌خواهی تابعت هر طولی را قبول کند، چیزی که لازم داری آرایه نیست، **برش** است. برش در [۱.۳.۴](../../03-borrowing-and-references/04-slices/README.fa.md) می‌آید و دقیقاً برای همین ساخته شده.

### `E0277` — تاپل با `{}` چاپ نمی‌شود

```text
error[E0277]: `(u32, f64, bool)` doesn't implement `std::fmt::Display`
 --> print-a-tuple.rs:3:20
  |
3 |     println!("{}", sample);
  |               --   ^^^^^^ `(u32, f64, bool)` cannot be formatted with the default formatter
  |
  = help: the trait `std::fmt::Display` is not implemented for `(u32, f64, bool)`
  = note: in format strings you may be able to use `{:?}` (or {:#?} for pretty-print) instead
```

**کامپایلر به چه اعتراض دارد:** `{}` یعنی «این را برای کاربر چاپ کن»، و Rust نمی‌داند یک تاپل را چطور باید به کاربر نشان داد — با کاما؟ با فاصله؟ با اسمِ فیلدها؟ جوابی ندارد، پس جواب نمی‌سازد.

**راه‌حل:** `{:?}` بنویس. و اگر تو در تو است، `{:#?}` که چندخطی و مرتب چاپ می‌کند.

**چرا این راه‌حل است:** آن دو خروجیِ متفاوت‌اند، نه دو ظاهر از یک چیز. `{}` برای *کاربر* است و `{:?}` برای *تو*. `Display` و `Debug` دو صفتِ جداگانه‌اند و [فاز ۲](../../../phase2-intermediate/03-generics-and-traits/README.fa.md) کاملش می‌کند.

### پنیکِ زمانِ اجرا — که خطای کامپایل نیست

```text
thread 'main' (12124) panicked at examples\04-out-of-bounds.rs:20:29:
index out of bounds: the len is 5 but the index is 5
note: run with `RUST_BACKTRACE=1` environment variable to display a backtrace
```

**چه اتفاقی افتاد:** برنامه بی‌هیچ خطایی کامپایل شد. مشکل زمانِ **اجرا** رسید، چون اندیس از جایی می‌آمد که کامپایلر نمی‌توانست از قبل حسابش کند.

**راه‌حل:** یا قبلش مطمئن شو اندیس معتبر است، یا `.get()` بگیر و حالتِ `None` را مدیریت کن.

**چرا این راه‌حل است:** برخلافِ سرریز، این پنیک در release هم هست، پس «در production خودش خوب می‌شود» اتفاق نمی‌افتد. تنها انتخابِ واقعی این است که پنیک کند یا تو حالتِ نبودن را بنویسی.

## تمرین

### گرم‌کردن

<details>
<summary>چرا <code>(u32, f64)</code> و <code>(f64, u32)</code> یکی نیستند؟</summary>

چون جایگاه بخشی از نوع است. تاپل «مجموعه‌ای از دو عدد» نیست؛ «یک `u32` در جایگاهِ صفر و یک `f64` در جایگاهِ یک» است. عوض کردنِ ترتیب یک نوعِ دیگر می‌سازد، و کامپایلر جلوی جابه‌جا دادنشان را می‌گیرد.

</details>

<details>
<summary><code>(7)</code> چه نوعی است؟ <code>(7,)</code> چطور؟</summary>

`(7)` یک عددِ صحیح است — پرانتز فقط گروه‌بندی است. `(7,)` یک تاپلِ یک‌عنصری است. کامای آخر تنها چیزی است که این دو را از هم جدا می‌کند.

</details>

<details>
<summary>یک تابع می‌خواهد <code>[i32; 5]</code> بگیرد. یک آرایه‌ی چهارتایی به آن می‌دهی. کِی خبردار می‌شوی؟</summary>

زمانِ کامپایل، با `E0308`. طول بخشی از نوع است، پس این خطای نوع است نه یک بررسیِ زمانِ اجرا.

</details>

<details>
<summary><code>readings[99]</code> روی یک آرایه‌ی پنج‌تایی چه می‌کند؟ و <code>readings.get(99)</code>؟</summary>

اولی پنیک می‌کند — در debug و در release، یکسان. دومی `None` می‌دهد و برنامه ادامه پیدا می‌کند. هر جا اندیس از داده‌ی بیرونی می‌آید، `.get()` بردار.

</details>

<details>
<summary>در <code>let (_, celsius, _) = sample;</code> آن دو <code>_</code> چه کار می‌کنند؟</summary>

هیچ چیزی را نمی‌بندند. فقط جایگاه‌ها را می‌شمارند تا الگو شکلِ مقدار را کامل پوشش بدهد. `_` یک متغیر نیست و بعداً نمی‌توانی به آن ارجاع بدهی.

</details>

### تعمیر

`examples/04-out-of-bounds.rs` را طوری عوض کن که دیگر پنیک نکند و به‌جایش وقتی اندیس معتبر نیست چیزی مناسب چاپ کند — بدونِ اینکه مقدارِ `wanted` را دست بزنی.

بعد در release هم اجرایش کن. حالا هر دو بیلد یک خروجی می‌دهند و هیچ‌کدام نمی‌ایستد. **همین نکته‌ی تمرین است.**

### پیاده‌سازی

پنج تابع در `src/lib.rs`:

```sh
cargo test -p p1-01-03-compound-types-and-destructuring
```

یک تستِ آنجا از بقیه مهم‌تر است: `splitting_and_rebuilding_gets_back_where_it_started`. سه نمونه را بررسی نمی‌کند؛ بررسی می‌کند که دو تابعت **معکوسِ هم** باشند. اگر بقیه پاس شدند و این نه، یکی از دو تابع نیمه‌درست است.

### بساز

یک `pub fn stats(readings: [i32; 5]) -> (i32, i32, i32)` بنویس که کمینه، بیشینه و مجموع را در همین ترتیب برگرداند.

بدونِ حلقه بنویسش — هنوز حلقه نخوانده‌ای و لازمش هم نداری. (`a.min(b)` و `a.max(b)` روی هر عددِ صحیحی کار می‌کنند و می‌شود زنجیرشان کرد.)

بعد یک جمله بنویس درباره‌ی اینکه چرا همین تابع برای یک `Vec` نمی‌تواند `(i32, i32, i32)` برگرداند. اگر جوابش را پیدا کنی، نصفِ درسِ [۱.۶.۱](../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) را از قبل فهمیده‌ای.

### چالش (اختیاری)

این را اجرا کن:

```rust
let grid = [[1, 2, 3], [4, 5, 6]];
println!("{:?}", grid);
println!("{}", grid.len());
println!("{}", grid[0].len());
println!("{}", grid[1][2]);
```

بعد جواب بده:

۱. نوعِ `grid` دقیقاً چیست؟ (کاملش بنویس، با هر دو عدد.)
۲. چرا `grid.len()` و `grid[0].len()` دو چیزِ متفاوت‌اند؟
۳. یک الگو بنویس که در یک خط هر شش عدد را به شش اسم بدهد.
۴. حالا `[[1, 2, 3], [4, 5]]` را امتحان کن. کدام خطا را می‌گیری و چرا این خطا دقیقاً همان چیزی است که می‌خواستی؟

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به کارت می‌آید |
|---|---|---|
| تاپل | تعدادِ ثابت از مقدارها، با نوع‌های ممکن‌است‌متفاوت | برگرداندنِ چند مقدار |
| آرایه `[T; N]` | تعدادِ ثابت از مقدارهای هم‌نوع | بافرها، جدول‌های ثابت |
| نوعِ یکه `()` | تاپلِ خالی؛ «هیچ مقداری» | `Result<(), E>` |
| واکافت | باز کردنِ یک مقدار با نوشتنِ شکلش | `let`، `match`، `if let` |
| الگو | همان شکلی که کامپایلر تطبیقش می‌دهد | همه‌جا، از اینجا به بعد |
| `_` در الگو | «یک فیلد هست، اسم نمی‌خواهم» | نادیده گرفتنِ فیلدها |
| بررسیِ مرزها | هر اندیس پیش از خواندن سنجیده می‌شود | هر دسترسیِ اندیسی |
| `.get()` | اندیس بدونِ ریسکِ پنیک | ورودیِ بیرونی |

### الان می‌دانی

- تاپل چیزهای متفاوت را کنار هم می‌گذارد و آرایه چیزهای هم‌جنس را؛ هر دو اندازه‌ی ثابت دارند.
- جایگاه در تاپل و طول در آرایه، هر دو بخشی از **نوع**‌اند.
- تاپل رایج‌ترین راهِ برگرداندنِ چند مقدار از یک تابع است.
- واکافت یعنی شکلِ مقدار را بنویسی، و `_` جایگاه را می‌شمارد بدونِ اینکه اسمی بسازد.
- هر اندیس بررسی می‌شود — گاهی زمانِ کامپایل، وگرنه با یک پنیکِ زمانِ اجرا که در release هم هست.
- `.get()` به‌جای پنیک `Option` می‌دهد.
