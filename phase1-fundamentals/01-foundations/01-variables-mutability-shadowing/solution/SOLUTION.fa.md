# راه‌حل — ۱.۱.۱ متغیرها، تغییرپذیری و سایه‌زنی

```rust
pub fn total_seconds(hours: u32, minutes: u32, seconds: u32) -> u32 {
    let from_hours = hours * 3600;
    let from_minutes = minutes * 60;
    from_hours + from_minutes + seconds
}

pub fn running_total(a: u32, b: u32, c: u32) -> u32 {
    let mut total = a;
    total += b;
    total += c;
    total
}

pub fn scaled(raw: u32) -> u32 {
    let raw = raw * 2;
    let raw = raw + 10;
    let raw = raw / 2;
    raw
}

pub fn full_orders(stock: u32) -> u32 {
    stock / MAX_PER_ORDER
}

pub const MAX_PER_ORDER: u32 = 50;
```

## `total_seconds` — چرا بایندِ نام‌دار بهتر از یک عبارت است

`hours * 3600 + minutes * 60 + seconds` درست است و در یک خط جا می‌شود. پس چرا سه بایند خواستیم؟

چون اسم ارزان‌ترین مستندسازیِ دنیاست. `from_hours` می‌گوید آن عدد *یعنی چه*؛ `hours * 3600` خواننده را وادار می‌کند ضرب را در ذهنش انجام بدهد تا بفهمد. روی یک جمعِ سه‌تایی فرقی ندارد. روی یک محاسبه‌ی واقعی — مالیات، آفستِ صفحه‌بندی، فاصله‌ی تلاشِ مجدد — همین تفاوتِ بینِ کدی است که می‌شود بازبینی‌اش کرد و کدی که باید رمزگشایی شود.

این قاعده‌ی Rust نیست. عادتی است که تمرین دارد جا می‌اندازد، و Rust مجانی در اختیارت می‌گذارد: این بایندها هیچ هزینه‌ای در زمانِ اجرا ندارند.

## `running_total` — نمونه‌ی کتابیِ `mut`

```rust
let mut total = a;
total += b;
total += c;
```

یک مقدارِ منطقی که در طولِ زمان به‌روز می‌شود. این کلِ تعریفِ «کِی `mut` درست است» است.

می‌شد `a + b + c` نوشت، و در کدِ واقعی همان را می‌نویسی. تمرین این شکل را اجباری می‌کند تا وقتی واقعاً لازمش داری برایت آشنا باشد — یعنی همان لحظه‌ای که داری داخلِ یک حلقه انباشت می‌کنی، در [۱.۱.۵](../../01-foundations/05-control-flow/README.fa.md).

اگر `let mut total = 0; total += a; ...` نوشتی، آن هم کاملاً درست است.

## `scaled` — چرا زنجیره‌اش نکنیم

```rust
let raw = raw * 2;
let raw = raw + 10;
let raw = raw / 2;
raw
```

`(raw * 2 + 10) / 2` کوتاه‌تر و درست است. باز هم تمرین دنبالِ شکل است.

ولی ببین سایه‌زنی چه چیزی برایت خرید: **سه گام، یک اسم، بدونِ هیچ شناسه‌ی دورریختنی.** بدونش باید `doubled` و `plus_ten` و `halved` می‌نوشتی — سه اسمی که دیگر هیچ‌وقت استفاده نمی‌شوند و خواننده باید هر سه را در ذهن نگه دارد.

این استدلالِ واقعیِ سایه‌زنی است، و وقتی نوعِ داده هم در هر گام عوض می‌شود خیلی قوی‌تر می‌شود — مثلِ همان زنجیره‌ی `raw → trimmed → parsed` که در [۱.۶](../../06-absence-and-failure/README.fa.md) واقعاً می‌نویسی‌اش.

## `full_orders` — تقسیمِ عددصحیح خودش باقی‌مانده را می‌اندازد

```rust
stock / MAX_PER_ORDER
```

اگر چیزی با بررسیِ باقی‌مانده نوشتی، کار می‌کند ولی لازم نبود: تقسیمِ عددصحیح در Rust باقی‌مانده را دور می‌ریزد. `49 / 50` می‌شود `0`.

دو چیز که ارزشِ ذخیره کردن دارند:

- **`120 / 50` می‌شود `2`، نه `2.4`.** هر دو عملوند عددِ صحیح‌اند، پس نتیجه هم عددِ صحیح است. Rust هیچ‌وقت بی‌سروصدا عددهای صحیحت را اعشاری نمی‌کند.
- **تقسیم بر صفر پنیک می‌کند.** اینجا نه، چون `MAX_PER_ORDER` ثابتِ ۵۰ است — ولی دقیقاً از همان جنسی است که [۱.۱.۲](../../01-foundations/02-scalar-types-and-overflow/README.fa.md) پوشش می‌دهد، همراه با اینکه وقتی حساب سرریز کند چه می‌شود.

## آن `const` انتهای فایل

```rust
pub const MAX_PER_ORDER: u32 = 50;
```

نوشتنِ `stock / 50` هم تست‌ها را پاس می‌کرد. آن ثابت به دو دلیل جایش را حق دارد: عدد یک اسم می‌گیرد که می‌گوید چیست، و در یک جا زندگی می‌کند، پس عوض کردنِ سیاست یک ویرایشِ تک‌خطی است نه یک جستجو.

این کلِ استدلالِ ضدِ «عددهای جادویی» است و در هر زبانی همین است. Rust فقط یک ثابتِ زمانِ کامپایل بدونِ هزینه‌ی اجرا بهت می‌دهد که با آن انجامش بدهی.
