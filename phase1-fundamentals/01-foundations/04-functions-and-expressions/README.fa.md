# ۱.۱.۴ — توابع و عبارت‌ها

## در یک نگاه

بعد از این درس می‌توانی:

- یک تابع با پارامترهای نوع‌دار و نوعِ بازگشتی بنویسی، و بگویی چرا Rust هرگز نوعِ پارامتر را حدس نمی‌زند.
- دستور را از عبارت تشخیص بدهی، و بگویی یک بلوک چقدر می‌ارزد.
- بگویی یک سمی‌کالنِ اضافه با نوعِ بازگشتیِ یک تابع چه می‌کند — و چرا این پرتکرارترین خطای تازه‌کارهاست.
- توضیح بدهی چرا `todo!()` داخلِ تابعی که قول داده یک عدد برگرداند، کامپایل می‌شود.

**زمان:** حدود ۴۰ دقیقه · **پیش‌نیاز:** [۱.۱.۳ — انواعِ مرکب و واکافت](../03-compound-types-and-destructuring/README.fa.md)

---

## چرا اهمیت دارد

تابع نوشتن را بلدی. این درس درباره‌ی نحوِ `fn` نیست — نحوش ده دقیقه‌ای تمام می‌شود. درباره‌ی یک تفاوتِ عمیق‌تر است که اگر ندیده بگیری، ماه‌ها با کامپایلر کشمکش خواهی داشت.

در پایتون زبان به دو نیمه تقسیم شده. یک نیمه **دستور** است — کاری می‌کند: `x = 5`، `if`، `for`، `return`. نیمه‌ی دیگر **عبارت** است — ارزشی دارد: `5`، `x + 1`، `f()`. و این دو با هم قاطی نمی‌شوند. برای همین است که پایتون مجبور شده یک نحوِ جداگانه بسازد تا بتوانی یک تصمیم را در یک مقدار بنشانی:

```python
label = "even" if n % 2 == 0 else "odd"
```

آن `if ... else` وسطِ خط، یک `if` معمولی نیست. یک ساختارِ جداگانه است که فقط به این خاطر به زبان اضافه شد که `if`ِ اصلی دستور بود و ارزشی نداشت.

Rust این تقسیم را تقریباً ندارد. **در Rust تقریباً همه‌چیز عبارت است**: یک بلوک، یک مقایسه، یک `if`، یک `match`. همه ارزشی دارند و همه را می‌شود در یک `let` نشاند. یعنی زبان به ساختارِ دومِ ویژه احتیاج ندارد، و کدی که می‌نویسی کوتاه‌تر و مستقیم‌تر می‌شود.

بهایش یک قاعده است که باید ملکه‌ی ذهنت شود: **سمی‌کالن یک عبارت را به دستور تبدیل می‌کند.** یک سمی‌کالنِ جاافتاده یا اضافه، نوعِ بازگشتیِ تابعت را عوض می‌کند. اگر «expected `u32`, found `()`» را بشناسی، ده‌ها دقیقه از عمرت را پس گرفته‌ای.

## مفهوم

### نوشتنِ یک تابع

```rust
fn area(width: u32, height: u32) -> u32 {
    width * height
}
```

چهار چیز در آن امضا هست و هر چهارتا اجباری‌اند:

| بخش | یعنی |
|---|---|
| `fn` | این یک تابع است |
| `area` | اسمش، به `snake_case` |
| `(width: u32, height: u32)` | پارامترها — **هرکدام با نوعِ صریح** |
| `-> u32` | چه چیزی برمی‌گرداند |

**Rust نوعِ پارامتر را هرگز حدس نمی‌زند.** داخلِ بدنه‌ی تابع مدام حدس می‌زند و در `let` هم حدس می‌زند، ولی در امضا نه — عمداً. امضا قراردادی است بینِ تو و هرکسی که این تابع را صدا می‌زند، و قراردادی که طرفش باید حدسش بزند قرارداد نیست. یک اثرِ جانبیِ خوب هم دارد: وقتی یک تابع خطای نوع می‌دهد، خطا سرِ همان تابع می‌ماند و به کلِ فایل سرایت نمی‌کند.

**ترتیب مهم نیست.** این کاملاً درست است:

```rust
fn main() {
    println!("{}", area(3, 4));
}

fn area(width: u32, height: u32) -> u32 {
    width * height
}
```

Rust کلِ فایل را می‌خواند و بعد کامپایل می‌کند. لازم نیست چیزی را «قبلاً تعریف» کرده باشی.

**نبودنِ `->` یعنی `()`.** تابعی که چیزی برنمی‌گرداند، در واقع همان نوعِ یکه‌ی درسِ قبل را برمی‌گرداند:

```rust
fn announce(order_id: u32) {
    println!("order {order_id} received");
}
```

```text
           order 7 received
announce:  ()
```

### دستور در برابر عبارت

این مرکزِ درس است، و تعریفش یک جمله است:

> **دستور کاری می‌کند. عبارت چیزی می‌ارزد.**

```rust
let total = 3 * 4;
```

آن کلِ خط یک **دستور** است: کاری می‌کند (یک اتصال می‌سازد) و خودش هیچ نمی‌ارزد. ولی `3 * 4` که سمتِ راستش نشسته یک **عبارت** است: می‌ارزد ۱۲.

عبارت‌هایی که تا حالا دیده‌ای: عددهای ثابت، `a + b`، `a == b`، `readings[0]`، `sample.1`، `area(3, 4)`. همه‌شان چیزی می‌ارزند و همه را می‌شود در یک `let` نشاند.

### بلوک هم یک عبارت است

اینجا Rust از پایتون جدا می‌شود:

```rust
let adjusted = {
    let base = 100;
    let bonus = 20;
    base + bonus
};
```

```text
adjusted:  120
```

آن آکولادها یک **بلوک** می‌سازند، و بلوک یک عبارت است. ارزشش برابرِ آخرین عبارتِ داخلش است — همانی که سمی‌کالن ندارد.

پایتون معادلی برای این ندارد. اگر بخواهی چند گام حساب کنی و نتیجه را در یک متغیر بگذاری، یا باید متغیرهای میانی را در فضای بیرونی رها کنی یا یک تابعِ کوچک بنویسی. اینجا `base` و `bonus` بیرونِ آن آکولادها اصلاً وجود ندارند.

### و حالا قاعده‌ی سمی‌کالن

همان بلوک، با یک سمی‌کالنِ اضافه در خطِ آخر:

```rust
let nothing = {
    let base = 100;
    let bonus = 20;
    base + bonus;
};
```

```text
nothing:   ()
```

`120` نیست. `()` است.

سمی‌کالن آن عبارت را به یک دستور تبدیل کرد، بلوک دیگر عبارتی برای ارزش‌گذاری نداشت، و ارزشش شد «هیچ». وقتی این را اجرا کنی کامپایلر هم تذکر می‌دهد، و تذکرش خودِ درس است:

```text
warning: unused arithmetic operation that must be used
  --> examples\02-expressions.rs:24:9
   |
24 |         base + bonus;
   |         ^^^^^^^^^^^^ the arithmetic operation produces a value
```

«این عملیات یک مقدار تولید می‌کند» — و تو دورش ریختی.

### عبارتِ پایانی همان مقدارِ بازگشتی است

بدنه‌ی تابع هم یک بلوک است، پس دقیقاً همین قاعده رویش صدق می‌کند:

```rust
fn with_tail_expression(n: u32) -> u32 {
    n * 3
}

fn with_return(n: u32) -> u32 {
    return n * 3;
}
```

```text
implicit:  30
explicit:  30
```

دو تابعِ یکسان. به همان کدِ ماشین کامپایل می‌شوند. **فرمِ اول اصطلاحِ رایجِ Rust است** و برنامه‌نویسِ Rust سریع‌تر می‌خواندش.

پس `return` برای چیست؟ برای **زودتر بیرون آمدن** — وقتی وسطِ تابع می‌فهمی جواب معلوم است و نمی‌خواهی بقیه را اجرا کنی. برای این کار به شرط احتیاج داری و شرط درسِ بعد است، پس تا آنجا `return` را کنار بگذار.

> **این را به خاطر بسپار، چون قرار است زیاد ببینی‌اش:** اگر کامپایلر گفت «expected `u32`, found `()`»، اول از همه دنبالِ یک سمی‌کالنِ اضافه در خطِ آخرِ تابعت بگرد. نُه بار از ده بار همان است.

### نوعِ هرگز — و اینکه چرا `todo!()` کامپایل می‌شود

سه درس است که داری این را می‌بینی:

```rust
pub fn clamped_add(a: u8, b: u8) -> u8 {
    todo!("add them in the way that clamps at the maximum")
}
```

آن تابع قول داده یک `u8` برگرداند. بدنه‌اش هیچ `u8`ای ندارد. چرا کامپایل می‌شود؟

چون `todo!()` نوعِ خودش را دارد: `!`، **نوعِ هرگز**. نوعِ عبارتی که مقدار تولید نمی‌کند، چون اصلاً تمام نمی‌شود. `todo!()` پنیک می‌کند؛ اجرا هرگز از آن رد نمی‌شود.

و همین‌جاست که ترفند شکل می‌گیرد: اگر یک عبارت هرگز مقداری تولید نکند، آن‌وقت «مقداری که تولید می‌کند» می‌تواند **هر نوعی** باشد، بدونِ اینکه دروغی گفته شود. پس `!` جای هر نوعی می‌نشیند — `u8`، `String`، هر چیزی.

هم‌خانواده‌هایش را هم دیده‌ای یا خواهی دید:

| عبارت | برای چه |
|---|---|
| `todo!()` | هنوز ننوشته‌امش |
| `unimplemented!()` | نمی‌خواهم بنویسمش |
| `panic!()` | اینجا اوضاع خراب است |
| `unreachable!()` | اجرا هرگز به اینجا نمی‌رسد |
| `std::process::exit(1)` | برنامه همین‌جا تمام می‌شود |

هر پنج تا نوعشان `!` است. برای همین است که همه‌ی اسکلت‌های تمرینِ این دوره کامپایل می‌شوند بدونِ اینکه یک خط کدِ واقعی داشته باشند. **`todo!()` یک جای‌نگه‌دار نیست؛ یک وعده است که کامپایلر باورش می‌کند.**

### عملگرها هم عبارت‌اند

این را راحت می‌شود از قلم انداخت، ولی نتیجه‌اش بزرگ است:

```rust
let year = 2024;
let leap = (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
```

```text
2024 leap: true
```

`year % 4 == 0` یک `bool` است، دقیقاً به همان معنایی که `2 + 2` یک `i32` است. یک قاعده‌ی سه‌شاخه در یک خط، **بدونِ هیچ `if`ای**.

`&&` و `||` **اتصالِ کوتاه** دارند: اگر سمتِ چپ جواب را معلوم کند، سمتِ راست اصلاً ارزیابی نمی‌شود. اینجا مهم نیست. جایی خیلی مهم می‌شود که سمتِ راست یک فراخوانیِ گران باشد یا چیزی که ممکن است پنیک کند.

### نام‌گذاری

توابع و متغیرها `snake_case`، ثابت‌ها `SCREAMING_SNAKE_CASE`، نوع‌ها `PascalCase`. لازم نیست حفظش کنی — `cargo clippy` که در [۰.۶](../../../phase0-setup/06-tooling-clippy-fmt-rust-analyzer/README.fa.md) نصبش کردی هر بار یادت می‌اندازد.

## خطاهایی که خواهی دید

### `E0308` — یک سمی‌کالنِ اضافه

پرتکرارترین خطای Rust برای تازه‌کارها، بدونِ رقیب.

```text
error[E0308]: mismatched types
  --> examples\04-stray-semicolon.rs:11:23
   |
11 | fn tripled(n: u32) -> u32 {
   |    -------            ^^^ expected `u32`, found `()`
   |    |
   |    implicitly returns `()` as its body has no tail or `return` expression
12 |     n * 3;
   |          - help: remove this semicolon to return this value
```

**کامپایلر به چه اعتراض دارد:** امضا قول داده `u32` برگردد. بدنه با یک دستور تمام می‌شود، پس ارزشِ کلِ بلوک `()` است.

**راه‌حل:** سمی‌کالن را بردار.

**چرا این راه‌حل است:** دقت کن این خطا چقدر خوب نوشته شده. سه چیز را جدا نشان می‌دهد: کجا قول داده شد (`-> u32`)، چرا شکست (`implicitly returns ()`)، و کدام کاراکتر مقصر است. مکانِ خطا امضای تابع است، ولی *راهنمایی* روی سمی‌کالن است — و راهنمایی همیشه به جای واقعی اشاره می‌کند. عادت کن خطاها را تا آخر بخوانی؛ همان چیزی است که [۰.۵](../../../phase0-setup/05-reading-compiler-errors/README.fa.md) درباره‌اش بود.

### دستور، جایی که عبارت لازم بود

این یکی فایلِ مثالی در درس ندارد: rustfmt نمی‌تواند فایلی را که تجزیه نمی‌شود قالب‌بندی کند، پس نگه داشتنش `cargo fmt --check` را می‌شکست. برای دیدنش خودت در یک فایلِ موقت بچسبانش.

```text
error: expected expression, found `let` statement
 --> statement-as-value.rs:4:14
  |
4 |     let x = (let y = 6);
  |              ^^^
  |
  = note: only supported directly in conditions of `if` and `while` expressions
```

**کامپایلر به چه اعتراض دارد:** سمتِ راستِ یک `let` باید عبارت باشد، و `let y = 6` یک دستور است. دستور چیزی نمی‌ارزد، پس چیزی برای بستن به `x` وجود ندارد.

**راه‌حل:** دو خطش کن.

**چرا این راه‌حل است:** این یکی از معدود جاهایی است که Rust تقسیمِ دستور و عبارت را نگه داشته، و عمدی است: `let x = y = 6` در C کامپایل می‌شود و تقریباً همیشه یعنی برنامه‌نویس `==` می‌خواسته. آن یادداشتِ آخر — «only supported directly in conditions of `if` and `while`» — به `if let` اشاره می‌کند که در [۱.۵.۵](../../05-your-own-types/05-if-let-while-let-let-else/README.fa.md) می‌آید.

### `E0061` — تعدادِ آرگومان‌ها نمی‌خواند

```text
error[E0061]: this function takes 2 arguments but 1 argument was supplied
  --> examples\05-missing-argument.rs:8:20
   |
 8 |     println!("{}", area(3));
   |                    ^^^^--- argument #2 of type `u32` is missing
   |
note: function defined here
  --> examples\05-missing-argument.rs:11:4
   |
11 | fn area(width: u32, height: u32) -> u32 {
   |    ^^^^             -----------
help: provide the argument
   |
 8 |     println!("{}", area(3, /* u32 */));
   |                          +++++++++++
```

**کامپایلر به چه اعتراض دارد:** امضا دو آرگومان می‌خواهد و یکی رسیده. آرگومانِ پیش‌فرض در Rust وجود ندارد.

**راه‌حل:** آرگومانِ دوم را بده.

**چرا این راه‌حل است:** یادداشتِ `note: function defined here` دقیقاً به تعریفِ تابع می‌برد و *همان پارامتری* را که جا افتاده زیرخط می‌کشد. اگر تابعِ کسِ دیگری است، همین یادداشت جای پریدن به تعریفش را می‌گیرد.

### پارامترِ بی‌نوع

```text
error: expected one of `:`, `@`, or `|`, found `)`
 --> untyped-parameter.rs:5:12
  |
5 | fn double(n) -> u32 {
  |            ^ expected one of `:`, `@`, or `|`
  |
help: if this is a parameter name, give it a type
  |
5 | fn double(n: TypeName) -> u32 {
  |            ++++++++++
```

**کامپایلر به چه اعتراض دارد:** پارامترِ بی‌نوع در Rust وجود ندارد. این خطای نوع هم نیست — از این جلوتر اصلاً نمی‌شود کد را تجزیه کرد.

**راه‌حل:** نوع را بنویس.

**چرا این راه‌حل است:** حواست به آن `TypeName` باشد؛ کامپایلر یک نوعِ ساختگی گذاشته چون واقعاً نمی‌داند چه می‌خواستی. برخلافِ `let` که از مقدار حدس می‌زند، در امضا چیزی برای حدس زدن وجود ندارد.

</details>

<summary><code>fn f() { }</code> چه چیزی برمی‌گرداند؟</summary>

`()` — نوعِ یکه. نبودنِ `-> ...` یعنی همین، و بدنه‌ی خالی هم دقیقاً همان را می‌ارزد.

</details>

<details>
<summary>چرا <code>todo!()</code> داخلِ تابعی که <code>-> u8</code> دارد کامپایل می‌شود؟</summary>

چون نوعش `!` است، نوعِ هرگز: هرگز مقداری تولید نمی‌کند، پس می‌تواند جای هر نوعی بنشیند بی‌آنکه دروغی گفته شود.

</details>

<details>
<summary>پرتکرارترین دلیلِ «expected <code>u32</code>, found <code>()</code>» چیست؟</summary>

یک سمی‌کالنِ اضافه در خطِ آخرِ تابع. اول همان را نگاه کن.

</details>

### تعمیر

`examples/04-stray-semicolon.rs` را درست کن. یک کاراکتر است.

بعد عمداً خرابش کن به روشِ دیگری: سمی‌کالن را برگردان و به‌جایش `return` بگذار. کامپایل می‌شود؟ چرا؟

بعد `-> u32` را کلاً از `tripled` بردار، ولی سمی‌کالن را نگه دار. حالا کامپایل می‌شود — و همین جالب است: کدی که خطا نمی‌دهد لزوماً کدی نیست که می‌خواستی.

### پیاده‌سازی

پنج تابع در `src/lib.rs`:

```sh
cargo test -p p1-01-04-functions-and-expressions
```

هر پنج تا را می‌شود بدونِ `return` و بدونِ شرط نوشت. اگر خودت را دیدی که دنبالِ `if` می‌گردی، دوباره به `is_leap_year` نگاه کن — یک تصمیم هم یک عبارت است.

### بساز

دو تابع بنویس:

```rust
pub fn bmi(weight_kg: f64, height_cm: f64) -> f64
pub fn bmi_is_healthy(weight_kg: f64, height_cm: f64) -> bool
```

`bmi` یعنی وزن بر مجذورِ قدِ **به متر**. `bmi_is_healthy` وقتی درست است که BMI بینِ ۱۸٫۵ و ۲۵ باشد — و باید `bmi` را صدا بزند، نه اینکه فرمول را دوباره بنویسد.

بعد یک جمله بنویس درباره‌ی اینکه چرا تابعِ دوم نباید فرمول را تکرار کند. جواب فقط «تکرار بد است» نیست؛ چیزی مشخص درباره‌ی همین دو تابع است.

### چالش (اختیاری)

**بخشِ یک.** بدونِ اجرا کردن، برای هرکدام نوع و مقدار را بنویس:

```rust
let a = { 1 + 1 };
let b = { 1 + 1; };
let c = { let d = 5; };
let e = ();
let f = { { { 7 } } };
```

بعد اجرا کن و ببین چند تا را درست زدی. کدام‌ها هم‌نوع‌اند؟

**بخشِ دو.** این را کامپایل کن:

```rust
fn stop() -> ! {
    todo!("this function never returns")
}
```

بعد جواب بده: چرا `-> !` مجاز است ولی `fn stop() -> ! { 5 }` نیست؟ و چه اتفاقی می‌افتد اگر `todo!()` را با `println!("bye")` عوض کنی؟

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به کارت می‌آید |
|---|---|---|
| امضا | اسم، پارامترهای نوع‌دار، نوعِ بازگشتی | هر تابعی که می‌نویسی |
| دستور | کاری می‌کند، چیزی نمی‌ارزد | `let x = 5;` |
| عبارت | چیزی می‌ارزد | `3 * 4`، `a == b`، یک بلوک |
| بلوکِ عبارتی | `{ ... }` که برابرِ آخرین عبارتش است | گروه‌بندیِ چند گام |
| عبارتِ پایانی | آخرین عبارتِ بدنه، بدونِ سمی‌کالن | مقدارِ بازگشتی |
| `return` | خروجِ صریح | فقط برای زودتر بیرون آمدن |
| `()` | نوعِ یکه، «هیچ مقداری» | نبودنِ `->` |
| `!` | نوعِ هرگز | `todo!`، `panic!`، `unreachable!` |
| اتصالِ کوتاه | `&&` و `||` سمتِ راست را رها می‌کنند | بررسی‌های زنجیره‌ای |

### الان می‌دانی

- پارامترها همیشه نوع می‌گیرند و ترتیبِ تعریفِ توابع در فایل مهم نیست.
- بلوک یک عبارت است و برابرِ آخرین عبارتش می‌ارزد.
- سمی‌کالن عبارت را به دستور تبدیل می‌کند، و بلوک را `()` می‌کند.
- عبارتِ پایانی همان مقدارِ بازگشتی است؛ `return` برای زودتر بیرون آمدن است.
- `!` نوعی است که هیچ مقداری ندارد، و برای همین جای هر نوعی می‌نشیند.
- `&&` و `||` مقدار تولید می‌کنند و اتصالِ کوتاه دارند — یک تصمیم لزوماً به `if` احتیاج ندارد.

### می‌توانی توضیح بدهی؟

- دستور و عبارت چه فرقی دارند، و کدام‌شان `let x = 5;` است؟
- یک بلوک چقدر می‌ارزد؟ و اگر خطِ آخرش سمی‌کالن داشته باشد چطور؟
- چرا Rust نوعِ پارامتر را حدس نمی‌زند ولی نوعِ `let` را حدس می‌زند؟
- `!` چیست و چرا `todo!()` هر امضایی را راضی می‌کند؟
- «expected `u32`, found `()`» یعنی چه و اول کجا را نگاه می‌کنی؟
- چطور یک قاعده‌ی سه‌شاخه را بدونِ `if` می‌نویسی؟
