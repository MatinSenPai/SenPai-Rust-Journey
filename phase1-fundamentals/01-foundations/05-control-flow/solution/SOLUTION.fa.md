# راه‌حل — ۱.۱.۵ جریانِ کنترل

```rust
pub fn grade(score: u32) -> char {
    if score >= 90 {
        'A'
    } else if score >= 80 {
        'B'
    } else if score >= 70 {
        'C'
    } else if score >= 60 {
        'D'
    } else {
        'F'
    }
}

pub fn sum_to(n: u32) -> u32 {
    let mut total = 0;
    for value in 1..=n {
        total += value;
    }
    total
}

pub fn count_digits(n: u32) -> u32 {
    let mut remaining = n;
    let mut digits = 1;
    while remaining >= 10 {
        remaining /= 10;
        digits += 1;
    }
    digits
}

pub fn index_of_first_negative(readings: [i32; 6]) -> usize {
    for position in 0..readings.len() {
        if readings[position] < 0 {
            return position;
        }
    }
    readings.len()
}

pub fn collatz_steps(start: u32) -> u32 {
    let mut current = start;
    let mut steps = 0;
    loop {
        if current == 1 {
            break steps;
        }
        current = if current % 2 == 0 {
            current / 2
        } else {
            current * 3 + 1
        };
        steps += 1;
    }
}
```

## `grade` — کلِ زنجیره یک عبارت است

به چیزی که آنجا **نیست** دقت کن: نه `return`ای، نه سمی‌کالنی سرِ شاخه‌ها، نه یک `let result = ...` که مقدار را جمع کند. زنجیره‌ی `if`/`else if`/`else` یک عبارتِ واحد است، آخرین چیزِ بدنه است، پس *همان* مقدارِ بازگشتی است.

نسخه‌ای که شاید اول نوشتی هم اشکالی ندارد:

```rust
if score >= 90 {
    return 'A';
}
if score >= 80 {
    return 'B';
}
// ...
```

کار می‌کند و قابلِ خواندن است. فرمِ زنجیره‌ای به یک دلیلِ مشخص بهتر است: **کامپایلر بررسی می‌کند که هر مسیر یک `char` تولید کند.** در نسخه‌ی `return`دار، جا انداختنِ حالتِ آخر به تو «expected `char`, found `()`» می‌دهد که به کلِ تابع اشاره می‌کند؛ در فرمِ زنجیره‌ای نبودنِ `else` با `E0317` دقیقاً همان‌جا علامت می‌خورد. کد را طوری بچین که کامپایلر بتواند کمکت کند.

**ترتیب مهم است و همان‌جا تله هست.** `score >= 60` برای ۹۵ هم درست است، نه فقط برای ۶۵. زنجیره کار می‌کند چون هر شاخه فقط وقتی بررسی می‌شود که همه‌ی شاخه‌های بالایش رد شده باشند. باندها را برعکس بچین و همه‌چیز `'D'` می‌شود.

## `sum_to` — `1..=n` و دلیلِ وجودِ `..=`

```rust
for value in 1..=n {
```

`1..n` یکی زودتر می‌ایستد: `sum_to(5)` می‌شد ۱۰ به‌جای ۱۵. `..=` انتها را هم شامل می‌شود.

قاعده‌اش یک بار و شفاف ارزشِ گفتن دارد، چون تعیین می‌کند کدام را برداری: **`a..b` فرمِ طبیعیِ اندیس‌هاست** (`0..len` هر جایگاهِ معتبر را دقیقاً یک بار می‌بیند)، و **`a..=b` فرمِ طبیعیِ شمردنِ چیزهاست** («یک تا پنج» یعنی پنج عدد). اگر خودت را دیدی که `0..len - 1` یا `1..n + 1` می‌نویسی، اشتباه انتخاب کرده‌ای.

`sum_to(0)` بدونِ هیچ حالتِ خاصی کار می‌کند، و این یک لحظه ارزشِ مکث دارد: `1..=0` یک بازه‌ی خالی است و بدنه‌ی حلقه اصلاً اجرا نمی‌شود، پس `total` صفر می‌ماند. بازه‌هایی که بی‌معنا هستند خالی‌اند، نه خطا.

البته فرمِ بسته هم وجود دارد:

```rust
n * (n + 1) / 2
```

همان جواب، بدونِ هیچ حلقه‌ای. کدِ بهتری است و تمرینِ این درس نبود. خوب است بدانی گاوس زودتر رسیده.

## `count_digits` — چرا از ۱ شروع می‌شود

```rust
let mut digits = 1;
while remaining >= 10 {
```

نسخه‌ی بدیهی از صفر شروع می‌کند و `while remaining > 0` می‌نویسد. برای همه‌چیز درست است جز خودِ `0`، که یک رقم دارد و آن‌طوری صفر رقم درمی‌آمد. شروع از ۱ و پرسیدنِ «می‌توانم یکی دیگر بردارم؟» صفر را بدونِ حالتِ خاص حل می‌کند.

این نمونه‌ی کوچکی از چیزی است که ارزشِ نام بردن دارد: **حالتِ مرزی معمولاً به شرطِ حلقه اشاره می‌کند، نه به یک `if`ِ جاافتاده.** وقتی یک حلقه دقیقاً برای یک ورودی اشتباه است، راه‌حل معمولاً بازچینیِ شرط است، نه چسباندنِ یک نگهبان به ابتدایش.

`while` اینجا درست است و `for` نه، چون تا کار تمام نشود هیچ‌کس نمی‌داند چند دور طول می‌کشد. قاعده‌اش همین است: `for` وقتی تعداد از قبل معلوم است، `while` وقتی شرط تصمیم می‌گیرد.

## `index_of_first_negative` — جوابی که عمداً بد است

```rust
for position in 0..readings.len() {
    if readings[position] < 0 {
        return position;
    }
}
readings.len()
```

اینجا دو چیز هم‌زمان دارد یاد داده می‌شود.

**بخشِ خوبش** آن `return`ِ زودهنگام است. همان لحظه که جواب معلوم می‌شود، تابع می‌ایستد. نه متغیرِ پرچم، نه `break` و بعد یک بررسیِ اضافه — کار تمام است، پس برو.

**بخشِ بدش مقدارِ بازگشتی است**، و قرار بود حسش کنی. `6` یعنی «پیدا نشد»، ولی `6` فقط یک عدد هم هست: هیچ چیزی جلوی یک صداکننده را نمی‌گیرد که `readings[index_of_first_negative(r)]` بنویسد و پنیک بگیرد. نوع می‌گوید `usize`، و `usize` نمی‌تواند «چنین چیزی نبود» را بیان کند.

این همان قراردادِ C است، سرچشمه‌ی تعدادِ عظیمی باگِ واقعی است، و دقیقاً همان چیزی است که [۱.۶.۱ — `Option`](../../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) برای حذفش وجود دارد. وقتی به آنجا برسی، امضا می‌شود `-> Option<usize>` و صداکننده **نمی‌تواند** از جواب استفاده کند بی‌آنکه اول با احتمالِ نبودنش روبه‌رو شود. آن‌وقت این تابع را به یاد بیاور.

## `collatz_steps` — `loop` و `break` با مقدار

```rust
let mut current = start;
let mut steps = 0;
loop {
    if current == 1 {
        break steps;
    }
    current = if current % 2 == 0 { current / 2 } else { current * 3 + 1 };
    steps += 1;
}
```

دو چیز آنجا جایشان را حق دارند.

**`break steps` یک مقدار را از حلقه بیرون می‌آورد**، پس کلِ `loop` یک عبارت است و *همان* مقدارِ بازگشتیِ تابع است. این همان ایده‌ی عبارتِ پایانی از [۱.۱.۴](../../04-functions-and-expressions/README.fa.md) است که روی یک حلقه اعمال شده.

**`current = if ... { } else { }`** همان `if`ِ عبارتیِ این درس است که دارد کارِ واقعی می‌کند. جایگزینش این است:

```rust
if current % 2 == 0 {
    current /= 2;
} else {
    current = current * 3 + 1;
}
```

هر دو درست‌اند. نسخه‌ی عبارتی یک بار می‌گوید «`current` یکی از این دو چیز می‌شود» به‌جای اینکه دو بار بگوید «به `current` نسبت بده» — و اگر `current` را تغییرِ نام بدهی، یک جا عوض می‌شود نه دو جا.

**چرا `loop` و نه `while current != 1`؟** نسخه‌ی `while` اینجا واقعاً خوب است و کمی کوتاه‌تر. `loop` انتخاب شد تا `break` با مقدار جایی برای دیده شدن داشته باشد. در کدِ واقعی، وقتی شرط را می‌شود از قبل بیان کرد `while` بردار، و `loop` را برای وقتی نگه دار که خروج وسطِ کار است یا باید چیزی از آن برگردانی.

## این درس واقعاً درباره‌ی چه بود

- **`if` یک عبارت است**، پس یک تصمیم یک مقدار است. همین که این جا بیفتد، حجمِ زیادی از کدی که با یک انباشتگرِ `mut` می‌نوشتی جمع می‌شود.
- **همه‌ی شاخه‌ها باید سرِ یک نوع توافق کنند**، و این محدودیت یک ویژگی است: همین است که به کامپایلر اجازه می‌دهد بفهمد همه‌ی حالت‌ها را پوشانده‌ای.
- **درستی‌نمایی وجود ندارد.** شرط یک `bool` است. `if x` که در آن `x` عدد باشد کامپایل نمی‌شود، و هر باگِ «if (x = 5)» در تاریخِ C برای تو در دسترس نیست.
- **سه حلقه، سه کار:** `for` وقتی تعداد معلوم است، `while` وقتی شرط تصمیم می‌گیرد، `loop` وقتی از وسط بیرون می‌زنی.
- **`return` برای زودتر بیرون آمدن است**، و حلقه همان جایی است که ارزشش را ثابت می‌کند.
