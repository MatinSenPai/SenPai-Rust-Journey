# ۱.۱.۵ — جریانِ کنترل

## در یک نگاه

بعد از این درس می‌توانی:

- یک تصمیم را به‌صورتِ *مقدار* بنویسی، نه به‌صورتِ چند دستورِ پشتِ سرِ هم.
- بگویی چرا `if x` وقتی `x` یک عدد است کامپایل نمی‌شود، و چرا این خبرِ خوبی است.
- بینِ `for` و `while` و `loop` انتخاب کنی و دلیلش را بگویی.
- یک مقدار را با `break` از دلِ یک حلقه بیرون بیاوری، و از یک حلقه‌ی تو در تو با برچسب بیرون بزنی.

**زمان:** حدود ۴۵ دقیقه · **پیش‌نیاز:** [۱.۱.۴ — توابع و عبارت‌ها](../04-functions-and-expressions/README.fa.md)

---

## چرا اهمیت دارد

`if` و `for` را در هر زبانی نوشته‌ای. دو چیز اینجا فرق می‌کند و هر دو مهم‌اند.

**اول: `if` یک عبارت است.** درسِ قبل گفت تقریباً همه‌چیز در Rust ارزشی دارد؛ حالا این را روی تصمیم‌ها می‌بینی. پایتون برای این کار مجبور شد یک نحوِ دوم بسازد:

```python
grade = "A" if score >= 90 else "B"     # نحوِ ویژه
if score >= 90:                          # و این، که ارزشی ندارد
    grade = "A"
```

در Rust فقط یک `if` هست و همان هم مقدار تولید می‌کند. یعنی الگویی که در پایتون و جاوا مدام می‌نویسی — «متغیر را تعریف کن، بعد در شاخه‌ها مقدارش را عوض کن» — اینجا لازم نیست، و متغیرت هم لازم نیست `mut` باشد.

**دوم: شرط باید `bool` باشد.** در پایتون `if items:` یعنی «اگر خالی نیست». در C، `if (n)` یعنی «اگر صفر نیست». در Rust هیچ‌کدام کامپایل نمی‌شود.

اولش اذیت می‌کند. بعد یادت می‌آید که یکی از قدیمی‌ترین باگ‌های C این است:

```c
if (x = 5) { ... }   // انتساب، نه مقایسه — و همیشه درست است
```

آن باگ برای تو در دسترس نیست. `x = 5` ارزشش `()` است و `()` یک `bool` نیست، پس کامپایلر جلویش را می‌گیرد. **یک کلاسِ کاملِ اشتباه، حذف‌شده با یک قاعده‌ی ساده.**

## مفهوم

### `if`، `else if`، `else`

```rust
if score >= 90 {
    println!("grade:     A");
} else if score >= 70 {
    println!("grade:     B");
} else {
    println!("grade:     C");
}
```

```text
grade:     B
```

دو تفاوتِ ظاهری با چیزی که عادت داری:

- **پرانتز دورِ شرط نمی‌خواهد.** می‌شود گذاشت ولی clippy تذکر می‌دهد.
- **آکولاد اجباری است**، حتی برای یک خط. آن `if (x) foo();` که یک روز کسی خطِ دوم را زیرش اضافه می‌کند و همه‌چیز خراب می‌شود، اینجا ممکن نیست.

### `if` به‌عنوان عبارت

اینجا جالب می‌شود:

```rust
let grade = if score >= 90 {
    'A'
} else if score >= 70 {
    'B'
} else {
    'C'
};
```

```text
grade:     B
```

دقت کن به آن سمی‌کالنِ آخر بعد از `}`: کلِ `if` سمتِ راستِ یک `let` است، پس این خط یک دستورِ `let` است مثلِ هر `let`ِ دیگری.

سه قاعده که با هم می‌آیند:

**۱. همه‌ی شاخه‌ها باید هم‌نوع باشند.** یک اتصال دقیقاً یک نوع دارد. `if ... { 'B' } else { "failed" }` کامپایل نمی‌شود، و خطایش در بخشِ بعدی است.

**۲. وقتی به‌عنوان مقدار استفاده می‌شود، `else` اجباری است.** بدونِ آن، وقتی شرط نادرست باشد هیچ مقداری وجود ندارد — و Rust در آن حالت `()` می‌دهد، که با نوعِ شاخه‌ی دیگر نمی‌خواند. باز هم خطایش پایین است.

**۳. شرط باید `bool` باشد.**

```rust
let capped = if score > 100 { 100 } else { score };
let message = if stock == 0 { "sold out" } else { "in stock" };
```

```text
capped:    73
message:   sold out
```

الگویی که این جایگزینش می‌کند را بشناس، چون احتمالاً عادتِ توست:

```rust
// چیزی که از زبانِ قبلی‌ات با خودت می‌آوری
let mut grade = 'C';
if score >= 90 {
    grade = 'A';
}
```

کار می‌کند. ولی `grade` را مجبور کردی `mut` باشد، یک مقدارِ اولیه‌ی الکی نوشتی، و اگر شاخه‌ای را جا بیندازی کامپایلر چیزی نمی‌گوید چون مقدارِ اولیه پوششش می‌دهد. **نسخه‌ی عبارتی هر سه مشکل را ندارد.**

### سه حلقه

Rust سه ساختارِ حلقه دارد و هرکدام کارِ خودش را دارد.

#### `for` — وقتی تعداد از قبل معلوم است

```rust
for n in 0..5 {
    print!("{n} ");
}
```

```text
0..5:      0 1 2 3 4 
```

`0..5` یک **بازه** است: از صفر شروع می‌کند و *قبل* از پنج می‌ایستد. اگر انتها را هم می‌خواهی، `..=`:

```text
0..=5:     0 1 2 3 4 5 
```

| فرم | شامل | کِی |
|---|---|---|
| `a..b` | `a` تا `b - 1` | اندیس‌ها — `0..len` هر جایگاه را دقیقاً یک بار می‌بیند |
| `a..=b` | `a` تا `b` | شمردنِ چیزها — «یک تا پنج» یعنی پنج عدد |

اگر خودت را دیدی که `0..len - 1` یا `1..n + 1` می‌نویسی، فرمِ اشتباه را برداشته‌ای.

و روی خودِ آرایه هم می‌شود حلقه زد، بدونِ هیچ اندیسی:

```rust
let readings = [12, 7, 19, 3, 14];
let mut total = 0;
for reading in readings {
    total += reading;
}
```

```text
total:     55
```

**اینجا `for`ِ C-ای با سه بخش وجود ندارد.** نه `for (i = 0; i < n; i++)`. اولش کم به‌نظر می‌رسد و بعد می‌فهمی که آن سه بخش دقیقاً همان جایی بود که خطای یکی‌کم‌یکی‌زیاد زاده می‌شد. `for x in collection` هیچ اندیسی ندارد که غلط باشد.

#### `while` — وقتی شرط تصمیم می‌گیرد

```rust
let mut remaining = 100;
let mut halvings = 0;
while remaining > 1 {
    remaining /= 2;
    halvings += 1;
}
```

```text
halvings:  6
```

هیچ‌کس از قبل نمی‌داند شش بار طول می‌کشد. برای همین `while` است نه `for`.

#### `loop` — وقتی از وسط بیرون می‌زنی

```rust
let mut attempt = 0;
let outcome = loop {
    attempt += 1;
    if attempt * attempt > 50 {
        break attempt;
    }
};
```

```text
outcome:   8
```

`loop` تا ابد اجرا می‌شود مگر چیزی بیرونش بیندازد. سؤالِ منصفانه این است که چرا وقتی `while true` هست، `loop` هم باشد. دو دلیل:

- **نیت را می‌گوید.** `loop` یعنی «این عمداً بی‌پایان است»، نه «شرطی داشتم که ساده شد».
- **کامپایلر می‌داند بی‌پایان است.** پس می‌داند اجرا از پایینش رد نمی‌شود، و می‌تواند سخت‌گیرانه‌تر درباره‌ی مقداردهی و نوعِ بازگشتی نتیجه بگیرد.

و آن `break attempt` نکته‌ی اصلی است: **`break` می‌تواند یک مقدار را بیرون بیاورد**، پس `loop` هم یک عبارت است، مثلِ هر چیزِ دیگری در این زبان. (`while` و `for` این را ندارند؛ فقط `loop`.)

### `continue` و برچسب‌ها

`continue` بقیه‌ی این دور را رد می‌کند:

```rust
for n in 0..10 {
    if n % 2 == 0 {
        continue;
    }
    print!("{n} ");
}
```

```text
odds:      1 3 5 7 9 
```

و وقتی حلقه‌ها تو در تو باشند، `break` نزدیک‌ترین را ترک می‌کند — که معمولاً آن چیزی نیست که می‌خواهی. برچسب این را حل می‌کند:

```rust
'search: for row_index in 0..grid.len() {
    for column_index in 0..grid[row_index].len() {
        if grid[row_index][column_index] > 6 {
            found = (row_index, column_index);
            break 'search;
        }
    }
}
```

```text
found at:  (0, 2)
```

آن `'search` یک **برچسبِ حلقه** است. علامتِ `'` جلویش همان چیزی است که در `'static` دیده‌ای و بعداً در طولِ‌عمرها می‌بینی. اگر C بلدی: این `goto` نیست. فقط می‌شود از حلقه‌های محصورکننده بیرون زد و به هیچ نقطه‌ی دلخواهی نمی‌شود پرید.

### `return`ِ زودهنگام — بالاخره کاربردی پیدا کرد

درسِ قبل گفت `return` برای زودتر بیرون آمدن است و باید صبر کنی. حالا:

```rust
fn split_evenly(total: u32, parts: u32) -> u32 {
    if parts == 0 {
        return 0;
    }
    total / parts
}
```

به این شکل **نگهبان** (guard clause) می‌گویند: حالتِ غیرممکن را اول تمام کن و برو، تا بقیه‌ی تابع لازم نباشد به آن فکر کند. جایگزینش این است که کلِ کارِ اصلی داخلِ یک `else` فرو برود، و هر نگهبانِ تازه یک سطحِ تورفتگی اضافه کند.

> برگرداندنِ `0` برای «نمی‌شود تقسیم کرد» جوابِ بدی است و احتمالاً همین حالا هم حسش می‌کنی: `0` یک جوابِ واقعیِ کاملاً معتبر هم هست. این را [۱.۶.۱](../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) درست می‌کند. فعلاً فقط بدان که ناراحت‌کننده است.

و کاربردِ دومش، بیرون آمدن از دلِ یک حلقه همان لحظه که جواب معلوم شد:

```rust
fn is_prime(n: u32) -> bool {
    if n < 2 {
        return false;
    }
    let mut divisor = 2;
    while divisor * divisor <= n {
        if n % divisor == 0 {
            return false;
        }
        divisor += 1;
    }
    true
}
```

```text
prime 97:  true
prime 91:  false
```

### پس کدام را کِی؟

| می‌خواهی | بردار |
|---|---|
| یک تصمیم که مقدار می‌دهد | `if`/`else` به‌عنوان عبارت |
| هر عنصرِ یک مجموعه | `for x in collection` |
| هر عددِ یک بازه | `for n in a..b` |
| تا وقتی شرطی برقرار است | `while` |
| بی‌پایان، با خروج از وسط | `loop` |
| یک مقدار از دلِ حلقه بیرون بیاید | `loop` + `break value` |
| بیرون زدن از حلقه‌ی بیرونی | `break 'label` |

## خطاهایی که خواهی دید

### `E0308` — شرط `bool` نیست

```text
error[E0308]: mismatched types
  --> examples\04-truthiness.rs:10:8
   |
10 |     if remaining {
   |        ^^^^^^^^^ expected `bool`, found integer
```

**کامپایلر به چه اعتراض دارد:** `remaining` یک عدد است و `if` یک `bool` می‌خواهد. Rust هیچ چیزی را به‌طورِ خودکار به `bool` تبدیل نمی‌کند.

**راه‌حل:** بنویس چه چیزی را واقعاً می‌پرسی: `if remaining > 0` یا `if remaining != 0`.

**چرا این راه‌حل است:** «درستی‌نمایی» در واقع یعنی زبان از طرفِ تو حدس بزند که «صفر یعنی نه». برای عدد شاید بدیهی باشد؛ برای یک رشته‌ی خالی، یک لیستِ خالی، یا `-1` اصلاً بدیهی نیست. Rust از حدس زدن امتناع می‌کند و در عوض یک کاراکترِ بیشتر تایپ می‌کنی که دقیقاً می‌گوید چه پرسیدی. همین است که `if (x = 5)` را غیرِممکن می‌کند.

### `E0308` — شاخه‌ها هم‌نوع نیستند

```text
error[E0308]: `if` and `else` have incompatible types
 --> examples\05-branch-types.rs:9:47
  |
9 |     let grade = if score >= 70 { 'B' } else { "failed" };
  |                                  ---          ^^^^^^^^ expected `char`, found `&str`
  |                                  |
  |                                  expected because of this
```

**کامپایلر به چه اعتراض دارد:** `grade` یک نوع دارد. شاخه‌ی اول `char` تولید می‌کند و شاخه‌ی دوم چیزِ دیگری.

**راه‌حل:** هر دو شاخه را هم‌نوع کن.

**چرا این راه‌حل است:** به `expected because of this` دقت کن — کامپایلر نوع را از **شاخه‌ی اول** برداشت و بقیه را با آن سنجید. یعنی اگر ترتیبِ شاخه‌ها را عوض کنی، همین خطا با نوع‌های جابه‌جا شده ظاهر می‌شود. مقصر واقعاً شاخه‌ی دوم نیست؛ این دو با هم نمی‌خوانند.

### `E0317` — `if` بدونِ `else`، به‌عنوان مقدار

```text
error[E0317]: `if` may be missing an `else` clause
 --> missing-else.rs:3:18
  |
3 |     let capped = if score > 100 { 100 };
  |                  ^^^^^^^^^^^^^^^^^---^^
  |                  |                |
  |                  |                found here
  |                  expected integer, found `()`
  |
  = note: `if` expressions without `else` evaluate to `()`
  = help: consider adding an `else` block that evaluates to the expected type
```

(این یکی فایلِ مثالی در درس ندارد — یک `let` است، نه یک تابعِ کامل.)

**کامپایلر به چه اعتراض دارد:** وقتی شرط نادرست باشد، آن `if` هیچ مقداری تولید نمی‌کند، و «هیچ مقداری» در Rust یعنی `()`. پس شاخه‌ها می‌شوند `i32` و `()`، که با هم نمی‌خوانند.

**راه‌حل:** یک `else` اضافه کن که مقداری از همان نوع بدهد.

**چرا این راه‌حل است:** یادداشتِ آخر همان قاعده را صریح می‌گوید: **`if` بدونِ `else` ارزشش `()` است.** برای همین است که به‌عنوان دستور کاملاً مجاز است (کارِ آن `if` انجامِ کاری بود، نه تولیدِ مقدار) و به‌عنوان مقدار مجاز نیست. یک قاعده، دو رفتار.

## تمرین

### گرم‌کردن

<details>
<summary>چرا <code>if remaining { }</code> وقتی <code>remaining</code> یک عدد است کامپایل نمی‌شود؟</summary>

چون شرط باید `bool` باشد و Rust هیچ تبدیلِ خودکاری به `bool` ندارد. «صفر یعنی نادرست» حدسی است که Rust حاضر نیست از طرفت بزند.

</details>

<details>
<summary><code>0..5</code> چند عدد دارد؟ <code>0..=5</code> چطور؟</summary>

پنج تا (۰ تا ۴) و شش تا (۰ تا ۵). برای اندیس زدنِ آرایه‌ای به طولِ ۵، `0..5` درست است.

</details>

<details>
<summary><code>let x = if c { 1 };</code> چرا خطا می‌دهد؟</summary>

چون وقتی `c` نادرست باشد آن `if` چیزی تولید نمی‌کند، یعنی `()`. شاخه‌ها می‌شوند `i32` و `()` و با هم نمی‌خوانند. به‌عنوان مقدار، `else` اجباری است.

</details>

<details>
<summary><code>loop</code> چه چیزی دارد که <code>while true</code> ندارد؟</summary>

دو چیز: نیت را صریح می‌گوید، و کامپایلر می‌داند از پایینش رد نمی‌شود. و فقط `loop` است که می‌تواند با `break value` مقدار بیرون بدهد.

</details>

<details>
<summary>در یک حلقه‌ی تو در تو، <code>break</code> کدام حلقه را ترک می‌کند؟</summary>

نزدیک‌ترین را. برای بیرون زدن از بیرونی، آن را برچسب بزن و `break 'label` بنویس.

</details>

<details>
<summary>«نگهبان» چیست و چه چیزی را بهتر می‌کند؟</summary>

یک `return`ِ زودهنگام در ابتدای تابع که حالتِ استثنایی را تمام می‌کند. بقیه‌ی تابع دیگر لازم نیست به آن فکر کند، و کدِ اصلی داخلِ `else` فرو نمی‌رود.

</details>

`index_of_first_negative` عمداً یک امضای بد دارد. هنگامِ نوشتنش حواست باشد چه چیزی آزارت می‌دهد — [۱.۶.۱](../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) دقیقاً همان را حل می‌کند.

### بساز

یک `pub fn nth_prime(n: u32) -> u32` بنویس که `n`اُمین عددِ اول را برگرداند، با شروع از `nth_prime(1) == 2`.

به دو حلقه احتیاج داری: یکی برای گشتن دنبالِ عددِ اولِ بعدی، یکی برای بررسیِ اول بودن. `is_prime` را از `examples/03-early-return.rs` بردار.

بعد یک جمله بنویس درباره‌ی اینکه چرا حلقه‌ی بیرونی `loop` است و نه `for`.

### چالش (اختیاری)

**بخشِ یک.** این را با یک `for` و بازه بنویس، بعد دوباره با `while`:

```
اعدادِ ۱ تا ۲۰ را چاپ کن، ولی مضرب‌های ۳ را رد کن.
```

بعد بگو کدام نسخه راحت‌تر خراب می‌شود، و چرا.

**بخشِ دو.** این را اجرا کن و توضیح بده:

```rust
let result = 'outer: loop {
    let mut n = 0;
    loop {
        n += 1;
        if n > 5 {
            break 'outer n * 100;
        }
    }
};
println!("{result}");
```

آن `break 'outer n * 100` سه کار هم‌زمان می‌کند. هر سه را نام ببر.

**بخشِ سه.** بدونِ اجرا کردن، بگو این چه چاپ می‌کند و چرا:

```rust
for n in (0..10).step_by(3) {
    print!("{n} ");
}
```

بعد اجرا کن. اگر جوابت غلط بود، `step_by` را در مستندات پیدا کن و بخوان.

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به کارت می‌آید |
|---|---|---|
| `if` به‌عنوان عبارت | یک تصمیم که مقدار می‌دهد | `let x = if ...` |
| هم‌نوعیِ شاخه‌ها | همه‌ی شاخه‌ها یک نوع تولید می‌کنند | هر `if`ای که مقدار است |
| نبودنِ درستی‌نمایی | شرط باید `bool` باشد | هر شرطی |
| بازه `a..b` | از `a` تا `b - 1` | اندیس‌ها |
| بازه `a..=b` | از `a` تا `b` | شمردن |
| `for` | تعداد از قبل معلوم | مجموعه‌ها، بازه‌ها |
| `while` | تا وقتی شرط برقرار است | تعدادِ نامعلوم |
| `loop` | بی‌پایان تا `break` | خروج از وسط |
| `break value` | یک مقدار از حلقه بیرون می‌آید | فقط `loop` |
| `continue` | بقیه‌ی این دور را رد کن | فیلتر کردن |
| برچسبِ حلقه `'name` | `break` کدام حلقه را ترک کند | حلقه‌های تو در تو |
| نگهبان | `return`ِ زودهنگام برای حالتِ استثنایی | ابتدای تابع |

### الان می‌دانی

- `if` یک عبارت است، پس یک تصمیم یک مقدار است و متغیرت لازم نیست `mut` باشد.
- همه‌ی شاخه‌ها باید هم‌نوع باشند، و به‌عنوان مقدار `else` اجباری است.
- شرط باید `bool` باشد؛ درستی‌نمایی وجود ندارد.
- `a..b` انتها را نمی‌گیرد و `a..=b` می‌گیرد.
- `for` وقتی تعداد معلوم است، `while` وقتی شرط تصمیم می‌گیرد، `loop` وقتی از وسط بیرون می‌زنی.
- `break` می‌تواند مقدار بیرون بیاورد و با برچسب می‌تواند از حلقه‌ی بیرونی بیرون بزند.
- `return`ِ زودهنگام برای نگهبان‌ها و برای ایستادن به‌محضِ معلوم شدنِ جواب است.

### می‌توانی توضیح بدهی؟

- چرا `let grade = if ... else ...` بهتر از تعریفِ یک `mut` و عوض کردنش در شاخه‌هاست؟
- چرا شرط باید `bool` باشد، و چه باگی را این حذف می‌کند؟
- `0..n` و `0..=n` چه فرقی دارند و هرکدام کِی درست‌اند؟
- سه حلقه را نام ببر و بگو هرکدام کِی درست است.
- `break` چطور می‌تواند مقدار برگرداند و کدام حلقه این را دارد؟
- نگهبان چیست و چرا کد را بهتر می‌کند؟
