# راه‌حل — ۱.۱.۶ مقدماتِ `Vec` و `String`

```rust
pub fn evens_up_to(n: u32) -> Vec<u32> {
    let mut evens = Vec::new();
    for value in 0..=n {
        if value % 2 == 0 {
            evens.push(value);
        }
    }
    evens
}

pub fn total(values: Vec<i64>) -> i64 {
    let mut sum = 0;
    for value in &values {
        sum += value;
    }
    sum
}

pub fn largest(values: Vec<i32>) -> i32 {
    let mut best = values[0];
    for value in &values {
        if *value > best {
            best = *value;
        }
    }
    best
}

pub fn joined(parts: Vec<String>, separator: char) -> String {
    let mut out = String::new();
    for index in 0..parts.len() {
        if index > 0 {
            out.push(separator);
        }
        out.push_str(&parts[index]);
    }
    out
}

pub fn byte_and_char_count(text: String) -> (usize, usize) {
    (text.len(), text.chars().count())
}
```

## `evens_up_to` — `Vec::new()` و اینکه نوعش از کجا می‌آید

```rust
let mut evens = Vec::new();
```

هیچ نوعی ننوشته‌ای و کامپایل می‌شود. Rust جلوتر را نگاه می‌کند: دو خط بعد یک `u32` را `push` می‌کنی و تابع قول داده `Vec<u32>` برگرداند، پس `evens` یک `Vec<u32>` است. آن `push` را پاک کن و نوشتنِ نوع اجباری می‌شود، چون دیگر چیزی برای استنتاج نمی‌ماند.

`0..=n` مهم است: `0..n` خودِ `n` را می‌انداخت، پس `evens_up_to(10)` سرِ ۸ می‌ایستاد. همان تله‌ی [۱.۱.۵](../../05-control-flow/README.fa.md).

نسخه‌ی کوتاه‌ترش با ابزارهای [فاز ۲](../../../../phase2-intermediate/02-iterators-and-closures/README.fa.md) وجود دارد:

```rust
(0..=n).filter(|value| value % 2 == 0).collect()
```

یک خط، بدونِ `mut`، بدونِ متغیرِ میانی. ارزش دارد همین حالا ببینی‌اش تا وقتی ایتریتورها آمدند بفهمی جایگزینِ چه چیزی شده‌اند.

## `total` — آن `&values` و دلیلِ بودنش

```rust
for value in &values {
```

`&` را بردار و باز هم کامپایل می‌شود — و آن‌وقت `values` دیگر نیست، حلقه مصرفش کرده. امتحان کن: بعد از حلقه یک `println!("{values:?}")` اضافه کن؛ نسخه‌ی `&`دار کامپایل می‌شود و آن یکی نه.

این اولین برخوردِ تو با **مالکیت** است، که کلِ [ماژولِ ۱.۲](../../../02-ownership-and-memory/README.fa.md) درباره‌ی آن است. خلاصه‌ی یک‌خطی‌اش: `for value in values` وکتور را به حلقه *می‌دهد* و `for value in &values` فقط *قرض* می‌دهد. چون این تابع بعدش کاری با `values` ندارد، هر دو اینجا کار می‌کنند. `&` همان عادتی است که ارزشِ ساختن دارد.

`sum += value` که در آن `value` یک `&i64` است هم کار می‌کند، چون `+=` می‌داند با یک مرجع به عدد چه کند. این راحتی‌ای است که به‌زودی دیگر متوجهش نمی‌شوی.

## `largest` — آن دو ستاره

```rust
if *value > best {
    best = *value;
}
```

اینجا `value` یک `&i32` است نه `i32`، چون `&values` هر عنصر را قرض می‌دهد نه اینکه تحویلش بدهد. `*` یعنی «آن چیزی که به آن اشاره شده». بدونِ آن داری یک مرجع را با یک عدد مقایسه می‌کنی و کامپایلر اعتراض می‌کند.

یک فرمِ کوتاه‌تر هم هست که ارزشِ دانستن دارد: مرجع را همان‌جا در خودِ حلقه با الگو باز کن.

```rust
for &value in &values {
    if value > best {
        best = value;
    }
}
```

آن `&value` سمتِ چپ یک *الگو* است — همان ماشینی که در [۱.۱.۳](../../03-compound-types-and-destructuring/README.fa.md) دیدی، که شکلِ «یک مرجع به چیزی» را تطبیق می‌دهد و آن چیز را می‌بندد. هر دو فرم اصطلاحی‌اند. همه‌ی این‌ها درسِ کاملِ خودشان را در [۱.۳.۱](../../../03-borrowing-and-references/01-shared-and-mutable-refs/README.fa.md) دارند.

**`values[0]` یک ریسکِ واقعی است** و چیزی که نجاتش می‌دهد خودِ مشخصات است. کامنتِ مستندات می‌گوید `values` هرگز خالی نیست؛ اگر بود، `values[0]` پنیک می‌کرد. وقتی `Option` را داشته باشی `.first()` می‌نویسی و دیگر هیچ قولی لازم نیست.

## `joined` — چرا این یکی اندیس می‌زند

هر تمرینِ دیگری اینجا روی عنصرها حلقه می‌زند. این یکی روی جایگاه‌ها:

```rust
for index in 0..parts.len() {
    if index > 0 {
        out.push(separator);
    }
```

چون قاعده درباره‌ی خودِ بخش‌ها نیست، درباره‌ی *فاصله‌های بینشان* است: جداکننده قبل از هر بخش می‌آید جز اولی. و اندیس همان چیزی است که می‌داند کدام بخش اولی است.

نسخه‌ی پرچم‌دار هم به همان اندازه درست و کمی دست‌وپاگیرتر است:

```rust
let mut first = true;
for part in &parts {
    if !first {
        out.push(separator);
    }
    out.push_str(part);
    first = false;
}
```

**`push` در برابر `push_str`.** `push` یک `char` می‌گیرد؛ `push_str` متن می‌گیرد. جداکننده یک `char` است و بخش‌ها `String`اند، پس هرکدام متدِ خودش را دارد. Rust یک `push`ِ سربارگذاری‌شده ندارد چون `char` و `&str` واقعاً دو چیزِ متفاوت‌اند — یک `char` دقیقاً یک اسکالرِ یونیکد است و یک `&str` هر تعداد بایت.

کتابخانه‌ی استاندارد البته این را دارد:

```rust
parts.join(&separator.to_string())
```

از تو خواسته شد یک بار دستی بسازی‌اش تا بدانی `join` دارد چه می‌کند. [۱.۴.۳](../../../04-text-and-strings/03-building-and-transforming-strings/README.fa.md) نسخه‌ی واقعی را می‌گوید.

## `byte_and_char_count` — مهم‌ترینش

```rust
(text.len(), text.chars().count())
```

یک خط، و مهم‌ترین خطِ این درس.

```text
english:   hello
  bytes:   5
  chars:   5
persian:   سلام
  bytes:   8
  chars:   4
```

**`len()` بایت می‌شمارد.** همیشه. اینطور نیست که «معمولاً کاراکتر است و گاهی نه» — یک شمارشِ بایت است که وقتی همه‌ی کاراکترها ASCII باشند اتفاقاً با شمارشِ کاراکتر برابر درمی‌آید. و دقیقاً به همین دلیل است که این باگ زنده می‌ماند: اگر همه‌ی داده‌ی تستت انگلیسی باشد، `len()` طوری به‌نظر می‌رسد که انگار کاراکتر می‌شمارد و همه‌ی تست‌ها پاس می‌شوند.

همان را به کاربرِ فارسی‌زبان تحویل بده و می‌شکند: متنی که وسطِ حرف بریده می‌شود، «حداکثر ۲۰ کاراکتر»ی که یک اسمِ ده‌حرفی را رد می‌کند، ستون‌هایی که تراز نمی‌شوند.

**چرا `len()` بایت است و نه کاراکتر؟** چون `len()` آنی است و شمردنِ کاراکتر نیست. یک `String` می‌داند چند بایت دارد؛ برای اینکه بداند چند کاراکتر دارد، چیزی باید کلش را قدم‌به‌قدم رمزگشایی کند — که دقیقاً همان کاری است که `.chars().count()` می‌کند. Rust اسمِ کوتاه را به عملیاتِ ارزان می‌دهد و مجبورت می‌کند گران را صریح بخواهی، به‌جای اینکه یک پیمایشِ O(n) را پشتِ چیزی که شبیهِ خواندنِ یک فیلد است پنهان کند.

**و خودِ کلمه‌ی «کاراکتر» هم غلط است**، و اینجاست که ماجرا واقعاً عمیق می‌شود. `.chars()` اسکالرهای یونیکد را می‌شمارد. برای `سلام` می‌شود ۴ و با آنچه می‌گویی می‌خواند. ولی برای متنی با علامت‌های ترکیبی، یا یک ایموجی با تغییردهنده‌ی رنگِ پوست، چیزی که یک آدم «یک کاراکتر» صدایش می‌زند می‌تواند چند اسکالر باشد. [۱.۴.۲ — یوتی‌اف-۸، بایت، کاراکتر، گرافیم](../../../04-text-and-strings/02-utf8-bytes-chars-graphemes/README.fa.md) درسِ کاملش است، و برای کسی که نرم‌افزارِ فارسی می‌نویسد یکی از باارزش‌ترین درس‌های این دوره است.

## این درس واقعاً درباره‌ی چه بود

- **`Vec<T>` و `String` یک ایده‌اند که دو بار تکرار شده**: یک بافرِ مالکْ‌دار و رشدکننده روی هیپ. `String` تقریباً همان `Vec<u8>` است، با این قول که بایت‌هایش UTF-8ِ معتبر باشند.
- **رشدکننده یعنی مالکْ‌دار یعنی هیپ**، و این پیامدهایی دارد که در [ماژولِ ۱.۲](../../../02-ownership-and-memory/README.fa.md) مستقیم به آن‌ها می‌خوری.
- **`&` سرِ یک حلقه یعنی «قرض بده، نده»** — اولین تصمیمِ مالکیتی که مجبور شده‌ای بگیری، و آخرین درسی که می‌شود بدونِ فهمیدنش از آن رد شد.
- **`len()` بایت است.** یک جایی بنویسش.
