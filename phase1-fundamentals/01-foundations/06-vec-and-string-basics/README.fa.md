# ۱.۱.۶ — مقدماتِ `Vec` و `String`

## در یک نگاه

بعد از این درس می‌توانی:

- یک `Vec` و یک `String` بسازی، رشدشان بدهی و بخوانی‌شان.
- بگویی چرا آرایه روی پشته می‌نشیند و `Vec` روی هیپ، و این یعنی چه.
- بگویی چرا `text.len()` برای «سلام» می‌شود ۸ و نه ۴ — و چرا این مهم‌ترین چیزی است که در این درس یاد می‌گیری.
- تفاوتِ `String` و `&str` را در یک جمله بگویی.

**زمان:** حدود ۵۰ دقیقه · **پیش‌نیاز:** [۱.۱.۵ — جریانِ کنترل](../05-control-flow/README.fa.md)

---

## چرا اهمیت دارد

در [۱.۱.۳](../03-compound-types-and-destructuring/README.fa.md) آرایه را دیدی و یک محدودیتِ بزرگ داشت: طولش بخشی از نوعش بود، پس رشد نمی‌کرد. برای داده‌ی واقعی این تقریباً همیشه اشتباه است. تعدادِ سطرهای یک فایل، تعدادِ کاربرانِ آنلاین، تعدادِ نتیجه‌های یک کوئری — هیچ‌کدام هنگامِ کامپایل معلوم نیستند.

`Vec<T>` همان آرایه است بدونِ آن محدودیت، و `String` همان چیز برای متن. اگر پایتون بلدی، این دو معادلِ `list` و `str` هستند و تقریباً همان‌طور رفتار می‌کنند.

دو چیز فرق می‌کند و هر دو ارزشِ توجه دارند.

**اول، حالا واقعاً به هیپ رسیدی.** آرایه اندازه‌اش هنگامِ کامپایل معلوم بود، پس کامپایلر می‌توانست جایش را روی پشته کنار بگذارد. `Vec` نمی‌تواند — اندازه‌اش تا زمانِ اجرا معلوم نیست — پس محتوایش روی هیپ می‌نشیند. این یک جزئیاتِ پیاده‌سازی نیست؛ همان چیزی است که کلِ [ماژولِ ۱.۲](../../02-ownership-and-memory/README.fa.md) درباره‌ی آن است، و تمامِ باقیِ Rust از همین‌جا معنا پیدا می‌کند.

**دوم، متن.** و اینجا Rust کاری می‌کند که پایتون نمی‌کند: مجبورت می‌کند بینِ «چند بایت» و «چند حرف» تفاوت قائل شوی. برای کسی که با متنِ انگلیسی کار می‌کند این آزاردهنده و به‌ظاهر بی‌فایده است. برای تو که فارسی می‌نویسی، **دقیقاً همان تفاوتی است که تعیین می‌کند نرم‌افزارت کار می‌کند یا اسمِ کاربر را وسطِ حرف می‌بُرد.**

## مفهوم

### `Vec<T>` — آرایه‌ای که رشد می‌کند

سه راه برای ساختنش، و هر سه را می‌بینی:

```rust
let mut readings: Vec<i32> = Vec::new();
let preset = vec![12, 7, 19];
let zeroed = vec![0_u8; 5];
```

```text
empty:     []
preset:    [12, 7, 19]
zeroed:    [0, 0, 0, 0, 0]
```

آن `vec![]` یک ماکرو است — علامتِ `!` همان را می‌گوید — و همان نحوِ آرایه را دارد، از جمله فرمِ «این مقدار، این‌قدر تا».

`Vec::new()` هیچ عنصری ندارد که نوع از آن استنتاج شود، پس یا باید نوع را بنویسی یا بعداً از یک `push` معلوم شود.

#### رشد دادن و خواندن

```rust
readings.push(12);
readings.push(7);
readings.push(19);
```

```text
pushed:    [12, 7, 19]
length:    3
empty?     false
popped:    Some(19)
after pop: [12, 7]
```

`push` یکی به آخر اضافه می‌کند. `pop` آخری را برمی‌دارد و یک **`Option`** می‌دهد — چون ممکن است آخری‌ای وجود نداشته باشد. باز هم همان `Option` که در `checked_add` و `.get()` دیدی؛ [۱.۶.۱](../../06-absence-and-failure/01-option-and-null-safety/README.fa.md) بالاخره کاملش می‌کند.

هر کاری که آرایه بلد بود، `Vec` هم بلد است:

```text
first:     12
get(9):    None
```

#### حلقه زدن، بدونِ مصرف کردنش

```rust
let mut total = 0;
for reading in &readings {
    total += reading;
}
```

```text
total:     19
still here:[12, 7]
```

آن `&` را ببین. **بدونِ آن هم کامپایل می‌شود** — و آن‌وقت `readings` بعد از حلقه دیگر وجود ندارد.

این اولین باری است که Rust از تو یک تصمیمِ مالکیتی می‌خواهد: به حلقه *بدهمش* یا فقط *قرض* بدهم؟ `&` یعنی «فقط نگاه کن». الان همین‌قدر بدان که `&` را بنویس؛ [ماژولِ ۱.۲](../../02-ownership-and-memory/README.fa.md) و [۱.۳.۱](../../03-borrowing-and-references/01-shared-and-mutable-refs/README.fa.md) کاملش می‌کنند.

#### طول در برابرِ ظرفیت

```text
len / cap: 0 / 0
  push 0: 1 / 4
  push 1: 2 / 4
  push 2: 3 / 4
  push 3: 4 / 4
  push 4: 5 / 8
```

**طول** یعنی چند تا داخلش هست. **ظرفیت** یعنی چقدر جا از قبل رزرو شده.

وقتی طول به ظرفیت می‌رسد، `Vec` یک بلوکِ بزرگ‌ترِ تازه می‌گیرد، همه‌چیز را کپی می‌کند و قبلی را رها می‌کند. آن جهشِ ۴ به ۸ همین است. چون هر بار دو برابر می‌شود، `n` بار `push` در مجموع هزینه‌ای متناسب با `n` دارد، نه `n²` — همان تحلیلِ سرشکنی که در `list` پایتون هم هست.

اگر تقریباً می‌دانی چند تا می‌آید، بگو:

```rust
let sized: Vec<i32> = Vec::with_capacity(100);
```

```text
reserved:  0 / 100
```

هنوز خالی است — ظرفیت جای رزروشده است، نه محتوا.

### `String` — بافرِ متنی که رشد می‌کند

همان الگو، دقیقاً:

```rust
let empty = String::new();
let from_literal = String::from("hello");
let converted = "hello".to_string();
```

```text
empty:     ""
from:      "hello"
converted: "hello"
```

و همان‌طور رشد می‌کند:

```rust
let mut greeting = String::from("hello");
greeting.push_str(", world");
greeting.push('!');
```

```text
greeting:  hello, world!
```

دو متد، چون دو چیزِ متفاوت‌اند: `push_str` متن اضافه می‌کند و `push` یک `char`. Rust این دو را قاطی نمی‌کند چون واقعاً یکی نیستند — یک `char` دقیقاً یک اسکالرِ یونیکد است.

### و حالا آن چیزی که همه را می‌گیرد

```rust
let english = String::from("hello");
let persian = String::from("سلام");
```

```text
english:   hello
  bytes:   5
  chars:   5
persian:   سلام
  bytes:   8
  chars:   4
```

**`len()` بایت می‌شمارد، نه حرف.**

برای `hello` هر دو ۵ است، و همین است که این باگ را این‌قدر ماندگار می‌کند: اگر همه‌ی داده‌ی تستت انگلیسی باشد، `len()` طوری رفتار می‌کند که انگار حرف می‌شمارد و همه‌چیز درست به‌نظر می‌رسد.

برای `سلام` می‌شود ۸ و ۴. هر حرفِ فارسی در UTF-8 دو بایت می‌گیرد.

پیامدهایش را بشمار:

- «حداکثر ۲۰ کاراکتر» روی یک اسمِ فارسی در واقع می‌شود حداکثر ده حرف.
- بریدنِ متن سرِ بایتِ بیستم می‌تواند وسطِ یک حرف بیفتد و متنِ خراب تحویل بدهد.
- ستون‌بندی بر اساسِ `len()` برای متنِ غیرِانگلیسی تراز نمی‌شود.

**چرا Rust این کار را می‌کند؟** چون `len()` آنی است: یک `String` عددِ بایت‌هایش را همان‌جا دارد. شمردنِ حرف‌ها یعنی کسی باید کلِ متن را از اول تا آخر رمزگشایی کند، و این هزینه دارد. Rust اسمِ کوتاه را به کارِ ارزان می‌دهد و کارِ گران را وادار می‌کند صریح بخواهی:

```rust
text.chars().count()
```

پایتون این را پشتِ `len()` پنهان می‌کند و بهایش را جای دیگری می‌دهد. Rust ترجیح می‌دهد بدانی داری چه می‌پرسی.

> **و خودِ کلمه‌ی «کاراکتر» هم دقیق نیست.** `.chars()` اسکالرهای یونیکد را می‌شمارد، که برای فارسی معمولاً همان چیزی است که می‌خواهی، ولی برای متنِ دارای علامتِ ترکیبی یا ایموجی نه. [۱.۴.۲](../../04-text-and-strings/02-utf8-bytes-chars-graphemes/README.fa.md) کلِ ماجرا را باز می‌کند و برای تو یکی از مهم‌ترین درس‌های دوره است.

### `String` در برابرِ `&str` — نسخه‌ی یک‌پاراگرافی

```rust
let borrowed: &str = "I am a literal";
let owned: String = borrowed.to_string();
```

- **`String`** متن را **مالک** است. روی هیپ زندگی می‌کند، رشد می‌کند، و وقتی صاحبش برود از بین می‌رود.
- **`&str`** یک **نما** به متنی است که جای دیگری است. رشد نمی‌کند و چیزی را مالک نیست.

هر رشته‌ی ثابتی که در برنامه‌ات می‌نویسی یک `&str` است — داخلِ فایلِ اجرایی پخته شده و همیشه آنجاست.

قاعده‌ی عملی‌اش این است، و از همین حالا رعایتش کن:

```rust
fn shout(text: &str) -> String {
    text.to_uppercase()
}
```

```text
shout:     I AM A LITERAL
shout:     A LITERAL DIRECTLY
```

**پارامترها را `&str` بگیر و `String` برگردان.** چون هر `String`ای را می‌شود به‌عنوانِ `&str` قرض داد، تابعی که `&str` می‌گیرد هر دو را قبول می‌کند؛ تابعی که `String` می‌گیرد صداکننده را مجبور می‌کند مالکیت بدهد یا یک کپیِ الکی بسازد.

درسِ کاملش [۱.۴.۱](../../04-text-and-strings/01-string-vs-str/README.fa.md) است. فعلاً همان قاعده کافی است.

### پشته و هیپ، در یک نگاه

| | کجا زندگی می‌کند | اندازه معلوم می‌شود |
|---|---|---|
| `i32`، `bool`، `char` | پشته | هنگامِ کامپایل |
| `[i32; 5]` | پشته | هنگامِ کامپایل |
| `Vec<i32>` | محتوا روی هیپ | هنگامِ اجرا |
| `String` | محتوا روی هیپ | هنگامِ اجرا |
| `&str` به یک ثابت | هیچ‌جا — فقط نگاه می‌کند | هنگامِ کامپایل |

خودِ متغیرِ `Vec` روی پشته است؛ چیزی که رویش هست سه عدد است: یک اشاره‌گر، یک طول، یک ظرفیت. آن اشاره‌گر است که به هیپ می‌رود.

**همین است که مالکیت را ضروری می‌کند.** آن بلوکِ هیپ باید یک روز آزاد شود، و باید دقیقاً یک بار آزاد شود. [۱.۲.۱](../../02-ownership-and-memory/01-stack-and-heap/README.fa.md) از همین‌جا شروع می‌کند.

## خطاهایی که خواهی دید

### `E0277` — `String` را نمی‌شود با عدد اندیس زد

```text
error[E0277]: the type `str` cannot be indexed by `{integer}`
   --> examples\04-indexing-a-string.rs:10:26
    |
 10 |     let first = greeting[0];
    |                          ^ string indices are ranges of `usize`
    |
    = help: the trait `SliceIndex<str>` is not implemented for `{integer}`
    = note: you can use `.chars().nth()` or `.bytes().nth()`
            for more information, see chapter 8 in The Book
    ...
    = note: required for `String` to implement `Index<{integer}>`
```

**کامپایلر به چه اعتراض دارد:** `greeting[0]` یعنی چه؟ اولین بایت یا اولین حرف؟ برای متنِ انگلیسی یکی است؛ برای `سلام` اولین بایت نصفِ یک حرف است و اصلاً یک `char`ِ معتبر نیست.

Rust نمی‌تواند تصمیم بگیرد کدام را می‌خواستی، و نمی‌خواهد عملیاتی به تو بدهد که برای متنِ انگلیسی درست کار کند و برای فارسی خاموش خراب شود. پس اصلاً این عملیات را ندارد.

**راه‌حل:** بگو کدام را می‌خواهی. `greeting.chars().nth(0)` اولین حرف را می‌دهد، `greeting.bytes().nth(0)` اولین بایت را. هر دو `Option` می‌دهند، چون متن ممکن است خالی باشد.

**چرا این راه‌حل است:** به آن `note` دقت کن — کامپایلر هر دو گزینه را نام برده و حتی به فصلِ کتاب ارجاع داده. این تنبیه نیست؛ دارد می‌گوید سؤالت مبهم بود و این دو سؤالِ روشن جایگزینش هستند. و هزینه‌ی `.nth(0)` هم پنهان نیست: باید از اول بشمارد، چون حرف‌ها عرضِ ثابت ندارند.

### `E0308` — آرایه یک `Vec` نیست

```text
error[E0308]: mismatched types
  --> examples\05-array-is-not-a-vec.rs:10:30
   |
10 |     let growable: Vec<i32> = fixed;
   |                   --------   ^^^^^ expected `Vec<i32>`, found `[{integer}; 3]`
   |                   |
   |                   expected due to this
   |
   = note: expected struct `Vec<i32>`
               found array `[{integer}; 3]`
help: try using a conversion method
   |
10 |     let growable: Vec<i32> = fixed.to_vec();
   |                                   +++++++++
```

**کامپایلر به چه اعتراض دارد:** یک محتوا را نگه می‌دارند و یکسان چاپ می‌شوند، ولی دو نوعِ متفاوت‌اند که در دو جای متفاوت زندگی می‌کنند. آرایه روی پشته است و اندازه‌اش در نوعش نوشته شده؛ `Vec` یک اشاره‌گر به هیپ است.

**راه‌حل:** `fixed.to_vec()`، همان‌طور که خودِ کامپایلر پیشنهاد داده.

**چرا این راه‌حل است:** این تبدیل مجانی نیست و برای همین خودکار هم نیست. `to_vec()` روی هیپ حافظه می‌گیرد و محتوا را کپی می‌کند. Rust هیچ‌وقت پشتِ یک انتساب برایت حافظه نمی‌گیرد؛ اگر تخصیصی در کار است، در کد دیده می‌شود.

`byte_and_char_count` یک خط است و مهم‌ترینشان. تستش هم فارسی دارد هم لاتین، عمداً.

### بساز

یک `pub fn truncate_to_chars(text: String, max_chars: usize) -> String` بنویس که متن را به حداکثر `max_chars` **حرف** کوتاه کند (نه بایت).

بعد نسخه‌ی غلطش را هم بنویس — همانی که به `max_chars` بایت می‌بُرد — و هر دو را روی `"سلام دنیا"` با `max_chars` برابرِ ۵ اجرا کن.

نسخه‌ی غلط یا متنِ خراب می‌دهد یا پنیک می‌کند. **بفهم کدام و چرا.** این دقیقاً همان باگی است که در سیستم‌های واقعی به متنِ فارسی می‌زند.

### چالش (اختیاری)

**بخشِ یک.** این را اجرا کن و توضیح بده:

```rust
let mut v: Vec<i32> = Vec::new();
for n in 0..1000 {
    if v.len() == v.capacity() {
        println!("regrowing at len {}", v.len());
    }
    v.push(n);
}
```

چند بار دوباره تخصیص داد؟ اگر با `Vec::with_capacity(1000)` شروع می‌کردی چطور؟

**بخشِ دو.** بدونِ اجرا کردن، بگو این چه چاپ می‌کند:

```rust
let s = String::from("سلام");
println!("{}", s.len());
println!("{}", s.chars().count());
println!("{:?}", s.chars().nth(1));
println!("{:?}", s.bytes().nth(1));
```

بعد اجرا کن. آن دو خطِ آخر چرا این‌قدر با هم فرق دارند؟

**بخشِ سه.** یک `String` بساز که ۳ حرف دارد ولی ۹ بایت است. (سرنخ: به فارسی محدود نیستی.)

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به کارت می‌آید |
|---|---|---|
| `Vec<T>` | آرایه‌ی رشدکننده، محتوا روی هیپ | هر فهرستی که طولش از قبل معلوم نیست |
| `vec![]` | ماکروی ساختنِ `Vec` | مقدارِ اولیه‌ی ثابت |
| `push` / `pop` | یکی اضافه کن / یکی از آخر بردار | رشد و کوچک شدن |
| ظرفیت | جای رزروشده، در برابرِ طول | `with_capacity` برای اندازه‌ی تقریبی |
| `String` | بافرِ متنیِ مالکْ‌دار و رشدکننده | متنی که می‌سازی |
| `&str` | نمایی به متنی که جای دیگری است | پارامترهای تابع |
| `push_str` / `push` | متن اضافه کن / یک `char` اضافه کن | ساختنِ متن |
| `len()` | تعدادِ **بایت** | همیشه — یادت بماند |
| `.chars().count()` | تعدادِ اسکالرِ یونیکد | هر جا حرف مهم است |
| `&` سرِ حلقه | قرض بده به‌جای دادن | حلقه‌ای که بعدش هم لازمش داری |

### الان می‌دانی

- `Vec<T>` و `String` هر دو بافرِ مالکْ‌دار و رشدکننده روی هیپ‌اند.
- ظرفیت با طول فرق دارد، و رشدِ `Vec` دو برابری است.
- `String` مالک است و `&str` نما؛ پارامترها را `&str` بگیر.
- `len()` بایت می‌شمارد. برای متنِ فارسی این با تعدادِ حرف‌ها یکی نیست.
- `String` را نمی‌شود با عدد اندیس زد، و دلیلش خوب است.
- `&` سرِ یک حلقه یعنی قرض، نه دادن — و این اولین تصمیمِ مالکیتِ توست.
