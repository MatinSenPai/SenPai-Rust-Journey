# راه‌حل

```rust
pub fn increment_n_times(times: u32) -> u32 {
    let mut count = 0;
    for _ in 0..times {
        count += 1;
    }
    count
}

pub fn parse_and_double(input: &str) -> i32 {
    let input: i32 = input.parse().expect("input should be a valid integer");
    let input = input * 2;
    input
}
```

تابع `increment_n_times` تو طول حلقه‌ها واقعاً داره همون متغیر `count` رو تغییر می‌ده — این یه مثال کلاسیک و کتابی برای استفاده از `mut` هستش: یه مقدار منطقی که تو طول زمان آپدیت می‌شه.

اما `parse_and_double` داره از اسم `input` سه بار استفاده می‌کنه که هر بار نوع/مقدار متفاوتی داره: اول پارامتر `&str` اصلی، بعد یه `i32` بعد از اجرای `.parse()`، و در نهایت همون `i32` دو برابر شده. سایه‌زنی (shadowing) دقیقاً برای همین کار ساخته شده: یه جریان (pipeline) کوتاه از تغییرات که ساختن اسم‌هایی مثل `raw_input`، `parsed_input` و `doubled_input` براش فقط اضافه‌کاریه، اونم برای مقادیری که هیچ‌وقت قرار نیست کنار هم بهشون نیاز پیدا کنی.

به قسمت `(...)input.parse().expect` توجه کن: متد `.parse()` یه `Result` برمی‌گردونه (آخرین بخش از فاز یک کاملاً این رو پوشش می‌ده) چون ممکنه تبدیل کردنش شکست بخوره — `.expect(msg)` به این معنیه که «اگه شکست خورد، برنامه رو با این پیام خطا کرش کن». این کار برای یه تمرین آموزشی هیچ مشکلی نداره اما تو یه کد واقعی نباید ورودی نامطمئن رو اینطوری هندل کنی (به جاش باید خطا رو به بالا بفرستی — به بخش `06-option-result-error-basics` نگاه کن).

یه نکته‌ی ریز و صادقانه: اگه رو `parse_and_double` دستور `cargo clippy` رو اجرا کنی، به خطِ `let input = input * 2; input` با پیغام `let_and_return` گیر میده و پیشنهاد می‌ده که این دو تا رو با هم ترکیب کنی و فقط بنویسی `input * 2` که بشه tail expression. پیشنهاد Clippy *درسته* که اینطوری کد کوتاه‌تر می‌شه — و تو یه کد واقعی به احتمال خیلی زیاد همین پیشنهاد رو قبول می‌کنی. اما این راه‌حل همچنان همون سایه‌زنیِ نهایی رو به‌طور واضح نگه داشته (با گذاشتن `#[allow(clippy::let_and_return)]`) فقط به این خاطر که هدف این تمرین اینه که با خود سایه‌زنی کار کنی؛ این یه نمونه‌ی اولیه‌ی خوبه برای اینکه بدونی همیشه «کد استاندارد (idiomatic)» با «چیزی که یه درس خاص می‌خواد بهت یاد بده» یکی نیستن، و اینکه خاموش کردنِ یه هشدار با `[...]allow#` همیشه باید یه دلیلی کنارش نوشته شده باشه، مثل همون کامنتی که بالای تابع گذاشته شده.
