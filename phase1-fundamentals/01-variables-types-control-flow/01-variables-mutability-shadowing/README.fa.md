# ۰۱.۱.۱ — متغیرها، mutability و shadowing

## پیش‌فرض تغییرناپذیر (Immutable by default)

```rust
let x = 5;
x = 6; // خطای کامپایلر: نمی‌تونی به متغیر غیرقابل‌تغییر `x` دوبار مقداردهی کنی
```

تو پایتون، هر متغیری به‌طور پیش‌فرض قابل مقداردهی مجدده. تو Rust، وقتی می‌نویسی `let x = 5` یعنی متغیر `x` **غیرقابل‌تغییر (immutable)** می‌شه — کامپایلر اصلاً اجازه نمی‌ده برنامه‌ای ساخته بشه که بخواد اون رو دوباره مقداردهی کنه. این یه محدودیت نیست که بخوای تا ابد باهاش بجنگی؛ بلکه یه پیش‌فرضه که باعث می‌شه خوندن کد خیلی راحت‌تر بشه (وقتی `x` یه بار نوشته شد یعنی همه‌جای کد، `x` دقیقاً همون مقداره). و هر موقع که واقعاً نیاز داشتی، خودت به صراحت این قانون رو دور می‌زنی:

```rust
let mut x = 5;
x = 6; // هیچ مشکلی نداره — با `mut` بهش اجازه دادی
```

## سایه‌زنی (Shadowing) — با تغییر مقدار فرق داره

```rust
let x = 5;
let x = x * 2;      // یه `x` کاملاً جدید که حتی می‌تونه نوع داده‌ی متفاوتی هم داشته باشه
let x = x.to_string();
```

این کد شبیه تغییر دادن مقدار به نظر می‌رسه اما اینطور نیست: هر `let x = ...` یه متغیر **جدید** می‌سازه که اتفاقاً می‌خواد از همون اسم `x` استفاده کنه و متغیر قبلی رو پنهان ("shadow") می‌کنه. پیامدهاش:
- می‌تونی تو جریان سایه‌زنی *نوع داده (type)* رو عوض کنی (بالا `i32` به `String` تبدیل شد) — در صورتی که `mut` هیچ‌وقت همچین اجازه‌ای بهت نمی‌ده؛ نوع یه متغیر `mut` تا ابد ثابته.
- مقدار قدیمی همونجا تغییر نمی‌کنه یا پاک (drop) نمی‌شه، فقط دیگه از طریق اون اسم قابل دسترسی نیست (البته طبق قواعد فصل بعدی فاز یک که مربوط به مالکیت هستش، پاکسازی می‌شه).

هر وقت واقعاً داری یه مقدار رو در طول زمان آپدیت می‌کنی (مثل یه شمارنده یا accumulator) از `mut` استفاده کن. هر وقت داری یه مقدار رو تو طی یک سری مراحل تغییر شکل میدی (transform می‌کنی) و نمی‌خوای برای هر مرحله یه اسم جدید دربیاری (مثل `raw_input` ← `trimmed` ← `parsed` که می‌تونی به جاش سه بار اسم `input` رو از طریق shadowing بازیافت کنی)، از shadowing استفاده کن.

## ثابت‌ها (`const`)

```rust
const MAX_RETRIES: u32 = 3;
```

همیشه تغییرناپذیره (چیزی به اسم `mut const` نداریم)، باید به طور صریح نوعش رو مشخص کنی و باید به مقداری ست بشه که کامپایلر بتونه تو زمان کامپایل حسابش کنه (نمی‌تونی تابعی رو صدا بزنی که نتیجه‌اش تا زمان اجرا مشخص نیست). نزدیک‌ترین معادلش تو پایتون همون متغیر سطح ماژولِ `MAX_RETRIES = 3` هستش که قول میدی هیچ‌وقت دوباره مقداردهی‌اش نکنی، با این تفاوت که Rust واقعاً پای این قول وامیسته و مجبور به رعایتش می‌کنه.
