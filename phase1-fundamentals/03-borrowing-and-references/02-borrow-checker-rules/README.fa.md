# ۰۳.۲ — قواعد Borrow Checker

درس قبلی از قرض‌گرفتن (borrowing) به شکل درستی استفاده کرد. این درس درباره‌ی اینه که وقتی این کار رو *درست* انجام نمیدی چه اتفاقی می‌افته — خوندن خطاهای واقعی کامپایلر یه مهارته، و خیلی می‌ارزه که قبل از اینکه تصادفاً باهاشون مواجه بشی، عمداً روی کدهای خراب تمرین کنی.

## دو قانون، به بیان دقیق

در هر نقطه‌ای از کد، برای هر مقدار مشخصی، می‌تونی موارد زیر رو داشته باشی:
- هر تعدادی ارجاعِ اشتراکی (`T&`)، **یا**
- دقیقاً یه ارجاعِ تغییرپذیر (`mut T&`)،

اما هیچ‌وقت نمی‌تونی هر دوی اینا رو به طور همزمان داشته باشی. همچنین: **عمر یه ارجاع هیچ‌وقت نباید از عمر مقداری که داره بهش اشاره می‌کنه بیشتر بشه** (هیچ «ارجاع آویزونی (dangling reference)»ای مجاز نیست — Rust خیلی ساده کدی رو که توش ممکنه همچین اتفاقی بیفته اصلاً کامپایل نمی‌کنه، والسلام).

## مثال کلاسیک از کد خراب شماره ۱: تغییرپذیر + اشتراکی به طور همزمان

```rust
let mut s = String::from("hello");
let r1 = &s;
let r2 = &mut s;      // خطا: نمی‌شه `s` رو به عنوان تغییرپذیر قرض گرفت چون
                       // همزمان به عنوان غیرقابل‌تغییر هم قرض گرفته شده
println!("{r1}");
```

## مثال کلاسیک از کد خراب شماره ۲: دو تا قرضِ تغییرپذیر به طور همزمان

```rust
let mut s = String::from("hello");
let r1 = &mut s;
let r2 = &mut s;       // خطا: نمی‌شه `s` رو بیشتر از یک بار به عنوان تغییرپذیر قرض گرفت
println!("{r1} {r2}");
```

## مثال کلاسیک از کد خراب شماره ۳: ارجاعِ آویزون (Dangling reference)

```rust
fn dangle() -> &String {
    let s = String::from("hello");
    &s  // خطا: متغیر `s` تو انتهای این تابع پاک (drop) می‌شه — ارجاعی که 
        // داری سعی می‌کنی برگردونی، قراره به یه حافظه‌ی آزادشده اشاره کنه
}
```

این یکی واضح‌ترین تضاد رو با زبانی مثل C داره: دقیقاً همین باگ (همون «اشاره‌گر آویزون (dangling pointer)») منبعِ کلاسیکِ آسیب‌پذیری‌های امنیتی واقعی و کرش‌های برنامه‌ها تو C/C++ هست. اما Rust این رو تو زمان اجرا (runtime) پیدا نمی‌کنه و صرفاً اونو به عنوان یه رفتار تعریف‌نشده (undefined behavior) مستند نمی‌کنه — بلکه اصلاً از کامپایل کردنش سرباز می‌زنه، واسه همیشه.

## وظیفه‌ی تو

فایل `src/lib.rs` سه تا تابع داره که شامل نسخه‌های *اصلاح‌شده‌ی* باگ‌هایی مثل نمونه‌های بالا هستن و از قبل پیاده‌سازی شدن (وظیفه‌ی تو اینه که بدنه‌ی `!()todo`ها رو درست پر کنی، نه اینکه چیزی رو خراب کنی). اون پایین، یه بلاک کد کامنت‌شده هست که مثال شماره ۱ رو دقیقاً شبیه‌سازی می‌کنه تا خودت از حالت کامنت درش بیاری و خطاش رو مستقیم ببینی.
