# پاسخ — ۱.۳.۴ برش‌ها

```rust
pub fn count_above(values: &[i32], threshold: i32) -> usize {
    let mut found = 0;
    for value in values {
        if *value > threshold {
            found += 1;
        }
    }
    found
}

pub fn middle(values: &[i32]) -> &[i32] {
    if values.len() < 3 {
        return &[];
    }
    &values[1..values.len() - 1]
}

pub fn halves(values: &[i32]) -> (&[i32], &[i32]) {
    values.split_at(values.len() / 2)
}

pub fn window_sum(values: &[i32], start: usize, length: usize) -> i32 {
    let window = &values[start..start + length];
    let mut sum = 0;
    for value in window {
        sum += value;
    }
    sum
}

pub fn double_in_place(values: &mut [i32]) {
    for value in values {
        *value *= 2;
    }
}
```

هیچ‌کدام از این‌ها تخصیصی نگرفتند. سه‌تایشان نگاهی به اعدادِ خودِ فراخواننده برگرداندند.

## `count_above` — نوعِ پارامتر همه‌ی ماجراست

```rust
for value in values {
    if *value > threshold {
```

اینجا `value` یک `&i32` است نه `i32`، چون حلقه روی یک `&[i32]` به تو نگاهی به هر عنصر می‌دهد نه خودِ عنصر را. پس مقایسه به یک `*` احتیاج دارد تا به عدد برسد — همان بازکردنِ ارجاع از [۱.۳.۱](../../01-shared-and-mutable-refs/README.fa.md).

می‌شد `if value > &threshold` هم نوشت، که دو ارجاع را با هم مقایسه می‌کند و دقیقاً به همان اندازه درست و کمی عجیب‌تر است.

تستِ جالب، آن حسابِ ساده نیست:

```rust
assert_eq!(count_above(&fixed, 3), 2);
assert_eq!(count_above(&grown, 3), 2);
assert_eq!(count_above(&grown[..2], 3), 1);
assert_eq!(count_above(&fixed[2..], 3), 1);
```

یک آرایه، یک وکتور، و تکه‌ای از هرکدام — یک تابع، بدونِ سربارگذاری، بدونِ جنریک، بدونِ اینکه چیزی دو بار نوشته شود. اگر پارامتر `&Vec<i32>` بود، دو تا از این چهار خط `E0308` می‌شدند.

## `middle` — نگهبانِ اول، خودِ تمرین است

```rust
if values.len() < 3 {
    return &[];
}
&values[1..values.len() - 1]
```

بدونِ آن نگهبان بنویسش؛ به نظر درست می‌آید و بعد روی یک برشِ تک‌عنصری وحشت می‌کند: `values.len() - 1` می‌شود `0`، پس بازه `1..0` است که برعکس می‌رود، و این را می‌گیری: `slice index starts at 1 but ends at 0`.

روی برشِ **خالی** بدتر هم هست. `values.len() - 1` روی یک `usize` که `0` است سرریزِ رو‌به‌پایین می‌دهد — همان سرریزِ [۱.۱.۲](../../../01-foundations/02-scalar-types-and-overflow/README.fa.md) که در debug وحشت می‌کند و در release به یک عددِ نجومی می‌پیچد. یعنی یک خطِ جاافتاده، دو شکستِ متفاوت، که فقط اولی در تست خودش را نشان می‌دهد.

`return &[];` کار می‌کند چون یک برشِ خالی لازم نیست به چیزی اشاره کند؛ از هیچ‌جا قرض نگرفته و به هر طولِ عمری می‌خورد.

## `halves` — کتابخانه‌ی استاندارد از قبل داشتش

```rust
values.split_at(values.len() / 2)
```

یک خط، و کلِ تابع همین است. `split_at` دقیقاً همان تاپلی را می‌دهد که خواسته شده بود، و تقسیمِ صحیح قاعده‌ی «عنصرِ اضافه می‌رود سمتِ راست» را مجانی انجام می‌دهد: `3 / 2` می‌شود `1`، پس برش بعد از یک عنصر می‌افتد و نیمه‌ی دوم دو تا می‌گیرد.

نسخه‌ی دستی هم درست است:

```rust
let cut = values.len() / 2;
(&values[..cut], &values[cut..])
```

همان نتیجه، با سه برابر سطحِ بیشتر برای اشتباه کردن. همین است دلیلِ آن جمله‌ی درس که «یک بار مستنداتِ `slice` را از بالا تا پایین بخوان»: `split_at` و `first` و `last` و `contains` و `starts_with` و `swap` و `sort` همه از قبل آن‌جا نشسته‌اند.

## `window_sum` — وحشتی که لازم نیست خودت بنویسی

```rust
let window = &values[start..start + length];
```

مستندات گفته بود تابع وقتی پنجره از انتها بیرون بزند وحشت می‌کند. اینجا هیچ چیزی این را بررسی نمی‌کند و باز هم وحشت می‌کند — چون خودِ برش‌گرفتن این بررسی را انجام می‌دهد، و پیامش هر دو عدد را می‌گوید:

```text
range end index 7 out of range for slice of length 3
```

این خطا از هر چیزی که خودت می‌نوشتی گویاتر است و مجانی هم هست. اگر یک `if` جلویش می‌گذاشتی، برای همان شرط یک پیامِ دومِ بدتر تولید کرده بودی.

و اینکه در دو گام نوشته شده، خواندنش را بهتر می‌کند تا یک عبارتِ طولانی:

```rust
let window = &values[start..start + length];
let mut sum = 0;
for value in window { /* ... */ }
```

`window` هیچ هزینه‌ای ندارد — دو کلمه روی پشته — پس اسم گذاشتن روی چیزی که می‌خواهی جمعش کنی، وضوحِ مجانی است.

## `double_in_place` — نوشتن از راهِ پنجره

```rust
for value in values {
    *value *= 2;
}
```

`values` یک `&mut [i32]` است، پس حلقه هر دور یک `&mut i32` به تو می‌دهد و `*value *= 2` از راهِ آن، داخلِ بافرِ فراخواننده می‌نویسد. چیزی برنمی‌گردد و چیزی تخصیص داده نمی‌شود.

نسخه‌ی اندیسی هم کار می‌کند:

```rust
for index in 0..values.len() {
    values[index] *= 2;
}
```

همان کار است با یک بررسیِ محدوده در هر دور، و `cargo clippy` با لینتِ `needless_range_loop` همین را می‌گوید.

تستی که مهم است، دومی است:

```rust
double_in_place(&mut values[1..4]);
assert_eq!(values, vec![1, 4, 6, 8, 5]);
```

به تابع یک پنجره‌ی سه‌عنصری داده شد و دقیقاً همان سه تا را عوض کرد. اصلاً راهی نداشت به آن دوتای دیگر برسد، چون یک برش فقط می‌داند از کجا شروع می‌شود و چند عنصر دارد.

## این درس واقعاً درباره‌ی چه بود

- **برش یک قرض است به‌علاوه‌ی یک طول.** دو کلمه: یک نشانی و یک تعداد.
- **`&[T]` نوعِ پارامتر است.** آرایه و وکتور و تکه‌ی هرکدام را می‌گیرد و برای فراخواننده هیچ هزینه‌ای ندارد.
- **برشی که از تابع برمی‌گردد هنوز یک نگاه است.** `middle` اعدادِ خودِ فراخواننده را پس می‌دهد، و برای همین لازم نبود چیزی کپی شود.
- **بررسیِ محدوده وقتی انجام می‌شود که برش ساخته می‌شود.** یک وحشتِ دقیق مجانی می‌گیری؛ چیزی که نمی‌گیری خطای کامپایل است.
- **`&str` همین است، روی بایت‌ها.** هر چیزی که اینجا دیدی همان ماشینی است که از درسِ اول برای متن به کار می‌بری — [۱.۴.۱](../../../04-text-and-strings/01-string-vs-str/README.fa.md).
