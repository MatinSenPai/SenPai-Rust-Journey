# ۰۳.۱ — ارجاع اشتراکی و تغییرپذیر

## چیزی که قرار است یاد بگیری

قرض‌گیری به تابع اجازه می‌دهد بدون گرفتن مالکیت، موقتاً داده را بخواند یا تغییر دهد.

```rust
fn calculate_length(s: &String) -> usize {
    s.len()
}

let s1 = String::from("hello");
let len = calculate_length(&s1);
println!("{s1} is {len} long");
```

`&s1` یک ارجاع می‌سازد. پایان محدوده این ارجاع، خود `String` را drop نمی‌کند چون ارجاع مالک آن نیست. برای API عمومی فقط‌خواندنی، معمولاً `&str` از `&String` انعطاف‌پذیرتر است.

## `&T`: چند خواننده

```rust
let s = String::from("hello");
let r1 = &s;
let r2 = &s;
println!("{r1} and {r2} and {s}");
```

چند ارجاع اشتراکی می‌توانند هم‌زمان وجود داشته باشند، چون از راه آن‌ها تغییری انجام نمی‌شود.

## `&mut T`: یک نویسنده‌ی انحصاری

```rust
fn add_exclamation(s: &mut String) {
    s.push_str("!");
}

let mut s = String::from("hello");
add_exclamation(&mut s);
```

تا وقتی یک ارجاع تغییرپذیر زنده است، ارجاع دیگری به همان مقدار نباید هم‌زمان استفاده شود. خلاصه‌ی رایج این قانون «چند خواننده یا یک نویسنده» است. با طول عمرهای غیرواژگانی (Non-Lexical Lifetimes)، قرض‌گیری معمولاً در آخرین استفاده پایان می‌یابد، نه لزوماً در پایان بلوک.

## مثال فارسی و بک‌اند

کارت سفارش را تصور کن: چند نفر می‌توانند نسخه‌ی فقط‌خواندنی وضعیت را ببینند؛ اما مجوز ویرایش باید موقتاً فقط دست یک نفر باشد. در پردازشگر نیز می‌توان پیکربندی را با `&Config` خواند، ولی تغییر وضعیت مشترک نیازمند قرارداد انحصاری یا synchronization است.

## این تشبیه کجا دیگر دقیق نیست؟

`&mut` قفل زمان اجرا نیست و روی یک ریسمان هزینه‌ی همگام‌سازی ندارد. این مجوز بخشی از دستگاه نوع Rust است؛ برای اشتراک میان چند ریسمان هنوز به `Mutex`، `RwLock` یا طراحی مبتنی بر پیام نیاز داری.
