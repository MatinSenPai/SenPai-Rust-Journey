# ۰۳.۱ — ارجاع‌های اشتراکی و تغییرپذیر (Shared and mutable references)

## قرض‌گرفتن به جای منتقل‌کردن

```rust
fn calculate_length(s: &String) -> usize {
    s.len()
} // متغیر s (که همون ارجاع ماست) تو اینجا از اسکوپ خارج می‌شه — اما چون مالکیتی
  // روی String نداره، هیچی drop نمی‌شه. پس String اصلی دست‌نخورده باقی می‌مونه.

let s1 = String::from("hello");
let len = calculate_length(&s1);
println!("{s1} is {len} long"); // متغیر s1 همچنان معتبره!
```

نوشتن `s1&` یه **ارجاع (reference)** به `s1` می‌سازه — تو فقط داری یه دسترسی موقت رو قرض می‌دی و به هیچ وجه مالکیت رو واگذار نمی‌کنی. تابع `calculate_length` یه ارجاع از نوع `String&` می‌گیره، از طریق همون ارجاع مقدار رو می‌خونه، و وقتی اسکوپِ ارجاع تموم شد، هیچ چیزی هم پاک (drop) نمی‌شه (چون چیزی وجود نداره که مالکش باشه). این همون روشیه که توش بدون اینکه از طریق انتقال (move) دسترسی به مقادیر رو از دست بدی، اون‌ها رو این‌ور و اون‌ور پاس می‌دی.

## ارجاع‌های اشتراکی: `T&` — فقط‌خواندنی، ولی می‌تونی همزمان چندتا ازش داشته باشی

```rust
let s = String::from("hello");
let r1 = &s;
let r2 = &s;
println!("{r1} and {r2} and {s}"); // هر سه تا همزمان معتبرن — هیچ مشکلی نیست
```

هر تعدادی از ارجاع‌های اشتراکی (`T&`) می‌تونن به طور همزمان وجود داشته باشن، به این دلیل ساده که هیچ‌کدومشون نمی‌تونن داده‌ها رو تغییر بدن — وجودِ «کلی خواننده بدون هیچ نویسنده‌ای»، همیشه ایمنه.

## ارجاع‌های تغییرپذیر: `mut T&` — انحصاری، و فقط یکی می‌تونه باشه

```rust
fn add_exclamation(s: &mut String) {
    s.push_str("!");
}

let mut s = String::from("hello");
add_exclamation(&mut s);
println!("{s}"); // "hello!"
```

برای تغییر دادنِ یه مقدار از طریق یه ارجاع، تو به `mut T&` نیاز داری و تازه همون متغیری هم که داره قرض گرفته می‌شه، باید از اول با `mut` تعریف شده باشه. قانون حیاتی‌ای که بدون هیچ هزینه‌ای در زمان اجرا، کاملاً تو همون زمان کامپایل اجرا می‌شه اینه:

> **تا زمانی که یه ارجاعِ تغییرپذیر (mutable reference) به یه مقدار وجود داره، هیچ ارجاع دیگه‌ای به اون مقدار — نه از نوع اشتراکی و نه از نوع تغییرپذیر — نمی‌تونه همزمان وجود داشته باشه.**

این قانون معمولاً با عنوان «یا نام مستعار، یا تغییرپذیری (aliasing XOR mutability)» شناخته می‌شه: یا چند تا نام مستعارِ فقط‌خواندنی داری، یا دقیقاً یدونه تغییرپذیر، هیچ‌وقت هر دو با هم نمی‌شن. این دقیقاً همون اصل بنیادینی هستش که ویژگیِ تیتریکِ زبان Rust (یعنی عدم وجود data races) رو تضمین می‌کنه؛ فقط اینجا این محدودیت روی یه ریسمان (thread) اعمال می‌شه — تو فاز ۲ وقتی برسیم به ماژول همروندی (concurrency)، دقیقاً با چشم می‌بینی که همین قانون چطور از باگ‌های سیستم‌های چندریسمانی (multi-threaded) جلوگیری می‌کنه.
