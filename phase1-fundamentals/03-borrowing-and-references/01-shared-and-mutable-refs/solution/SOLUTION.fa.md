# راه‌حل — ۱.۳.۱ ارجاع‌های اشتراکی و تغییرپذیر

```rust
pub fn longest_length(lines: &Vec<String>) -> usize {
    let mut longest = 0;
    for line in lines {
        if line.len() > longest {
            longest = line.len();
        }
    }
    longest
}

pub fn count_above(values: &Vec<i32>, limit: &i32) -> usize {
    let mut found = 0;
    for value in values {
        if *value > *limit {
            found += 1;
        }
    }
    found
}

pub fn append_all(target: &mut String, extras: &Vec<String>) {
    for extra in extras {
        target.push_str(extra);
    }
}

pub fn clamp_all(values: &mut Vec<i32>, ceiling: &i32) {
    for value in values {
        if *value > *ceiling {
            *value = *ceiling;
        }
    }
}

pub fn transfer(from: &mut i32, to: &mut i32, amount: &i32) {
    *from -= *amount;
    *to += *amount;
}
```

پنج تابع، پنج امضا، و در هیچ‌کدام یک `.clone()` هم نیست. دو تایشان فقط نگاه می‌کنند و سه تایشان می‌نویسند، و بدونِ خواندنِ حتی یک خط از بدنه‌ها می‌فهمی کدام کدام است — این همان چیزی است که یک ارجاع در امضا برایت می‌خرد.

## `longest_length` — آنکه اصلاً ستاره ندارد

```rust
for line in lines {
    if line.len() > longest {
        longest = line.len();
    }
}
```

`lines` یک `&Vec<String>` است، پس هر `line` یک `&String` است. با این حال هیچ‌جا `*` نمی‌بینی: `line.len()` صدا زدنِ متد است و نقطه‌ی متد خودش ارجاع را باز می‌کند. این همان بازکردنِ خودکارِ ارجاع است، و دلیلِ اینکه کدِ واقعیِ Rust این‌قدر کم ستاره دارد.

`longest` یک `usize` ساده است — عددی که مالکش خودت هستی و روی قابِ همین تابع زندگی می‌کند. هیچ‌کس قرضش نگرفته و لازم هم نیست.

حالتِ خالی خودبه‌خود درست درمی‌آید. `longest` از `0` شروع می‌شود، حلقه اصلاً اجرا نمی‌شود، و `0` همان جوابی است که مشخصات خواسته بود. نگهبان لازم نشد — و این ارزشِ دقت دارد: یک مقدارِ اولیه‌ی خوب اغلب یک حالتِ خاص را حذف می‌کند.

## `count_above` — جایی که ستاره‌ها برمی‌گردند

```rust
if *value > *limit {
    found += 1;
}
```

هم `value` و هم `limit` از نوعِ `&i32` هستند. `*value > *limit` دو عدد را مقایسه می‌کند.

و اینجا همان‌جایی است که آدم‌ها گیر می‌کنند: `value > limit` هم کامپایل می‌شود و همان جواب را می‌دهد، چون کتابخانه‌ی استاندارد مقایسه بینِ ارجاع‌ها را هم پیاده کرده. `value > &5` هم همین‌طور. سه شکلِ نوشتن، یک نتیجه.

کدام را بنویسی؟ `*value > *limit`، دستِ‌کم تا وقتی داری یاد می‌گیری. صریح می‌گوید چه چیزی با چه چیزی مقایسه می‌شود، و روزی که نوع‌ها دیگر عددهای `Copy` نباشند همین شکل است که سرِ پا می‌ماند.

اینکه `limit` یک `&i32` است کمی مصنوعی است — در کدِ واقعی یک `i32` ساده می‌گرفتی، چون کپی کردنِ چهار بایت از دنبال کردنِ یک فلش ارزان‌تر است. اینجا این‌طور نوشته شده تا دستِ‌کم یک بار یک ارجاعِ اشتراکی به یک نوعِ `Copy` را دیده باشی. جای اصلیِ این بحث فاز ۲ و کدِ جنریک است.

تست چیزی فراتر از خودِ شمارش را بررسی می‌کند:

```rust
assert_eq!(count_above(&values, &limit), 2);
assert_eq!(values.len(), 3);
assert_eq!(limit, -1);
```

هر دو آرگومان بعد از فراخوانی سالم مانده‌اند. با `&` همیشه همین‌طور می‌شد — و دقیقاً همان چیزی است که درسِ قبل مجبور بود با یک تاپل تقلیدش کند.

## `append_all` — یک `&mut` و یک `&` در یک امضا

```rust
for extra in extras {
    target.push_str(extra);
}
```

دو ارجاع با دو کارِ متفاوت، کنارِ هم. `target` تغییرپذیر قرض داده شده چون قرار است عوض شود؛ `extras` اشتراکی قرض داده شده چون فقط خوانده می‌شود. امضا خودش مستندات است.

`push_str` یک برشِ متنی می‌خواهد و `extra` یک `&String` است، و باز هم کار می‌کند — Rust سرِ فراخوانی خودش یکی را به آن یکی تبدیل می‌کند. آن تبدیل اسم دارد و درسِ خودش را دارد ([۱.۴.۱](../../../04-text-and-strings/01-string-vs-str/README.fa.md))؛ فعلاً فقط توجه کن که اتفاق افتاد و لازم نشد چیزی بخواهی.

هیچ مقدارِ برگشتی‌ای نیست. چیزی برای برگرداندن وجود ندارد: `target` مالِ صداکننده است و خودش تغییرش را می‌بیند. حالا مقایسه کن با شکلی که همین تابع یک درس قبل مجبور بود داشته باشد:

```rust
fn append_all(target: String, extras: Vec<String>) -> (String, Vec<String>)
```

این همان الگویی است که کلِ این ماژول برای حذفش وجود دارد.

## `clamp_all` — نوشتن از روی متغیرِ حلقه

```rust
for value in values {
    if *value > *ceiling {
        *value = *ceiling;
    }
}
```

`values` یک `&mut Vec<i32>` است، پس `for value in values` هر دور یک `&mut i32` به تو می‌دهد. همین یک نکته همه‌ی ستاره‌های بدنه را توضیح می‌دهد: `value` یک فلش است، پس خواندنش `*value` می‌خواهد و نوشتن رویش `*value = ...`.

ستاره‌ی خطِ آخر را بردار و همان `E0308`ِ بخشِ خطاهای درس را می‌گیری، با لباسِ دیگری:

```text
expected `&mut i32`, found `i32`
```

همان اشتباه، همان راه‌حل. انتساب هیچ‌وقت حدس نمی‌زند.

`values.len()` دست نخورده — محدود کردن مقدارها را عوض می‌کند، نه تعدادشان را. تست با مقایسه‌ی کلِ `Vec` بررسی‌اش می‌کند، که هم «عددِ اشتباه» را می‌گیرد و هم «طولِ اشتباه» را.

## `transfer` — سه ارجاع، دو تایشان تغییرپذیر

```rust
*from -= *amount;
*to += *amount;
```

دو `&mut i32` هم‌زمان زنده، و کامپایلر اعتراضی ندارد، چون به دو متغیرِ متفاوت اشاره می‌کنند. حالا `transfer(&mut a, &mut a, &1)` را صدا بزن و **اعتراض** می‌کند — آن `E0499` است و مالِ [۱.۳.۲](../../02-borrow-checker-rules/README.fa.md).

هر کدام از آن ستاره‌ها واجب است. اولی را بردار و یک کدِ خطای سوم هم به مجموعه‌ات اضافه می‌شود:

```text
error[E0368]: binary assignment operation `-=` cannot be applied to type `&mut i32`
help: `-=` can be used on `i32` if you dereference the left-hand side
```

کدِ متفاوت، درسِ یکسان: فلش آن چیزی نیست که به آن اشاره می‌کند.

مشخصات عمداً هیچ زرنگی‌ای نمی‌کند. هیچ‌چیز بررسی نمی‌شود، `amount`ِ منفی جهت را برعکس می‌کند، و `from` اجازه دارد زیرِ صفر برود. این تنبلی نیست — برای این است که کامنتِ مستندساز رفتار را کاملاً تعیین کند، و هیچ تستی نتواند با قاعده‌ای که هیچ‌وقت به تو گفته نشده غافلگیرت کند.

## این درس واقعاً درباره‌ی چه بود

- **یک ارجاع، فلشی به مقدارِ کسِ دیگری است.** مالکِ چیزی نیست، چیزی کپی نمی‌کند، و وقتی تمام می‌شود هیچ‌چیز آزاد نمی‌شود.
- **`&T` می‌خواند، `&mut T` می‌نویسد، `T` می‌گیرد.** ضعیف‌ترینی را بردار که کار را راه می‌اندازد، و امضا تبدیل به مستنداتی می‌شود که هیچ‌کس نمی‌تواند کهنه‌اش کند.
- **`*` برای انتساب است؛ بقیه‌اش را نقطه‌ی متد انجام می‌دهد.** تقریباً هر ستاره‌ای که می‌نویسی یا سمتِ چپِ یک `=` است یا داخلِ حلقه‌ای روی `&mut`.
- **`&mut` لازم دارد که مالک `mut` باشد.** مجوزی که نداری قابلِ قرض دادن نیست، و `E0596` همین را در یک خط می‌گوید.
- **تاپلِ «پس دادن» رفت.** از این به بعد، تابعی که چیزی را فقط برای پس دادن برمی‌گرداند یعنی یک `&` جا افتاده.

دو سؤال که این درس عمداً باز گذاشت: وقتی یک قرضِ اشتراکی و یک قرضِ تغییرپذیر روی **یک** مقدار هم‌پوشانی کنند چه می‌شود، و یک قرض دقیقاً کِی دیگر زنده حساب نمی‌شود. آن‌ها [۱.۳.۲](../../02-borrow-checker-rules/README.fa.md) و [۱.۳.۳](../../03-borrow-scopes-and-nll/README.fa.md) هستند، به همین ترتیب.
