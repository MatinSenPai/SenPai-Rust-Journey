# راه‌حل

```rust
pub fn longest_word(text: &str) -> &str {
    text.split_whitespace()
        .max_by_key(|word| word.len())
        .unwrap_or("")
}
```

بخش جالب این کد، اون زنجیره‌ی متدهای iterator نیست (که تو فاز ۲ کامل بررسیشون می‌کنیم) — بلکه امضای (signature) همون تابع است: `fn longest_word(text: &str) -> &str`. اینجا یه رابطه‌ی پنهان وجود داره که کامپایلر داره اعمالش می‌کنه، حتی با وجود اینکه هیچ طول عمری (lifetime) به‌طور صریح نوشته نشده: اون `str&` که برگردونده می‌شه، فقط تا زمانی معتبره که خود متغیر `text` معتبر باشه، چرا که این فقط یه بُرش هست که مستقیماً از همون `text` قرض گرفته شده و به هیچ وجه فضای جدیدی رو برای خودش نگرفته. این کار بدون اینکه تو هیچ‌جا نیاز داشته باشی بنویسی `<'a>`، به لطف **lifetime elision (حذف یا نادیده‌گرفتن طول عمرها)** درست کار می‌کنه — برای تابعی که دقیقاً یه دونه پارامتر از نوع ارجاع داره و نوعِ بازگشتیش هم ارجاعیه، اون طول عمرها به‌طور خودکار استنتاج می‌شن (به زبان ساده‌تر یعنی: «خروجی دقیقاً از همون یه دونه ورودی داره قرض می‌گیره»). درس طول عمرها (lifetimes) تو فاز ۲ این قانون رو خیلی شفاف توضیح میده؛ فعلاً در همین حد بدون که کامپایلر همین حالا هم داره تو پس‌زمینه و بی‌سروصدا برات اینا رو پیگیری می‌کنه.

اینکه `(&greet(owned` به‌خوبی کامپایل می‌شه تو شرایطی که تابع `greet` انتظار گرفتنِ `str&` رو داره و `owned` خودش از نوع `String` هست، به خاطر وجودِ **deref coercion** هست: زبان Rust به‌طور خودکار تو محل فراخوانی تابع (مثل همینجا)، یه `String&` رو به `str&` تبدیل می‌کنه (این کار از طریق پیاده‌سازی traitِ `Deref` که `String` برای `str` داره انجام می‌شه)، دلیلش هم اینه که تبدیلِ «من ارجاعی به بافری دارم که مال منه، اما تو فقط یه نمای قرضی ازش رو می‌خوای» همیشه یه تبدیلِ ایمن و بدون هزینه‌ست.
