# ۰۴.۱ — `String` در برابر `str&`

تو طول فاز صفر و یک، بدون اینکه توضیح کاملی داده بشه از هر دوی اینا استفاده کردی — این درس قراره توضیحش رو بهت بده.

## دو تا نوع داده، با یک هدف واحد

- **`String`** — یک بافر دارای **مالکیت (owned)** با قابلیت رشد، که روی حافظه‌ی heap قرار می‌گیره و متن UTF-8 رو تو خودش نگه می‌داره. تو مالکش هستی؛ وقتی که از اسکوپ خارج می‌شه، پاک (drop) می‌شه (تمام مباحث مالکیت فاز یک دقیقاً روش اعمال می‌شه، چون این نوع `Copy` نیست).
- **`str&`** («بُرش رشته» یا "string slice") — یه نمای **قرض‌گرفته‌شده (borrowed)** به متن UTF-8 که یه جای دیگه‌ای قرار داره: مثلاً می‌تونه داخل یه `String` باشه، یا اصلاً یه string literal باشه که مستقیماً داخل خودِ باینری کامپایل‌شده جاگذاری شده (مثلاً `"hello"` در واقع یه `str 'static&` هست — یعنی یه ارجاع که برای کل طول اجرای برنامه معتبره، چون بخشی از خود باینریه، نه اینکه تو زمان اجرا بهش حافظه اختصاص داده بشه).

هر `String`ی می‌تونه به‌عنوان `str&` قرض گرفته بشه (این همون چیزیه که `my_string&` یا `()my_string.as_str` بهت می‌دن). اما یه `str&` نمی‌تونه به `String` تبدیل بشه مگه اینکه واقعاً حافظه براش اختصاص پیدا کنه و کپی بشه (با استفاده از `()to_string.` یا `()to_owned.`).

## چرا دو نوع، در حالی که پایتون فقط یه `str` داره؟

نوع `str` تو پایتون همیشه و به‌طور ضمنی روی heap قرار می‌گیره و با reference-counting (شمارش ارجاع) مدیریت می‌شه — تو هیچ‌وقت به این فکر نمی‌کنی که اون حافظه کجاست، چون محیط زمان اجرایِ پایتون (runtime) با همه‌چیز یکسان برخورد می‌کنه. زبان Rust این انتخاب رو *مرئی (visible)* و *صریح (explicit)* می‌کنه، چون این موضوع برای عملکرد برنامه (performance) و طراحی APIها به‌شدت مهمه:

```rust
fn greet(name: &str) -> String {   // مقداری رو قرض می‌گیره، و یه مقدار دارای مالکیت رو خروجی می‌ده
    format!("Hello, {name}!")
}
```

تابع `greet` یه `str&` می‌گیره چون فقط نیاز داره که اسم رو *بخونه* — گرفتنِ `str&` یعنی این تابع بدون هیچ کپی‌کردنی کار می‌کنه، فرقی هم نداره که فراخواننده یه `String` داشته باشه، یا یه string literal، و یا یه بُرش از یه رشته‌ی بزرگتر. خروجی تابع هم یه `String` هست، چون اون عبارتِ احوال‌پرسی یه داده‌ی کاملاً جدیده که بالاخره باید یه جایی ذخیره بشه، و تابع هم نمی‌تونه ارجاعی به چیزی که همینجا و به شکل محلی ساخته رو برگردونه (این همون تله‌ی «ارجاع آویزون (dangling reference)» تو درس borrow-checker هست) — پس باید یه مقدار با مالکیت کامل برگردونه.

**قانون سرانگشتی**: پارامترهای تابع که فقط قراره متنی رو بخونن باید تقریباً همیشه `str&` باشن، نه `String&` (تو فاز صفر و تو همون درس مربوط به ابزارها، دقیقاً همین قضیه رو به‌واسطه‌ی هشدار `ptr_arg` از سمت clippy محکم‌ترش کردی). و هر وقت داری یه متن جدید می‌سازی که خودت مالکش هستی، `String` رو برگردون.

## مفهوم UTF-8، و اینکه چرا چیزی به اسم `[s[3` وجود نداره

نوع‌های `String` تو زبان Rust با فرمت UTF-8 کدگذاری می‌شن، و هر کاراکتر می‌تونه از ۱ تا ۴ بایت فضا اشغال کنه (درس مربوط به `char`/`len_utf8` رو یادت بیاد). به همین خاطر، زبان Rust **عمداً** از اندیس‌گذاریِ (indexing) یه `String` بر اساس موقعیتِ کاراکتر پشتیبانی نمی‌کنه (`[s[3` اصلاً کامپایل نمی‌شه) — اگه بخوای با ایندکسِ بایت تو یه متنِ چند-بایتیِ UTF-8 جابه‌جا بشی، ممکنه صاف بیافتی وسطِ یه کاراکتر، که هیچ معنی و مفهومی نداره. به جای این کار، باید بر اساس یه محدوده‌ی بایتی از یه بُرش (slice) استفاده کنی (درس بعدی)، و یا اینکه مستقیماً از طریق `()chars.` روی کاراکترها iterate کنی.
