# راه‌حل

`&s[..n]` و `&nums[1..nums.len() - 1]` range indexing هستند. `..n` ابتدا تا پیش از `n` و `..` کل بازه است. خروجی fat اشاره‌گر شامل اشاره‌گر و طول است، نه copy داده.

برای دو عضو، range می‌شود `1..1`: ابتدا و انت‌ها برابرند، پس خالی ولی معتبر است. start بزرگ‌تر از end یا end بیرون مجموعه panic می‌کند.

`sum_slice(nums: &[i32])` به مالک اصلی اهمیت نمی‌دهد؛ فقط دنباله‌ی پیوسته و قابل‌خواندن `i32` می‌خواهد. بنابراین آرایه، بردار و subslice با یک API کار می‌کنند.
