# ۰۴.۲ — بُرش‌ها (Slices)

در واقع `str&` فقط یه حالتِ خاص از یه ایده‌ی خیلی جامع‌تره: یک **بُرش (slice)** به معنی یه نمای قرض‌گرفته‌شده (borrowed) به یه *بخش متوالی (contiguous run)* از عناصریه که داخلِ یه collection بزرگتر قرار دارن — بدون هیچ حافظه‌ی اختصاصیِ اضافه‌ای، و بدون هیچ کپی‌کردنی؛ فقط شامل یه پوینتر به اضافه‌ی طول اون بخش می‌شه.

## برش‌های رشته (String slices) به‌طور دقیق

```rust
let s = String::from("hello world");
let hello: &str = &s[0..5];   // بایت‌های ۰ تا ۴
let world: &str = &s[6..11];
let whole: &str = &s[..];     // کلش
```

عبارتِ `[s[0..5&` یه **ایندکسِ بازه‌ای (range index)** به بایت‌های زیربناییِ `s` هستش. این همون ایندکس‌گذاری بر اساسِ محدوده‌ی بایتیه که تو درس قبلی گفتیم `String` از اون به صورت کاراکتر تکی (مثل `[s[3`) پشتیبانی نمی‌کنه — محدوده‌ها کاملاً مجازن (و اصلاً نیازمندِ همین روش هستی) دقیقاً به این دلیل که تعیینِ مرزهای یه محدوده چیزیه که *تو* انتخابش می‌کنی، و Rust تو زمان اجرا (runtime) اگه مرزی رو انتخاب کنی که صاف بیافته وسطِ یه کاراکترِ چندبایتی، برنامه رو کرش (panic) می‌کنه (مثلاً `[s[0..1&` روی رشته‌ای که با `'🦀'` شروع می‌شه حتماً باعث panic می‌شه — این یه لبه‌ی برنده‌ی واقعیه که ارزش داره به طور صریح ازش خبر داشته باشی، به جای اینکه بی‌سروصدا کدت بهت داده‌ی خراب تحویل بده).

## بُرش‌های آرایه و Vec — همون ایده که تعمیم داده شده

```rust
let nums = [1, 2, 3, 4, 5];
let middle: &[i32] = &nums[1..4]; // [2, 3, 4]
```

عبارت `[i32]&` یه نوع برای بُرش (slice type) به حساب میاد: یه نمای قرضی به هر بخش متوالی از مقادیر `i32`، حالا فرقی نمی‌کنه که اون بخش داخل یه آرایه با سایز ثابت باشه، داخل یه `Vec<i32>` (که تو فاز ۲ می‌بینیم) باشه، یا داخل یه بُرشِ دیگه قرار گرفته باشه. توابعی که فقط نیاز دارن یه دنباله (sequence) رو *بخونن*، تقریباً همیشه باید به جای گرفتنِ `Vec<T>&`، یه `[T]&` بگیرن — این دقیقاً همون منطقیه که به خاطرش `str&` رو به `String&` ترجیح می‌دیم (و بله، خطایابِ clippy با قانون `ptr_arg` این یکی رو هم مچش رو می‌گیره و هشدار می‌ده).
