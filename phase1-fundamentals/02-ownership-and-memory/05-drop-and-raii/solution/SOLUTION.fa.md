# راه‌حل

```rust
pub fn drop_order_in_one_scope() -> Vec<String> {
    take_log();
    {
        let _a = Tracker::new("a");
        let _b = Tracker::new("b");
        let _c = Tracker::new("c");
    }
    take_log()
}
```

متغیرهای `a`، `b` و `c` دقیقاً به همین ترتیب تعریف می‌شن، اما لاگی که برمی‌گرده این شکلیه `["c", "b", "a"]` — یعنی با ترتیبِ **معکوس (reverse)** نسبت به تعریف‌شدن. این قضیه دیمی و تصادفی نیست: مقادیری که دیرتر تعریف می‌شن ممکنه (به طور کلی) وابسته به زنده بودنِ مقادیری باشن که زودتر ساخته شدن (مثلاً ممکنه یه ارجاع یا reference بهشون داشته باشن — که موضوع ماژول بعدی از فاز یکمونه)، پس Rust مجبوره همه‌چیز رو برعکسِ همون ترتیبی که ساخته بود از بین ببره؛ دقیقاً همونطوری که پرانتزهای تودرتو رو از داخل به بیرون می‌بندی.

```rust
pub fn early_drop_demo() -> Vec<String> {
    take_log();
    {
        let first = Tracker::new("first");
        let _second = Tracker::new("second"); // به طور طبیعی تو آخر بلاک پاک می‌شه
        drop(first);
    }
    take_log()
}
```

دستور `drop(first)` متغیر `first` رو مجبور می‌کنه که بلافاصله و خارج از اون روال طبیعیِ آخر اسکوپ پاک بشه — به همین دلیله که به جای لاگ با ترتیبِ معکوسِ `["second", "first"]` (که اگه اون `drop` صریح رو نمی‌نوشتیم می‌گرفتیم)، لاگ به شکلِ `["first", "second"]` برمی‌گرده. تابع `std::mem::drop` هیچ جادویی نداره؛ این فقط یه تابع معمولیه که مالکیت (ownership) آرگومانی که بهش می‌دی رو می‌گیره و بعدش هیچ کاری باهاش نمی‌کنه — اون مقدار هم فقط به این دلیل پاک (drop) می‌شه که اسکوپِ (بسیار کوتاه) خود اون تابع بلافاصله تموم می‌شه.

```rust
fn create_tracker(name: &str) -> Tracker {
    Tracker::new(name)
}

pub fn move_extends_lifetime() -> Vec<String> {
    take_log();
    {
        let _t = create_tracker("moved");
    }
    take_log()
}
```

لاگ خروجی همیشه فقط یه ورودیِ `"moved"` تو خودش داره، که یک‌بار هم ثبت شده، اونم در انتهای بلاکِ *بیرونی (outer)* — نه درون تابع `create_tracker`. تابع `create_tracker` شیء `Tracker` رو می‌سازه و بلافاصله اون رو برمی‌گردونه و با این کار مالکیتش رو به فراخواننده (caller) منتقل (move) می‌کنه؛ از اونجایی که محل مالکِ اون مقدار تا زمان تموم‌شدنِ `{ ... }` بیرونی تغییر نمی‌کنه، دقیقاً همونجا — و فقط همونجا — است که مقدار پاک (drop) می‌شه.
