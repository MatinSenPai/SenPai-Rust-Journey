# راه‌حل

`keep_and_modify` از `Copy` بودن `i32` استفاده می‌کند: `let mut m = n` یک عدد مستقل می‌سازد و `n` معتبر می‌ماند؛ پس `(n, m)` به clone نیاز ندارد.

`duplicate_and_uppercase` و `double_prices` به `.clone()` صریح نیاز دارند، چون `String` و `Vec<f64>` `Copy` نیستند. trait به نوع کامل مربوط است، نه فقط اعضای آن. `Vec<T>` یک اشاره‌گر، طول، ظرفیت و بخشی از حافظه‌ی heap را در اختیار دارد؛ کپی پنهانی آن هم هزینه‌ای نامعلوم داشت و هم خطر مالکیت دوگانه می‌ساخت.

بدون clone، مصرف `prices` در `for price in prices`، `IntoIterator::into_iter` را با مقدار صدا می‌زند و بردار منتقل می‌شود. تلاش برای return کردن original به خطایی از خانواده‌ی `E0382` می‌رسد.
