# ۰۲.۲ — `Clone` و `Copy`

## چیزی که قرار است یاد بگیری

```rust
let x = 5;
let y = x;
println!("{x}");
```

این کد معتبر است چون `i32` صفت `Copy` دارد. نوع‌های `Copy` هنگام assignment بیت‌به‌بیت کپی می‌شوند؛ `x` و `y` دو مقدار مستقل‌اند. عدد‌های صحیح و اعشاری، `bool`، `char` و tuple/آرایههایی که همه‌ی عضوهایشان `Copy` است معمولاً این صفت را دارند.

`String` و `Vec<T>` مالک حافظه‌ای روی heap هستند و `Copy` نیستند. اگر مقداردهی یک `String` ده‌مگابایتی را پنهانی تکثیر می‌کرد، هزینه‌ای بزرگ و نامرئی می‌ساخت. Rust به‌صورت پیش‌فرض مالکیت را منتقل می‌کند و ساختن نسخه‌ی مستقل را صریح می‌خواهد.

## مثال فارسی روزمره

عدد پیگیری سفارش را می‌توان روی دو رسید نوشت: هر عدد مستقل و ارزان است؛ این شبیه `Copy` است. برای ساخت کارت عضویت مستقل باید کارت تازه‌ای صادر شود؛ این کار زمان و هزینه دارد و شبیه `Clone` است.

```rust
let s1 = String::from("hello");
let s2 = s1.clone();
println!("{s1} {s2}");
```

`.clone()` می‌گوید آگاهانه نسخه‌ی دارای مالکیت و مستقلی می‌خواهی. هر نوع دارای `Copy`، `Clone` هم هست؛ اما هر `Clone` لزوماً `Copy` نیست.

## پل به بک‌اند

clone کردن درخواست body یا فهرست بزرگ response برای عبور از خطای move می‌تواند تأخیر و مصرف حافظه را بالا ببرد. اگر تابع فقط داده را می‌خواند، اغلب `&T` یا `&str` قرارداد دقیق‌تری است. clone همیشه بد نیست؛ snapshot مستقل برای کار صف یا جداکردن عمر task ممکن است لازم باشد.

## این تشبیه کجا دیگر دقیق نیست؟

`Copy` الزاماً به معنای «روی stack» نیست و stack/heap معیار رسمی trait نیست؛ معیار این است که duplicate بیت‌به‌بیت نوع امن باشد. همچنین کامپایلر آزاد است storage را optimize کند.
