# ۰۲.۳ — متد Drop و مفهوم RAII

## وقتی یه مقدار از اسکوپِ مالکش خارج می‌شه دقیقاً چه اتفاقی می‌افته

```rust
{
    let s = String::from("hello");
    // ... استفاده از s ...
} // اسکوپِ s تو این نقطه تموم می‌شه — Rust دقیقاً همینجا به‌طور خودکار
  // و قطعی تابع `(drop(s` رو صدا می‌زنه. هیچ زباله‌روبی تصمیم نمی‌گیره که این کار «بعداً، هر وقت شد» انجام بشه.
```

این الگو — «به محض اینکه یه مقدار ساخته می‌شه یه منبعی (resource) رو در اختیار بگیر، و به محض اینکه اسکوپِ مالکش تموم شد به‌طور خودکار آزادش کن» — یه اسمی داره: **RAII** (مخفف Resource Acquisition Is Initialization)، و این همون ایده‌ی سازمان‌دهی‌کننده‌ایه که پشتِ تقریباً تمام مدیریت منابع در Rust قرار داره: بله حافظه شاملش می‌شه، اما همین‌طور هندلِ فایل‌ها (file handles)، سوکت‌های شبکه، اتصال‌های دیتابیس، قفل‌های mutex — هر چیزی که به پاکسازی نیاز داره، به‌طور خودکار و *قطعی* اون رو دریافت می‌کنه و این کار به اسکوپ گره خورده، نه به زمانی که زباله‌روب (GC) تصادفاً اجرا بشه.

با پایتون مقایسه‌اش کن: `f = open("file.txt")` هیچ تضمینی نمی‌ده که فایل `f` تو هیچ نقطه‌ی مشخصی بسته بشه — برای اینکه بسته‌شدنِ فایل به اسکوپ گره بخوره، تو به `:with open(...) as f` (همون context manager) نیاز داری که اونم یه کار اختیاری و موردیه که توسط هرکسی که اون کلاس رو نوشته تصمیم‌گیری می‌شه. تو زبان Rust، **هر** نوعی (type) این قابلیت رو از طریق traitِ `Drop` به صورت رایگان دریافت می‌کنه — هیچ قانون جداگانه‌ای برای اینکه «یادت بمونه ببندیش» وجود نداره که بخوای رعایتش کنی.

## ویژگی `Drop` (همون Drop Trait)

```rust
struct LoudResource {
    name: String,
}

impl Drop for LoudResource {
    fn drop(&mut self) {
        println!("Cleaning up: {}", self.name);
    }
}
```

با پیاده‌سازی `Drop` برای یه نوع (type)، این امکان بهت داده می‌شه که دقیقاً تو همون لحظه‌ای که یه متغیر از اسکوپ خارج می‌شه، یه منطق دلخواه برای پاکسازی (custom cleanup logic) اجرا کنی. بعداً از این ویژگی برای کارهایی مثل «بستن این اتصال دیتابیس» یا «آزاد کردن این قفل» استفاده می‌کنی — اما برای این درس، ازش استفاده می‌کنی تا فرایند پاکسازی رو *مرئی (visible)* کنی، تا بتونی تو عمل ببینی که قوانین مالکیت از دو درس قبلی چطوری کار می‌کنن.

دو تا قانون که همین الان باید بدونی:
- نمی‌تونی مستقیماً `.drop()` رو صدا بزنی (این یه متد معمولی نیست) — در عوض، اگه خواستی یه چیزی رو زودتر از موعد پاک (drop) کنی، باید تابع `std::mem::drop(value)` رو صدا بزنی (یه تابع آزاد که فقط مالکیت رو می‌گیره و بلافاصله اجازه می‌ده تا متغیر از اسکوپ خارج بشه).
- ترتیب اهمیت داره: مقادیر تو همون اسکوپ دقیقاً با **ترتیب معکوس (reverse order)** نسبت به زمان تعریف‌شدنشون پاک می‌شن، و با منتقل کردن یه متغیر (که تو درس‌های قبلی دیدی) در واقع *زمان* پاک‌شدنش رو هم تغییر می‌دی — عملِ drop هر جایی که اسکوپِ *آخرین مالکِ* مقدار تموم بشه اتفاق می‌افته، نه اونجایی که در اصل ساخته شده بود.

## وظیفه‌ی تو

فایل `src/lib.rs` یه نوع به اسم `Tracker` داره که `Drop` رو طوری پیاده‌سازی کرده که یه پیغام رو به یه لاگِ مشترک (shared log) اضافه می‌کنه (تا تست‌ها بتونن ترتیبِ dropها رو بدون تکیه به خروجی `!println` رصد کنن). توابعی که باهاش کار می‌کنن رو پیاده‌سازی کن.
