# ۱.۲.۲ — معناشناسیِ حرکت

## در یک نگاه

بعد از این درس می‌توانی:

- بگویی `let b = a;` وقتی `a` یک `String` است دقیقاً چه می‌کند — و چرا بعدش `a` قابلِ استفاده نیست.
- `E0382` را ببینی و بدانی چه چیزی را نگاه کنی، به‌جای اینکه `.clone()` بپاشی رویش.
- بگویی چرا `let b = a;` وقتی `a` یک `i32` است هیچ مشکلی ندارد.
- بگویی چرا `for x in v` وکتور را می‌بلعد و `for x in &v` نه.

**زمان:** حدود ۵۰ دقیقه · **پیش‌نیاز:** [۱.۲.۱ — پشته و هیپ](../01-stack-and-heap/README.fa.md)

---

## چرا اهمیت دارد

این آن درسی است که Rust را به Rust تبدیل می‌کند.

در پایتون این کاملاً بی‌خطر است:

```python
first = ["a", "b"]
second = first
second.append("c")
print(first)   # ['a', 'b', 'c']  ← اولی هم عوض شد
```

هر دو نام به یک لیست اشاره می‌کنند. اگر انتظارش را داری خوب است و اگر نداری منبعِ باگ است، و پایتون هیچ کمکی به تشخیصش نمی‌کند.

در C++ همان خط یک کپیِ کاملِ عمیق می‌سازد — که امن است ولی ممکن است بی‌سروصدا گران باشد؛ یا اگر کلاس را خودت نوشته باشی و درست تعریفش نکرده باشی، **دو شیء می‌شوند مسئولِ یک بافر و هر دو آزادش می‌کنند.** همان آزادسازیِ دوباره‌ی [۱.۲.۱](../01-stack-and-heap/README.fa.md).

Rust جوابِ سومی می‌دهد که هیچ زبانِ پرکاربردی قبلش به‌عنوانِ پیش‌فرض نداده بود: **مقدار حرکت می‌کند.** `second` مالک می‌شود و `first` دیگر نیست. نه کپی، نه اشتراک، نه ابهام. و اگر بعدش از `first` استفاده کنی، برنامه کامپایل نمی‌شود.

این تنها بخشِ Rust است که واقعاً باید *یاد بگیری* نه اینکه فقط به خاطر بسپاری. اگر این ماژول برایت جا بیفتد، بقیه‌ی زبان پشتِ سرش می‌آید.

## مفهوم

### `let b = a;` واقعاً چه می‌کند

```rust
let first = String::from("hello");
let second = first;
```

از [۱.۲.۱](../01-stack-and-heap/README.fa.md) می‌دانی `first` سه کلمه روی پشته است که به یک بافر روی هیپ اشاره می‌کند.

آن انتساب **آن سه کلمه را کپی می‌کند.** بافر تکان نمی‌خورد. حالا دو مجموعه‌ی سه‌کلمه‌ای داری که به یک بافرِ واحد اشاره می‌کنند.

و همین‌جا مسئله است: هر دو `first` و `second` سرِ آکولادِ بسته آزاد می‌شوند. دو آزادسازی برای یک بافر. **آزادسازیِ دوباره.**

Rust مسئله را با یک تصمیم حل می‌کند که به‌سادگیِ خودش برجسته است: **بعد از آن انتساب، `first` دیگر یک اتصالِ معتبر نیست.** استفاده از آن یک خطای کامپایل است. یک بافر، یک مالک، یک آزادسازی.

به این می‌گویند **حرکت** (move). چیزی که حرکت کرد داده نبود — **مسئولیت** بود.

```text
second:     hello
length:     5
third:      hello
its buffer: 0x22a8d281890
```

### حرکت ارزان است، و همیشه به یک اندازه

```rust
let large = vec![0_u8; 10_000_000];
let also_large = large;
```

```text
ten MB moved, 24 bytes copied
```

ده مگابایت «حرکت کرد» و چیزی که واقعاً کپی شد بیست‌وچهار بایت بود. **هزینه‌ی یک حرکت به اندازه‌ی داده بستگی ندارد**، چون داده اصلاً جابه‌جا نمی‌شود. فقط سه کلمه.

این نکته‌ی مهمی است که آدم‌ها دیر می‌فهمند: پاس دادنِ یک `Vec`ِ بزرگ به یک تابع «کپیِ گران» نیست. رایگان است. چیزی که گران است `.clone()` است، و آن را باید صریح بنویسی.

### چه چیزی حرکت می‌کند و چه چیزی نه

```rust
let a = 5_i32;
let b = a;
println!("a: {a}, b: {b}");     // هر دو کار می‌کنند
```

```text
a: 5, b: 5
bool:  true true
char:  س س
f64:   1.5 1.5
array: [1, 2, 3] [1, 2, 3]
tuple: (1, true) (1, true)
```

`a` بعدش هنوز کار می‌کند. چرا؟

چون یک `i32` مالکِ هیچ چیزی نیست. کلِ مقدار همان چهار بایت است؛ کپی کردنشان کلِ چیز را کپی می‌کند، و هیچ بافری وجود ندارد که کسی مسئولش باشد. دو مالک برای هیچ‌چیز، مشکلی نیست.

خطِ تقسیم دقیقاً همین است:

| کپی می‌شود | حرکت می‌کند |
|---|---|
| `i32`، `u8`، `usize`، `f64` | `String` |
| `bool`، `char` | `Vec<T>` |
| `&T` | هر چیزی که یکی از این‌ها را داشته باشد |
| آرایه و تاپلی که همه‌چیزِ داخلش کپی‌شونده باشد | |

و آن سطرِ آخر مهم است:

```rust
let labelled = (1_i32, String::from("owned"));
let labelled_again = labelled;
// println!("{labelled:?}");   // <- E0382
```

یک تاپل با یک `String` داخلش حرکت می‌کند، چون حالا بافری هست که کسی باید مسئولش باشد.

> صفتی که تعیین می‌کند یک نوع در کدام ستون است `Copy` نام دارد، و [۱.۲.۳](../03-clone-and-copy/README.fa.md) کاملش می‌کند. فعلاً قاعده‌ی ذهنی این است: **مالکِ چیزی روی هیپ هست؟ پس حرکت می‌کند.**

### حالا آن `&` از ۱.۱.۶ معنا پیدا می‌کند

```rust
for line in &lines {
    total += line.len();
}
```

```text
total bytes: 14
still here:  ["alpha", "beta", "gamma"]
```

در برابرِ:

```rust
for line in lines {
    // ...
}
// println!("{lines:?}");   // <- E0382
```

بدونِ `&`، حلقه **مالکیتِ وکتور را می‌گیرد**. بعدش `lines` وجود ندارد.

با `&`، حلقه فقط قرض می‌گیرد. عنصرها را نگاه می‌کند و وکتور مالِ تو می‌ماند.

کدام را بنویسی؟ **قرض بده مگر اینکه بخواهی مصرف کنی.** فرمِ مصرف‌کننده وقتی درست است که واقعاً خودِ عنصرها را می‌خواهی — نه فقط اطلاعاتی درباره‌شان.

و یک تله که ارزشِ دیدن دارد:

```rust
let numbers = vec![1, 2, 3];
for n in numbers {
    sum += n;
}
// numbers رفته
```

`i32` کپی می‌شود، پس چرا `numbers` رفت؟ چون **خودِ `Vec` حرکت کرد، نه `i32`ها.** `Vec` مالکِ بافرش است، و حلقه آن مالکیت را گرفت. عناصر داخلش کپی‌شونده بودن هیچ ربطی به این ندارد.

### چرا Rust این را انتخاب کرد

ارزش دارد که این را صریح ببینی، چون توضیح می‌دهد چرا زبان این‌طوری است و نه جورِ دیگری.

| رویکرد | چه می‌کند | بهایش |
|---|---|---|
| **اشتراک** (پایتون، جاوا) | هر دو نام به یک شیء | تغییرِ یکی دیگری را عوض می‌کند؛ نمی‌شود گفت کِی آزاد شود |
| **کپیِ عمیق** (پیش‌فرضِ C++) | یک کپیِ کامل | گران و پنهان؛ اگر اشتباه بنویسی‌اش، آزادسازیِ دوباره |
| **حرکت** (Rust) | انتقالِ مسئولیت | مبدأ غیرِقابلِ‌استفاده می‌شود |

حرکت تنها گزینه‌ای است که هم ارزان است و هم امن. بهایش این است که باید ردِ اینکه چه کسی مالکِ چیست را نگه داری — و کارِ کامپایلر دقیقاً همین است که این را برایت نگه دارد.

## خطاهایی که خواهی دید

### `E0382` — استفاده بعد از حرکت

این پرتکرارترین خطای Rust است بعد از سمی‌کالن، و آنی است که آدم‌ها را از زبان فراری می‌دهد. خوب بخوانش و از این کمترش می‌شود.

```text
error[E0382]: borrow of moved value: `first`
  --> examples\04-use-after-move.rs:11:24
   |
 6 |     let first = String::from("hello");
   |         ----- move occurs because `first` has type `String`, which does not implement the `Copy` trait
 7 |     let second = first;
   |                  ----- value moved here
...
11 |     println!("first:  {first}");
   |                        ^^^^^ value borrowed here after move
   |
help: consider cloning the value if the performance cost is acceptable
   |
 7 |     let second = first.clone();
   |                       ++++++++
```

**کامپایلر به چه اعتراض دارد:** خطا سه جای متفاوت را نشان می‌دهد و هر سه لازم‌اند:

۱. **خطِ ۶** — چرا اصلاً حرکت کرد: `String` صفتِ `Copy` را ندارد.
۲. **خطِ ۷** — کجا حرکت کرد.
۳. **خطِ ۱۱** — کجا بعدش استفاده شد.

با هم یک روایتِ کامل‌اند: اینجا ساخته شد، اینجا داده شد، اینجا خواسته شد.

**راه‌حل:** بستگی دارد به اینکه واقعاً چه می‌خواستی، و **این سؤالی است که باید از خودت بپرسی**:

| اگر می‌خواستی | بنویس |
|---|---|
| فقط به مقدار نگاه کنی | `let second = &first;` — [۱.۳.۱](../../03-borrowing-and-references/01-shared-and-mutable-refs/README.fa.md) |
| دو تا کاملاً مستقل داشته باشی | `let second = first.clone();` |
| فقط یکی داشته باشی | ترتیبِ کد را عوض کن تا بعد از حرکت به `first` احتیاج نداشته باشی |

**چرا این «راه‌حل» است:** به آن `help` دقت کن و به عبارتی که در آن هست — «*if the performance cost is acceptable*». کامپایلر دارد `.clone()` را پیشنهاد می‌دهد **و هم‌زمان می‌گوید که رایگان نیست.**

این را جدی بگیر. `.clone()` همیشه هر `E0382` را ساکت می‌کند، و همین است که خطرناکش می‌کند: تازه‌کارها یاد می‌گیرند بپاشندش روی هر خطا و بعد تعجب می‌کنند چرا برنامه‌ی Rustشان از پایتون کندتر است. **قبل از هر `.clone()` از خودت بپرس آیا واقعاً به دو نسخه‌ی مستقل احتیاج داری.** نُه بار از ده بار جواب نه است و چیزی که می‌خواستی یک `&` بود.

### `E0507` — بیرون آوردن از یک `Vec`

```text
error[E0507]: cannot move out of index of `Vec<String>`
  --> examples\05-move-out-of-a-vec.rs:10:17
   |
10 |     let first = lines[0];
   |                 ^^^^^^^^ move occurs because value has type `String`, which does not implement the `Copy` trait
   |
help: consider borrowing here
   |
10 |     let first = &lines[0];
   |                 +
help: consider cloning the value if the performance cost is acceptable
   |
10 |     let first = lines[0].clone();
   |                         ++++++++
```

**کامپایلر به چه اعتراض دارد:** `lines[0]` می‌خواهد آن `String` را بیرون بیاورد. ولی آن‌وقت `Vec` یک سوراخ پیدا می‌کند — جایگاهی که مقدارِ معتبری ندارد — و چنین چیزی وجود ندارد. هر جایگاه از ۰ تا `len` باید معتبر باشد.

**راه‌حل:** باز هم بستگی دارد چه می‌خواهی:

| اگر می‌خواستی | بنویس |
|---|---|
| نگاهی به آن بیندازی | `&lines[0]` |
| یک نسخه‌ی خودت | `lines[0].clone()` |
| **واقعاً بیرونش بیاوری** | `lines.remove(0)` |

**چرا این راه‌حل است:** `remove(0)` قانونی است چون سوراخ را درست می‌کند: عنصر را می‌دهد و بقیه را یکی به عقب می‌کشد، پس `Vec` یکی کوتاه‌تر می‌شود و همچنان بی‌سوراخ.

دقت کن که کامپایلر `remove` را پیشنهاد نداد — دو گزینه‌ی امن‌ترش را پیشنهاد داد. راهنماییِ کامپایلر عالی است ولی خواندنِ ذهن نیست؛ **تصمیم درباره‌ی اینکه چه می‌خواستی مالِ توست.**

## تمرین

### گرم‌کردن

<details>
<summary><code>let b = a;</code> وقتی <code>a</code> یک <code>String</code> است چه می‌کند؟</summary>

سه کلمه‌ی روی پشته را کپی می‌کند و `a` را نامعتبر می‌کند. بافرِ روی هیپ تکان نمی‌خورد؛ فقط مسئولیتش منتقل می‌شود.

</details>

<details>
<summary>حرکت دادنِ یک <code>Vec</code> با ده میلیون عنصر چقدر بایت کپی می‌کند؟</summary>

بیست‌وچهار. سه کلمه، مثلِ هر حرکتِ دیگری. اندازه‌ی داده هیچ ربطی ندارد.

</details>

<details>
<summary>چرا <code>let b = a;</code> وقتی <code>a</code> یک <code>i32</code> است مشکلی ندارد؟</summary>

چون `i32` مالکِ هیچ چیزی نیست. کلِ مقدار همان چهار بایت است و کپی کردنشان کلِ چیز را کپی می‌کند. هیچ بافری نیست که دو نفر مسئولش باشند.

</details>

<details>
<summary><code>(1, true)</code> و <code>(1, String::new())</code> چه فرقی دارند؟</summary>

اولی کپی می‌شود چون همه‌ی اجزایش کپی‌شونده‌اند. دومی حرکت می‌کند، چون آن `String` بافری روی هیپ دارد.

</details>

<details>
<summary><code>for x in v</code> و <code>for x in &amp;v</code> چه فرقی دارند؟</summary>

اولی مالکیتِ `v` را می‌گیرد و بعدش `v` وجود ندارد. دومی قرضش می‌گیرد و `v` می‌ماند.

</details>

<details>
<summary>چرا <code>lines[0]</code> روی یک <code>Vec&lt;String&gt;</code> کامپایل نمی‌شود؟</summary>

چون بیرون آوردنِ آن عنصر در `Vec` یک سوراخ می‌گذاشت، و `Vec` نمی‌تواند سوراخ داشته باشد. `remove(0)` قانونی است چون هم‌زمان سوراخ را می‌بندد.

</details>

<details>
<summary>وقتی <code>E0382</code> گرفتی، اولین سؤالی که از خودت می‌پرسی چیست؟</summary>

«آیا واقعاً به دو نسخه‌ی مستقل احتیاج دارم؟» اگر نه — که معمولاً نه است — چیزی که می‌خواستی یک `&` بود، نه یک `.clone()`.

</details>

### تعمیر

`examples/04-use-after-move.rs` را **سه** جورِ متفاوت درست کن:

۱. با `.clone()`.
۲. با `&`، بدونِ هیچ کلونی.
۳. با عوض کردنِ ترتیبِ خط‌ها، بدونِ کلون و بدونِ `&`.

بعد بگو کدام بهترین است و چرا. جوابت باید کلمه‌ی «تخصیص» را داشته باشد.

بعد `examples/05-move-out-of-a-vec.rs` را طوری درست کن که `first` واقعاً یک `String`ِ مالکْ‌دار باشد — نه یک ارجاع و نه یک کلون.

### پیاده‌سازی

پنج تابع در `src/lib.rs`:

```sh
cargo test -p p1-02-02-move-semantics
```

هر پنج تا مالکیتِ چیزی را می‌گیرند و چیزِ تازه‌ای پس می‌دهند. این شکل تصادفی نیست: کدِ Rust وقتی مقدارها حرکت می‌کنند همین شکلی می‌شود.

یکی از پنج تا برای اینکه کارش را بکند لازم است `mut` باشد، و امضایش این را نمی‌گوید. بفهم کدام و چرا مجازی که خودت اضافه‌اش کنی.

### بساز

یک `pub fn drain_into(source: Vec<String>, mut target: Vec<String>) -> Vec<String>` بنویس که همه‌چیزِ `source` را به انتهای `target` منتقل کند و `target` را برگرداند.

بعد این را جواب بده: **چند تخصیصِ حافظه اتفاق افتاد؟** با `Vec::with_capacity` امتحان کن و ببین می‌توانی به صفر برسانی‌اش.

بعد امضا را به `drain_into(source: Vec<String>, target: Vec<String>)` عوض کن — بدونِ `mut`. هنوز کار می‌کند؟ چرا؟

### چالش (اختیاری)

**بخشِ یک.** این کامپایل می‌شود؟ اگر نه، دقیقاً کدام خط و چرا؟

```rust
let a = String::from("x");
let b = a;
let a = b;
println!("{a}");
```

**بخشِ دو.** این چطور؟

```rust
let mut a = String::from("x");
let b = a;
a = String::from("y");
println!("{a} {b}");
```

اگر تعجب کردی، دلیلش را بگو. سرنخ: یک اتصالِ حرکت‌کرده نابود نشده، فقط **مقداردهی‌نشده** است.

**بخشِ سه.** این را اجرا کن و نشانی‌ها را توضیح بده:

```rust
let first = String::from("hello");
println!("{:p}", first.as_ptr());
let second = first;
println!("{:p}", second.as_ptr());
let third = second;
println!("{:p}", third.as_ptr());
```

سه حرکت، و آن نشانی چه کرد؟ حالا در یک جمله بگو حرکت واقعاً چیست.

---

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به کارت می‌آید |
|---|---|---|
| حرکت | انتقالِ مالکیت؛ مبدأ نامعتبر می‌شود | هر انتساب یا پاس دادنِ یک نوعِ مالکْ‌دار |
| مالک | تنها اتصالی که مسئولِ آزاد کردن است | همه‌جا |
| `Copy` | نوع‌هایی که به‌جای حرکت کپی می‌شوند | اعداد، `bool`، `char` |
| `E0382` | استفاده بعد از حرکت | پرتکرارترین خطای این ماژول |
| `E0507` | بیرون آوردن از یک مجموعه | `vec[0]` روی `Vec<String>` |
| `.clone()` | یک نسخه‌ی کاملاً مستقل | فقط وقتی واقعاً دو تا می‌خواهی |
| `remove(i)` | عنصر را بیرون می‌آورد و بقیه را می‌کشد | بیرون آوردنِ قانونی از `Vec` |
| `mut` روی پارامتر | داخلِ بدنه تغییرش می‌دهم | بخشی از امضا نیست |

### الان می‌دانی

- انتساب برای نوع‌های مالکْ‌دار مسئولیت را منتقل می‌کند، نه داده را.
- یک حرکت همیشه سه کلمه است، هرقدر داده بزرگ باشد.
- مبدأ عمداً نامعتبر می‌شود؛ همین است که از آزادسازیِ دوباره جلوگیری می‌کند.
- نوع‌هایی که مالکِ چیزی روی هیپ نیستند کپی می‌شوند نه حرکت.
- `for x in v` مصرف می‌کند و `for x in &v` قرض می‌گیرد.
- `E0382` سه جا را نشان می‌دهد، و `.clone()` جوابِ پیش‌فرض نیست.

### می‌توانی توضیح بدهی؟

- `let b = a;` وقتی `a` یک `String` است چه می‌کند؟
- چرا حرکت دادنِ یک وکتورِ ده‌مگابایتی ارزان است؟
- چرا `i32` حرکت نمی‌کند؟
- چرا مبدأ نامعتبر می‌شود، و اگر نمی‌شد چه اتفاقی می‌افتاد؟
- `for x in v` و `for x in &v` چه فرقی دارند؟
- وقتی `E0382` می‌بینی، سه سؤالی که می‌پرسی چیست؟
