# راه‌حل — ۱.۲.۲ معناشناسیِ حرکت

```rust
pub fn extended(mut text: String, suffix: char) -> String {
    text.push(suffix);
    text
}

pub fn reversed(values: Vec<i32>) -> Vec<i32> {
    let mut out = Vec::with_capacity(values.len());
    for offset in 0..values.len() {
        out.push(values[values.len() - 1 - offset]);
    }
    out
}

pub fn total_bytes_of(values: Vec<String>) -> usize {
    let mut bytes = 0;
    for value in &values {
        bytes += value.len();
    }
    bytes
}

pub fn take_first(mut values: Vec<String>) -> String {
    values.remove(0)
}

pub fn merged(left: Vec<i32>, right: Vec<i32>) -> Vec<i32> {
    let mut out = left;
    for value in right {
        out.push(value);
    }
    out
}
```

## `extended` — آن `mut`ای که در امضا ظاهر شد

تمرین به تو `text: String` داده بود. راه‌حل `mut text: String` دارد. به‌نظر می‌رسد امضا عوض شده، و نشده:

```rust
pub fn extended(mut text: String, suffix: char) -> String
```

**`mut` روی یک پارامتر بخشی از نوعِ تابع نیست.** صداکننده آن را نمی‌بیند، برایش مهم نیست، و هیچ چیزی در نحوه‌ی صدا زدنت عوض نمی‌شود. فقط یک چیز به کامپایلر می‌گوید: *داخلِ این بدنه قصد دارم نسخه‌ی خودم از این اتصال را تغییر بدهم.* و مجازی، چون حالا مالِ توست — صداکننده دادش به تو.

اگر این را نوشتی، دقیقاً همان است:

```rust
pub fn extended(text: String, suffix: char) -> String {
    let mut text = text;
    text.push(suffix);
    text
}
```

این همان سایه‌اندازیِ [۱.۱.۱](../../../01-foundations/01-variables-mutability-shadowing/README.fa.md) است که همان کار را در دو خط می‌کند. هر دو خوب‌اند؛ `mut` در امضا چیزی است که در کدِ واقعی می‌بینی.

و این همان چیزی است که حرکت برایت می‌خرد. در زبانی که ممکن است صداکننده هنوز آن رشته را در دست داشته باشد، تغییر دادنش یک غافلگیریِ بی‌ادبانه است. اینجا نمی‌تواند باشد: طرف دادش و رفت.

## `reversed` — چرا `with_capacity` و نه `new`

```rust
let mut out = Vec::with_capacity(values.len());
```

دقیقاً می‌دانی چند تا می‌آید. گفتنش یعنی یک تخصیص به‌جای یک سریِ تخصیصِ دوبرابری، در ازای چهار کلمه تایپِ بیشتر. نسخه‌ی مجانیِ درسِ [۱.۲.۱](../../01-stack-and-heap/README.fa.md) است.

حسابِ اندیس‌ها جایی است که اشتباه‌ها زندگی می‌کنند. `values.len() - 1 - offset` از انتها راه می‌رود: در `offset` صفر می‌شود آخرین عنصر، و در `offset == len - 1` می‌شود عنصرِ صفر. اگر `values.len() - offset` می‌نوشتی، همان دورِ اول یکی آن‌طرفِ انتها اندیس می‌زدی و پنیک می‌گرفتی.

`values[...]` روی یک `Vec<i32>` یک کپی می‌دهد نه یک حرکت، و برای همین است که این اصلاً کامپایل می‌شود — برای یک `Vec<String>` همان خط می‌شود `E0507`، همان خطای `05-move-out-of-a-vec.rs`.

البته `values.reverse()` هم هست که درجا و بدونِ `Vec`ِ دوم این کار را می‌کند، و `.into_iter().rev().collect()` که وقتی [فاز ۲](../../../../phase2-intermediate/02-iterators-and-closures/README.fa.md) را داشته باشی همان را می‌نویسی. یک بار دستی ساختنش همان چیزی است که باعث می‌شود آن‌ها را بخوانی و بدانی چه هزینه‌ای دارند.

## `total_bytes_of` — آنکه قرض می‌گیرد

```rust
for value in &values {
```

هر تمرینِ دیگری اینجا مصرف می‌کند. این یکی `&` دارد، و دلیلش ارزشِ گفتن دارد: `.len()` فقط لازم است به هر رشته *نگاه* کند. مالکیتِ هرکدام را گرفتن فقط برای پرسیدنِ طولش و بعد رهایش کردن، کارِ بی‌نتیجه است.

`&` را بردار و باز هم کامپایل می‌شود و پاس می‌شود، چون بعدش `values` را نمی‌خواهیم. نکته خودِ عادت است. **وقتی خودِ چیز را می‌خواهی مالکیت بگیر؛ وقتی می‌خواهی نگاه کنی قرض بگیر.** آن جمله از قبل بخشِ عمده‌ی [ماژولِ ۱.۳](../../../03-borrowing-and-references/README.fa.md) است.

## `take_first` — راهِ قانونیِ بیرون آوردن از یک `Vec`

```rust
values.remove(0)
```

`values[0]` کامپایل نمی‌شود:

```text
error[E0507]: cannot move out of index of `Vec<String>`
```

دلیلش ارزش دارد که شفاف باشد. اگر بیرون آوردنِ عنصرِ صفر مجاز بود، آن `Vec` یک سوراخ پیدا می‌کرد — جایی که `String`ش را داده و چیزی ندارد — و چیزی به اسمِ «`Vec`ِ سوراخ‌دار» وجود ندارد. هر جایگاه از ۰ تا `len` باید یک مقدارِ معتبر داشته باشد.

`remove(0)` قانونی است چون همان را درست می‌کند: عنصر را بیرون می‌آورد **و** بقیه را یکی به عقب می‌کشد، پس `Vec` یکی کوتاه‌تر می‌شود و هیچ سوراخی ندارد. خودِ عنصر را تحویلت می‌دهد، حرکت‌کرده، مالِ تو.

آن جابه‌جایی هزینه دارد. حذف از ابتدای یک `Vec`ِ هزارتایی، ۹۹۹ عنصر را جابه‌جا می‌کند. دو چیز ارزشِ دانستن دارد:

- **`swap_remove(0)`** آنی است: به‌جای کشیدنِ همه، آخرین عنصر را می‌گذارد داخلِ سوراخ. وقتی ترتیب مهم نیست همین را بردار.
- **`VecDeque`** مجموعه‌ای است که برای برداشتن از هر دو سر ساخته شده، و در [فاز ۲](../../../../phase2-intermediate/01-collections/README.fa.md) می‌آید.

## `merged` — استفاده‌ی دوباره از یک تخصیص به‌جای ساختنِ تازه

```rust
let mut out = left;
for value in right {
    out.push(value);
}
out
```

`let mut out = left;` یک حرکت است، و دارد کارِ واقعی می‌کند: `out` بافری را که `left` از قبل داشت تحویل می‌گیرد، و ممکن است هرچه داخلش `push` می‌شود بدونِ هیچ تخصیصِ تازه‌ای جا شود. شروع کردن از `Vec::new()` یعنی دور ریختنِ یک بافرِ کاملاً سالم و ساختنِ دوباره‌اش.

`for value in right` آن یکی را مصرف می‌کند، که دقیقاً درست است — مقدارها را می‌خواهیم، نه نگاه کردن به آن‌ها.

راهِ کتابخانه‌ی استاندارد `out.append(&mut right)` است که عنصرها را در یک عملیاتِ حافظه‌ای منتقل می‌کند نه یکی‌یکی. به `&mut` احتیاج دارد، که [۱.۳.۱](../../../03-borrowing-and-references/01-shared-and-mutable-refs/README.fa.md) است.

## این درس واقعاً درباره‌ی چه بود

- **حرکت انتقالِ مسئولیت است، نه کپیِ داده.** سه کلمه کپی می‌شود؛ بافر دقیقاً همان‌جا که بود می‌ماند.
- **هزینه‌ی حرکت به اندازه بستگی ندارد.** ده بایت یا ده مگابایت، سه کلمه است.
- **مبدأ غیرِقابلِ‌استفاده می‌شود، و کلِ نکته همین است** — دو مالک یعنی دو آزادسازی، و آزادسازیِ دوباره یکی از آن سه باگِ [۱.۲.۱](../../01-stack-and-heap/README.fa.md) است.
- **عددها حرکت نمی‌کنند چون مالکِ هیچ چیزی نیستند.** خطِ تقسیم «کوچک در برابرِ بزرگ» نیست؛ «کسی مسئولِ بافری هست یا نه» است.
- **وقتی خودِ مقدار را می‌خواهی مالکیت بگیر؛ وقتی می‌خواهی نگاه کنی قرض بگیر.** همه‌ی ماژولِ ۱.۳ از همین جمله بیرون می‌آید.
