# ۰۲.۱ — معنای انتقال

## چیزی که قرار است یاد بگیری

مالکیت (Ownership) یعنی مسئولیت هر مقدار دقیقاً با یک مالک است. وقتی محدوده‌ی آن مالک تمام شود، Rust مقدار را به‌شکل قطعی پاک‌سازی می‌کند. انتقال (Move) یعنی همین مسئولیت از یک نام به نامی دیگر سپرده شود.

## مثال فارسی روزمره

فرض کن کارت عضویت کتابخانه به نام متین است. وقتی کارت را کامل به سارا می‌سپاری، همان یک کارت جابه‌جا شده است؛ کارت دومی ساخته نشده و متین دیگر نمی‌تواند از کارت قبلی استفاده کند.

```rust
let s1 = String::from("hello");
let s2 = s1;              // ownership of the String MOVES from s1 to s2
println!("{s1}");         // compile error: borrow of moved value: `s1`
```

در Python، عبارت `s2 = s1` معمولاً نام دومی برای همان شیء می‌سازد. در Rust، عبارت `let s2 = s1;` مالکیت را منتقل می‌کند و از آن لحظه `s1` دیگر معتبر نیست. محتوای `String` کپی نشده؛ فقط اشاره‌گر، طول و ظرفیت آن جابه‌جا شده‌اند. کامپایلر جلوی استفاده‌ی دوباره از نام قبلی را می‌گیرد تا یک بخش از حافظه دو مالک پیدا نکند.

## قانون دقیق Rust

هر مقدار یک مالک دارد. مقداردهی، فرستادن آرگومان و برگرداندن مقدار می‌توانند مالکیت نوع‌هایی را که `Copy` نیستند منتقل کنند. وقتی مالک از محدوده بیرون می‌رود، `Drop::drop` دقیقاً یک‌بار اجرا می‌شود.

برای `i32` رفتار متفاوت است:

```rust
let x = 5;
let y = x;
println!("{x}");
```

این کد معتبر است، چون `i32` صفت `Copy` دارد و کپی آن ارزان و مستقل است. عدد پیگیری سفارش را می‌توان روی دو رسید نوشت؛ هر نسخه مستقل است.

## نمونه‌ی بک‌اند و مقایسه با Django

```rust
fn enqueue(body: String) {
    println!("queued: {body}");
} // body is dropped here

let request_body = String::from("order=42");
enqueue(request_body);
// request_body is no longer valid here
```

در Django معمولاً ارجاع یک `str` یا شیء را به تابع می‌دهی و زباله‌روب زمان آزادسازی را مدیریت می‌کند. اینجا امضای `enqueue(body: String)` صریحاً می‌گوید تابع `enqueue` مالک بدنه‌ی درخواست می‌شود. اگر فقط خواندن لازم باشد، در فصل بعد از `&str` استفاده می‌کنیم.

## خطای رایج کامپایلر و روش خواندن آن

```text
error[E0382]: borrow of moved value: `request_body`
```

برای خواندن این خطا اول محل استفاده‌ی دوباره را پیدا کن. بعد سراغ `value moved here` برو تا محل انتقال را ببینی؛ عبارت `does not implement the Copy trait` هم می‌گوید چرا این جابه‌جایی یک انتقال بوده است. خلاصه‌ی `E0382` این است: بعد از انتقال، دوباره از مقدار قبلی استفاده کرده‌ای.

## این تشبیه کجا دیگر دقیق نیست؟

در دنیای واقعی شاید بتوانی کارت را پس بگیری یا مالکیت مشترک تعریف کنی. در Rust این رفتار باید صریحاً با return، قرض‌گیری، `Clone`، `Rc` یا `Arc` مدل شود؛ انتقال خودبه‌خود برگشت‌پذیر نیست.
