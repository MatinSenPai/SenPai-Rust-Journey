# ۰۲.۱ — معنای انتقال (Move semantics)

## قانون

**هر مقداری دقیقاً یک مالک (owner) داره.** وقتی که اون مالک از اسکوپ (scope) خارج بشه، Rust اون مقدار رو به صورت خودکار پاکسازی می‌کنه (درس بعدی: `Drop`). اینجا هیچ زباله‌روبی (garbage collector) وجود نداره که تصمیم بگیره *چه زمانی* باید حافظه آزاد بشه، و نیازی هم به `free()` دستی نیست — مالکیت به‌طور کامل تو زمان کامپایل پیگیری می‌شه و پاکسازی هم کاملاً قطعی و دقیقاً تو همون لحظه‌ای که اسکوپِ مالک تموم می‌شه اتفاق می‌افته.

نتیجه‌گیری‌ای که تو نگاه اول هر توسعه‌دهنده‌ی پایتونی رو به دردسر می‌ندازه:

```rust
let s1 = String::from("hello");
let s2 = s1;              // مالکیت این String از s1 به s2 منتقل (MOVE) می‌شه
println!("{s1}");         // خطای کامپایلر: قرض‌گرفتن مقداری که جابه‌جا شده: `s1`
```

تو پایتون وقتی می‌نویسی `s2 = s1`، در واقع `s2` می‌شه یه اسم دوم که به همون شیءِ *مشترک* اشاره می‌کنه — و هر دوشون هم کاملاً قابل استفاده باقی می‌مونن. اما تو Rust خطِ `let s2 = s1;` باعث **انتقال (move)** مالکیت می‌شه: بعد از این خط دیگه اصلاً `s1` معتبر نیست. این کپی کردنِ محتویات رشته نیست (که برای یه `String` بزرگ کار پرهزینه و بیهوده‌ایه) — این انتقالِ مسئولیته، و کامپایلر به‌صورت ایستا (statically) استفاده از اون اسم قدیمی رو بعد از این کار ممنوع می‌کنه. دلیل مشخصش اینه که دو تا متغیر نتونن همزمان فکر کنن که مالکِ یه حافظه‌ی تخصیص داده شده روی heap هستن (و بعداً هر دو سعی کنن همون یه حافظه رو آزاد کنن).

اما چرا این قضیه فقط سر `String` به پستت می‌خوره و سرِ یه چیزی مثل `i32` گیر نمیده؟
کد `let x = 5; let y = x; println!("{x}");` کاملاً بی‌مشکل کامپایل می‌شه — این موضوعِ درس بعدیه (انواعِ `Copy`).

## انتقال‌ها در مرز تابع‌ها هم اتفاق می‌افتن

```rust
fn takes_ownership(s: String) {
    println!("{s}");
} // متغیر s تو این نقطه، یعنی آخرِ تابع پاک (drop) می‌شه

let s = String::from("hello");
takes_ownership(s);
// s تو اینجا دیگه معتبر نیست — منتقل شده به داخلِ تابع
```

پاس دادن `s` به `takes_ownership` همونطور که `let s2 = s1` باعث انتقال می‌شه، دقیقاً همون کار رو می‌کنه. کلاً به *همین دلیل* هم هست که چیزی به اسم قرض‌گرفتن (borrowing که تو ماژول بعدی می‌خونیمش) وجود داره: اینکه فقط چون یه مقدار رو پاس دادی به یه تابع و برای همیشه دسترسی بهش رو از دست بدی، کار کردن با کد رو غیرممکن می‌کنه. اما برای این درس، سعی کن *با* انتقالات (moves) کار کنی نه با دور زدنشون — به الگوهای پایین‌تر دقت کن که تابع چطور از قصد مالکیت رو می‌گیره و بعدش دوباره اونو **پس میده**.
