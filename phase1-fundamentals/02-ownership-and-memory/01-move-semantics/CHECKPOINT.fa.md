# چک‌پوینت

1. بلاک `moved_value_demo` رو از حالت کامنت خارج کن، و `cargo check -p p1-02-01-move-semantics` رو اجرا کن. کد دقیق اون خطا رو (مثلاً `E0382`) اینجا پیست کن و با کلمات خودت توضیح بده که داره بهت چی می‌گه. وقتی تموم شد، بلاک رو دوباره کامنت کن.
2. تابع `reclaim_and_extend` یه `s: String` می‌گیره و یه `String` برمی‌گردونه. چرا اصلاً نیازه که دوباره همون `s` رو برگردونه — اگه این تابع فقط `s` رو می‌گرفت و در ازاش `()` رو برمی‌گردوند، سر توانایی فراخواننده‌ی این تابع (caller) برای استفاده مجدد از رشته‌اش چه بلایی می‌اومد؟
3. تابع `total_length` یه `Vec<String>` رو (و نه `&Vec<String>`) می‌گیره. آیا بعد از فراخوانی `(total_length(strings`، متغیر `strings` همچنان برای فراخواننده قابل استفاده‌ست؟ چرا تمرین برای اینجا `Vec<String>` رو خواست به جای اینکه چیزی بخواد که به فراخواننده اجازه بده بتونه همچنان ازش استفاده کنه؟
4. تو زبان پایتون، آیا قانونی هست که توسط خود زبان تحمیل بشه که بگه «این متغیر بعد از این خط دیگه معتبر نیست»، یا اینکه این قضیه تو پایتون فقط یه باگه که ممکنه خودت به اشتباه درستش کنی (مثلاً استفاده از یه متغیر بعد از `del x`)؟
