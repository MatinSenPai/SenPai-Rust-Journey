# ۰۲.۲ — Clone و Copy

## چرا `i32` تو درس قبلی منتقل (Move) نشد؟

```rust
let x = 5;
let y = x;
println!("{x}"); // بدون مشکل! هیچ خطایی نیست
```

نوعِ `i32`، traitای به نام **`Copy`** رو پیاده‌سازی می‌کنه. نوع‌هایی که با تگ `Copy` مشخص می‌شن تو زمان تخصیص دادن مقدار، به جای اینکه منتقل بشن (moved)، به صورت بایت‌به‌بایت کپی می‌شن — داده‌های ارزون، با طول ثابت، و داده‌هایی که فقط روی استک (stack) قرار می‌گیرن (مثل همه‌ی انواع عدد صحیح/اعشاری، `bool`، `char` و توپل‌ها/آرایه‌هایی که اعضاشون `Copy` باشن) این قابلیت رو دارن. بعد از اینکه `let y = x` رو می‌نویسی، هر دوی `x` و `y` به عنوان دو تا `i32` کاملاً مستقل و معتبر می‌مونن. این نزدیک‌ترین رفتاریه که Rust به رفتار پایتون داره (که تو پایتون «همه چیز فقط یه ارجاع به یه عدد صحیح تغییرناپذیره که کپیش هزینه‌ای نداره») — با این تفاوت که اینجا برای هر نوع داده کاملاً صریح و انتخابی تعریف می‌شه، نه به صورت یه قانون کلی و جهانی.

اما `String`، `Vec<T>`، و بیشترِ نوع‌هایی که مالک بخشی از حافظه‌ی heap هستن، `Copy` **نیستن** — کپی کردن یواشکیِ اونا سرِ هر بار تخصیص دادن، هزینه‌ی پنهان و نامحدودی روی عملکرد برنامه داره (مثلاً فقط به این خاطر که نوشتی `let s2 = s1`، بیاد یه `String` ده‌مگابایتی رو کپی کنه). Rust این هزینه رو بهت نشون میده و شفافش می‌کنه: حالت پیش‌فرض انتقال (move) هست، و اگه تو واقعاً به یه نسخه‌ی تکراری و مستقل از داده احتیاج داری، باید با کمال میل ازش بخوای.

## متد `Clone` — تکرارِ صریحِ داده که احتمالاً هم پرهزینه‌ست

```rust
let s1 = String::from("hello");
let s2 = s1.clone();       // s1 همچنان معتبره — این یه کپی واقعی و مستقله
println!("{s1} {s2}");     // هر دو قابل استفاده هستن
```

استفاده از `.clone()` روشیه که تو باهاش می‌گی «آره، من واقعاً یه کپی دوم و مستقل از این داده‌ی توی heap می‌خوام، و درک می‌کنم که کپی کردنش هزینه‌داره». هر نوعی که `Copy` باشه، خودش `Clone` هم هست (مثلاً کلون کردن یه `i32` دقیقاً همون... کپی کردنشه)، اما هر نوعی که `Clone` باشه لزوماً `Copy` نیست — `Clone` مکانیسم همه‌منظوره برای «کپی کردن این چیز» هست، اما `Copy` یه حالت خاصه و مال زمانیه که کپی کردن اونقدر ارزونه که می‌تونه ضمنی و بدون سر و صدا انجام بشه.

## قانون سرانگشتی

- یه کپی مستقل و دارای مالکیت (owned) از یه داده‌ی توی heap می‌خوای؟ از `.clone()` استفاده کن — و اینو بدون که نسبت به اندازه‌ی اون داده، یه هزینه‌ی واقعی برای اجرای برنامه به همراه داره.
- داری با داده‌های کوچیک و با اندازه‌ی ثابت کار می‌کنی (مثل اعداد، بولین‌ها، کاراکترها، توپل‌های ساده)؟ احتمالاً خودشون `Copy` هستن — لازم نیست بهش فکر کنی.
- فقط واسه اینکه یه خطای انتقال (move error) که کامل درکش نکردی رو دور بزنی، داری دست به دامنِ `.clone()` می‌شی؟ دست نگه دار — خیلی وقتا چیزی که واقعاً می‌خوای یه **قرض‌گرفتن (borrow)** (با علامت `&`) هست، که تو ماژول بعدی می‌خونیمش و اصلاً نیازی به کپی کردن نداره.
