# راه‌حل — ۱.۲.۳ `Clone` و `Copy`

```rust
pub fn duplicated(text: String) -> (String, String) {
    let copy = text.clone();
    (text, copy)
}

pub fn array_survives(values: [i32; 4]) -> ([i32; 4], i32) {
    let mut total = 0;
    for value in values {
        total += value;
    }
    (values, total)
}

pub fn shrunk(values: Vec<i32>) -> Vec<i32> {
    let mut values = values;
    values.shrink_to_fit();
    values
}

pub fn doubled_up(values: Vec<String>) -> Vec<String> {
    let mut out = Vec::with_capacity(values.len() * 2);
    for value in values {
        out.push(value.clone());
        out.push(value);
    }
    out
}

pub fn repeated(text: String, times: usize) -> Vec<String> {
    if times == 0 {
        return Vec::new();
    }
    let mut out = Vec::with_capacity(times);
    for _ in 1..times {
        out.push(text.clone());
    }
    out.push(text);
    out
}
```

دو تای این‌ها به کلون احتیاج داشتند. دو تا نه. یکی دقیقاً به `n - 1` تا احتیاج داشت.

## `duplicated` — کلونی که واقعاً توجیه دارد

```rust
let copy = text.clone();
(text, copy)
```

`.clone()` برای همین است. صداکننده دو رشته‌ی مستقل خواسته، دو رشته‌ی مستقل یعنی دو بافر، و دو بافر یعنی یک تخصیص. هیچ زرنگی‌ای در دسترس نیست.

تست طوری نوشته شده که استقلال را ثابت کند نه برابری را:

```rust
left.push('!');
assert_eq!(left, "hi!");
assert_eq!(right, "hi", "the two must not share a buffer");
```

اگر راهی پیدا کرده بودی که دو اسم برای یک بافر تحویل بدهی، همان assert می‌گرفتش. در پایتون این تست برای یک لیست شکست می‌خورد، چون `second = first` اشتراک می‌سازد. اینجا اشتراک بدونِ ابزارهای [فاز ۲](../../../../phase2-intermediate/05-smart-pointers/02-rc-and-arc/README.fa.md) اصلاً قابلِ بیان نیست.

ترتیب کمی مهم است: اول کلون، بعد ساختنِ تاپل. اگر `(text, text.clone())` بنویسی، `text` را قبل از اجرای کلون به داخلِ تاپل حرکت داده‌ای — `E0382`.

## `array_survives` — آنکه اصلاً کلون نمی‌خواهد

```rust
for value in values {
    total += value;
}
(values, total)
```

دقت کن. حلقه `values` را مصرف می‌کند… و خطِ بعدی `values` را برمی‌گرداند. در [۱.۲.۲](../../02-move-semantics/README.fa.md) این `E0382` بود.

کامپایل می‌شود چون **`[i32; 4]` نوعِ `Copy` است**. حلقه آرایه را نگرفت؛ یک کپی از آن گرفت، و اصلی دست‌نخورده ماند. نوع را به `[String; 4]` عوض کن و همان کد بلافاصله از کار می‌افتد.

کلِ تمایز در یک تابع همین است. `Copy` یعنی «کلونِ ارزان‌تر» نیست — یعنی *«حرکت دادنِ این نوع مبدأ را نامعتبر نمی‌کند، چون چیزی نیست که کسی مسئولش باشد.»*

اینجا شانزده بایت کپی می‌شود. که کارِ واقعی است — ولی یک کپیِ روی پشته است بدونِ دخالتِ تخصیص‌دهنده، و این مرتبه‌ی هزینه‌ی متفاوتی است با `.clone()` روی یک `String`.

## `shrunk` — و اینکه چرا `.clone()` هم جواب می‌داد

```rust
values.shrink_to_fit();
values
```

`shrink_to_fit` از تخصیص‌دهنده بلوکی دقیقاً به اندازه‌ی لازم می‌خواهد و محتوا را منتقل می‌کند. بیانِ مستقیمِ همان چیزی است که خواسته شده.

ولی این هم همان است:

```rust
values.clone()
```

چون **کلون کردنِ یک `Vec` دقیقاً به اندازه‌ی `len` تخصیص می‌گیرد، نه `capacity`.** در خروجیِ مثال دیده می‌شود:

```text
roomy len/cap:  3/100
clone len/cap:  3/3
```

هر دو کار می‌کنند. `shrink_to_fit` نیتت را می‌گوید، و یک تفاوتِ واقعی هم هست: `.clone()` لحظه‌ای **هر دو** بافر را نگه می‌دارد، پس اوجِ مصرفِ حافظه مجموعِ آن دو است. برای وکتوری که داشتی کوچکش می‌کردی چون بزرگ بود، این جهتِ اشتباه است.

هیچ‌کدام از `capacity() == len()` را زبان تضمین نکرده — کاری است که کتابخانه‌ی استاندارد می‌کند. تست بررسی‌اش می‌کند چون رفتارِ قابلِ مشاهده همین است، به همان شکلی که تستِ [۱.۲.۱](../../01-stack-and-heap/README.fa.md) دوبرابر شدن را بررسی می‌کرد.

## `doubled_up` — یک بار کلون، بعد حرکت

```rust
for value in values {
    out.push(value.clone());
    out.push(value);
}
```

دو `push`، یک کلون. کپیِ اول باید کلون باشد چون `push`ِ دوم هنوز به اصل احتیاج دارد؛ `push`ِ دوم یک حرکت است چون بعدش هیچ‌کس `value` را نمی‌خواهد.

نوشتنِ `out.push(value.clone()); out.push(value.clone());` هم تست‌ها را پاس می‌کند و دو برابر تخصیص می‌دهد. **آخرین استفاده از یک مقدار باید یک حرکت باشد.** این عادت را همین حالا بساز: نگاه کن مقدار کجا برای آخرین بار استفاده می‌شود، و آنجا کلون نکن.

`Vec::with_capacity(values.len() * 2)` نوشتنش مجانی است و تخصیص‌های دوبرابری را حذف می‌کند، چون طولِ نهایی دقیقاً معلوم است.

## `repeated` — `n - 1` کلون، نه `n`

```rust
for _ in 1..times {
    out.push(text.clone());
}
out.push(text);
```

نسخه‌ی بدیهی `for _ in 0..times { out.push(text.clone()) }` می‌نویسد و بعد `text` بی‌استفاده در انتهای تابع رها می‌شود. یعنی یک تخصیص گرفته شده و دور ریخته شده.

بازه‌ای که از ۱ شروع می‌شود همان شمارش را انجام می‌دهد: `1..times` دقیقاً `times - 1` بار اجرا می‌شود. بعد اصل آخر از همه می‌رود داخل، حرکت‌کرده نه کلون‌شده. برای `times == 1` حلقه اصلاً اجرا نمی‌شود و صفر کلون داریم.

`for _ in` نوشته شده نه `for n in`، چون خودِ عدد را نمی‌خواهیم. همان `_`ِ [۱.۱.۳](../../../01-foundations/03-compound-types-and-destructuring/README.fa.md) است که همان کار را در جای دیگری می‌کند: جایگاهی که شمرده شده و عمداً اسم نگرفته.

نگهبانِ `times == 0` لازم است چون `1..0` یک بازه‌ی خالی است و آن `push`ِ آخر باز هم اجرا می‌شد و به‌جای هیچ، یک عنصر می‌داد. یک نگهبان، از [۱.۱.۵](../../../01-foundations/05-control-flow/README.fa.md).

## این درس واقعاً درباره‌ی چه بود

- **`.clone()` تخصیص می‌گیرد.** برای یک `Vec<String>` به‌ازای هر عنصر یکی، به‌علاوه‌ی یکی برای خودِ وکتور.
- **`Copy` یک قول است نه یک بهینه‌سازی**: کپی کردنِ بایت‌ها کلِ مقدار را کپی می‌کند و چیزی برای تمیز کردن نمی‌ماند.
- **هر نوعِ `Copy` نوعِ `Clone` هم هست؛ برعکسش نه.** `String` نوعِ `Clone` است و هرگز نمی‌تواند `Copy` باشد.
- **آخرین استفاده از یک مقدار باید یک حرکت باشد.** بیشترِ کلون‌های بی‌فایده در کدِ واقعی روی مقداری هستند که بعدش هیچ‌کس نمی‌خواستش.
- **وقتی دستت سمتِ `.clone()` رفت، بپرس به‌جایش چه لازم داشتی.** معمولاً یک `&` — و آن [ماژولِ ۱.۳](../../../03-borrowing-and-references/README.fa.md) است.
