# ۰۲ — مالکیت و حافظه

این فصل احتمالاً بزرگ‌ترین تغییر ذهنی تو در گذر از Python به Rust است. نه زباله‌روب داریم و نه لازم است دستی `free()` صدا بزنیم؛ کامپایلر پیش از اجرا بررسی می‌کند مسئول هر مقدار دقیقاً چه کسی است و کدی را که این مسئولیت در آن مبهم باشد نمی‌پذیرد. متین، این فصل را آرام پیش برو؛ قرض‌گیری، طول عمر، اشاره‌گرهای هوشمند و حتی async روی همین پایه ساخته می‌شوند.

## مثال روزمره‌ی ایرانی

یک سفارش فروشگاه فقط یک مسئول نهایی دارد. مسئولیت می‌تواند از صندوق‌دار به انبار منتقل شود، اما دو نفر نباید هم‌زمان تصور کنند صاحب نهایی همان سفارش‌اند. Rust همین ابهام را پیش از اجرای برنامه حذف می‌کند.

## پل به بک‌اند

وقتی بدنه‌ی درخواست را به یک پردازشگر می‌دهی یا کاری را برای پردازش به صف می‌فرستی، امضای تابع روشن می‌کند داده واقعاً منتقل شده یا فقط مدتی در دسترس قرار گرفته است. به این ترتیب، خطاهایی مثل `use-after-free` و `double-free` پیش از رسیدن کد به محیط واقعی متوقف می‌شوند.

## این تشبیه کجا دیگر دقیق نیست؟

سفارش واقعی می‌تواند با یک تماس تلفنی میان چند نفر هماهنگ شود؛ مقدار heap در Rust قواعد دقیق نوع و محدوده دارد. تشبیه فقط برای فهم «مسئولیت یکتا» است، نه مدل کامل حافظه.
