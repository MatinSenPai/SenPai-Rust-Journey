# راه‌حل — ۱.۲.۴ مالکیت در عبور از توابع

```rust
pub fn appended(mut base: String, extra: String) -> String {
    base.push_str(&extra);
    base
}

pub fn longer_of(left: String, right: String) -> String {
    if right.len() > left.len() {
        right
    } else {
        left
    }
}

pub fn measure_and_return(text: String) -> (usize, String) {
    let length = text.len();
    (length, text)
}

pub fn length_of(text: &str) -> usize {
    text.len()
}

pub fn split_off_first(mut values: Vec<i32>) -> (i32, Vec<i32>) {
    let first = values.remove(0);
    (first, values)
}
```

## `appended` — استفاده‌ی دوباره از بافری که به تو داده‌اند

```rust
base.push_str(&extra);
base
```

`base` مالکْ‌دار آمده، پس مالِ توست: می‌توانی رشدش بدهی، و هر ظرفیتِ اضافه‌ای که از قبل داشته پیش از هر تخصیصِ تازه‌ای استفاده می‌شود. بعد همان بیرون می‌رود، حرکت‌کرده، بدونِ هیچ کپی‌ای.

نسخه‌ای که هم‌ارز به‌نظر می‌رسد و نیست:

```rust
let mut out = String::new();
out.push_str(&base);
out.push_str(&extra);
out
```

این یک بافرِ کاملاً سالم را دور می‌ریزد و یکی از نو می‌سازد. همان جواب، یک تخصیصِ اضافه و یک کپیِ اضافه از `base`. **وقتی تابعی یک مقدارِ مالکْ‌دار تحویل می‌گیرد، رشد دادنِ همان مقدار تقریباً همیشه از ساختنِ یکی تازه ارزان‌تر است.**

`&extra` نوشته شده نه `extra`، چون `push_str` فقط لازم است بایت‌هایی را که کپی می‌کند بخواند. `extra` در هر حال در انتهای تابع رها می‌شود.

## `longer_of` — آرگومانی که برنمی‌گردانی

```rust
if right.len() > left.len() {
    right
} else {
    left
}
```

هر دو آرگومان مالِ این تابع‌اند. دقیقاً یکی‌شان بیرون می‌رود؛ آن یکی همچنان مالکْ‌دار به آکولادِ بسته می‌رسد و همان‌جا رها می‌شود. این نه نشت است و نه اتلاف — همان کاری است که [۱.۲.۱](../../01-stack-and-heap/README.fa.md) توصیفش کرد، دقیقاً در همان لحظه‌ای که توصیفش کرد.

دقت کن که این بدونِ هیچ `.clone()`ای کامپایل می‌شود. در زبانی که ممکن است صداکننده هنوز هر دو رشته را در دست داشته باشد، برگرداندنِ یکی‌شان یک ارجاعِ اشتراکی می‌بود و رها کردنِ آن یکی مسئله‌ی کسِ دیگری. اینجا سؤالِ مالکیت یک جواب دارد و کامپایلر از قبل می‌داندش.

`>` نوشته شده نه `>=`، چون مشخصات همین را می‌گوید: `longer_of("ab", "cd")` باید `"ab"` بدهد، پس تساوی سمتِ چپ را نگه می‌دارد. و تستِ `"a"` در برابرِ `"س"` برای این است که صادق بمانی — `.len()` بایت است، پس یک حرفِ فارسی از یک حرفِ لاتین سنگین‌تر است. اگر دستت سمتِ `.chars().count()` رفت، آن assert را می‌انداختی، و کامنتِ مستندات گفته بود بایت.

## `measure_and_return` در برابرِ `length_of` — کلِ درس، کنارِ هم

```rust
pub fn measure_and_return(text: String) -> (usize, String) {
    let length = text.len();
    (length, text)
}

pub fn length_of(text: &str) -> usize {
    text.len()
}
```

دو تابع که یک کار می‌کنند. ببین تست‌ها مجبورند چه فرقی بگذارند.

```rust
let (length, text) = measure_and_return("hello".to_string());
```

صداکننده یک تاپل را باز می‌کند و باید `text` را دوباره ببندد تا بتواند استفاده‌اش کند. دو بار صدایش بزن، دو بار همین رقص را می‌نویسی.

```rust
let owned = String::from("hello");
assert_eq!(length_of(&owned), 5);
assert_eq!(length_of(&owned), 5);
assert_eq!(owned, "hello");
```

دو بار صدا زده شد بدونِ هیچ تشریفاتی، و `owned` در پایان همچنان `owned` است. **و یک رشته‌ی ثابت را مستقیم قبول می‌کند** — `length_of("سلام")` اصلاً به ساختنِ هیچ `String`ای احتیاج ندارد، پس در آن فراخوانی هیچ تخصیصی وجود ندارد.

`measure_and_return` کدِ بدی نیست. همان چیزی است که مجبور بودی بنویسی اگر قرض گرفتن وجود نداشت، و یک بار نوشتنش خودِ نکته است: [ماژولِ ۱.۳](../../../03-borrowing-and-references/README.fa.md) با همان مسئله‌ای باز می‌شود که این تابع دور زدنِ آن است.

به چیزی که `length_of` **لازم نداشت** هم دقت کن: نه `mut`، نه برگرداندنِ آرگومان، نه تاپل. امضایی که کمتر می‌خواهد، راحت‌تر صدا زده می‌شود، راحت‌تر خوانده می‌شود، و سخت‌تر اشتباه می‌شود.

## `split_off_first` — باز هم `mut` روی پارامتر

```rust
pub fn split_off_first(mut values: Vec<i32>) -> (i32, Vec<i32>) {
    let first = values.remove(0);
    (first, values)
}
```

`values[0]` برای یک `Vec<String>` کامپایل نمی‌شد — همان `E0507`ِ [۱.۲.۲](../../02-move-semantics/README.fa.md). اینجا اتفاقاً کامپایل می‌شود چون `i32` نوعِ `Copy` است، و در هر حال غلط بود: مشخصات اولین عنصر **و بقیه** را می‌خواهد، پس آن عنصر واقعاً باید بیرون بیاید.

`remove(0)` هر دو کار را می‌کند: عنصر را تحویلت می‌دهد و شکاف را می‌بندد. و `mut` لازم است چون `Vec` را تغییر می‌دهد — کاری که حق داری بکنی، چون آن `Vec` حالا مالِ توست. صداکننده متوجه نمی‌شود؛ `mut` روی پارامتر بخشی از امضا نیست.

`remove(0)` هر عنصرِ باقی‌مانده را یکی به عقب می‌کشد، که `O(n)` است. برای یک تستِ سه‌عنصری هیچ است. برای یک حلقه‌ی داغ روی یک `Vec`ِ بزرگ ابزارِ اشتباهی است، و ابزارهای درست `swap_remove` است وقتی ترتیب مهم نیست و `VecDeque` وقتی مهم است.

## این درس واقعاً درباره‌ی چه بود

- **پاس دادنِ یک مقدار به تابع یک حرکت است**، دقیقاً با همان قواعدِ انتساب. مفهومِ جداگانه‌ای به اسمِ «پاس دادنِ آرگومان» برای یاد گرفتن وجود ندارد.
- **امضای یک تابع یک مطالبه است.** `String` می‌گوید «این را واگذار کن»؛ `&str` می‌گوید «بگذار نگاه کنم». کوچک‌ترین چیزی را بخواه که کار را راه می‌اندازد.
- **برگرداندن مالکیت را واگذار می‌کند**، و همین‌جاست که مقدارهای تازه از آن می‌آیند و چرا `build() -> String` هیچ تشریفاتی لازم ندارد.
- **مقداری که وارد می‌شود و بیرون نمی‌رود سرِ آکولادِ بسته رها می‌شود**، و کلِ داستانِ پاک‌سازی همین است.
- **الگوی «پسش بده» کار می‌کند و هیچ‌کس نمی‌نویسدش.** حالا که یک بار نوشتی‌اش، همان لحظه که قرض گرفتن از راه برسد می‌فهمی برای چیست.
