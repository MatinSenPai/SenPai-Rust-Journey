# راه‌حل — ۱.۴.۳ ساختن و دگرگون‌کردنِ رشته

```rust
pub fn joined(parts: &[String], separator: &str) -> String {
    parts.join(separator)
}

pub fn aligned_row(label: &str, amount: f64) -> String {
    format!("{label:<10}{amount:>8.2}")
}

pub fn tidy(text: &str) -> String {
    let mut words: Vec<&str> = Vec::new();
    for word in text.split_whitespace() {
        words.push(word);
    }
    words.join(" ")
}

pub fn shout(text: &str) -> String {
    let mut out = text.trim().to_uppercase();
    out.push('!');
    out
}

pub fn preview(text: &str, limit: usize) -> String {
    if text.chars().count() <= limit {
        return text.to_string();
    }
    let mut out = format!("{text:.limit$}");
    out.push('…');
    out
}
```

دو تا یک‌خطی، و سه تا که پاراگراف‌های زیر را می‌ارزند.

## `joined` — بدهیِ ۱.۱.۶، پرداخت‌شده

```rust
parts.join(separator)
```

همین. چیزی که در [۱.۱.۶](../../../01-foundations/06-vec-and-string-basics/README.fa.md) نوشته بودی این بود:

```rust
let mut out = String::new();
for index in 0..parts.len() {
    if index > 0 {
        out.push(separator);
    }
    out.push_str(&parts[index]);
}
out
```

همان جواب. ولی نسخه‌ی دستی از یک بافرِ خالی شروع می‌کند و بزرگش می‌کند، پس برای یک لیستِ بلند چند بار در راه تخصیصِ تازه می‌گیرد — `String` وقتی پر شود دو برابر می‌شود، دقیقاً مثلِ همان `Vec` در ۱.۱.۶.

`join` این کار را نمی‌کند. یک بار روی برش راه می‌رود و طول‌ها را جمع می‌زند، **یک** بافر دقیقاً به همان اندازه می‌گیرد، و بعد کپی می‌کند. یک تخصیص، بدونِ رشد، بدونِ فضای هدررفته در انتها.

آن نسخه را یک بار با دست نوشتی تا «join» چیزی باشد که می‌فهمی، نه چیزی که فقط صدایش می‌زنی. از حالا به بعد صدایش بزن.

دو جزئیات که تست‌ها می‌گیرند و راحت از دست می‌روند. برشِ خالی `""` می‌دهد نه یک جداکننده‌ی تنها — `join` جداکننده را *بین* چیزها می‌گذارد و بینِ هیچ‌چیز، هیچ‌چیز است. و `joined(&["a", "b"], "")` می‌دهد `"ab"`، چون جداکننده‌ی خالی هم یک جداکننده‌ی کاملاً معتبر است؛ این همان `concat` است که جور دیگری نوشته شده.

## `aligned_row` — یک رشته‌ی قالب، دو ستون

```rust
format!("{label:<10}{amount:>8.2}")
```

از چپ بخوانش، دقیقاً همان چیزی را می‌گوید که مشخصات می‌گفت:

- `label` — متغیر، درجا از دامنه برداشته‌شده.
- `:<10` — چپ‌چین، کمینه‌ی عرض ده.
- `amount` — متغیرِ دوم.
- `:>8.2` — راست‌چین، کمینه‌ی عرض هشت، دو رقم بعد از نقطه.

بینِ این دو گروه هیچ چیزی نیست، و برای همین بینِ دو ستون هم هیچ چیزی ظاهر نمی‌شود.

**علامت‌های تراز اینجا اختیاری نیستند، حتی با اینکه همان پیش‌فرض‌اند.** متن از قبل چپ می‌رود و عدد از قبل راست. نوشتنشان یعنی روزی که کسی نوعِ `amount` را عوض کند، سطر بی‌سروصدا از نو چیده نمی‌شود. و یعنی خواننده مجبور نیست پیش‌فرض‌ها را از حفظ باشد.

آن `.2` **گرد می‌کند**، نمی‌بُرد. تستِ `aligned_row("x", 12.3456)` که `"x            12.35"` می‌خواهد دقیقاً همین را می‌سنجد — `12.34` بریدن بود و اتفاق نیفتاد.

و تستی که می‌گوید `aligned_row("a-very-long-label", 1.0)` باید ۲۵ کاراکتر باشد، نیمه‌ی دیگرِ قاعده را می‌سنجد: عرض یک *کمینه* است. مقداری که پهن‌تر از ستونش باشد سطر را هل می‌دهد، بریده نمی‌شود. اگر بیشینه هم می‌خواهی، آن دقت روی متن است — `{label:<10.10}` — و آن‌وقت برچسب‌های بلند بریده می‌شوند.

## `tidy` — تکه کن و دوباره بچسبان، و تکه‌ها هیچ خرجی ندارند

```rust
let mut words: Vec<&str> = Vec::new();
for word in text.split_whitespace() {
    words.push(word);
}
words.join(" ")
```

ترفند این است که «بیرون را بگیر و داخل را فشرده کن» اگر درست نگاهش کنی یک عملیات است: فقط تکه‌های ناخالی را بردار، بعد بینشان تک‌فاصله بگذار.

`split_whitespace` هر دو نیمه را با هم انجام می‌دهد. برخلافِ `split(' ')`، هر دنباله‌ای از فاصله را یک جداکننده حساب می‌کند و هیچ تکه‌ی خالی نمی‌سازد — برای همین `"a\t\tb\nc"` سه کلمه می‌شود و `"   "` هیچ کلمه‌ای. و دو سرِ متن را هم مجانی مرتب می‌کند، پس `trim` لازم نیست.

به نوع دقت کن: `Vec<&str>` است، نه `Vec<String>`. هر تکه یک **پنجره به خودِ `text`** است، پس پر کردنِ آن وکتور هیچ متنی را کپی نمی‌کند. تنها تخصیصِ کلِ تابع همان یکی است که `join` در آخر می‌گیرد — به‌اضافه‌ی بافرِ خودِ وکتور، که به‌جای حرف، نشانی نگه می‌دارد.

این کلِ درسِ امروز است در یک تابع. تا وقتی چیزی واقعاً ساخته نشود، چیزی کپی نمی‌شود.

حالتِ `""` هم مجانی درست درمی‌آید: هیچ تکه‌ای نیست، پس `join` یک `String` خالی می‌دهد. شرطِ جداگانه‌ای لازم نیست.

## `shout` — همان که فارسی نکته‌اش است

```rust
let mut out = text.trim().to_uppercase();
out.push('!');
out
```

سه عملیات، و فقط یکی‌شان تخصیص می‌گیرد.

`trim` یک `&str` به همان بافر می‌دهد. `to_uppercase` همان تخصیص است: یک `String` نو می‌سازد، و مجبور است، چون بزرگ‌کردنِ حروف می‌تواند طولِ متن را عوض کند. `push` یک کاراکترِ دیگر در بافرِ موجود می‌نویسد.

ترتیب روی هزینه اثر دارد. `text.to_uppercase().trim().to_string()` همان جواب را با **دو** تخصیص می‌دهد: یکی برای نسخه‌ی بزرگ‌شده، یکی برای اینکه پنجره‌ی پیراسته را دوباره به یک رشته‌ی مالک تبدیل کند. اول پنجره را ببُر، بعد یک بار از رویش تخصیص بگیر.

و حالا آن تستی که مهم است:

```rust
assert_eq!(shout("سلام"), "سلام!");
```

`to_uppercase` اجرا شد، یک بافر گرفت، هر هفده بایت را داخلش کپی کرد، و متنی دقیقاً یکسان تحویل داد. فارسی حروفِ بزرگ ندارد، پس نگاشتِ بزرگ‌کردنِ یونیکد برای هرکدام از این حرف‌ها خودِ همان حرف است.

ارزشِ کمی مکث دارد، چون عادتی که باید بشکند عادتِ رایجی است. «قبل از مقایسه کوچکش کن» در یک کدبیسِ پایتونی رفلکس است و برای ورودیِ فارسی *بی‌معنا* است — هیچ یکسان‌سازی‌ای انجام نمی‌دهد و یک کپیِ کامل هم خرج برمی‌دارد. اگر می‌خواهی `چای` و `چای`ی که با `ي` عربی نوشته شده برابر دربیایند، آن کارِ `replace` است، نه کارِ تغییرِ حروف.

## `preview` — کاراکتر بشمار، نه بایت

```rust
if text.chars().count() <= limit {
    return text.to_string();
}
let mut out = format!("{text:.limit$}");
out.push('…');
out
```

خطِ جالب همان رشته‌ی قالب است. `{text:.limit$}` یعنی «`text` را با دقتی که از متغیرِ `limit` می‌آید قالب‌بندی کن»، و دقت روی متن یعنی **حداکثر این‌قدر کاراکتر**.

آن `$` همان چیزی است که می‌گذارد حد یک مقدارِ زمانِ اجرا باشد، نه عددی که داخلِ رشته پخته شده.

اصلاً چرا از راهِ قالب‌بند؟ چون تنها ابزارِ این درس است که متن را **امن** کوتاه می‌کند. نوشتنِ `&text[..limit]` یک اندیسِ *بایت* است، و در فارسی این دو واحد هیچ‌وقت بر هم منطبق نمی‌شوند: `&"سلام"[..2]` به تو `"س"` می‌دهد — یک حرف، جایی که دو حرف خواسته بودی — و `&"سلام"[..3]` اصلاً چیزی نمی‌دهد، چون بایتِ سه وسطِ حرفِ `ل` است و برنامه همان‌جا پنیک می‌کند. بریدنِ متن با نشانیِ بایت کارِ [۱.۴.۴](../../04-slicing-text-safely/README.fa.md) است و ابزارهایی می‌خواهد که هنوز نداری.

آن شرطِ اول در دو جهت کارِ واقعی می‌کند. بدونش، `preview("hi", 5)` یک `…` به متنی می‌چسباند که اصلاً کوتاه نشده، که یعنی دروغ گفتن درباره‌ی داده. و آن `chars().count()` داخلش همان شمارشی است که دقت هم استفاده می‌کند، پس این دو ذاتاً با هم می‌خوانند — اگر آنجا `len()` می‌نوشتی، تابع متنِ فارسیِ کاملاً جاشده را هم می‌بُرید.

و یک هشدارِ کوچک که تست‌ها عمداً کاری به آن ندارند. `preview("می‌شود", 3)` می‌دهد `"می‌…"` — سه کاراکتر که یکی‌شان نیم‌فاصله است، پس دو حرف می‌بینی و یک نقطه‌چین. تابع دقیقاً همان کاری را می‌کند که گفته. این «کاراکتر» است که واحدِ لغزنده‌ای است، و موضوعِ تمرینِ چالش هم همین است.

## این درس واقعاً درباره‌ی چه بود

- **رشته‌ی قالب کد است.** `{name}` یک جست‌وجوی متغیر است، و غلط نوشتنش خطای کامپایل است نه یک زنگِ ساعتِ سه صبح.
- **`{}` و `{:?}` دو سؤالِ متفاوت‌اند.** بعضی نوع‌ها فقط یکی‌شان را جواب می‌دهند.
- **عرض و دقت کاراکتر می‌شمارند.** نه بایت، و نه آنچه خواننده می‌بیند — و دقیقاً همین شکاف است که فارسی رویش دست می‌گذارد.
- **بدان چه چیزی تخصیص می‌گیرد.** `trim` و `split` قرض می‌گیرند؛ `format!` و `join` و `replace` و `to_uppercase` هر کدام یک بافرِ نو می‌سازند.
- **هرجا می‌شود، در یک بافر بساز.** `push_str` روی یک `String`ِ اندازه‌گرفته، یا `write!` — به‌جای یک `format!` در هر دورِ حلقه.
