# راه‌حل — ۱.۴.۲ یوتی‌اف-۸: بایت، اسکالر، گرافیم

```rust
pub fn counts(text: &str) -> (usize, usize) {
    (text.len(), text.chars().count())
}

pub fn bytes_for(letter: char) -> usize {
    letter.len_utf8()
}

pub fn bytes_of_widest(text: &str) -> usize {
    let mut widest = 0;
    for letter in text.chars() {
        if letter.len_utf8() > widest {
            widest = letter.len_utf8();
        }
    }
    widest
}

pub fn bytes_of_first(text: &str, n: usize) -> usize {
    let mut seen = 0;
    for (at, _letter) in text.char_indices() {
        if seen == n {
            return at;
        }
        seen += 1;
    }
    text.len()
}

pub fn continuation_bytes(text: &str) -> usize {
    let mut found = 0;
    for byte in text.bytes() {
        if (0x80..=0xBF).contains(&byte) {
            found += 1;
        }
    }
    found
}
```

پنج تابع، سه سطح: بایت، اسکالر، و مرزِ بینشان.

## `counts` — دو سؤالِ متفاوت در یک خط

```rust
(text.len(), text.chars().count())
```

نکته‌ی این تابع خودِ کد نیست؛ این است که دو عدد را کنارِ هم مجبورت می‌کند بنویسی و ببینی که یکی نیستند.

`text.len()` آنی است: یک `&str` دو کلمه است، اشاره‌گر و طول، و طول از قبل آنجا نشسته. `text.chars().count()` باید کلِ بافر را بخواند و بایت‌های شروع را بشمارد. برای یک متنِ کوتاه اهمیتی ندارد؛ برای فیلتر کردنِ ده‌هزار ردیف در یک درخواست دارد.

تستِ `counts("سلام، من متین هستم.")` جوابِ `(34, 19)` را می‌خواهد. اگر این عدد را حدسی نوشته بودی، غلط می‌شد — و همین است که چرا این درس همه‌چیزش را چاپ می‌کند به‌جای اینکه ادعا کند.

## `bytes_for` — تفاوتِ `size_of` و `len_utf8`

```rust
letter.len_utf8()
```

یک متد، ولی انتخابش کلِ درس است. `size_of::<char>()` همیشه ۴ می‌دهد، چون یک `char` در حافظه یک قوطیِ چهاربایتی است. `letter.len_utf8()` می‌گوید همان مقدار وقتی به بایت‌های یوتی‌اف-۸ تبدیل شود چند بایت می‌شود.

اگر داری فضای لازم برای نوشتنِ چیزی روی دیسک یا سوکت حساب می‌کنی، `len_utf8` را می‌خواهی. اگر داری اندازه‌ی یک آرایه‌ی `char` را حساب می‌کنی، `size_of` را.

## `bytes_of_widest` — یک حلقه‌ی بیشینه‌گیری، و صفر برای متنِ خالی

```rust
let mut widest = 0;
for letter in text.chars() {
    if letter.len_utf8() > widest {
        widest = letter.len_utf8();
    }
}
widest
```

شروع از صفر دو کار می‌کند: هم مقدارِ اولیه‌ی درست برای مقایسه است، هم دقیقاً جوابی است که برای متنِ خالی می‌خواهیم. برای متنِ خالی حلقه هیچ دوری نمی‌زند و همان صفر برمی‌گردد. لازم نبود حالتِ خاص بنویسی؛ کافی بود مقدارِ اولیه را درست انتخاب کنی.

`bytes_of_widest("Rust برای بک‌اند")` سه است، نه دو. غافلگیرکننده است تا وقتی یادت بیاید نیم‌فاصله سه بایت است. این تست عمداً آنجاست.

## `bytes_of_first` — چرا `char_indices` و نه `chars`

```rust
let mut seen = 0;
for (at, _letter) in text.char_indices() {
    if seen == n {
        return at;
    }
    seen += 1;
}
text.len()
```

با `.chars()` هم می‌شد نوشت — پهنای هر حرف را جمع می‌زدی. ولی `.char_indices()` همان جمع را از قبل انجام داده و بدونِ هزینه‌ی اضافه به تو می‌دهد: `at` **همان** تعدادِ بایت‌هایی است که تا اینجا رد شده‌ای.

آن `return` وسطِ حلقه یک خروجِ زودهنگام است؛ اگر شماره‌ی `n` پیدا شود همان‌جا تمام می‌شود. و اگر پیدا نشود — یعنی متن کمتر از `n` اسکالر دارد — حلقه تمام می‌شود و `text.len()` برمی‌گردد. این همان چیزی است که مشخصات خواسته بود، و برای `bytes_of_first("", 3)` هم صفر می‌دهد چون طولِ متنِ خالی صفر است.

`_letter` با زیرخط شروع می‌شود چون به خودِ حرف کاری نداریم. همان `_` از [۱.۱.۳](../../../01-foundations/03-compound-types-and-destructuring/README.fa.md) در نقشِ «این را می‌بینم و عمداً نامش نمی‌برم».

**و این تابع دقیقاً همان عددی است که برای کوتاه کردنِ امنِ متن لازم داری.** بعد از اینکه بدانی «۳۰ حرفِ اول از بایتِ فلان شروع می‌شود»، برش امن است. راهِ استانداردش در [۱.۴.۴](../../04-slicing-text-safely/README.fa.md) است.

## `continuation_bytes` — اثباتِ قاعده

```rust
for byte in text.bytes() {
    if (0x80..=0xBF).contains(&byte) {
        found += 1;
    }
}
```

`0x80..=0xBF` در دودویی یعنی هر بایتی که با `10` شروع می‌شود. دقیقاً همان الگویی که در جدولِ درس دیدی.

`.bytes()` را انتخاب کردیم نه `.as_bytes()`، چون فقط می‌خواهیم از رویشان رد شویم و ایندکس لازم نداریم. با `.as_bytes()` هم درست کار می‌کند و یک بایت هم کمتر یا بیشتر کپی نمی‌شود — هیچ‌کدام چیزی کپی نمی‌کنند.

و حالا آن تستِ آخر:

```rust
let (bytes, scalars) = counts(text);
assert_eq!(bytes - continuation_bytes(text), scalars);
```

این تست دو تابعِ جدا را به هم گره می‌زند و یک واقعیت را ثابت می‌کند: **هر بایتی در یک `String` یا شروعِ یک اسکالر است یا ادامه‌ی یکی.** سومی وجود ندارد. برای همین است که تفاوتِ `len()` و `.chars().count()` هیچ‌وقت رازآلود نیست — همیشه دقیقاً تعدادِ بایت‌های ادامه است.

اگر یکی از دو تابع را غلط نوشته باشی این تست می‌ترکد، حتی اگر تست‌های خودِ آن تابع پاس شده باشند. تستی که یک قانون را می‌سنجد نه یک مقدار را، از هر دوی آن‌ها ارزشمندتر است.

## این درس واقعاً درباره‌ی چه بود

- **یوتی‌اف-۸ هر اسکالر را در ۱ تا ۴ بایت می‌نویسد**، و بیت‌های اولِ هر بایت می‌گویند کدام است.
- **`len()` بایت است و همیشه بایت خواهد ماند.** برای انگلیسی تصادفاً درست به نظر می‌رسد.
- **تفاوتِ بایت و اسکالر همان تعدادِ بایت‌های ادامه است** — یک قانون، نه یک اتفاق.
- **`.char_indices()` عددی می‌دهد که همه‌ی مسائلِ برش با آن حل می‌شوند.**
- **`.chars().count()` هنوز جوابِ «کاربر چند کاراکتر می‌بیند» نیست.** آن سؤال جوابش خوشه‌ی گرافیم است و به یک کِرِیت احتیاج دارد.
- و مهم‌ترینش: **قبل از هر شمارشی بپرس این عدد را چه کسی می‌خواند.** اگر کاربر است، گرافیم. اگر بافر است، بایت.
