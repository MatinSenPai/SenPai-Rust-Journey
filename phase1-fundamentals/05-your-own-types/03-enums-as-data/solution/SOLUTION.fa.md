# راه‌حل — ۱.۵.۳ شمارشی‌ها به‌عنوان داده

```rust
pub fn from_episode(watched: u32) -> Entry {
    if watched == 0 {
        Entry::Planned
    } else {
        Entry::Watching(watched)
    }
}

pub fn rate(score: u8) -> Entry {
    let score = if score > 10 { 10 } else { score };
    Entry::Rated { score }
}

pub fn drop_at(episode: u32, reason: String) -> Entry {
    let reason = if reason.is_empty() {
        String::from("no reason given")
    } else {
        reason
    };
    Entry::Dropped { episode, reason }
}

impl Entry {
    pub fn is_watching(&self) -> bool {
        matches!(self, Entry::Watching(_))
    }

    pub fn is_favourite(&self) -> bool {
        matches!(self, Entry::Rated { score } if *score >= 8)
    }
}
```

در هیچ‌کدام یک `match` هم نیست. سه تای اول فقط گونه‌ی درست را می‌سازند و دو تای آخر یک پرسشِ تک‌کلمه‌ای درباره‌ی یک مقدار می‌پرسند.

## `from_episode` — شمارشی همان نوعِ بازگشتی است

```rust
if watched == 0 {
    Entry::Planned
} else {
    Entry::Watching(watched)
}
```

هر دو شاخه‌ی `if` یک `Entry` می‌دهند، و تنها به همین دلیل این کد به‌صورتِ یک عبارت کامپایل می‌شود: `if` یک عبارت است و هر دو شاخه‌اش باید یک نوع داشته باشند. `Entry::Planned` و `Entry::Watching(7)` دارند — و همین کلِ فایده‌ی شمارشی است.

تصور کن بخواهی همین را بدونِ شمارشی بنویسی. یک تاپلِ `(bool, u32)` برمی‌گرداندی، یا یک ساختار با فیلدِ `started`، و بعد هر فراخوان‌کننده باید یادش می‌ماند که وقتی `started` نادرست است، `episode` بی‌معناست. شمارشی کارِ فراخوان‌کننده را با دقیق‌تر کردنِ کارِ تو کوچک می‌کند.

دقت کن که `return`ی در کار نیست. این همان عبارتِ پایانیِ [۱.۱.۴](../../../01-foundations/04-functions-and-expressions/README.fa.md) است و راهِ معمولِ نوشتنِ یک تابعِ دو شاخه‌ای در Rust.

## `rate` — محدود کردن، و میان‌برِ فیلد

```rust
let score = if score > 10 { 10 } else { score };
Entry::Rated { score }
```

دو نکته اینجا هست.

اولی سایه‌اندازی (shadowing) از [۱.۱.۱](../../../01-foundations/01-variables-mutability-shadowing/README.fa.md) است: `score` دوم یک بایندِ تازه با همان نام است، پس هیچ چیزی لازم نیست `mut` باشد و از آن نقطه به بعد فقط مقدارِ محدودشده دیده می‌شود. `score.min(10)` همین کار را کوتاه‌تر می‌کند و در کدِ واقعی همان را می‌نویسی.

دومی `Entry::Rated { score }` است به‌جای `Entry::Rated { score: score }`. این **میان‌برِ مقداردهیِ فیلد (field init shorthand)** است، دقیقاً مثل یک ساختارِ عادی — گونه‌ی ساختاری با همان نحوِ ساختارها ساخته می‌شود، پس هر چه درباره‌ی ساختارها می‌دانی بی‌کم‌وکاست اینجا هم برقرار است.

و به این هم دقت کن که آن محدود کردن *برای چیست*. یک `u8` از ۰ تا ۲۵۵ را می‌پذیرد؛ دامنه‌ی مسئله از ۰ تا ۱۰. نوع از حقیقت بازتر است، پس یک جایی باید تنگش کرد. اینجا با یک محدودسازی؛ جوابِ تیزترش — نوعی که اصلاً نتواند ۲۰۰ را نگه دارد — همان الگوی newtype در [۱.۵.۲](../../02-tuple-structs-and-newtype/README.fa.md) است.

## `drop_at` — حرکت دادنِ یک `String` به داخلِ گونه

```rust
let reason = if reason.is_empty() {
    String::from("no reason given")
} else {
    reason
};
Entry::Dropped { episode, reason }
```

شاخه‌ی `else` یک **حرکت** است، نه یک کلون. `reason` با مقدار وارد شده، هیچ‌کس دیگری به آن احتیاج ندارد، و مستقیم داخلِ گونه می‌رود — پس ساختنِ یک `Entry::Dropped` اصلاً تخصیصی نمی‌گیرد. این همان درسِ [۱.۲.۲](../../../02-ownership-and-memory/02-move-semantics/README.fa.md) است که بی‌سروصدا کار می‌کند: گونه‌ای که یک `String` را حمل می‌کند مالکش است، و از بین رفتنِ `Entry` آن را هم از بین می‌برد.

اگر آنجا `reason.clone()` می‌نوشتی تست‌ها باز هم پاس می‌شدند و یک بافرِ دوم بی‌دلیل تخصیص می‌گرفت. دیدنِ همین بود که [۱.۲.۳](../../../02-ownership-and-memory/03-clone-and-copy/README.fa.md) برایش نوشته شد.

`{ episode, reason }` باز همان میان‌برِ فیلد است، این بار دو بار.

## `is_watching` — فقط شکل

```rust
matches!(self, Entry::Watching(_))
```

`matches!` یک مقدار و یک الگو می‌گیرد و `true` یا `false` می‌دهد. آن `_` همان جانشینی است که از [۱.۱.۳](../../../01-foundations/03-compound-types-and-destructuring/README.fa.md) به بعد استفاده می‌کنی — «اینجا چیزی هست و برایم مهم نیست چه». پس این هم برای `Watching(0)` درست است و هم برای `Watching(9000)`.

جایگزینش بدونِ `matches!` به `match` احتیاج دارد، و آن درسِ [۱.۵.۴](../../04-match-in-depth/README.fa.md) است:

```rust
match self {
    Entry::Watching(_) => true,
    _ => false,
}
```

`matches!` واقعاً ماکرویی است که به همین گسترش پیدا می‌کند. clippy هم شکلِ بلند را با لینتِ `match_like_matches_macro` به شکلِ کوتاه بازنویسی می‌کند.

## `is_favourite` — داده، نه فقط شکل

```rust
matches!(self, Entry::Rated { score } if *score >= 8)
```

این یکی جانِ تمرین است، چون اولین باری است که به چیزی که گونه *حمل می‌کند* نگاه می‌کنی.

`Entry::Rated { score }` نامِ `score` را به آن فیلد وصل می‌کند. آن `if` انتهایی یک **نگهبان (guard)** است: هم الگو باید بخورد و هم نگهبان باید درست باشد. پس `Rated { score: 8 }` مورد علاقه است، `Rated { score: 7 }` نه، و `Planned` اصلاً به نگهبان نمی‌رسد.

آن `*` در `*score` هست چون `self` یک `&Entry` است، پس تطبیق از پشتِ ارجاع، `score` را به‌صورتِ `&u8` وصل می‌کند و ستاره آن را به `u8` برمی‌گرداند. اگر حس کردی این جزئیاتی است که باید حدس می‌زدی، درست حس کردی — Rust به این قاعده «حالت‌های پیش‌فرضِ اتصال» می‌گوید و دقیقاً از همان چیزهایی است که [۱.۵.۴](../../04-match-in-depth/README.fa.md) رویش آرام می‌گیرد. `score >= &8` هم به همان خوبی کامپایل می‌شود.

و این جوابِ صادقانه‌ی «پس چرا نمی‌شود همان `entry.score` را نوشت؟» هم هست: می‌شود به داده رسید، ولی فقط بعد از اینکه مشخص شد کدام گونه در دست است. نگهبان همین را مشخص می‌کند و فیلد را در همان خط تحویلت می‌دهد.

## این درس واقعاً درباره‌ی چه بود

- **هر گونه داده حمل می‌کند و شکلِ داده‌ی هر گونه مالِ خودش است.** همین تفاوتِ شمارشیِ Rust با C است، و همین است که شمارشی می‌تواند یک ماشینِ حالتِ کامل را مدل کند.
- **حالتِ نامعتبر گرفته نمی‌شود — بیان‌شدنی نیست.** هیچ `Planned`ای نمی‌تواند نمره داشته باشد، پس هیچ کدی لازم نیست دنبالش بگردد.
- **نامِ شمارشی بخشی از مسیر است و شکل بخشی از ساختن.** `Entry::Rated { score: 9 }`، نه `Rated(9)`.
- **`Option` و `Result` شمارشی‌هایی‌اند که خودت می‌توانستی بنویسی.** از اینجا به بعد `Some` و `None` گونه‌اند، نه واژه‌ی جادویی.
- **یک شمارشی هزینه‌ی بزرگ‌ترین گونه به‌علاوه‌ی شناسه را دارد.** و اغلب حتی همان شناسه هم به‌لطفِ بهینه‌سازیِ جای‌خالی مجانی است.
- **`matches!` شکل را می‌پرسد؛ `match` داده را می‌گیرد.** الان نصفِ ابزار را داری و نصفِ دیگرش [۱.۵.۴](../../04-match-in-depth/README.fa.md) است.
