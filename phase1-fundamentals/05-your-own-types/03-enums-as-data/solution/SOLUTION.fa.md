# راه‌حل

تابعِ `is_readable` از ماکروی `!(matches!(status, Status::Cancelled` استفاده می‌کنه که تو مواقعی که فقط می‌خوای بپرسی «آیا این مقدار با این الگوی مشخص همخونی داره؟» و در جواب هم یه `bool` می‌خوای، این یه روش مختصر برای نوشتن یه `match` کامله — و در واقع معادل یه همچین کدیه که برعکس شده باشه (به خاطر علامت نقیض):
`match status { Status::Cancelled => true, _ => false }`

متد `latest_available_chapter` عملیات نشان‌زدایی (dereference) رو انجام میده (عبارت `latest_chapter*`) چون استفاده از `match status` رو یه متغیر از نوعِ `&Status` باعث می‌شه تک‌تک فیلدها هم به عنوان یه ارجاع اختصاص داده بشن (`latest_chapter: &u32`) — از اونجایی که `u32` دارای قابلیت `Copy` هست، عبارتِ `latest_chapter*` خیلی ساده و مستقیم مقدارش رو ازش می‌خونه، بدون اینکه هیچ تداخلی با پیچیدگی‌های borrow-checker داشته باشه.

در مورد سؤال دوم مرور: نسخه‌ای که بخواد با struct و فیلدهای `Option` نوشته بشه —
```rust
struct Status {
    latest_chapter: Option<u32>,
    since_chapter: Option<u32>,
    total_chapters: Option<u32>,
    is_cancelled: bool,
}
```
— اجازه می‌ده به حالت‌های کاملاً چرند و غیرمنطقی‌ای برسی که تو مدلِ enum حتی امکانِ نمایشش هم نیست: مثلاً ممکنه هر دو فیلد `latest_chapter` و `total_chapters` همزمان مقدار داشته باشن، یا در حالی که `is_cancelled: true` هست، فیلد `latest_chapter` همچنان مقدار `Some(42)` رو نگه داشته باشه، یا اصلاً هر چهار تا فیلد `None`/`false` باشن بدون اینکه اصلاً مشخص باشه این یعنی چی. بعضی وقتا این مفهوم رو به صورت یه قانون خلاصه می‌کنن که: «کاری کن که حالات غیرمجاز، غیرقابل نمایش بشن (make illegal states unrepresentable)» — یعنی نوع‌های داده‌ات (types) رو طوری طراحی کن که یه مقداری که اصلاً نباید وجود داشته باشه، عملاً نتونه ساخته بشه، به جای اینکه بخوای به هر تیکه‌کدی که به اون ساختار دست می‌زنه اعتماد کنی تا شاید بیاد با اما و اگر اون قانون و یکپارچگی رو حفظ کنه.
