# راه‌حل — ۱.۵.۱ ساختارها و متدها

```rust
impl Series {
    pub fn new(title: String, episodes: u32) -> Self {
        Self {
            title,
            episodes,
            watched: 0,
            favourite: false,
        }
    }

    pub fn remaining(&self) -> u32 {
        self.episodes.saturating_sub(self.watched)
    }

    pub fn watch_one(&mut self) -> bool {
        if self.watched < self.episodes {
            self.watched += 1;
            true
        } else {
            false
        }
    }

    pub fn mark_favourite(&mut self) {
        self.favourite = true;
    }

    pub fn summary(&self) -> String {
        let mut line = format!("{} {}/{}", self.title, self.watched, self.episodes);
        if self.favourite {
            line.push_str(" (favourite)");
        }
        line
    }

    pub fn into_title(self) -> String {
        self.title
    }
}
```

شش امضا، چهار جورِ مختلفِ `self`. هیچ‌کدامشان دلبخواهی نیست.

## `new` — تابعِ وابسته، و دو معنیِ `Self`

```rust
pub fn new(title: String, episodes: u32) -> Self {
    Self {
        title,
        episodes,
        watched: 0,
        favourite: false,
    }
}
```

`self` نمی‌گیرد، چون هنوز `Series`ای وجود ندارد که بگیرد. این تعریفِ تابعِ وابسته است.

`Self` در این چند خط دو بار آمده و هر دو بار یعنی «`Series`»: یک بار به‌عنوانِ نوعِ بازگشتی و یک بار در ساختنِ مقدار. می‌شد هر دو جا `Series` نوشت و کاملاً درست بود. `Self` را ترجیح می‌دهیم چون اگر روزی نوع اسمش عوض شود، داخلِ بلوکِ `impl` هیچ چیزی لازم نیست تغییر کند.

`title,` و `episodes,` همان کوته‌نویسیِ مقداردهیِ فیلد است، و دلیلِ اینکه پارامترها دقیقاً هم‌نامِ فیلدها انتخاب شده‌اند همین بود.

دو فیلدِ دیگر با دست پُر شده‌اند. این یعنی «شروعِ یک `Series` یعنی این» و آن جمله را در یک جا می‌نویسی، نه در هر جایی از برنامه که یک `Series` ساخته می‌شود. همان علامتی که در بخشِ `E0063` گفتیم: وقتی مدام همان مقدارهای شروع را تکرار می‌کنی، نوع یک `new` می‌خواهد.

## `remaining` — تفریقی که می‌توانست panic کند

```rust
pub fn remaining(&self) -> u32 {
    self.episodes.saturating_sub(self.watched)
}
```

نسخه‌ی بدیهی `self.episodes - self.watched` است و برای هر ورودیِ معقولی درست کار می‌کند. تستِ آخر ورودیِ معقول نمی‌دهد:

```rust
show.watched = 30;
assert_eq!(show.remaining(), 0, "never wraps around the bottom of a u32");
```

`28 - 30` روی یک `u32` سرریزِ رو به پایین است. در حالتِ دیباگ panic می‌کند و در حالتِ ریلیز به `4294967294` می‌رسد — همان چیزی که ۱.۱.۲ نشانش داد و همان دلیلی که خانواده‌ی `checked_`/`saturating_`/`wrapping_` وجود دارد.

`saturating_sub` یعنی «کف صفر است». برای یک شمارنده‌ی پیشرفت دقیقاً همین را می‌خواهی.

`if self.watched >= self.episodes { 0 } else { self.episodes - self.watched }` هم درست است و کمی طولانی‌تر. انتخاب بینشان سلیقه است؛ انتخاب بینِ این دو و تفریقِ خام نیست.

و به `&self` دقت کن: این متد فقط می‌خواند، پس ارزان‌ترین امضایی که کارش را راه می‌اندازد همین است. صداکننده مقدارش را نگه می‌دارد و می‌تواند بلافاصله دوباره صدایش بزند.

## `watch_one` — تغییر می‌دهد و گزارش هم می‌دهد

```rust
pub fn watch_one(&mut self) -> bool {
    if self.watched < self.episodes {
        self.watched += 1;
        true
    } else {
        false
    }
}
```

`&mut self` چون فیلد عوض می‌شود، و بازگشتِ `bool` چون صداکننده باید بفهمد چیزی اتفاق افتاد یا نه.

`if` اینجا یک **عبارت** است، نه یک دستور: هر دو شاخه با یک مقدارِ `bool` بدونِ نقطه‌ویرگول تمام می‌شوند و همان مقدار از تابع بیرون می‌رود. این همان چیزی است که ۱.۱.۴ گفت، و `return true;` نوشتن هم کار می‌کند ولی سبکِ Rust نیست.

اهمیتِ نگهبان را دست‌کم نگیر. بدونِ `if`، این متد `watched` را از `episodes` رد می‌کرد و آن‌وقت `remaining` باید یک وضعیتِ ناممکن را مدیریت می‌کرد. اینجا است که خصوصی بودنِ فیلدها به کار می‌آید: تنها راهِ بالا بردنِ `watched` از بیرون همین متد است، پس «`watched` هرگز از `episodes` بیشتر نمی‌شود» یک **ناوردا (invariant)** است که خودِ نوع نگهش می‌دارد.

اگر `watched` را `pub` کرده بودی، این تضمین همان لحظه از بین می‌رفت.

## `mark_favourite` — یک خط، و چرا ارزشِ وجود دارد

```rust
pub fn mark_favourite(&mut self) {
    self.favourite = true;
}
```

سؤالِ منصفانه: چرا یک متد برای کاری که `show.favourite = true;` بود؟

چون بیرون از این فایل آن خط اصلاً وجود ندارد — فیلد خصوصی است. متد تنها راه است، و همین که تنها راه است یعنی فردا می‌توانی کارِ بیشتری هم داخلش بگذاری (زمانِ ثبت، یک لاگ، شمارشِ علاقه‌مندی‌ها) بدونِ اینکه هیچ صداکننده‌ای بشکند.

بازگشتی ندارد چون چیزی برای گفتن ندارد. مستنداتش هم می‌گوید که دو بار صدا زدنش خطا نیست، و پیاده‌سازیْ بی‌آنکه تلاشِ خاصی بکند همین را برآورده می‌کند.

## `summary` — بساز، بعد شرطی اضافه کن

```rust
pub fn summary(&self) -> String {
    let mut line = format!("{} {}/{}", self.title, self.watched, self.episodes);
    if self.favourite {
        line.push_str(" (favourite)");
    }
    line
}
```

`format!` بخشِ همیشگی را می‌سازد و `push_str` دُمِ اختیاری را اضافه می‌کند. یک تخصیص برای `format!`، و `push_str` معمولاً داخلِ همان ظرفیتِ موجود جا می‌شود — همان حساب‌وکتابِ ۱.۴.۳.

نسخه‌ی وسوسه‌انگیزِ دیگر دو `format!` کامل در دو شاخه‌ی `if` می‌نویسد. کار می‌کند و قالبِ اصلی را دو بار تکرار می‌کند؛ روزی که تصمیم بگیری جداکننده را از `/` به چیزِ دیگری عوض کنی، باید یادت باشد هر دو جا را عوض کنی.

`&self` است چون رشته‌ی تازه‌ای می‌سازد و به خودِ `Series` دست نمی‌زند. متدی که یک `String` تازه برمی‌گرداند تقریباً همیشه `&self` می‌گیرد.

## `into_title` — یک خط، و کلِ درسِ مالکیت

```rust
pub fn into_title(self) -> String {
    self.title
}
```

`self` یعنی این متد کلِ `Series` را می‌گیرد. `self.title` آن `String` را از داخلش بیرون می‌کشد و برمی‌گرداند — بدونِ کلون، چون هیچ‌کس دیگری قرار نیست از این ساختار استفاده کند. سه فیلدِ باقی‌مانده همان‌جا رها می‌شوند.

اگر امضا `&self` بود، این خط کامپایل نمی‌شد: از پشتِ یک ارجاعِ اشتراکی نمی‌شود مقدار را بیرون کشید. آن `E0507`ِ ۱.۲.۲ است. جوابش آن‌وقت `self.title.clone()` می‌شد — یعنی یک تخصیص، برای مقداری که داشت دور ریخته می‌شد.

پس انتخابِ `self` اینجا یک تصمیمِ آگاهانه است: «مطمئنم که بعد از این کار به این `Series` احتیاجی نیست، و در ازایش تخصیص نمی‌دهم». امضا این معامله را به صداکننده اعلام می‌کند، و پیشوندِ `into_` هم قبل از خواندنِ امضا خبرش را می‌دهد.

## این درس واقعاً درباره‌ی چه بود

- **ساختار یک نوع است، نه یک کیسه.** اسمِ فیلدها در نوع می‌نشیند و کامپایلر جابه‌جا نوشتنِ دو `u32` را می‌گیرد.
- **`self` را امضا انتخاب می‌کند و آن یک قول است.** `&self` نگاه، `&mut self` نگاهِ انحصاری، `self` بلعیدن. اول تصمیم بگیر صداکننده باید چه چیزی داشته باشد، بعد بنویس.
- **خصوصی بودن است که ناوردا می‌سازد.** «`watched` هرگز از `episodes` بیشتر نمی‌شود» فقط تا وقتی درست است که تنها راهِ بالا بردنش یک متد باشد.
- **`derive` کارِ بدیهی را می‌کند.** `Debug` برای دیدن، `Clone` برای کپی، `PartialEq` برای `==` — و هر سه فیلد‌به‌فیلدند.
- **`new` یک اسم است، نه یک قابلیت.** Rust سازنده ندارد؛ فقط توابعِ وابسته دارد و یک قراردادِ محکم درباره‌ی اسمشان.
