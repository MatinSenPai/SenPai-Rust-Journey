# ۱.۵.۱ — ساختارها و متدها

## در یک نگاه

بعد از این درس می‌توانی:

- یک `struct` با فیلدهای نام‌دار تعریف کنی، نمونه بسازی و فیلدهایش را بخوانی و عوض کنی.
- بین `&self`، `&mut self` و `self` انتخاب کنی و بگویی هر کدام برای صداکننده چه معنایی دارد.
- یک تابع وابسته مثل `Self::new` بنویسی و توضیح بدهی چرا `new` یک قرارداد است نه یک کلیدواژه.
- با `#[derive(...)]` رفتارهای بدیهی مثل `Debug`، `Clone` و `PartialEq` را بگیری و `E0616` را وقتی فیلدی خصوصی است بخوانی.

## چرا اهمیت دارد

درسِ تاپل‌ها با یک بدهی تمام شد: «تاپل تا سه فیلد قابلِ تحمل است. از آن به بعد `thing.3` معما می‌شود و باید اسم بگذاری.» این درس همان بدهی را می‌پردازد.

ولی ساختار فقط «تاپل با اسم» نیست. سه چیز را با هم می‌آورد که تا حالا نداشتی:

۱. **یک نوعِ تازه.** `Anime` دیگر جایگزینِ `(String, u32, u32, bool)` نیست؛ نوعی است که فقط خودش است. تابعی که `Anime` می‌خواهد، یک تاپلِ هم‌شکل را قبول نمی‌کند.
۲. **جایی برای رفتار.** بلوکِ `impl` توابعی را به نوع می‌چسباند. دیگر لازم نیست بگردی ببینی کدام تابعِ آزاد با کدام داده کار می‌کند.
۳. **یک مرز.** فیلدها بیرون از ماژول خصوصی‌اند مگر خلافش را بنویسی. یعنی می‌توانی تضمین کنی که `watched` هرگز از `episodes` بیشتر نشود — و کامپایلر پشتِ آن تضمین می‌ایستد.

و یک نکته‌ی مالکیت که تمامِ فاز ۱ برایش آماده‌ات کرده: وقتی متد می‌نویسی، در امضایش تصمیم می‌گیری که صداکننده مقدارش را **نگه دارد**، **عوض شده تحویل بگیرد**، یا **از دست بدهد**. این همان `&T`، `&mut T` و حرکت است، این بار روی نوعی که خودت ساخته‌ای.

## مفهوم

### تاپلی که از دستت در رفت

چهار مقدار که به هم تعلق دارند، به شکلِ تاپل:

```rust
let as_tuple = (String::from("Cowboy Bebop"), 26_u32, 26_u32, true);
println!("tuple:   {} {} {}", as_tuple.0, as_tuple.1, as_tuple.3);
```

```text
tuple:   Cowboy Bebop 26 true
```

کد کامپایل می‌شود و درست هم کار می‌کند. مشکل جای دیگری است: `as_tuple.1` و `as_tuple.2` هر دو `u32`اند. یکی طولِ سریال است و یکی مقدارِ دیده‌شده — ولی کدام کدام؟ اگر جایشان را عوض کنی، کامپایلر یک کلمه هم نمی‌گوید.

حالا همان چهار مقدار با اسم:

```rust
struct Anime {
    title: String,
    episodes: u32,
    watched: u32,
    favourite: bool,
}

let bebop = Anime {
    title: String::from("Cowboy Bebop"),
    episodes: 26,
    watched: 26,
    favourite: true,
};
```

```text
struct:  Cowboy Bebop 26/26 favourite=true
```

`struct` یک **نوعِ تازه (struct)** اعلام می‌کند. اسمِ فیلدها بخشی از نوع‌اند، نه یک قرارداد که در ذهنت نگه داری.

بلوکِ دومی که `bebop` را می‌سازد یک **عبارتِ ساختنِ ساختار (struct literal)** است. سه چیز درباره‌اش بدان:

- **صدا کردنِ تابع نیست.** ترتیبی برای حفظ کردن وجود ندارد؛ می‌توانی `favourite` را اول بنویسی و `title` را آخر.
- **هر فیلد باید باشد.** یکی را جا بیندازی `E0063` می‌گیری، و خطا اسمِ همان‌هایی را که کم داری می‌گوید.
- **مقدارها را می‌گیرد.** آن `String::from("Cowboy Bebop")` حالا مالِ `bebop` است. ساختار مالکِ داده‌اش است.

> **پلِ پایتون:** نزدیک‌ترین چیز `@dataclass` است. جایی که پل خراب می‌شود: اینجا نوعِ هر فیلد در زمانِ کامپایل بررسی می‌شود، `__dict__`ای وجود ندارد که موقعِ اجرا فیلدِ تازه به آن اضافه کنی، و غلط تایپ کردنِ نامِ یک فیلد به‌جای ساختنِ بی‌سروصدای یک صفتِ جدید، خطای کامپایل است.

### خواندن یک فیلد، و عوض کردنِ یکی

خواندن با نقطه است: `bebop.title`. نوشتن هم — به شرطی که بایندِ ساختار `mut` باشد:

```rust
let mut frieren = Anime {
    title: String::from("Frieren"),
    episodes: 28,
    watched: 3,
    favourite: false,
};
frieren.watched += 1;
frieren.favourite = true;
```

```text
changed: Frieren 4/28 favourite=true
```

دقت کن `mut` کجاست: روی **بایند**، نه روی فیلد. چیزی به اسمِ `mut watched: u32` در تعریفِ ساختار وجود ندارد. یک ساختار یا کلاً تغییرپذیر است یا کلاً نیست.

این همان قاعده‌ی ۱.۱.۱ است که به نوعِ خودت رسیده: تغییرپذیری خاصیتِ **بایند** است نه خاصیتِ داده. یادت که برود، `E0594` می‌گیری — که در بخشِ خطاها هست.

### کوته‌نویسیِ مقداردهیِ فیلد

وقتی متغیری که داری از قبل هم‌نامِ فیلد است، اسم را دو بار ننویس:

```rust
fn start_watching(title: String, episodes: u32) -> Anime {
    let watched = 0;
    Anime {
        title,
        episodes,
        watched,
        favourite: false,
    }
}
```

```text
started: Mushishi 0/26
```

`title,` دقیقاً یعنی `title: title`. این **کوته‌نویسیِ مقداردهیِ فیلد (field init shorthand)** است و در کدِ واقعیِ Rust همه‌جا هست — به‌خصوص در `new`ها، جایی که آرگومان‌ها عمداً هم‌نامِ فیلدها انتخاب می‌شوند.

شکلِ طولانی هم مجاز است، ولی clippy با لینتِ `redundant_field_names` تذکر می‌دهد.

### یک ساختار از روی یکی دیگر

می‌خواهی همان سریال را دوباره از اول ببینی: همه‌چیز مثلِ قبل، فقط `watched` صفر و `favourite` روشن.

```rust
let rewatch = Anime {
    watched: 0,
    favourite: true,
    ..started
};
println!("left of started: episodes {}", started.episodes);
```

```text
rewatch: Mushishi 0/26
left of started: episodes 26
```

`..started` یعنی «بقیه‌ی فیلدها را از آن یکی بردار». این **نحوِ به‌روزرسانیِ ساختار (struct update syntax)** است. باید آخرین چیزِ داخلِ آکولاد باشد و بعدش کاما نمی‌آید.

و حالا مهم‌ترین نکته‌اش، که تازه‌کارها را غافلگیر می‌کند: **`..started` کپی نمی‌کند، حرکت می‌دهد.**

آن `title` یک `String` است، پس به `rewatch` منتقل شد. دو فیلدِ `u32` نوعِ `Copy` بودند (۱.۲.۳)، پس کپی شدند و هنوز خوانده می‌شوند — برای همین `started.episodes` بالا کار کرد. ولی `started` به‌عنوان یک مقدارِ کامل از بین رفته: اگر بخواهی آن را به تابعی بدهی یا `started.title` را بخوانی، `E0382` می‌گیری. به این حالت **حرکتِ جزئی (partial move)** می‌گویند.

### `#[derive(Debug)]` و دیدنِ کلِ مقدار

`println!("{}", bebop)` کامپایل نمی‌شود، و این عمدی است: Rust نمی‌داند نوعِ تو را چطور باید به کاربر نشان داد. ولی برای خودت — برای وقتی که فقط می‌خواهی ببینی داخلش چیست — یک راهِ آماده هست:

```rust
#[derive(Debug, Clone, PartialEq)]
struct Anime {
    title: String,
    episodes: u32,
    watched: u32,
    favourite: bool,
}
```

```rust
println!("{bebop:?}");
println!("{bebop:#?}");
```

```text
Anime { title: "Cowboy Bebop", episodes: 26, watched: 26, favourite: true }

Anime {
    title: "Cowboy Bebop",
    episodes: 26,
    watched: 26,
    favourite: true,
}
```

`derive` همان چیزی است که در ۱.۲.۳ دیدی: «پیاده‌سازیِ بدیهی را برایم بنویس». برای `Debug` بدیهی یعنی «اسمِ نوع، بعد هر فیلد با اسمش».

- `{:?}` یک‌خطی است. برای لاگ.
- `{:#?}` — همان اطلاعات، هر فیلد در یک خط. برای چشمِ آدم. این همان پرچمِ `#` از زبانِ قالب‌بندیِ ۱.۴.۳ است.

و دقت کن `Debug` رشته را داخلِ گیومه می‌گذارد. عمدی است: `Debug` می‌خواهد نشان بدهد مقدار **چیست**، نه اینکه چطور خوانده می‌شود.

اگر `Debug` را مشتق نکنی و `{:?}` بنویسی، `E0277` می‌گیری — پایین‌تر هست.

### `Clone` و `PartialEq`، مشتق‌شده

همان یک خط `derive` دو چیزِ دیگر هم به `Anime` داد:

```rust
let copy = bebop.clone();
println!("bebop == copy:   {}", bebop == copy);
let mut edited = bebop.clone();
edited.watched = 1;
println!("bebop == edited: {}", bebop == edited);
```

```text
bebop == copy:   true
bebop == edited: false
```

`Clone`ِ مشتق‌شده هر فیلد را کلون می‌کند. اینجا یعنی یک تخصیص برای آن `String` و کپیِ ساده‌ی سه فیلدِ کوچک — همان `n` تخصیصِ ۱.۲.۳، این بار روی نوعِ خودت.

`PartialEq`ِ مشتق‌شده هر فیلد را مقایسه می‌کند. یعنی `==` روی `Anime` دقیقاً یعنی «هر چهار فیلد برابرند». اگر برابریِ درست برای نوعِ تو چیزِ دیگری است — مثلاً فقط `title` مهم باشد — باید خودت بنویسی‌اش، و نوشتنِ صفت‌ها با دست کارِ فاز ۲ است.

`Copy` را اینجا نمی‌توانی بگیری: آن `String` مانع است، و خطایش همان `E0204`ِ ۱.۲.۳ است.

### متدها، و `&self`

بلوکِ `impl` توابع را به نوع می‌چسباند:

```rust
impl Anime {
    fn remaining(&self) -> u32 {
        self.episodes - self.watched
    }
}
```

```text
remaining:  28
```

`&self` کوته‌نویسیِ `self: &Self` است، و `Self` داخلِ یک بلوکِ `impl` یعنی «همان نوعی که این بلوک برایش است» — اینجا `Anime`.

پس `remaining` یک **ارجاعِ اشتراکی** به ساختار می‌گیرد: فقط نگاه می‌کند. صداکننده مقدارش را نگه می‌دارد و بعدش هم می‌تواند استفاده‌اش کند.

نحوِ صدا زدنش شکر است. این دو خط یک کارِ واحدند:

```rust
println!("remaining:  {}", show.remaining());
println!("same call:  {}", Anime::remaining(&show));
```

```text
remaining:  26
same call:  26
```

آن `&` که هیچ‌وقت تایپ نمی‌کنی را نحوِ نقطه‌ای خودش می‌گذارد. این را بدان، چون وقتی خطای قرض روی یک صدا زدنِ متد بگیری، دلیلش همان `&`ِ نامرئی است.

> **پلِ پایتون:** در پایتون هم `self` صریح است، و این نصفِ راه است. تفاوت این است که Rust مجبورت می‌کند بگویی **چطور** آن را می‌خواهی، و پایتون برای این تمایز اصلاً کلمه‌ای ندارد.

### `&mut self` — متدی که عوض می‌کند

```rust
fn watch_one(&mut self) {
    if self.watched < self.episodes {
        self.watched += 1;
    }
}

show.watch_one();
show.watch_one();
```

```text
watched:    2/28
```

`&mut self` یک **ارجاعِ انحصاری** است، دقیقاً همان `&mut T`ِ ۱.۳.۱. صداکننده مقدارش را نگه می‌دارد و تغییر را می‌بیند.

دو شرط دارد که هر دو از قاعده‌ی هم‌نامی می‌آیند:

- بایندِ طرفِ صداکننده باید `mut` باشد، وگرنه کامپایلر جلویت را می‌گیرد.
- تا وقتی این متد در حالِ اجراست، هیچ ارجاعِ دیگری به آن ساختار زنده نیست.

### `self` — متدی که مقدار را می‌بلعد

```rust
fn into_title(self) -> String {
    self.title
}

let title = show.into_title();
println!("title:      {title}");
```

```text
title:      Frieren
```

اینجا `self` خودِ مقدار است، نه ارجاعی به آن. متد مالکیت را می‌گیرد و صداکننده بعد از آن خطْ ساختارش را ندارد.

چرا کسی باید چنین چیزی بنویسد؟ چون گاهی می‌خواهی یک فیلد را بیرون بکشی بدونِ کلون. `into_title` بافرِ همان `String` را مستقیم تحویل می‌دهد — صفر تخصیص. قیمتش این است که بقیه‌ی ساختار همان‌جا آزاد می‌شود.

قراردادِ اسم‌گذاری هم همین را می‌گوید: متدی که با `into_` شروع می‌شود مقدار را مصرف می‌کند. `to_` کپی می‌گیرد و `as_` فقط نگاهی ارزان است. این قرارداد در کلِ کتابخانه‌ی استاندارد رعایت شده.

و مصرف‌شدن پشتِ نحوِ نقطه‌ای پنهان می‌ماند: `show.into_title()` هیچ ظاهری از یک حرکت ندارد. اگر بعدش از `show` استفاده کنی، `E0382` می‌گیری — و خطا دقیقاً همین را می‌گوید.

### کدام `self` را برداری

| می‌نویسی | صداکننده | کِی |
|---|---|---|
| `&self` | مقدارش را نگه می‌دارد و می‌خواند | خواندن، محاسبه، قالب‌بندی — بیشترِ متدها |
| `&mut self` | نگه می‌دارد و تغییر را می‌بیند؛ بایندش باید `mut` باشد | عوض کردنِ یک فیلد |
| `self` | مقدارش را از دست می‌دهد | تبدیلِ کلِ مقدار به چیزِ دیگر |
| بدونِ `self` | هنوز مقداری وجود ندارد | سازنده‌ها و بقیه‌ی توابعِ وابسته |

این جدول کلِ ماژول‌های ۱.۲ و ۱.۳ است که روی نوعِ خودت نشسته. امضای متد یک **قول به صداکننده** است و یک بار داده می‌شود؛ عوض کردنش بعداً یعنی شکستنِ کدِ دیگران.

قاعده‌ی عملی: پیش‌فرض `&self` باشد. وقتی مجبوری چیزی را عوض کنی برو سراغِ `&mut self`. `self` را فقط وقتی بردار که مقدار بعد از آن کار واقعاً دیگر معنایی ندارد.

### توابعِ وابسته، و اینکه چرا `new` کلیدواژه نیست

تابعی داخلِ `impl` که `self` نگیرد، متد نیست:

```rust
impl Anime {
    fn new(title: String, episodes: u32) -> Self {
        Self {
            title,
            episodes,
            watched: 0,
            favourite: false,
        }
    }
}

let mut show = Anime::new(String::from("Frieren"), 28);
```

```text
remaining:  28
```

به این می‌گویند **تابعِ وابسته (associated function)**: به نوع وصل است نه به یک نمونه، و با `::` از راهِ خودِ نوع صدا زده می‌شود.

Rust سازنده ندارد. `new` فقط یک اسم است که همه رویش توافق کرده‌اند؛ هیچ چیزی در زبان این اسم را نمی‌شناسد. می‌توانی `Anime::from_file` داشته باشی، یا `Anime::empty`، یا هر سه، یا هیچ‌کدام.

و این شکل را از قبل دیده‌ای: `String::from`، `Vec::new`، `Vec::with_capacity`. همه‌شان توابعِ وابسته‌اند. حالا می‌دانی آن `::` چه بود.

> **پلِ پایتون:** `__init__` هم نامش خاص است و هم دقیقاً یکی بیشتر نداری. `new` هیچ‌کدام نیست. جایی که پل خراب می‌شود: در پایتون شیء اول ساخته می‌شود و بعد `__init__` پُرش می‌کند؛ اینجا مقدار تا وقتی هر چهار فیلدش نباشد اصلاً وجود ندارد. حالتِ «نیمه‌ساخته» قابلِ بیان نیست.

### فیلدها بیرون از ماژول خصوصی‌اند

مثالِ ۰۷ همین را داخلِ یک ماژول تعریف می‌کند و بعد از بیرون `episodes` را می‌خواند:

```rust
pub struct Anime {
    pub title: String,
    episodes: u32,
    watched: u32,
}
```

```text
error[E0616]: field `episodes` of struct `Anime` is private
```

`pub` روی خودِ ساختار فقط **نوع** را بیرون قابلِ استفاده می‌کند و درباره‌ی فیلدها هیچ نمی‌گوید. هر فیلد جداگانه خصوصی است مگر `pub` بگیرد.

و خصوصی یعنی خصوصی نسبت به **ماژول**، نه نسبت به ساختار. کدی که در همان ماژول است آزادانه می‌خواندشان — برای همین است که تستِ داخلِ `src/lib.rs` می‌تواند فیلدهای خصوصی را ببیند.

این پیش‌فرضْ عکسِ پایتون است: آنجا همه‌چیز عمومی است و `_name` یک خواهش است. اینجا کامپایلر اجرایش می‌کند. و دقیقاً همین است که ساختار را از یک کیسه‌ی داده به یک نوعِ واقعی تبدیل می‌کند: اگر `watched` خصوصی باشد و تنها راهِ زیاد کردنش `watch_one` باشد، آن‌وقت «`watched` هرگز از `episodes` بیشتر نمی‌شود» دیگر یک آرزو نیست، یک تضمین است.

ماژول‌ها درسِ خودشان را در فاز ۲ دارند. فعلاً همین‌قدر کافی است که مرزی وجود دارد و متدهای تو دروازه‌ی آن مرزند.

یک نکته‌ی آخر: هر ساختارِ این درس **مالکِ** داده‌اش است — `String` دارد، نه `&str`. ساختاری که به‌جای مالکیت، ارجاع نگه دارد به یک طولِ عمرِ صریح احتیاج دارد، و آن کارِ فاز ۲ است.

## خطاهایی که خواهی دید

### `E0063` — یک فیلد جا مانده

```text
error[E0063]: missing fields `favourite` and `watched` in initializer of `Anime`
  --> examples\04-missing-a-field.rs:15:16
   |
15 |     let show = Anime {
   |                ^^^^^ missing `favourite` and `watched`
```

**کامپایلر به چه اعتراض دارد:** یک عبارتِ ساختنِ ساختار یا هر فیلد را نام می‌برد یا اصلاً مقداری از آن نوع نیست. مقدارِ «نیمه‌ساخته» در Rust قابلِ بیان نیست — همان چیزی که پایتون با یک `__init__`ِ ناقص به راحتی می‌سازد.

**راه‌حل:** فیلدهای گم‌شده را بنویس، یا اگر واقعاً مقدارِ مناسبی برایشان نداری، یک تابعِ وابسته مثل `Anime::new` بساز که مقدارهای شروع را بگذارد.

**چرا این راه‌حل است:** دقت کن خطا **اسمِ** فیلدهای کم را می‌گوید، نه فقط «تعداد اشتباه است». روی یک ساختارِ بیست‌فیلدی همین یک خط تفاوتِ بینِ ده ثانیه و ده دقیقه است.

و اگر خودت را مدام در حالِ نوشتنِ همان مقدارهای شروع دیدی، همان علامت است که این ساختار یک `new` می‌خواهد.

### `E0594` و `E0596` — یک اشتباه، دو خطا

```text
error[E0594]: cannot assign to `show.watched`, as `show` is not declared as mutable
  --> examples\05-a-field-you-cannot-change.rs:27:5
   |
27 |     show.watched += 1;
   |     ^^^^^^^^^^^^^^^^^ cannot assign
   |
help: consider changing this to be mutable
   |
21 |     let mut show = Anime {
   |         +++
```

```text
error[E0596]: cannot borrow `show` as mutable, as it is not declared as mutable
  --> examples\05-a-field-you-cannot-change.rs:28:5
   |
28 |     show.watch_one();
   |     ^^^^ cannot borrow as mutable
   |
help: consider changing this to be mutable
   |
21 |     let mut show = Anime {
   |         +++
```

**کامپایلر به چه اعتراض دارد:** به یک چیز، دو بار. `show` با `let` ساده بایند شده، پس تغییرناپذیر است. `E0594` وقتی می‌آید که مستقیم به فیلد نسبت بدهی؛ `E0596` وقتی می‌آید که متدی با `&mut self` صدا بزنی، چون آن `&mut`ِ نامرئی همان‌جا ساخته می‌شود.

**راه‌حل:** `let mut show = ...`. هر دو راهنماییْ دقیقاً همین را نشان می‌دهند.

**چرا این راه‌حل است:** چون `mut` روی بایند است نه روی فیلد. راهی برای تغییرپذیر کردنِ تنها یک فیلد وجود ندارد و این عمدی است — «این مقدار ممکن است زیرِ دستت عوض شود» حرفی است که در یک جا گفته می‌شود و برای کلِ مقدار صدق می‌کند.

اگر همین را روی `&self` ببینی هم داستان یکی است: در `fn rename(&self)` نوشتنِ `self.title = ...` باز `E0594` است، چون آن ارجاع فقط‌خواندنی است. راهِ حلش `&mut self` است.

### `E0277` — نوعت بلد نیست خودش را چاپ کند

```text
error[E0277]: `Anime` doesn't implement `Debug`
  --> examples\06-printing-without-debug.rs:20:15
   |
20 |     println!("{show:?}");
   |               ^^^^^^^^ `Anime` cannot be formatted using `{:?}` because it doesn't implement `Debug`
   |
   = help: the trait `Debug` is not implemented for `Anime`
   = note: add `#[derive(Debug)]` to `Anime` or manually `impl Debug for Anime`
help: consider annotating `Anime` with `#[derive(Debug)]`
   |
 7 + #[derive(Debug)]
 8 | struct Anime {
   |
```

**کامپایلر به چه اعتراض دارد:** `{:?}` رایگان نیست. یک نفر باید گفته باشد این نوع چطور چاپ می‌شود، و برای نوعِ تازه‌ی تو هنوز کسی نگفته.

**راه‌حل:**

```rust
#[derive(Debug)]
struct Anime {
```

**چرا این راه‌حل است:** خطا خودش هر دو راه را می‌گذارد جلویت: `derive` کن، یا با دست بنویس. تا وقتی چاپِ بدیهی کافی است — و برای اشکال‌زدایی تقریباً همیشه هست — `derive` جوابِ درست است. نوشتنش با دست وقتی لازم می‌شود که بخواهی چیزی را پنهان کنی، مثلاً یک فیلدِ رمز.

و به تفاوتِ `{}` و `{:?}` دقت کن. `{}` برای متنی است که کاربر می‌خواند و صفتِ `Display` را می‌خواهد؛ `{:?}` برای برنامه‌نویس است و `Display` را مشتق نمی‌شود گرفت — چون Rust نمی‌تواند حدس بزند نوعِ تو برای یک آدم چطور باید خوانده شود.

### `E0616` — فیلدی که از بیرون دیده نمی‌شود

```text
error[E0616]: field `episodes` of struct `Anime` is private
  --> examples\07-a-private-field.rs:39:35
   |
39 |     println!("episodes: {}", show.episodes);
   |                                   ^^^^^^^^ private field
```

**کامپایلر به چه اعتراض دارد:** `Anime` عمومی است و `title` هم `pub` گرفته، ولی `episodes` نگرفته. `pub` روی ساختار به فیلدها سرایت نمی‌کند.

**راه‌حل:** یکی از این دو، و انتخاب بینشان یک تصمیمِ طراحی است:

```rust
impl Anime {
    pub fn episodes(&self) -> u32 {
        self.episodes
    }
}
```

یا `pub episodes: u32` در خودِ تعریف.

**چرا این راه‌حل است:** متدِ خواننده فیلد را خصوصی نگه می‌دارد. یعنی فردا می‌توانی نحوه‌ی ذخیره‌سازی را عوض کنی — مثلاً `episodes` را از یک شمارنده به چیزی محاسبه‌شده تبدیل کنی — بدونِ اینکه کدِ هیچ‌کس بشکند. `pub` کردنِ فیلد آن آزادی را برای همیشه می‌فروشد.

پیش‌فرض را خصوصی بگذار و فقط وقتی `pub` کن که ساختار واقعاً چیزی جز یک کیسه‌ی داده نباشد.

### `E0382` — متدی که مقدار را برد

```text
error[E0382]: borrow of moved value: `show`
  --> examples\08-consumed-by-its-own-method.rs:27:41
   |
20 |     let show = Anime {
   |         ---- move occurs because `show` has type `Anime`, which does not implement the `Copy` trait
...
25 |     let title = show.into_title();
   |                      ------------ `show` moved due to this method call
26 |
27 |     println!("{title} has {} episodes", show.episodes);
   |                                         ^^^^^^^^^^^^^ value borrowed here after move
   |
note: `Anime::into_title` takes ownership of the receiver `self`, which moves `show`
  --> examples\08-consumed-by-its-own-method.rs:14:19
   |
14 |     fn into_title(self) -> String {
   |                   ^^^^
```

**کامپایلر به چه اعتراض دارد:** `into_title` با `self` نوشته شده، پس صدا زدنش یک حرکت است. این همان `E0382`ِ ۱.۲.۲ است، فقط این بار حرکت پشتِ یک نقطه پنهان شده بود.

آن `note`ِ آخر را بخوان: کامپایلر خودش رفته امضای متد را پیدا کرده و `self` را زیرخط کشیده. عملاً دارد می‌گوید «مقصر اینجاست».

**راه‌حل:** بستگی دارد به اینکه واقعاً چه می‌خواستی.

- اگر ساختار را بعدش لازم داری، متد نباید `self` بگیرد. `&self` بگذار و یک کپی برگردان.
- اگر واقعاً لازمش نداری، ترتیب را عوض کن: اول `show.episodes` را بردار، بعد `into_title` را صدا بزن.

**چرا این راه‌حل است:** چون سؤال هیچ‌وقت «چطور خطا را ساکت کنم» نیست، «این متد قرار بود چه قولی بدهد» است. `into_` در اسمش یعنی «این مقدار را می‌گیرم و چیزِ دیگری تحویل می‌دهم». اگر آن قول را نمی‌خواهی، امضا اشتباه است نه صداکننده.

## تمرین

### گرم‌کردن

<details>
<summary>در <code>struct Anime { title: String, ... }</code> چند بایت روی پشته می‌نشیند و چند تا روی هیپ؟</summary>

فیلدها روی پشته کنارِ هم می‌نشینند: سه کلمه برای `String` به‌علاوه‌ی دو `u32` و یک `bool`. تنها چیزی که روی هیپ است، بافرِ متنِ خودِ `String` است. ساختار چیزِ تازه‌ای به هیپ اضافه نمی‌کند؛ فقط فیلدهایش را کنارِ هم می‌چیند.

</details>

<details>
<summary>کدام‌یک از این دو <code>println!</code> کامپایل می‌شود؟</summary>

```rust
let b = Anime {
    watched: 1,
    ..a
};
println!("{}", a.episodes);
println!("{}", a.title);
```

اولی. `a.episodes` نوعِ `u32` است و کپی شده، پس هنوز خواندنی است. `a.title` به `b` حرکت کرده و خواندنش `E0382` است.

</details>

<details>
<summary>این کامپایل می‌شود؟</summary>

```rust
impl Anime {
    fn rename(&self, new_title: String) {
        self.title = new_title;
    }
}
```

نه. `&self` فقط‌خواندنی است، پس نسبت دادن به `self.title` خطای `E0594` می‌دهد. امضای درست `&mut self` است.

</details>

<details>
<summary>فرقِ <code>Anime::new(...)</code> با <code>show.remaining()</code> در چیست؟</summary>

اولی یک تابعِ وابسته است: `self` نمی‌گیرد و از راهِ خودِ نوع صدا زده می‌شود، چون هنوز نمونه‌ای وجود ندارد. دومی یک متد است: نحوِ نقطه‌ای یک `&show` می‌سازد و به‌عنوانِ `self` تحویلش می‌دهد.

</details>

<details>
<summary>اگر <code>new</code> را <code>build</code> صدا بزنی چه می‌شود؟</summary>

هیچ. `new` کلیدواژه نیست و هیچ چیزی در زبان این اسم را نمی‌شناسد؛ فقط قراردادی است که خواندنِ کدِ دیگران را راحت می‌کند.

</details>

<details>
<summary>چرا تستِ داخلِ <code>src/lib.rs</code> می‌تواند فیلدهای خصوصی را بخواند ولی مثالِ ۰۷ نمی‌تواند؟</summary>

چون خصوصی‌بودن نسبت به ماژول سنجیده می‌شود، نه نسبت به ساختار. `mod tests` داخلِ همان فایل است؛ مثالِ ۰۷ بیرونِ `mod catalog` ایستاده.

</details>

### پیاده‌سازی

شش عضو روی `Series` در `src/lib.rs`:

```sh
cargo test -p p1-05-01-structs-and-methods
```

فیلدها خصوصی‌اند و همین‌طور هم می‌مانند. قبل از نوشتنِ هر بدنه، به امضایش نگاه کن و بگو چرا `self`ِ آن همان است که هست: `new` هیچ `self`ای ندارد، `remaining` و `summary` با `&self` کارشان راه می‌افتد، `watch_one` و `mark_favourite` به `&mut self` احتیاج دارند، و `into_title` مقدار را می‌بلعد.

یکی از این شش تا اگر با تفریقِ ساده نوشته شود در حالتِ خاصی panic می‌کند. مستنداتش می‌گوید کدام حالت.

### بساز

یک `WatchList` بنویس که چند `Series` را کنارِ هم نگه دارد:

```rust
pub struct WatchList {
    name: String,
    shows: Vec<Series>,
}
```

سه عضو برایش بساز:

- یک `new` که فهرستی خالی با اسمِ داده‌شده بسازد.
- یک متد که یک `Series` را به فهرست اضافه کند. امضایش را خودت انتخاب کن و بگو چرا `Series` باید مالکیتش را واگذار کند.
- یک متد که مجموعِ قسمت‌های دیده‌نشده‌ی کلِ فهرست را برگرداند. با یک حلقه‌ی `for` روی `&self.shows` بنویسش.

بعد یک جمله بنویس: چرا `shows` باید خصوصی بماند، حتی وقتی که کدِ بیرونی فقط می‌خواهد آن را بخواند؟

### چالش (اختیاری)

**بخشِ یک.** متدهایی که `self` می‌گیرند و `Self` برمی‌گردانند به هم زنجیر می‌شوند:

```rust
let show = Anime::new(String::from("Frieren"), 28)
    .favourite()
    .watched(3);
```

`fn favourite(mut self) -> Self` و `fn watched(mut self, count: u32) -> Self` را بنویس تا این کد کار کند. دقت کن `mut self` نه `&mut self`: مقدار را می‌گیری، عوضش می‌کنی و پسش می‌دهی.

بعد جواب بده: بینِ این و چهار خط `let mut` و انتساب، کدام را ترجیح می‌دهی و چرا؟ این الگو اسم دارد و در فاز ۳ روی پیکربندیِ سرور دوباره می‌بینی‌اش.

**بخشِ دو.** `#[derive(PartialEq)]` را از `Series` بردار و تست‌ها را بگیر. کدام تست می‌شکند و خطایش چیست؟ بعد فکر کن: اگر برابریِ درستِ دو `Series` فقط برابریِ `title` باشد، `derive` چه کارِ اشتباهی کرده بود؟

**بخشِ سه.** یک ساختارِ کوچکِ خودت بنویس با یک `pub fn new() -> Self` که **هیچ** آرگومانی نگیرد، و `cargo clippy` بگیر. یک پیشنهاد می‌دهد. `new_without_default` را در مستنداتش بخوان، بگو چرا clippy این را می‌خواهد — و چرا درباره‌ی `Series::new` چیزی نمی‌گوید. (جوابش صفتِ `Default` است و درسش در فاز ۲ است.)

| عبارتِ ساختنِ ساختار | `Anime { ... }` با همه‌ی فیلدها | ساختنِ نمونه |
| کوته‌نویسیِ مقداردهیِ فیلد | `title,` به‌جای `title: title` | تقریباً هر `new` |
| نحوِ به‌روزرسانیِ ساختار | `..other` بقیه‌ی فیلدها را می‌آورد | تغییرِ یکی دو فیلد از روی یک مقدار |
| حرکتِ جزئی | فیلدهای غیرِ `Copy` بیرون رفته‌اند | بعد از `..other` |
| بلوکِ impl | جایی که رفتارِ نوع می‌نشیند | همه‌ی متدها |
| متد | تابعی که `self` می‌گیرد | `show.remaining()` |
| تابعِ وابسته | تابعی داخلِ `impl` بدونِ `self` | `Anime::new`، `String::from` |
| `Self` | خودِ نوعِ این بلوک | نوعِ بازگشتیِ سازنده‌ها |
| `#[derive(Debug)]` | `{:?}` و `{:#?}` را می‌دهد | هر نوعی که اشکال‌زدایی می‌کنی |
| `E0063` | فیلدی در ساختن جا مانده | اسمِ فیلدها در خطا هست |
| `E0616` | فیلد بیرون از ماژول خصوصی است | پیش‌فرضِ Rust |

### الان می‌دانی

- `struct` یک نوعِ تازه می‌سازد و اسمِ فیلدها بخشی از نوع‌اند.
- `mut` روی بایند است، نه روی فیلد؛ ساختار یا کلاً تغییرپذیر است یا نیست.
- `..other` بقیه‌ی فیلدها را می‌آورد و فیلدهای غیرِ `Copy` را **حرکت** می‌دهد.
- `derive` پیاده‌سازیِ بدیهی را می‌نویسد: `Debug` برای دیدن، `Clone` برای کپی، `PartialEq` برای `==`.
- `&self` نگاه است، `&mut self` نگاهِ انحصاری، و `self` بلعیدن — و این انتخاب یک قول به صداکننده است.
- `show.remaining()` شکرِ `Anime::remaining(&show)` است؛ آن `&` را نحوِ نقطه‌ای می‌گذارد.
- `new` کلیدواژه نیست، یک قرارداد است. Rust سازنده ندارد.
- فیلدها بیرون از ماژول خصوصی‌اند و همین است که ساختار را به یک نوعِ واقعی تبدیل می‌کند.

### می‌توانی توضیح بدهی؟

- یک ساختار چه چیزی به یک تاپلِ هم‌شکل اضافه می‌کند؟
- چرا `mut` روی بایند است و نه روی فیلد؟
- بعد از `..other` چه بلایی سرِ `other` می‌آید، و چرا بعضی فیلدهایش هنوز خواندنی‌اند؟
- `&self`، `&mut self` و `self` هر کدام چه قولی به صداکننده می‌دهند؟

- چرا `new` کلیدواژه نیست، و چه چیزی آن را کار می‌اندازد؟
- «فیلد خصوصی است» یعنی خصوصی نسبت به چه؟
