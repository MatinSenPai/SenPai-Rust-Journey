# پاسخ — ۱.۵.۲ ساختارهای تاپلی و الگوی newtype

```rust
impl Rial {
    pub fn new(amount: i64) -> Rial {
        Rial(amount)
    }

    pub fn amount(self) -> i64 {
        self.0
    }
}

impl Percent {
    pub fn new(value: u8) -> Percent {
        if value > 100 {
            Percent(100)
        } else {
            Percent(value)
        }
    }

    pub fn value(self) -> u8 {
        self.0
    }

    pub fn of(self, amount: Rial) -> Rial {
        Rial(amount.0 * self.0 as i64 / 100)
    }
}

pub fn total(amounts: &[Rial]) -> Rial {
    let mut sum = 0;
    for amount in amounts {
        sum += amount.0;
    }
    Rial(sum)
}

pub fn transfer(from: AccountId, to: AccountId, amount: Rial) -> String {
    format!("{} -> {}: {} rial", from.0, to.0, amount.amount())
}
```

تقریباً هر خط اینجا یک عبارت است. و همین نکته است: newtype نوشتنش ارزان است، و چیزی که در ازایش می‌گیری یک کامپایلر است که نمی‌گذارد `transfer` را با ترتیبِ اشتباه صدا بزنی.

## `Rial::new` و `Rial::amount` — در و پنجره

```rust
Rial(amount)
```

`Rial` هم نوع است و هم تابعی که آن نوع را می‌سازد، پس سازنده یک فراخوانی بیشتر نیست. اعتبارسنجی‌ای در کار نیست چون `Rial` چیزی برای سنجیدن ندارد: مبلغِ منفی یعنی برگشتِ وجه، و صفر هم یعنی صفر.

این را صریح می‌گویم چون یک تصمیمِ طراحی است نه فراموشی. `Percent` اعتبارسنجی می‌کند؛ `Rial` نه. یک newtype دو کارِ جداشدنی می‌کند — **نام‌گذاری** و **نگهبانی** — و این یکی فقط برای نام‌گذاری آمده است.

`amount(self)` نوشتیم نه `amount(&self)`: `Rial` نوعِ `Copy` است، پس `self` هشت بایت کپی می‌کند و یک ارجاع هم هشت بایت است که باید دنبالش بروی. برای پوششی دورِ یک عددِ اسکالر، `self` بگیر. برای پوششی دورِ یک `String`، `&self` — قاعده همان [۱.۲.۳](../../../02-ownership-and-memory/03-clone-and-copy/README.fa.md) است و عوض نشده.

فیلد خصوصی است، پس `Rial::new` تنها راهِ ساختنِ یک `Rial` *از ماژولِ دیگر* است. داخلِ همین فایل `Rial(sum)` آزاد است، و برای همین `total` می‌تواند بنویسدش. حریم در Rust در سطحِ ماژول است، نه نوع.

## `Percent::new` — جایی که ضمانت ساخته می‌شود

```rust
if value > 100 {
    Percent(100)
} else {
    Percent(value)
}
```

یک `if` که به‌عنوانِ عبارت به‌کار رفته، از [۱.۱.۴](../../../01-foundations/04-functions-and-expressions/README.fa.md): هر دو شاخه یک `Percent` می‌دهند و خودِ `if` مقدارِ بازگشتیِ تابع است.

بخشِ مهم بریدن نیست؛ بخشِ مهم چیزی است که بریدن به‌علاوه‌ی فیلدِ خصوصی با هم می‌خرند: **در هر جای دیگری از برنامه، می‌دانی که یک `Percent` حداکثر ۱۰۰ است.** `Percent::of` چک نمی‌کند. هیچ‌جا چک نمی‌شود. چک یک بار انجام شد، سرِ تنها در.

معنیِ «مرزِ اعتبارسنجی» همین است، و دلیلِ اینکه ۲۴۰ هرگز `Percent` نمی‌شود همین است.

با این حال برای یک کتابخانه رفتارِ غلطی است. بریدن، ورودیِ خراب را به خروجیِ ظاهراً معقول تبدیل می‌کند — ۲۴۰ بی‌صدا ۱۰۰ می‌شود و به فراخوان هیچ‌وقت گفته نمی‌شود که ورودی‌اش بی‌معنی بوده. نسخه‌ی صادق یک `Result` برمی‌گرداند و آن را در [۱.۶.۳](../../../06-absence-and-failure/03-result-and-question-mark/README.fa.md) می‌نویسی. نسخه‌ی امروز بهترین چیزی است که درسی بدونِ `Result` می‌تواند بسازد، و دانستنِ اینکه چرا کافی نیست از خودِ کد ارزشمندتر است.

## `Percent::of` — تنها جایی که تله دارد

```rust
Rial(amount.0 * self.0 as i64 / 100)
```

اول ضرب، بعد تقسیم. نوشتنِ `amount.0 / 100 * self.0` هم کامپایل می‌شود، از نظرِ نوع هم درست است، و جوابش غلط است:

| مبلغ | درصد | اول ضرب | اول تقسیم |
|---|---|---|---|
| ۱۰۵۰ | ۱۰ | **۱۰۵** | ۱۰۰ |
| ۱۰۵۰ | ۳ | **۳۱** | ۳۰ |
| ۹۹ | ۵۰ | **۴۹** | ۰ |

تقسیمِ صحیح باقی‌مانده را دور می‌ریزد، پس اگر اول تقسیم کنی، هر چیزی زیرِ صد ریال قبل از اینکه اصلاً درصد اعمال شود دور ریخته می‌شود. این همان خطرِ [۱.۱.۲](../../../01-foundations/02-scalar-types-and-overflow/README.fa.md) است که می‌گفت پول یک عددِ صحیح است: اعدادِ صحیح دقیق‌اند، ولی فقط اگر ترتیبِ عملیات را طوری بچینی که بریدن آخر اتفاق بیفتد.

`self.0 as i64` لازم است چون مقدارهای داخلی یکی `u8` است و یکی `i64`، و Rust این دو را بی‌سروصدا قاطی نمی‌کند. این تبدیل در جهتِ پهن‌شدن امن است — هر `u8`ای در یک `i64` جا می‌شود.

و دقت کن newtype از چه چیزی نتوانست نجاتت بدهد. `amount.0 * self.0 as i64` یک ضربِ معمولیِ `i64` است و برای مبلغی به‌اندازه‌ی کافی بزرگ دقیقاً همان‌طور که [۱.۱.۲](../../../01-foundations/02-scalar-types-and-overflow/README.fa.md) گفت سرریز می‌کند: در debug توقف، در release مقدارِ چرخیده. newtype **معنی** را بررسی می‌کند، نه **بازه** را. ابزارِ نیمه‌ی بازه `checked_mul` است، و گذاشتنش اینجا به یک `Result` احتیاج دارد تا شکست را گزارش کند.

## `total` — یک حلقه‌ی ساده، و اینکه چرا `Rial(sum)` آخر است

```rust
let mut sum = 0;
for amount in amounts {
    sum += amount.0;
}
Rial(sum)
```

`amounts` یک `&[Rial]` است — یک برش، از [۱.۳.۴](../../../03-borrowing-and-references/04-slices/README.fa.md) — پس حلقه `&Rial` می‌دهد و `amount.0` از رویِ ارجاع می‌خواند بی‌آنکه چیزی حرکت کند.

جمع را در یک `i64` لخت نگه می‌داریم و آخرِ کار یک بار می‌پیچیمش. راهِ دیگر — نگه داشتنِ یک `Rial` و باز کردنش در هر دور — به‌جای یک بار در هر تابع، یک بار در هر عنصر `.0` می‌نویسد، برای همان جواب. **پوشش باید تا جای ممکن دیر باز شود و تا جای ممکن زود برگردد.** آن نوارِ باریکِ بینشان جایی است که اشتباه ممکن می‌شود، و هر چه باریک‌تر بهتر.

حالتِ خالی به رسیدگیِ جداگانه احتیاج ندارد: حلقه اجرا نمی‌شود، `sum` صفر می‌ماند، و `Rial(0)` بیرون می‌آید. همان شکلِ بی‌نیاز از نگهبان که در برش‌های خالیِ [۱.۳.۴](../../../03-borrowing-and-references/04-slices/README.fa.md) دیدی.

## `transfer` — امضایی که این درس برایش وجود دارد

```rust
format!("{} -> {}: {} rial", from.0, to.0, amount.amount())
```

بدنه یک `format!` است از [۱.۴.۳](../../../04-text-and-strings/03-building-and-transforming-strings/README.fa.md). امضا خودِ درس است:

```rust
pub fn transfer(from: AccountId, to: AccountId, amount: Rial) -> String
```

با نسخه‌ای که این درس با آن شروع شد مقایسه‌اش کن:

```rust
fn transfer(from: u64, to: u64, rial: u64) -> String
```

هر دو سه عدد می‌گیرند. در دومی شش ترتیب کامپایل می‌شود و یکی‌شان درست است. در اولی مبلغ نمی‌تواند در جایگاهِ حساب بنشیند و شماره‌ی حساب هم نمی‌تواند در جایگاهِ مبلغ، پس آن شش تا می‌شود دو تا.

دو تا، نه یکی — `AccountId` و `AccountId` هنوز یک نوع‌اند، پس `from` و `to` همچنان قابلِ جابه‌جایی‌اند. ارزشِ مکث دارد، چون حدِ صادقانه‌ی این الگوست: **newtype چیزهای متفاوت را از هم جدا می‌کند، نه نقش‌های متفاوت را.** اگر جابه‌جا شدنِ فرستنده و گیرنده خطری است که باید بسته شود، جوابش یک ساختارِ فیلددار است، از [۱.۵.۱](../../../05-your-own-types/01-structs-and-methods/README.fa.md):

```rust
pub struct Transfer {
    pub from: AccountId,
    pub to: AccountId,
    pub amount: Rial,
}
```

حالا محلِ فراخوانی مجبور است اسمِ فیلدها را بنویسد و دیگر چیزی نمی‌ماند که ترتیبش اشتباه شود. شکلِ کلیِ این معامله همین است: ساختارِ تاپلی برای یک مقدار که یک معنی دارد، فیلدهای بااسم برای چند مقدار که نقش‌هایشان فرق می‌کند.

## این درس واقعاً درباره‌ی چه بود

- **ساختارِ تاپلی ساختاری است که فیلدهایش شماره دارند نه اسم**، و `struct Meters(f64);` یک تعریفِ کاملِ نوع است، با سمی‌کالن و همه‌چیز.
- **دو newtype دورِ یک نوعِ پایه، دو نوعِ بی‌ربط‌اند.** جمله‌ی `expected 'Meters', found 'Feet'` در `E0308` کلِ استدلالِ این الگوست.
- **فیلدِ خصوصی به‌علاوه‌ی سازنده یعنی مقداری که نمی‌شود اشتباه ساختش** — یک بار سرِ در بررسی می‌شود و بعد از آن همه‌جا مورد اعتماد است.
- **هزینه‌ی زمانِ اجرا صفر است.** اندازه‌ی `Rial` همان اندازه‌ی `i64` است. هزینه، تبدیل‌هایی است که خودت می‌نویسی، و `E0369` روی `price + fee` یکی از همان صورت‌حساب‌هاست.
- **هر `.0` لحظه‌ای است که محافظت خاموش است.** دیر باز کن، زود ببند، و فاصله را کوتاه نگه دار.
