# راه‌حل — ۱.۶.۲ ترکیب‌گرهای `Option`

```rust
pub fn shout(word: Option<&str>) -> Option<String> {
    word.map(|w| format!("{}!", w.to_uppercase()))
}

pub fn safe_half(n: Option<i32>) -> Option<i32> {
    n.and_then(|x| if x % 2 == 0 { Some(x / 2) } else { None })
}

pub fn positive_only(n: Option<i32>) -> Option<i32> {
    n.filter(|v| *v > 0)
}

pub fn take_and_reset(slot: &mut Option<String>) -> Option<String> {
    slot.take()
}

pub fn coordinates(x: Option<i32>, y: Option<i32>) -> Option<(i32, i32)> {
    x.zip(y)
}

pub fn first_available(primary: Option<i32>, backup: Option<i32>) -> Option<i32> {
    primary.or(backup)
}
```

شش تابع، شش ترکیب‌گرِ متفاوت. هیچ‌کدامشان `match` نمی‌خواست.

## `shout` — یک `.map()` ساده

```rust
word.map(|w| format!("{}!", w.to_uppercase()))
```

`word` یا `Some(w)` است یا `None`. اگر `Some` باشد، کلوژر رویش اجرا می‌شود و نتیجه دوباره در `Some` می‌رود؛ اگر `None` باشد، هیچ‌وقت کلوژر صدا زده نمی‌شود و خودِ `None` برمی‌گردد. دقیقاً همان تعریفِ `.map()` که در درس دیدی — بدونِ هیچ شاخه‌ای که خودت بنویسی.

نوشتنش با `match` هم کار می‌کرد:

```rust
match word {
    Some(w) => Some(format!("{}!", w.to_uppercase())),
    None => None,
}
```

سه خط بیشتر برای همان نتیجه، و الگویِ «`Some` بگیر، تبدیل کن، دوباره در `Some` بگذار» را باید هر بار دستی تکرار کنی. این دقیقاً همان تکراری است که `.map()` برایش ساخته شده.

## `safe_half` — چرا `.and_then()` و نه `.map()`

```rust
n.and_then(|x| if x % 2 == 0 { Some(x / 2) } else { None })
```

فرقش با `shout` این است: کلوژر خودش یک `Option<i32>` برمی‌گرداند، نه یک `i32`. اگر اینجا به‌جای `.and_then()` می‌نوشتی `.map(...)`, کامپایلر یک `Option<Option<i32>>` می‌ساخت و تابع دیگر با امضای اعلام‌شده‌اش — `Option<i32>` — جور در نمی‌آمد؛ همان `E0308`ی که در بخشِ خطاهای درس دیدی.

قاعده همان چیزی بود که در «مفهوم» خواندی: به امضای تابعی که داخلِ کلوژر صدا می‌زنی نگاه کن. اینجا خودِ کلوژر (نه یک تابعِ جدا) هست که یا `Some(x / 2)` می‌دهد یا `None` — پس همان قاعده صدق می‌کند: کلوژر `Option` برمی‌گرداند، پس `.and_then()`.

## `positive_only` — `.filter()` و آن ارجاع

```rust
n.filter(|v| *v > 0)
```

`v` اینجا از نوعِ `&i32` است، نه `i32` — برای همینِ `*v > 0` نوشتیم نه `v > 0`. اگر `*` را بردار، کامپایلر می‌گوید نمی‌تواند `&i32` را با `i32` مقایسه کند؛ همان چیزی که در بخشِ «مفهوم» توضیح داده شد: `.filter()` باید بتواند مقدار را، اگر شرط رد شد، دست‌نخورده در `None`اش بگذارد، پس فقط نگاهش می‌اندازد.

تست‌ها هم `Some(0)` را چک می‌کنند: چون شرط `*v > 0` است نه `*v >= 0`، صفر رد می‌شود. اگر عملگر را اشتباه می‌زدی، همان تستِ `positive_only(Some(0))` شکست می‌خورد.

## `take_and_reset` — `.take()` روی `&mut Option`

```rust
slot.take()
```

امضای تابع `&mut Option<String>` می‌گیرد، نه `Option<String>` — چون `.take()` روی خودِ متغیر کار می‌کند، نه یک کپی. `.take()` هرچه در `slot` است را بیرون می‌کشد و `None` را جایش می‌گذارد، بدونِ هیچ کلونی: فقط جابه‌جاییِ مالکیت، همان چیزی که در ۱.۲.۲ دیدی.

نوشتنِ `slot.clone()` هم تستِ اول را پاس می‌کرد، ولی تستِ دوم — `assert_eq!(slot, None)` — رد می‌شد، چون کلون کردن `slot` را دست‌نخورده می‌گذاشت.

## `coordinates` — `.zip()`

```rust
x.zip(y)
```

`.zip()` دو `Option` را در یک تاپل جفت می‌کند، فقط اگر هردو `Some` باشند. اینجا هیچ تودرتویی در کار نیست چون نه `x` و نه `y` تابعی نیستند که خودشان `Option` برگردانند — فقط دو مقدارِ ساده‌اند که کنارِ هم گذاشته می‌شوند.

## `first_available` — `.or()`

```rust
primary.or(backup)
```

اگر `primary` از قبل `Some` بود، `backup` اصلاً لازم نمی‌شد. این با `.unwrap_or()` فرق دارد: آنجا یک *مقدار* جایگزین می‌شد، اینجا یک *`Option` کامل* — برای همین نتیجه‌ی `first_available(None, None)` هنوز `None` است، نه یک عددِ پیش‌فرض.

## این درس واقعاً درباره‌ی چه بود

- **`.map()` نتیجه‌ی کلوژر را دوباره در `Some` می‌پیچد؛ `.and_then()` این کار را نمی‌کند** چون کلوژرش خودش از قبل پیچیده بود. سؤالی که همیشه باید بپرسی: «کلوژری که دارم می‌دهم، خودش `Option` برمی‌گرداند یا نه؟»
- **`.filter()` یک `&T` می‌گیرد، نه `T`** — باید بتواند اگر شرط رد شد، مقدار را دست‌نخورده نگه دارد.
- **`.take()` و مشابه‌هایش روی خودِ متغیر کار می‌کنند**، نه یک کپی — به همین دلیل امضایشان `&mut Option<T>` است.
- **`.zip()` هیچ‌وقت تودرتو نمی‌سازد** چون دو طرفش تابع نیستند، مقدارند.
- **`.or()` جایگزینِ `Option` کامل می‌دهد؛ `.unwrap_or()` جایگزینِ مقدار.** با هم اشتباه نگیرشان.

اگر می‌خواهی ببینی همین شش تابع به‌شکلِ `match` چه شکلی می‌شدند، به بخشِ «`match` یا زنجیره؟» در [README](../README.fa.md) برگرد — همان‌جا هر دو نسخه کنارِ هم هستند.
