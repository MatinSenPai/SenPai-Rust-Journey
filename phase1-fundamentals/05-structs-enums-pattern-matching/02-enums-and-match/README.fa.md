# ۰۵.۲ — نوع Enum و match

## نوع Enumها «دقیقاً یکی از این حالت‌ها» رو مدل‌سازی می‌کنن

```rust
enum WatchStatus {
    PlanToWatch,
    Watching { episode: u32 },
    Completed { rating: u8 },
    Dropped,
}
```

این واقعاً ابزاری کاملاً متفاوت (و خیلی دقیق‌تر) نسبت به چیزیه که تو پایتون معمولاً بهش تکیه می‌کنی. یه توسعه‌دهنده‌ی پایتون ممکنه این رو با یه فیلد متنی (مثل `"status = "watching`) مدل‌سازی کنه و در کنارش فیلدهای مجزا و شلخته‌ای (مثل `episode` و `rating`) داشته باشه که فقط برای *بعضی* از وضعیت‌ها معنی دارن — تو پایتون هیچی جلوت رو نمی‌گیره که به اشتباه وقتی که `"status == "watching` هست، فیلد `rating` رو هم مقداردهی کنی. نوع `enum` تو زبان Rust به‌طور ساختاری جلوی این اشتباه رو می‌گیره و غیرممكنش می‌کنه: حالت `Watching` *با خودش* مقدار `episode` رو حمل می‌کنه، `Completed` *با خودش* مقدار `rating` رو می‌بره، و هیچ راهی برای ساختنِ یه `WatchStatus` وجود نداره که توش `rating` مقدار داشته باشه اما وضعیّتش `Completed` نباشه. هر کدوم از این گونه‌ها (variants) می‌تونه داده‌ی مرتبطِ کاملاً متفاوتی رو همراه خودش داشته باشه (یا حتی هیچی نداشته باشه، مثل `PlanToWatch`) — به این مدل، خیلی وقتا «نوعِ جمعی (sum type)» یا «اجتماعِ تگ‌دار (tagged union)» می‌گن، و این یکی از پرکاربردترین ویژگی‌های زبان Rust برای مدل‌سازیِ واقعیِ دامنه‌ی داده (domain modeling) تو سیستم‌های بک‌اند هست.

## دستور `match` حالت‌های مختلفِ یه Enum رو جامع‌ومانع (exhaustively) بررسی می‌کنه

```rust
fn describe(status: &WatchStatus) -> String {
    match status {
        WatchStatus::PlanToWatch => "not started yet".to_string(),
        WatchStatus::Watching { episode } => format!("on episode {episode}"),
        WatchStatus::Completed { rating } => format!("finished, rated {rating}/10"),
        WatchStatus::Dropped => "dropped".to_string(),
    }
}
```

هر بازویِ `match`، هم بررسی می‌کنه (**checks**) که این متغیر کدوم یک از این گونه‌هاست و هم تو یه حرکت تمام داده‌هایی که اون گونه با خودش آورده رو باز می‌کنه (**destructures**) (مثلاً `{ episode }` میاد فیلدِ `episode`ِ گونه‌ی `Watching` رو مستقیماً می‌گیره و می‌ذاره تو متغیری به همین اسم). اگه بعداً یه حالتِ پنجم هم به enum اضافه کنی و یادت بره این `match` رو آپدیت کنی چی می‌شه؟ کامپایلر اصلاً کدت رو نمی‌سازه — این همون بررسیِ جامعیت (exhaustiveness) هست که اینجا داره کارِ اساسی می‌کنه: تو این حالت کامپایلر می‌گه «یه وضعیت جدید اضافه کردی و یادت رفته یه‌جا هندلش کنی»؛ یعنی یه دسته‌ی کامل از باگ‌ها (مخصوصاً تو سیستم‌های بک‌اندی که دارن مدام بزرگ‌تر می‌شن) رو به جای اینکه بذاره تو زمان اجرا و به عنوان یه شاخه‌یِ `else`ای که هیشکی براش کد ننوشته خودشون رو نشون بدن، همونجا تو زمان کامپایل مچشون رو می‌گیره.

## وظیفه‌ی تو

فایل `src/lib.rs` یه نوع `Status` (از جنس enum) برای پیگیریِ وضعیت انتشار یه مانگا/وب‌تون تعریف کرده. توابعی که باهاش کارهای pattern-match انجام می‌دن رو پیاده‌سازی کن.
