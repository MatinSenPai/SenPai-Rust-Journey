# راه‌حل

کلماتِ `Self` و `Book` اینجا دقیقاً با هم یکی هستن — کلمه‌ی `Self` در واقع یه اختصارنویسیه برای اینکه بگی «اون نوعی (type) که این بلاکِ `impl` برای اون نوشته شده»، بنابراین داخل یه بلاک مثل `impl Book { ... }` هر دو عبارتِ `Self ->` و `Book ->` تبدیل به یه چیز یکسان کامپایل می‌شن. عرفِ برنامه‌نویسیِ Rust اینه که ترجیح می‌دن از `Self` استفاده کنن: اینطوری اگه یه زمانی خواستی اسم `Book` رو عوض کنی، امضای همه‌ی متدها بدون نیاز به دستکاری همچنان درست و سالم می‌مونن.

عبارتِ `self.chapters_read as f64` دقیقاً همون سینتکسِ Rust برای تبدیلِ صریحِ اعداد (numeric cast) هست — اینجا برخلاف بعضی زبون‌های دیگه هیچ تبدیلِ ضمنی از نوع صحیح (int) به اعشاری (float) انجام نمی‌شه؛ تو زبان Rust تو همیشه دقیقاً چیزی رو می‌نویسی که منظورت همونه.

متد `describe`، اون متغیر `star` رو اول به شکل یه متغیرِ ساده‌ی `&str` آماده می‌کنه (مقدارش یا `" *"` می‌شه یا `""`) و بعد داخل اون فراخوانیِ یکتا از `!format` ازش استفاده می‌کنه — این روش خیلی ساده‌تر از اینه که بخوایم رو کلِ ساختارِ اون رشته‌ی قالب‌بندی (format string)، شاخه‌بندی (branching) و شرط بذاریم.

در مورد سؤال دومِ مرور: اگه تابعِ `describe` به جای `&self` از `&mut self` استفاده می‌کرد، فراخوانی اون نیازمندِ یه قرض‌گرفتنِ *انحصاری (exclusive)* از شیء `Book` می‌شد، حتی با وجود اینکه این متد اصلاً هیچ چیزی توش نمی‌نویسه — یعنی مثلاً نمی‌تونستی تابع `()describe` رو روی یه کتاب همزمان دوبار صدا بزنی، یا اینکه بخوای یه جایی از برنامه‌ات یه ارجاعِ اشتراکی (shared reference) به اون کتاب نگه داری و همون موقع `()describe` رو هم روش صدا بزنی. گرفتنِ `&self` وقتی که تو فقط می‌خوای داده رو بخونی، همون چیزیه که به فراخواننده‌ها (callers) این اجازه رو میده تا بتونن دسترسی‌های اشتراکی رو آزادانه با هم داشته باشن و نگه دارن؛ این دقیقاً همون مفهومِ «یا نام مستعار، یا تغییرپذیری (aliasing XOR mutability)» هست که تو ماژولِ قرض‌گرفتن باهاش آشنا شدی، با این تفاوت که اینجا به‌طور خودکار روی اون شیء (`self`) که متد روش صدا زده شده اعمال می‌شه.
