# ۰۷ — استقرار (Deployment) و عملیات (Operations)

تا اینجا هر درسی که تو این فاز داشتیم، روی این فرض می‌چرخید که خب یه سرویسِ Rust از قبل وجود داره، ران شده، در دسترسه، و آماده‌ست تا فراخوانی بشه. این ماژول قراره دقیقاً همین شکاف و جای خالی رو پر کنه: خروجیِ دستور `cargo build --release` (که همون فایلِ اجرایی یا باینریه) چطوری تو دنیای واقعی تبدیل می‌شه به یه کانتینرِ در-حال-اجرا که بغل دستِ یه دیتابیس نشسته؟ و اون خط‌لوله یا پایپ‌لاینِ CI (مخفف Continuous Integration) که تا الان خیلی بی‌سروصدا رو هر پُش (push) تو فایلِ `.github/workflows/ci.yml` داشته کارای `fmt/clippy/test` رو انجام می‌داده، چطوری باید به پروسه‌ی *دیپلوی و ارسال (shipping)* اون کانتینر متصل بشه؟
