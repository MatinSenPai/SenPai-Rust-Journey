# راهنمای راه‌اندازی و ستاپ (Setup Guide)

این کارا رو دقیقاً فقط یک بار و همون اوایل قبل از اینکه بخوای واردِ درسِ `phase0-setup/04-cargo-basics` بشی انجامشون بده. همون دو تا درسِ اول از فاز 0 به صورت مفصل *چرایی (why)* و دلیلِ کارا رو بهت توضیح دادن؛ ولی این صفحه قرارِ روی بحثِ *چگونگی (how)* تمرکز کنه، و عمداً و کاملاً از بقیه فایل‌ها جدا نگه داشته شده تا هروقت خواستی بتونی سریع و بی‌دردسر بیای یه نگاه بهش بندازی.

## ۱. نصبِ Rust از طریق ابزارِ `rustup`

نصب و مدیریت کردن نسخه‌هایِ Rust از طریقِ ابزارِ `rustup` انجام می‌شه، که در واقع یه سیستمِ مدیریت نسخه یا همون version manager هستش (کلاً تو مایه‌هایِ چیزایی مثل `pyenv`/`nvm` می‌مونه، با این تفاوت که رسمیه و تنها روشِ استانداردیه که کلاً همه باهاش Rust رو رو سیستمشون می‌ریزن):

```sh
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
```

ترمینالت (shell) رو ببند و دوباره بازش کن، بعد اینطوری چک کن و مطمئن شو (confirm):

```sh
rustc --version
cargo --version
```

این مخزن (repo) ابزارِ برنامه‌نویسیِ (toolchain) مختص خودش رو مستقیماً تو فایلِ `rust-toolchain.toml` پین و مشخص کرده (کانال = نسخه پایدار یا همون stable) — پس اگه حتی نسخه‌ی دیفالت و گلوبالیِ (global default) روی سیستمت فرق داشته باشه، هروقت تو دلِ دایرکتوری‌های این مخزن باشی و دستورایِ `cargo`/`rustc` رو ران کنی، `rustup` کاملاً اتوماتیک میاد همون نسخه‌یِ درخواستی رو نصب و از همون استفاده می‌کنه.

## ۲. تنظیم و راه‌اندازیِ ادیتور (Editor setup)

افزونه‌ی **rust-analyzer** رو روی ادیتور خودت نصب کن (برای VS Code: عبارت "rust-analyzer" رو تو بخش مارکت‌پلیس یا همون extensions جستجو کن). این کار کلاً باعث می‌شه همونجا موقع تایپ کردن متوجه نوع داده‌ها بشی (inline type hints)، بتونی راحت بری به خطی که اون متغیر یا تابع تعریف شده (jump-to-definition)، و — از همه چی مهم‌تر واسه یادگیری — اینکه دقیقاً *همون لحظه‌ای که تایپ می‌کنی* ارورهای کامپایلر رو درجا ببینی (inline compiler errors)، به جای اینکه همش منتظر بمونی تا با ران کردن دستورِ `cargo build` تازه بفهمی چه گندی زدی.

این دو تا کامپوننت و ابزار (components) رو هم حتماً نصب کن (اینا از قبل تو همون فایلِ `rust-toolchain.toml` لیست شدن، اما واقعاً ارزششو داره که بدونی دارن چیکار می‌کنن):
- **ابزارِ `rustfmt`** — همون ابزار فرمت‌کننده‌ی کد (formatter)ِ استاندارد و اصلی. تو هر کجای هر کریّت (crate) که باشی کافیه بزنی `cargo fmt` تا کدت مرتب شه.
- **ابزارِ `clippy`** — یه برنامه‌ی ارزیابی‌کننده‌ی کد (linter) که دقیقاً دست می‌ذاره رو الگوها و کدهایی که استانداردها و عرفِ برنامه‌نویسی رو رعایت نکردن (non-idiomatic patterns)، چیزایی که خودِ کامپایلر شخصاً بهشون اصلاً گیر نمی‌ده و براش مهم نیست. تو هر کجای هر کریّت که باشی بزن `cargo clippy`. به تک‌تکِ اخطارها و وارنینگ‌هایی (warnings) که این ابزار بهت می‌ده به چشم یه مینی-درسِ آموزشی نگاه کن، نه به عنوان یه پارازیتِ (noise) رو اعصاب که فقط می‌خوای بی‌صداش کنی (silence).

## ۳. اولین دستوراتی که باید اجراشون کنی

از تو همون دایرکتوریِ روت و اصلیِ مخزن:

```sh
cargo build --workspace   # تمام کریت‌های درسی‌ای که تا همین لحظه تو پروژه وجود دارنو همزمان کامپایل می‌کنه
cargo test -p p0-04-cargo-basics   # واسه تست گرفتنِ یک دونه درسِ مشخص، از طریقِ همون اسم پکیج‌ِ اختصاصیش
```

تا وقتی که رسماً نرسیدی به فاز 3، تو به **هیچ‌وجه** نیازی به سیستم‌هایی مثل PostgreSQL، Redis، Docker، یا هیچ زیرساختِ مربوط به بک‌اندِ (backend infrastructure) دیگه‌ای نخواهی داشت — تک‌تک اون درس‌ها همون موقع تو فایلِ `README.md`شون دقیقاً بهت می‌گن که کِی و تو چه لحظه‌ای باید چی رو رو سیستمت نصب کنی، نه قبل‌تر از اون.

## ۴. وقتی یه چیزی کامپایل نمی‌شه و اصلاً نمی‌فهمی چرا

این قضیه قراره مدام و با فرکانس بالا اتفاق بیفته و کلاً و کاملاً عادیه (normal) — پرحرف و وراج بودنِ کامپایلر کلاً یه چیزِ عمدیه. پیامِ خطایی که بهت می‌ده رو کامل و با دقت، از بالا تا پایینِ خط بخونش (خطاهای Rust کلاً خیلی رک و مستقیم می‌گن دقیقاً کجای کار می‌لنگه و مشکل چیه، و اکثراً حتی راهِ حلِ (fix) برطرف کردنشونم همونجا برات چاپ می‌کنن)، بعد اگه کلمه‌ی ناآشنا و عجیب غریبی دیدی اول یه نگاه بنداز به فایلِ `docs/glossary.fa.md`، اونم قبل از اینکه بخوای از کسی دیگه سؤال بپرسی.
