# پاسخ تشریحی

```rust
pub fn make_multiplier(factor: i32) -> impl Fn(i32) -> i32 {
    move |x| x * factor
}
```

واژه‌ی مهم `move` است. بدون آن، `|x| x * factor` تلاش می‌کند `factor` را از stack frame تابع `make_multiplier` **قرض بگیرد**. اما به‌محض برگشت تابع، آن stack frame از بین می‌رود و closure ارجاعی به حافظه‌ای نامعتبر نگه می‌دارد. borrow checker این حالت را رد می‌کند؛ همان use-after-free خاموشی که در زبانی مثل C ممکن بود رخ دهد.

با `move`، مقدار `factor` داخل خود closure کپی می‌شود؛ چون `i32` نوعی `Copy` است. بنابراین closure نسخه‌ی خصوصی خودش را دارد و این مقدار به‌اندازه‌ی خود closure زنده می‌ماند و دیگر به frame تابع وابسته نیست.

```rust
pub fn call_n_times<F: FnMut()>(mut f: F, n: u32) {
    for _ in 0..n {
        f();
    }
}
```

دو نکته مهم‌اند. اول اینکه خود پارامتر باید `mut f: F` باشد. فراخوانی closure از نوع `FnMut` دسترسی انحصاری `&mut` به آن می‌خواهد و Rust اجازه نمی‌دهد از bindingای که `mut` نیست ارجاع تغییرپذیر بگیری، حتی اگر نوع `f` از قبل نشان دهد که closure چیزهایی را تغییر می‌دهد.

دوم، `f()` داخل حلقه شکل کوتاه‌شده‌ی `FnMut::call_mut(&mut f, ())` است. هر بار فقط برای همان فراخوانی، `f` دوباره به‌شکل تغییرپذیر قرض گرفته می‌شود؛ به همین دلیل می‌توانیم آن را در حلقه چند بار صدا بزنیم. محدودیت یک‌بار فراخوانی همان چیزی است که `FnOnce` را از `FnMut` جدا می‌کند.

پاسخ پرسش اول: بدنه‌ی `|x| { count += 1; x + 1 }` متغیر captureشده‌ی `count` را تغییر می‌دهد، پس `FnMut` و طبق سلسله‌مراتب `FnOnce` را پیاده می‌کند، اما **`Fn` نیست**؛ چون `Fn` فقط قرض مشترک از captureها را مجاز می‌داند. دادن آن به `apply_twice` با bound برابر `F: Fn(i32) -> i32` با خطایی در این معنا رد می‌شود: «closureای انتظار می‌رفت که trait `Fn` را پیاده کند، اما این closure فقط `FnMut` را پیاده می‌کند.»

bound پارامتر جنریک یک قرارداد است. `apply_twice` گفته فقط closureهایی را می‌پذیرد که captureهایشان برای فراخوانی به دسترسی تغییرپذیر نیاز ندارند، و کامپایلر فراخواننده را به همین قرارداد مقید می‌کند.
