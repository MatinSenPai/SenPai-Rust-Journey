# ۰۲.۱ — کلوژرها و traitهای `Fn`

## کلوژر چیه

یه کلوژر (Closure)، یه تابعِ ناشناس (بدون اسم) و درون‌خطی (inline) هستش که می‌تونه **متغیرها رو از اسکوپی (scope) که توش تعریف شده، اسیر کنه و گیر بندازه (capture)**:

```rust
let threshold = 10;
let is_long = |title: &str| title.len() > threshold;
```

تابعِ `is_long` اصلاً نیازی نداشت که متغیر `threshold` رو به عنوان پارامتر ورودی بگیره — اون خیلی راحت دست دراز کرد و اونو از اسکوپِ اطرافش برداشت. اگه تا حالا تو پایتون کلوژر نوشته باشی، دقیقاً همین ایده اونجا هم هست:

```python
threshold = 10
is_long = lambda title: len(title) > threshold
```

تفاوت تو این نیست که *آیا* کلوژرها می‌تونن متغیر اسیر کنن یا نه — هر دو زبان این اجازه رو می‌دن. فرقش اینجاست که borrow checker تو زبان Rust پاشو می‌کنه تو کفشِ اینکه این اسیر کردن *چطوری* اتفاق می‌افته (از طریق ارجاع، ارجاعِ تغییرپذیر، یا گرفتنِ کامل مالکیت)، و تازه این تصمیم رو به‌طور خودکار و بر اساس اینکه کلوژر داره با متغیر اسیرشده *چه کاری* انجام می‌ده می‌گیره. این تصمیم‌گیری دقیقاً همون چیزیه که اون سه تا traitِ `Fn` دارن توصیفش می‌کنن.

## خصیصه‌های `FnMut` ،`Fn` و `FnOnce` — چیزی نیستن که تو انتخاب کنی، Rust خودش استنتاج می‌کنه

هر کلوژری بسته به اینکه بدنه‌اش چطور از متغیرهای اسیرشده استفاده می‌کنه، به‌طور خودکار یکی (یا بیشتر) از این سه تا trait رو پیاده‌سازی می‌کنه:

- **`Fn`** — فقط متغیرهای اسیرشده رو می‌خونه (به شکل `T&` قرضشون می‌گیره). می‌تونه هر چند بار که بخوای صدا زده بشه. کلوژر `is_long` تو مثال بالا از نوع `Fn` هست: چون فقط مقدار `threshold` رو می‌خونه.
- **`FnMut`** — یه متغیر اسیرشده رو تغییر می‌ده (به شکل `mut T&` قرضش می‌گیره). بازم می‌تونه بارها صدا زده بشه، اما هر بار ممکنه چیزی که اسیر کرده رو تغییر بده. مثال: یه کلوژر که یه شمارنده (counter) رو اسیر کرده و هربار یکی بهش اضافه می‌کنه.
- **`FnOnce`** — متغیر اسیرشده رو مصرف می‌کنه (منتقل و move می‌کنه). فقط می‌تونه **یک بار** صدا زده بشه، چون بعد از اولین فراخوانی اون مقداری که به داخلش move شده بود کلاً از بین می‌ره و پاک می‌شه. مثال: یه کلوژر که یه `String` دارای مالکیت رو با برگردوندن تو خروجیش مصرف می‌کنه.

اینا با هم یه سلسله‌مراتب (hierarchy) تشکیل می‌دن: هر کلوژرِ `Fn` یه `FnMut`ِ معتبر هم هست («خوندن» خودش حالتِ خاصی از «عدم نیاز به دسترسی انحصاری» به حساب میاد)، و هر کلوژر `FnMut` یه `FnOnce`ِ معتبر هم هست («تغییر دادنِ مکرر» حالتِ خاصی از «حداقل یک‌بار فراخوانی» محسوب می‌شه). بنابراین `FnOnce` *ضعیف‌ترین* تضمینه و `Fn` *قوی‌ترین* تضمین — وقتی داری برای پارامترِ genericت یه محدودیت (bound) می‌ذاری، ضعیف‌ترینِ traitای که تابعت واقعاً بهش نیاز داره رو بخواه تا فراخواننده‌های تابعت بیشترین انعطاف‌پذیری رو داشته باشن.

تو هیچ‌وقت با دست خودت نمی‌نویسی `impl Fn for MyClosure` — کامپایلر خودش بدنه‌ی کلوژر رو نگاه می‌کنه و محدودترین traitای که براش صدق می‌کنه رو استنتاج می‌کنه.

## استفاده از کلوژرها به عنوان پارامتر و خروجیِ تابع

```rust
fn apply<F: Fn(i32) -> i32>(f: F, x: i32) -> i32 {
    f(x)
}

fn make_adder(n: i32) -> impl Fn(i32) -> i32 {
    move |x| x + n
}
```

تابع `make_adder` خروجیِ `impl Fn(i32) -> i32` برمی‌گردونه — یعنی «یه نوعِ ملموسی که `Fn(i32) -> i32` رو پیاده‌سازی می‌کنه، اما من بهت نمی‌گم دقیقاً چه نوعیه». هر کلوژری نوعِ یکتا و تولیدشده‌توسط‌کامپایلرِ (compiler-generated) خودش رو داره، پس استفاده از `impl Trait` تو جایگاه مقدارِ بازگشتیِ تابع، تنها راهیه که باهاش می‌تونی اصلاً «یه کلوژر» رو برگردونی بدون اینکه بخوای اون نوعِ تولیدشده رو دستی بنویسی. کلمه‌ی کلیدی `move` کلوژر رو مجبور می‌کنه که مالکیتِ متغیر `n` رو (به جای قرض‌گرفتنش) کامل بگیره — و اینجا کاملاً هم لازمه، چون `n` یه متغیر محلی (local) هست که اگه این کار رو نمی‌کردیم بعد از تموم شدن اجرایِ `make_adder` از بین می‌رفت و پاک (drop) می‌شد، و کلوژر رو با یه ارجاع آویزون (dangling reference) رها می‌کرد.

اما یه نکته داره: دستور `impl Fn(i32) -> i32` فقط و فقط قولِ **یه نوعِ ملموسِ واحد (one single concrete type)** رو می‌ده — یعنی نمی‌تونی از یه شاخه‌یِ `if` کلوژرِ `move |x| x + n` رو برگردونی و از شاخه‌یِ `else` یه کلوژرِ *متفاوت* رو برگردونی، حتی با وجود اینکه جفتشون شرطِ `Fn(i32) -> i32` رو ارضا می‌کنن. هروقت به این انعطاف نیاز داشتی، باید اون نوعِ ملموس رو با استفاده از `Box<dyn Fn(i32) -> i32>` پاک کنی (type erasure)، که تو این حالت کلوژر رو پشتِ یه شئِ خصیصه (trait object) روی حافظه‌ی heap ذخیره می‌کنه. تو فاز ۲ ماژول ۵ (اشاره‌گرهای هوشمند) با `<Box<dyn Fn` و `<Box<dyn FnMut` بیشتر کار می‌کنی — فعلاً فقط در همین حد بشناستش که «این همون راهِ فراریه که وقتی `impl Trait` به خاطر متنوع بودن نوع ملموس کار نمی‌کنه، می‌تونی ازش استفاده کنی».
