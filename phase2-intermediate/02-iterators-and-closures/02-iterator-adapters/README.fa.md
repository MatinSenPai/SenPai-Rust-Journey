# ۰۲.۲ — آداپتورهای Iterator

این یکی از بزرگ‌ترین تغییر عادت‌های روزمره برای کسیه که از سمتِ پایتون میاد. جایی که تو پایتون سراغِ list comprehension می‌رفتی، راه و روش اصولیِ Rust رفتن به سراغ زنجیره‌ای از **آداپتورهای iterator** هستش.

## سه روش برای پیمایش (Iteration)، در ارتباط با مالکیت (فاز ۱، ماژول ۰۲)

```rust
let titles = vec!["Frieren".to_string(), "Mob Psycho".to_string()];

for t in titles.iter() {}      // t: &String  — تک‌تک عناصر رو قرض می‌گیره، `titles` بعد از این همچنان قابل استفاده‌ست
for t in titles.iter_mut() {}  // t: &mut String — به شکل تغییرپذیر قرض می‌گیره، نیاز داره که وکتور با `let mut titles` تعریف بشه
for t in titles.into_iter() {} // t: String  — کلاً `titles` رو مصرف می‌کنه؛ بعد از این حلقه دیگه وجود نداره
```

عبارتِ `for t in &titles` یه خلاصه‌نویسی برای `.iter()` هست، و `for t in titles` (بدونِ `&`) هم خلاصه‌نویسیِ `.into_iter()` ئه. این دقیقاً همون تمایز بین «قرض‌گرفتن» در مقابلِ «انتقال دادن (move)» از فاز ۱ هستش: به‌طور پیش‌فرض سراغ `.iter()` برو (چون تقریباً همیشه فقط می‌خوای به داده‌ها *نگاه کنی*)، و تنها زمانی از `.into_iter()` استفاده کن که واقعاً بخوای مالکیتِ تک‌تک عناصر رو بدی بره و دیگه هم کاری با کالکشن اصلی نداشته باشی.

## آداپتورها تَنبل (lazy) هستن — تا زمانی که مصرفشون نکنی هیچ اتفاقی نمی‌افته

```rust
let doubled = vec![1, 2, 3].iter().map(|n| n * 2); // تا اینجا هیچ اتفاقی نیفتاده
let doubled: Vec<i32> = doubled.collect();          // *حالا* عمل مپ (map) اجرا می‌شه
```

متدهای `.map()`، `.filter()`، `.enumerate()`، `.zip()`، `.take()`، `.skip()` و `.take_while()` همگی یه پیمایشگر (iterator) جدید برمی‌گردونن که به تنهایی هیچ کاری انجام نمی‌ده — اونا فقط یه خط لوله (pipeline) رو توصیف می‌کنن. فقط وقتی یه متدِ **مصرف‌کننده (consuming)** مثل `.collect()`، `.sum()`، `.fold()`، `.count()` یا `.for_each()` رو صدا می‌زنی، داده‌ها واقعاً کشیده می‌شن داخل خط لوله و کار انجام می‌شه. این یه تفاوت واقعی و معنادار با پایتونه:

```python
doubled = [n * 2 for n in [1, 2, 3]]  # بلافاصله و دقیقاً همینجا با ولع اجرا می‌شه
```

توی پایتون لیست‌کامپریهنشن (list comprehension) تو همون لحظه‌ای که می‌نویسیش اجرا می‌شه. اما زنجیره‌ی iteratorها تو Rust بیشتر شبیه یه *نقشه و برنامه* است که اول می‌چینیش — این یعنی می‌تونی با خیال راحت یه عالمه `.filter()` رو بعد از `.map()` و بعد از `.enumerate()` پشت‌سرهم زنجیر کنی، بدون اینکه Rust اصلاً واسه هر کدوم از این قدم‌ها بیاد الکی یه `Vec`ِ میانی (intermediate) بسازه؛ کلِ این خط لوله فقط بعد از اینکه مصرفش کردی، تازه اونم عنصر به عنصر تو یه گذرِ واحد (single pass) اجرا می‌شه.

## متد `.fold()` — ابزارِ همه‌کاره برای «رسیدن به یه مقدارِ واحد (reduce)»

```rust
let total = vec![1, 2, 3].iter().fold(0, |acc, n| acc + n); // 6
```

متدِ `(...)fold(initial, |accumulator, item|.` دقیقاً معادلِ نوشتن دستیِ یه حلقه‌ست:

```rust
let mut total = 0;
for n in vec![1, 2, 3].iter() {
    total = total + n;
}
```

متدِ `.sum()` در واقع همون `.fold(0, |acc, n| acc + n)` هست که فقط یه اسمِ دوستانه‌تر واسه این حالتِ خیلی رایج روش گذاشتن؛ هر زمان که نیاز داشتی همه‌ی آیتم‌ها رو با هم ترکیب کنی و به یه نتیجه برسی اما اون منطقِ ترکیب‌کردن صرفاً یه جمع/ضرب/شمارش ساده نبود، باید بری سراغ `.fold()`.

## متد `.collect()` باید بدونه چی قراره بسازه

متد `.collect()` رو میشه با هر نوعی که `FromIterator` رو پیاده‌سازی می‌کنه (generic over FromIterator) تطبیق داد — می‌تونه از رو یه iterator واحد، هم `Vec` بسازه، هم `HashMap`، هم `String` و خیلی چیزای دیگه. پس زبان Rust برای اینکه بدونه منظور تو کدومشه، نیاز داره نوعِ مقصد (type annotation) رو بدونه:

```rust
let v: Vec<i32> = (1..5).collect();          // نوع متغیر رو مشخص کن، یا...
let v = (1..5).collect::<Vec<i32>>();        // ...از سینتکس توربوفیش (turbofish) به شکل `<>..` استفاده کن
```

اگه هر دوتاش رو یادت بره، یه خطای کامپایل («type annotations needed») می‌گیری — این کاملاً عادیه و نشونه‌ی این نیست که جای دیگه‌ای مشکلی داره؛ فقط باید به Rust بگی که داری چی می‌سازی.

## حلقه (Loop) در برابر زنجیره (Chain)، کنار هم

اینجا تابعِ `total_episodes` (که تو `src/lib.rs` می‌بینیش) به دو روش نوشته شده تا این نکته روشن بشه که زنجیره‌ی iteratorها هیچ جادویی نداره — این دقیقاً همون حلقه‌ست که فقط به شکل تعریفی‌تری (declaratively) بیان شده:

```rust
// حلقه‌ی دستی با یه متغیر جمع‌کننده (accumulator)
fn total_episodes_loop(shows: &[(String, u32)]) -> u32 {
    let mut total = 0;
    for (_, episodes) in shows {
        total += episodes;
    }
    total
}

// زنجیره‌ی Iterator
fn total_episodes_iter(shows: &[(String, u32)]) -> u32 {
    shows.iter().map(|(_, episodes)| episodes).sum()
}
```

هر دو با انجام کارِ یکسان، نتیجه‌ی کاملاً یکسانی رو تولید می‌کنن. نسخه‌ی زنجیره‌ای فقط اون دوتا قدم رو اسم‌گذاری می‌کنه («هر سریال رو فقط به تعداد قسمت‌هاش نگاشت یا map کن»، «جمعشون بزن») به جای اینکه بخواد مراحل نگهداری رو دونه‌دونه بنویسه (مثلاً بگه: متغیر `total` رو تعریف کن، تغییرش بده، برش گردون) — وقتی خوندنِ آداپتورها برات راحت و روون بشه، روش زنجیره‌ای *منظورت* رو خیلی سریع‌تر از حلقه منتقل می‌کنه، بدون اینکه از میزانِ صریح بودنِ چیزی که داره اتفاق می‌افته کم کنه.
