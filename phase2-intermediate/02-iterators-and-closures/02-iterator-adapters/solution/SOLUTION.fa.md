# پاسخ تشریحی

```rust
pub fn first_n_completed<'a>(shows: &'a [(String, bool)], n: usize) -> Vec<&'a str> {
    shows
        .iter()
        .filter(|(_, done)| *done)
        .map(|(title, _)| title.as_str())
        .take(n)
        .collect()
}
```

ترتیب `.filter()` و سپس `.take(n)` مهم است و پاسخ پرسش پنجم را می‌دهد. `.take(n)` چیزی درباره‌ی «تکمیل‌شدن» نمی‌داند؛ فقط پس از عبور `n` عضو از مراحل پیش از خودش، pipeline را متوقف می‌کند.

اگر ابتدا `.take(n)` را اجرا کنیم—یعنی `shows.iter().take(n).filter(...)`—نخستین `n` عنوان **فهرست اصلی** را می‌گیریم، چه کامل باشند چه نباشند، و بعد فقط همان‌ها را filter می‌کنیم. حتی اگر کمی جلوتر عنوان کامل فراوان باشد، ممکن است خروجی کمتر از `n` عضو داشته باشد. وقتی `.filter()` اول باشد، فقط عنوان‌های کامل به `.take()` می‌رسند؛ پس عبارت دقیقاً «نخستین `n` عنوانی که از filter گذشته‌اند» معنا می‌دهد.

این نمونه تنبلی را هم خوب نشان می‌دهد: `.take(n)` به‌محض گرفتن `n` عضو کل زنجیره را کوتاه می‌کند و دیگر از `.filter()` نمی‌خواهد باقی عنوان‌ها را بررسی کند؛ برخلاف روش ساده‌ی پایتون که ممکن است ابتدا کل فهرست را filter و سپس slice کند.

```rust
pub fn total_episodes(shows: &[(String, u32)]) -> u32 {
    shows.iter().map(|(_, episodes)| episodes).sum()
}
```

closure در `.map(|(_, episodes)| episodes)` هر ارجاع به tuple از نوع `&(String, u32)` را destructure می‌کند، عنوان را کنار می‌گذارد و فقط ارجاع به تعداد قسمت‌ها را نگه می‌دارد. سپس `.sum()` همه را جمع می‌کند.

در پاسخ پرسش سوم، به‌محض اینکه مرحله‌ی ترکیب چیزی غیر از جمع ساده باشد سراغ `.fold()` برو: بیشینه‌ای با قاعده‌ی شکستن تساوی، چسباندن رشته‌ها با جداکننده‌ی سفارشی یا ساخت تدریجی یک struct. `.fold(initial, |acc, item| ...)` همه‌ی این‌ها را بیان می‌کند؛ `.sum()` فقط «جمع‌کردن» را.

پاسخ پرسش دوم: `vec![1, 2, 3].iter().map(|n| n * 2)` به‌تنهایی **هیچ ضربی انجام نمی‌دهد**. فقط یک مقدار iterator از نوع `Map` می‌سازد که هنوز اجرا نشده است. اگر آن را با `.collect()`، `.sum()` یا حلقه مصرف نکنی، ضرب هرگز رخ نمی‌دهد. معمولاً compiler یا clippy برای چنین iterator رهاشده‌ای هشدار `unused Map that must be used` می‌دهد، چون اغلب نشانه‌ی اشتباه است.

این تنبلی باعث می‌شود زنجیره‌ای طولانی از `.filter().map().enumerate()` به یک حلقه‌ی فشرده روی داده‌ی منبع تبدیل شود و در هر مرحله `Vec` میانی نسازد. پس این رفتار فقط شکل رابط نیست؛ تصمیمی واقعی برای کارایی است.
