# ایست بازرسی

۱. `long_titles` یک `&[String]` می‌گیرد و به‌جای `Vec<String>` مقدار `Vec<&str>` برمی‌گرداند. برای برگرداندن `Vec<String>` چه تغییری در پیاده‌سازی لازم بود؟ تفاوت عملی دو امضا در حافظه چیست؟

۲. بدون اجرای کد بگو `vec![1, 2, 3].iter().map(|n| n * 2)` به‌تنهایی و بدون `.collect()`، `.sum()` یا مصرف‌کننده‌ی دیگری چه می‌سازد. آیا عددی ضرب می‌شود؟ چرا iteratorهای Rust به‌جای اجرای eager مانند list comprehension پایتون این‌طور طراحی شده‌اند؟

۳. `total_episodes` را هم با `.sum()` و هم با `.fold(0, |acc, episodes| acc + episodes)` می‌شود نوشت. اینجا پاسخ هر دو یکی است. چه زمانی واقعاً مجبور می‌شوی از `.fold()` استفاده کنی چون `.sum()` از پس کار برنمی‌آید؟

۴. اگر روی iterator متد `.collect()` را بدون هیچ annotation نوع یا turbofish صدا بزنی، کامپایلر چه خطایی می‌دهد؟ چرا Rust نمی‌تواند حدس بزند «احتمالاً `Vec` می‌خواهی»؟

۵. `first_n_completed` ترکیبی از `.filter()` و `.take(n)` است. برای هدف «نخستین `n` عنوان تکمیل‌شده»، چرا `.take(n)` باید **پس از** `.filter()` بیاید؟
