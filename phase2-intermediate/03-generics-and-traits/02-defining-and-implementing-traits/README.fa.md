# ۰۳.۲ — تعریف و پیاده‌سازی traitها

درس ۰۱ از یه *محدودیت (bound)* (مثل `T: PartialOrd`) استفاده کرد — یعنی یه خصیصه (trait) که یه کس دیگه‌ای (یعنی کتابخونه‌ی استاندارد) از قبل تعریفش کرده بود و تو فقط بهش تکیه کردی. اما این درس در مورد اینه که چطوری traitِ **خودت** رو بنویسی: یه قرارداد که خودت طراحیش می‌کنی و ساختارهایی (structs) که می‌نویسی (یا مال هر کس دیگه‌ای) می‌تونن قول بدن که بهش عمل می‌کنن.

## تعریف (Declare) کردن یک trait

```rust
pub trait Summarize {
    fn title(&self) -> String;

    fn summary(&self) -> String {
        format!("{} (no summary available)", self.title())
    }
}
```

یه trait در واقع یه مجموعه از *امضاهایِ* توابع (method signatures) هستش. اینجا `title` هیچ بدنه‌ای نداره — در نتیجه هر نوعی (type) که قرار باشه `Summarize` رو پیاده‌سازی کنه **مجبوره** که `title` مخصوص خودش رو فراهم کنه. اما از طرف دیگه، `summary` واسه خودش بدنه داره: به این می‌گن یه **پیاده‌سازی پیش‌فرض (default implementation)**. هر کسی که این trait رو پیاده‌سازی می‌کنه، `summary` رو دقیقاً همون‌طوری که نوشته شده و کاملاً رایگان دریافت می‌کنه، مگه اینکه خودش تصمیم بگیره اونو با نسخه‌ی مخصوص خودش بازنویسی (override) کنه.

نکته‌ی جالب اینه که بدنه‌ی پیش‌فرضِ `summary` داره `()self.title` رو صدا می‌زنه — یعنی متدی رو فراخوانی می‌کنه که تو اون نقطه‌ای که trait داره *تعریف* می‌شه، اصلاً هنوز وجود خارجی نداره. این کد کامپایل می‌شه چون خودِ این trait تضمین می‌کنه که هر پیاده‌کننده‌ای (implementor) حتماً باید یه `title` از خودش ارائه بده؛ بنابراین کامپایلر برای اینکه بدونه این فراخوانی ایمنه نیازی نداره نوعِ ملموس و واقعی رو بشناسه، همین که بدونه هر نوعی که قراره اینجا قرار بگیره این trait رو ارضا می‌کنه، براش کافیه.

## پیاده‌سازی کردنِ اون (Implementing)

```rust
pub struct AnimeSeries {
    pub title: String,
    pub episodes: u32,
}

impl Summarize for AnimeSeries {
    fn title(&self) -> String {
        self.title.clone()
    }

    fn summary(&self) -> String {
        format!("{} — {} episodes", self.title, self.episodes)
    }
}
```

ساختارِ `AnimeSeries` هم `title` رو (که اجباری بود) فراهم می‌کنه و هم `summary` مخصوص خودش رو (که روی حالت پیش‌فرض override شده). یه struct دیگه می‌تونه فقط `title` رو پیاده‌سازی کنه و `summary` رو دقیقاً همون‌طوری که بود و بدون هیچ تغییری به ارث ببره (inherit کنه) — کاری که تو با `MangaVolume` تو تمرین‌های همین درس قراره انجام بدی دقیقاً همینه.

## مقایسه با پایتون

نزدیک‌ترین چیزی که احتمالاً تو پایتون ازش استفاده کردی، یا یه کلاس **ABC** (همون `abc.ABC` + دکوراتور `abstractmethod@`) بوده و یا یه `Protocol`، که شایدم در کنارش از یه **mixin** کمک گرفته باشی:

```python
class Summarize(ABC):
    @abstractmethod
    def title(self) -> str: ...

    def summary(self) -> str:
        return f"{self.title()} (no summary available)"
```

ایده دقیقاً همونه — تو اینجا `title` یه متد انتزاعی یا abstract هستش (باید override بشه)، و `summary` یه متدِ mixin محسوب می‌شه که یه بدنه‌ی پیش‌فرض داره و میاد همون متد انتزاعی رو صدا می‌زنه. تفاوت اصلی تو اینه که این بررسی *چه زمانی* انجام می‌شه. پایتون فقط زمانی متوجه می‌شه که تو متد `title` رو override نکردی که برای اولین بار سعی کنی از اون کلاس یه نمونه (instance) بسازی (یا اگه از یه `Protocol`ِ ساده استفاده کنی، ممکنه اصلاً هیچ‌وقت هم نفهمه — پایتون تا زمانی که کدت دقیقاً نرسه به همون خطی که اون متدِ ناموجود رو صدا می‌زنه و برنامه متلاشی بشه، جلوی پاس دادنِ شیئی که اون متد رو نداره نمی‌گیره). اما کامپایلر Rust تک‌تک بلاک‌هایِ `impl Summarize for X` رو تو زمان کامپایل (compile time) چک می‌کنه: اگه تو نوعِ `X` متدِ `title` وجود نداشته باشه، همون لحظه و قبل از اینکه هیچ کدی اجرا بشه عملیاتِ `cargo build` با شکست مواجه می‌شه و تازه اسم دقیق متدی رو هم که جا انداختی بهت می‌گه.
