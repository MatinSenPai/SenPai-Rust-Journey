# پاسخ تشریحی

```rust
pub fn largest<T: PartialOrd + Copy>(items: &[T]) -> Option<T> {
    let mut max = *items.first()?;
    for &item in items {
        if item > max {
            max = item;
        }
    }
    Some(max)
}
```

متد `items.first()` مقدار `Option<&T>` می‌دهد؛ اگر عضوی باشد ارجاع به نخستین عضو. عملگر `?` برای slice خالی فوراً `None` را از `largest` برمی‌گرداند و در غیر این صورت نتیجه را به `&T` باز می‌کند.

علامت `*` آن ارجاع را به `T` dereference می‌کند و این دقیقاً جایی است که `Copy` لازم می‌شود. گرفتن یک نسخه‌ی دارای مالکیت از پشت ارجاع مشترک فقط وقتی مجاز است که کامپایلر بداند مقدار با کپی بیتی ارزان تکثیر می‌شود؛ نه تخصیص heap دارد و نه cleanup سفارشی که دو بار اجرا شود. بدون `Copy`، عبارت `*items.first()?` می‌کوشد `T` را از خانه‌ای داخل `items` move کند. این کار ممنوع است، چون تو مالک آن خانه نیستی و فقط ارجاع مشترک داری؛ moveکردن از پشت آن ارجاع در مجموعه حفره‌ای بی‌مالک می‌گذاشت. این پاسخ پرسش اول است.

حلقه‌ی `for &item in items` هم از همان الگوی مبتنی بر `Copy` استفاده می‌کند. پیمایش `&[T]` در هر مرحله `&T` می‌دهد و pattern به‌شکل `&item` بی‌درنگ مقدار را به `item` دارای مالکیت کپی می‌کند تا بدنه با `>` مستقیم مقایسه کند.

پاسخ پرسش دوم **دو نسخه** است. وقتی `cargo build` استفاده‌ی واقعی از `Stack<i32>` و `Stack<String>` را می‌بیند، فرایند monomorphization برای هر متد `Stack<T>` دو نسخه‌ی مستقل می‌سازد: یکی با `T = i32` و دیگری با `T = String`؛ انگار `StackI32` و `StackString` را دستی نوشته باشی. اگر نوع concrete سومی در جای دیگری استفاده شود، نسخه‌ی سوم هم تولید می‌شود.

این گسترش فقط هنگام compile رخ می‌دهد. به همین دلیل در runtime برای `.push()` یا `.pop()` هزینه‌ی بررسی نوع نداریم؛ آن موقع `Stack<i32>::push` یک تابع معمولی و کاملاً concrete است.
