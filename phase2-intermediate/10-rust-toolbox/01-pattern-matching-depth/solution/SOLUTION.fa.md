# راه‌حل

```rust
pub fn describe_status(status: u16) -> String {
    match status {
        200 => "OK".to_string(),
        n @ 200..=299 => format!("success ({n})"),
        301 | 302 | 307 | 308 => "redirect".to_string(),
        n @ 400..=499 => format!("client error ({n})"),
        n @ 500..=599 => format!("server error ({n})"),
        other => format!("unrecognized status {other}"),
    }
}
```

دو چیز این‌جا بارِ اصلی را می‌کشند. اول، **ترتیبِ بازوها**: `200` و `200..=299` هم‌پوشانی دارند، و بازوها از بالا به پایین امتحان می‌شوند، پس آن عددِ دقیق باید بالاتر بنشیند — جایشان را عوض کن و `describe_status(200)` می‌شود `"success (200)"`، و تستِ اول fail می‌کند. کامپایلر سرِ این هم‌پوشانی چیزی نمی‌گوید (هر دو بازو هنوز قابلِ رسیدن‌اند)، پس مدیریتش پایِ خودِ توست. دوم، اتصال با `@`: تنها `400..=499 => ...` تطبیق می‌دهد ولی خودِ کد را گم می‌کند، و یک `n => ...` ساده کد را نگه می‌دارد ولی با همه‌چیز مچ می‌شود. `n @ 400..=499` تنها راهی است که هم «تویِ این بازه» را می‌گیرد هم «این هم مقدارِ واقعی‌اش» را، از یک الگو.

```rust
LogEvent::Message { severity: Severity::Error, text } => Some(format!("error: {text}")),
LogEvent::Message { severity: Severity::Warning, text } if text.contains("disk") => ...
```

در `noteworthy`، بازویِ `Error` **هیچ نگهبانی لازم ندارد** — «severity برابرِ Error است» یک شرطِ ساختاری است، پس جایش تویِ خودِ الگوست (`severity: Severity::Error` یک زیرالگوست، نه یک مقایسه). بازویِ `Warning` به هر دو نیاز دارد: بخشِ ساختاری تویِ الگو، و `text.contains("disk")` — که هیچ الگویی نمی‌تواند بیانش کند — به‌عنوانِ نگهبان. مرزی که باید تویِ ذهنت بماند همین است: شکل‌ها می‌روند تویِ الگو، شرط‌هایِ دلبخواه می‌روند تویِ نگهبان. توجه کن به `if *status >= 500` هم: چون داریم یک `&LogEvent` را تطبیق می‌دهیم، `status` یک `&u16` است، پس مقایسه‌اش با یک لیترال نشان‌زدایی لازم دارد. بازویِ آخر، `_ => None`، اجباری است، حتی با اینکه نگهبان‌ها «واضح» همه‌چیز را پوشش می‌دهند — نگهبان‌ها در جامع بودن حساب نمی‌شوند، پس بدونِ یک بازویِ بی‌نگهبان این `match` اصلاً کامپایل نمی‌شد.

```rust
pub fn method_of(event: &LogEvent) -> Option<&str> {
    match event {
        LogEvent::Request { method, .. } => Some(method.as_str()),
        _ => None,
    }
}
```

کلِ نکته‌ی این تابع یک نوع است: `method` از جنسِ `&String` است، نه `String`، چون تطبیق از پشتِ یک ارجاع، خودکار با ارجاع بایند می‌کند — یک حالتِ اتصالِ پیش‌فرض. اگر با مقدار بایند می‌شد، بازو مجبور بود `method` را از دلِ چیزی که فقط قرض گرفته‌ایم بیرون بکشد — خطایِ کامپایل. `Some(method)` به‌تنهایی `Option<&String>` می‌داد، پس `.as_str()` پلی می‌زند به همان `&str`ی که امضای تابع قول داده.

```rust
match samples {
    [] => "no samples".to_string(),
    [only] => format!("1 sample: {only}ms"),
    [first, .., last] => format!("{} samples, first {first}ms, last {last}ms", samples.len()),
}
```

الگوهایِ برش بر اساسِ **طول** جامع بودنشان چک می‌شود: `[]` طولِ ۰ را می‌پوشاند، `[only]` طولِ ۱ را، `[first, .., last]` طولِ ۲ و بیشتر را. بازویِ `[only]` را پاک کن، کامپایلر می‌گوید `&[_]` پوشش داده نشده — یک زنجیره‌یِ `if`/`else` با `.len()` و ایندکس همین شکاف را دارد و بی‌سروصدا کامپایل می‌شود، فقط تو زمانِ اجرا پنیک می‌کند یا عددِ غلط می‌دهد.

```rust
pub fn middle_samples(samples: &[u64]) -> &[u64] {
    match samples {
        [_, rest @ .., _] => rest,
        _ => &[],
    }
}
```

`[_, rest @ .., _]` حداقل دو عضو می‌خواهد — یکی برایِ هر `_` — پس برشی با طولِ ۰ یا ۱ اصلاً به این بازو نمی‌رسد و بازویِ `_` یک برشِ خالی می‌دهد. برایِ دقیقاً دو عضو هم `rest` باز یک برشِ خالی می‌شود (چیزی بینِ دو عضوِ کناره‌هم نیست) — به همین دلیل `middle_samples(&[7, 3])` هم `&[]` است، نه پنیک و نه یک حالتِ خاص که با دست بنویسی.

```rust
pub fn first_alert(events: &[LogEvent]) -> Option<String> {
    match events {
        [LogEvent::Request { status, path, .. }, ..] if *status >= 500 => {
            Some(format!("first event: server error {status} on {path}"))
        }
        _ => None,
    }
}
```

یک بازو سه کار را هم‌زمان انجام می‌دهد: شکلِ بیرونی، `[..., ..]`، می‌گوید «فقط اولین عضو مهم است، بقیه هرچه باشند»؛ `LogEvent::Request { status, path, .. }` تودرتویش، همان اولین عضو را — درست همان لحظه که فهمید `Request` است — استخراج می‌کند؛ و نگهبان، `if *status >= 500`، رویِ چیزی فیلتر می‌زند که هیچ الگویی نمی‌تواند بیانش کند. اگر با `events.first()` و بعد یک `match` جدا رویِ `Option<&LogEvent>`ی که برمی‌گرداند می‌رفتی، برایِ گفتنِ همین یک چیز به دو تا `match` نیاز داشتی (یکی پنهان تویِ `Option`ِ خودِ `first()`، یکی صریح) — الگویِ برش همه‌اش را یک‌بار می‌گوید.
