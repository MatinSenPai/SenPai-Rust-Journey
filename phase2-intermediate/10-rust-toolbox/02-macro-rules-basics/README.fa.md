# ۰۸.۲ — مبانیِ `!macro_rules`

از همون اولین باری که از `!println` استفاده کردی، تو داشتی ماکروها رو *صدا می‌زدی* — اون علامتِ `!` نشونه و پرچمِ ماکروهاست. این درس در مورد اینه که چطوری با استفاده از `!macro_rules` که سیستمِ ماکرونویسیِ **اعلامی (declarative)** تو زبان Rust هست، ماکروی خودت رو بنویسی (ماکروهای رویه‌ای (procedural) مثل `#[derive(Serialize)]` یه مکانیزمِ کاملاً متفاوت و سنگین‌تر هستن — که تو زودترین حالت مال فاز ۳ به بعدن).

تو زبان پایتون هیچ معادل واقعی و دقیقی برای این مفهوم نداریم. دکوراتورها (Decorators) و متاکلاس‌ها میان *اشیا رو تو زمان اجرا (runtime)* تغییر میدن؛ اما یه ماکرو میاد *کد منبع (source code) رو تو زمان کامپایل* تغییر میده — ماکرو همون توکن‌ها (کلمات و علائم) که تو نوشتی رو می‌گیره و قبل از اینکه کامپایلر اصلی اصلاً چشمش به کدت بیفته، اونا رو بسط و گسترش میده (expand می‌کنه) و تبدیل می‌کنه به کدهای جدید. دلیل اینکه چرا Rust به این ویژگی نیاز داره اما پایتون نه، اینه: توابع پایتون می‌تونن `args*` رو دریافت کنن و نوعِ ورودیشون هم هر چیزی می‌تونه باشه، پس تابعی مثل `max(a, b, c)` خیلی ساده فقط یه تابعه. اما توابعِ زبان Rust دارای تعداد ورودی ثابت (arity) و نوعِ ورودی ثابت هستن، پس هر چیزی که تعداد ورودی‌هاش متغیر باشه (variadic) — مثل `!println`، `!vec` و `!format` — *مجبوره* که به شکل ماکرو پیاده بشه.

## تطبیق‌دهنده (Matcher) و نسخه‌نویس (transcriber)

تعریف یه `!macro_rules` شامل یه لیست از بازوها (arms) می‌شه، که هر کدوم به شکلِ `} transcriber { => (matcher)` هستن. تطبیق‌دهنده یا همون matcher در واقع یه الگو (pattern) برای تست کردنِ *توکن‌هاست* (دقیقاً مثل `match`، منتها برای کدِ منبع)؛ و نسخه‌نویس یا همون transcriber یه قالب (template) هست که توکن‌های اسیرشده توش جاگذاری (paste) می‌شن:

```rust
macro_rules! square {
    ($x:expr) => {
        $x * $x // حواست باشه — بخش "فقط یک‌بار اجرا کن" تو پایین رو بخون
    };
}
```

عبارتِ `x:expr$` یه **مشخص‌کننده‌ی قطعه (fragment specifier)** است: یعنی یه *عبارت (expression)* کامل رو بگیر و اسیر کن و اسمشو بذار `x$`. قطعه‌هایی که تو تو دنیای واقعی استفاده می‌کنی اینان: `expr` (برای عبارت)، `ident` (برای یه نام — کاربردش تو تولید متغیرها یا توابع جدید)، `ty` (برای یه نوع یا type)، `pat` (برای یه الگو یا pattern)، `literal`، و `tt` (یه درخت از توکن‌های خام (token tree) — که راه فرارته). یه `expr`ی که اسیر می‌شه، موقع بسط داده شدن (expansion) حالتِ یکپارچه و اتمی داره: دستورِ `square!(1 + 2)` از لحاظ مفهومی به جای اینکه بشه `2 + 1 * 2 + 1`، به `(2 + 1) * (2 + 1)` بسط پیدا می‌کنه — یعنی مقدار اسیرشده گروه‌بندیِ خودش رو حفظ می‌کنه. اما به این دقت کن که حالا عبارت `1 + 2` رو **دو بار** ارزیابی و محاسبه (evaluate) می‌کنه — برای کارهای واقعی بهتره اول اونو تو یه متغیر ذخیره کنی: `{ let x = $x; x * x }`. تستی که برای `!timed` تو پایین نوشته شده، دقیقاً همین مشکل رو چک می‌کنه.

## تکرار (Repetition)

عبارت `*, ( ... )$` با یه چیزی که با کاما جدا شده باشه، صفر یا چند بار تطبیق پیدا می‌کنه (اگه از `+` استفاده کنی یعنی یک‌یا‌چند بار، و اگه از `?` استفاده کنی یعنی صفر‌یا‌یک بار). دقیقاً از همین سینتکس استفاده می‌کنی تا مقادیر اسیرشده رو داخل transcriber دوباره بازپخش (replay) کنی:

```rust
macro_rules! string_vec {
    ( $( $s:expr ),* $(,)? ) => {{
        let mut v = Vec::new();
        $( v.push($s.to_string()); )*
        v
    }};
}
```

اون `?(,)$` که آخرِ الگو اومده یه مدل احترام‌گذاشتنِ رایج تو زبان Rustئه — این تیکه میگه که وجود یه کامایِ انتهایی (trailing comma) اختیاریه، دقیقاً همون‌طوری که تمام ماکروهای توکار (builtin) این کار رو می‌کنن. بازوهای مختلف از بالا به پایین چک می‌شن (اولین تطبیق‌دهنده‌ای که با شرایط جور در بیاد برنده است)، و هر بازو می‌تونه خودِ ماکرو رو به صورت بازگشتی (recursively) صدا بزنه — دقیقاً با همین روشه که ماکروی `!max_of` (تو مثال پایین) N تا آرگومان رو می‌گیره و اونا رو تقلیل می‌ده به زنجیره‌ای از فراخوانی‌هایِ ۲تایی از تابع `std::cmp::max`، و یه بازوی تک‌ورودی رو هم به عنوان نقطه‌ی پایانِ (base case) بازگشت در نظر می‌گیره.

## بهداشتِ ماکروها (Hygiene)، به طور خلاصه

اسامی و متغیرهایی که *داخل* یه ماکرو تولید می‌شن، فقط تو اسکوپِ مخصوص به خودشون زندگی می‌کنن: مثلاً اگه transcriberِ ماکرویِ `!timed` بیاد خطِ `;()let start = Instant::now` رو تولید کنه، و اون کسی که داره ماکرو رو صدا می‌زنه (caller) از قبل تو همونجا یه متغیر به اسم `start` داشته باشه، این دو تا هیچ تداخلی با هم پیدا نمی‌کنن — از نظر کامپایلر، متغیرِ `start`ِ داخل ماکرو با متغیرِ `start`ِ فراخواننده دو تا اسمِ کاملاً متفاوتن. به این ویژگی **بهداشت (hygiene)** می‌گن، و این همون دلیلیه که چرا ماکروهای Rust برخلاف `#define`های کلاسیک تو C که کلاً فاجعه به بار می‌آوردن، اونقدر امنن. اما اون روی سکه اینه که: یه ماکرو *نمی‌تونه* یواشکی یه متغیر جدید تعریف کنه که بعداً فراخواننده (caller) بتونه ازش استفاده کنه — که البته این محدودیت خودش یه قابلیت و مزیت محسوب می‌شه.

## کی *نباید* ماکرو بنویسی (یه راهنماییِ صادقانه)

استفاده از ماکرو باید **آخرین** گزینه‌ات باشه. یه تابع معمولی همون‌طوری که نوشته شده چک می‌شه، تو پیام‌های خطا نوع‌های واقعی (real types) رو نشون می‌ده، و ابزارهایی مثل rust-analyzer به طور کامل پشتیبانیش می‌کنن؛ اما یه ماکرو موقع بسط داده شدن (expansion) چک می‌شه، خطاهایی تولید می‌کنه که دارن به کدهایی اشاره می‌کنن که تو ننوشتی (generated code)، و امکانات تکمیل خودکار (autocomplete) داخلِ بدنه ماکرو هم کلاً یه چیز داغونیه. اگه فقط مشکلت «همون منطقِ تکراری برای نوع‌های مختلفه»، Genericها خیلی راحت اون رو پوشش می‌دن. موارد منطقی و مجازِ استفاده از ماکرو خیلی محدود و باریکن: داشتنِ ورودی‌های متغیر (مثل `!max_of`)، استفاده از سینتکسی که یه تابع معمولی اصلاً نمی‌تونه قبولش کنه (مثلاً `"k" => "v"` یه عبارتِ (expression) معتبر نیست، پس `!string_map` *مجبوره* ماکرو باشه)، پیچیدنِ یه بخش کُدِ قبل‌وبعد به دور یه عبارت بدونِ اینکه مجبور باشی اونو تو یه کلوژر قرار بدی (مثل `!timed`)، و در نهایت تولید کدهای به‌شدت تکراری و الگووار. اگه مشکل تو با نوشتن یه `fn` ساده حل می‌شه و کامپایل هم می‌شه، بدون که نوشتن نسخه‌ی ماکروی اون کلاً یه کار اشتباه و بدتره. والسلام.

## وظیفه‌ی تو — و اینکه این فایل اسکلتِ تمرین چطوری کار می‌کنه

تو ماکروها نمی‌شه مثل بدنه‌ی توابع از `todo!()` استفاده کرد (بدنه‌ی ماکرو فقط یه مشت توکنه؛ این توکن‌ها فقط زمانی تبدیل به کُد می‌شن که یه جایی *استفاده* بشن — یعنی تو تست‌ها). پس فعلاً هرکدوم از نسخه‌نویس‌ها (transcribers) قراره بسط پیدا کنن به فراخوانیِ تابع `(...)unsolved`، که این تابع یه تابعِ کمکیه و فقط پنیک (panic) می‌کنه: واسه همینه که کُدت در حالتِ عادی با موفقیت **بیلد (build)** می‌شه، اما وقتی `cargo test` رو می‌زنی **fail می‌شه** تا زمانی که اون کدهای موقت (placeholder) رو پاک کنی و یه transcriberِ واقعی جاشون بذاری. همینطور که پیش می‌ری اون فراخوانی‌های `unsolved` رو پاک کن؛ وقتی کار هر سه تا ماکرو تموم بشه، دیگه کلاً هیچ‌چیزی تو کدت اون رو صدا نمی‌زنه.

- ماکروی `... ,"string_map! { "k" => "v` — یه `<HashMap<String, String>` می‌سازه. نیاز به استفاده از تکرار (Repetition) و استفاده از توکنِ `=>` تو matcher داره.
- ماکروی `max_of!(a, b, c, ...)` — یه maxِ متغیر (variadic) که از طریق بازگشت (recursion) و استفاده از `std::cmp::max` کار می‌کنه.
- ماکروی `timed!(expr)` — عبارت `expr` رو دقیقاً **یک بار** ارزیابی و محاسبه می‌کنه، و در نهایت خروجیِ توپلِ `(result, elapsed)` رو برمی‌گردونه.
