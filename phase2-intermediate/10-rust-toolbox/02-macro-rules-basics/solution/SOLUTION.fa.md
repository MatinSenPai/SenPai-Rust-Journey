# راه‌حل

```rust
#[macro_export]
macro_rules! string_map {
    () => {
        ::std::collections::HashMap::new()
    };
    ( $( $key:expr => $value:expr ),+ $(,)? ) => {{
        let mut map = ::std::collections::HashMap::new();
        $( map.insert($key.to_string(), $value.to_string()); )+
        map
    }};
}
```

اصلاً چرا دو تا بازو؟ نوشتنِ یه دونه بازو به شکلِ `*, ( ... )$` خودش حالت خالی (empty case) رو هم پوشش می‌ده — اما اگه این کار رو می‌کردی، اونوقت کدِ بسط داده شده تو حالتِ خالی تبدیل می‌شد به `let mut map = ...; map`، و داشتنِ `mut` روی متغیری که تو ادامه‌ی کد هیچ‌جوره تغییر پیدا نمی‌کنه، خودش یه اخطار (warning) تو Rustئه. جدا کردنِ بازوی مربوط به حالت خالی (base case)، باعث می‌شه هر دو خروجی کاملاً بدون اخطار و تمیز دربیان. بازویی که وظیفه‌ی پردازشِ جفت‌ها رو داره، دو تا الگوی (idiom) خیلی مهم رو نشون می‌ده که تا ابد تو ماکرونویسی به دردت می‌خورن: استفاده از دو تا آکولادِ تودرتو `} ... {{` (آکولادِ بیرونی بدنه و بازویِ ماکرو رو می‌بنده، و آکولادِ درونی نقشِ یه عبارت بلوکی (block expression) رو بازی می‌کنه تا کدِ بسط‌یافته هم بتونه تو خودش دستورات مختلف (statements) داشته باشه *و هم* تو خروجی مقدار (value) برگردونه)، و استفاده از `+ ( ... )$` تو قسمتِ نسخه‌نویس (transcriber) که میاد دقیقاً همون چیزی رو که بخش تطبیق‌دهنده (matcher) اسیر کرده بود دوباره پخش می‌کنه و تکرارش می‌کنه. ضمناً به علامتِ `=>` تو بخشِ matcher دقت کن: همون یک دونه توکنِ ناقابل دقیقاً همون دلیلیه که باعث می‌شه نتونیم این کد رو تو قالب یه تابع دربیاریم — عبارت `"k" => "v"` اصلاً یه عبارتِ (expression) مجاز و معتبر تو زبان Rust نیست، در نتیجه فقط یه ماکروئه که می‌تونه این سینتکس عجیب و غریب رو بپذیره. مسیرهای مربوط به ساختارها هم با استفاده از `::std::collections::HashMap` نوشته شدن (مسیر کامل، با `::` که میاد همون اولش) تا این ماکرو بتونه با خیال راحت کارشو بکنه حتی اگه فراخواننده‌ی اون، `HashMap` رو تو فایل خودش وارد (import) نکرده باشه — فراموش نکن که یه ماکرو همیشه *تو همون محلِ فراخوانی‌اش (call site)* بسط داده می‌شه و در نتیجه فقط و فقط importهای همون محل رو می‌بینه، نه importهایی که تو فایلِ تعریفِ ماکرو بودن.

```rust
#[macro_export]
macro_rules! max_of {
    ( $only:expr ) => { $only };
    ( $first:expr, $( $rest:expr ),+ $(,)? ) => {
        ::std::cmp::max($first, $crate::max_of!( $( $rest ),+ ))
    };
}
```

این دقیقاً یه ساختار بازگشتی (recursive) کلاسیکه. عبارتِ `max_of!(3, 9, 7)` اول از همه میاد با بازویِ دوم مچ می‌شه، در نتیجه `first = 3$` و `rest = 9, 7$` رو می‌سازه، و این تبدیل می‌شه به کدِ `(max(3, max_of!(9, 7`؛ یه دور دیگه بازگشت، اینو تبدیل می‌کنه به `((max(3, max(9, max_of!(7`؛ حالا این تک‌عبارتیِ باقیمونده میره با *اولین* بازو مچ می‌شه (بازوها از بالا به پایین چک می‌شن) و بالاخره بازگشت به تهش می‌رسه (bottoms out) و خروجی نهایی می‌شه `max(3, max(9, 7))`. حالا اگه بیای اون بازویِ پایانی (base case) رو پاک کنی، اونوقت بازگشت دیگه هیچ‌جایی رو نداره که بخواد روش متوقف شه — کامپایلر هم برای جلوگیری از حلقه‌ی بی‌نهایت (loop forever)، اونو با خطای "recursion limit reached" درجا می‌کشه. عبارتِ `!crate::max_of$` یه جزئیات خیلی ظریفه که تا حدودی همسایه‌ی همون بحث بهداشت (hygiene) ماکروهاست: کلمه‌ی کلیدیِ `crate$` همیشه اشاره می‌کنه به همون کریتی که ماکرو توش *تعریف شده*، پس فراخوانیِ بازگشتی به راحتی مسیر درست رو پیدا می‌کنه و جواب می‌ده حتی اگه یه کریتِ کاملاً غریبه بیاد و این ماکرو رو بدون اینکه با اسمِ دقیقِ `max_of` وارد (import) کرده باشه، صدا بزنه.

```rust
#[macro_export]
macro_rules! timed {
    ( $work:expr ) => {{
        let start = ::std::time::Instant::now();
        let result = $work;
        (result, start.elapsed())
    }};
}
```

دو تا جزئیات خیلی مهم و تعمدی تو این کد وجود داره. اولاً، استفاده از خطِ `;let result = $work` باعث می‌شه که اون عبارتی که فراخواننده به ماکرو پاس داده، دقیقاً و فقط **یک بار** (once) تو کُد جاگذاری (paste) بشه — یه راهِ میانبرِ خیلی وسوسه‌کننده این بود که مستقیماً بنویسیم `(()work, start.elapsed$)`، که خب اینم دقیقاً یک‌بار اجراش می‌کنه، اما اگه یه مدلی رو طراحی می‌کردی که `work$` دو بار توش جاگذاری بشه (مثلاً یه بار بخواد لاگش کنه و بار دوم برگردوندش)، اونوقت تمام آثار جانبی (side effects) کدهای کاربر، دو بار و دوباره اجرا می‌شدن؛ تستی هم که واسه شمارنده نوشتیم (همون تستی که تو بلوکش `1 =+ calls` نوشته بود) دقیقاً و مشخصاً برای گرفتن مچِ همین دسته از باگ‌ها اونجاست. دوماً، بهداشتِ (hygiene) ماکروها رو تو عمل می‌تونی اینجا ببینی: متغیرِ `start` که تو بخشِ نسخه‌نویس (transcriber) ماکرو ساخته می‌شه، به هیچ‌وجه نمی‌تونه با متغیری به همین اسم یعنی `start` که سمتِ کاربرِ فراخواننده تعریف شده تداخل یا کلاژن (collide) داشته باشه — یعنی اگه کاربر بنویسه `timed!(start + 1)` در حالی که متغیرِ `start` رو بیرون از ماکرو به عنوان یه عدد صحیح تعریف کرده باشه، همه چی عالی کار می‌کنه، چون اون متغیر `start` که داخل خود ماکروست از زاویه‌ی دید کامپایلر کلاً یه اسم دیگه‌ست و ربطی به این نداره. این دقیقاً همون تضمین و گارانتی‌ایه که `#define` تو زبان C هیچ‌وقت تو خوابش هم نمی‌دید.

و به عنوان یه نکته‌ی صادقانه‌ی پایانی: بینِ این سه تا، فقط `!string_map` و `!max_of` بودن که *مجبور بودن* و واقعاً نیاز داشتن که ماکرو باشن (به خاطر سینتکس عجیب‌وغریب و ورودی‌های متغیر (variadic)). ماکروی `!timed` رو خیلی راحت می‌شد به صورتِ یه تابعِ معمولی مثلِ `fn timed<T>(f: impl FnOnce() -> T) -> (T, Duration)` نوشت که تو محل فراخوانی یه کلوژر بگیره — یعنی `((timed(|| work`. نوشتنِ نسخه‌ی ماکرو، فقط باعث شد محل فراخوانی یه کوچولو خوشگل‌تر (nicer) به نظر بیاد اما در ازاش تمامِ اون چیزایی رو که تو فایلِ README بابتشون هشدار دادیم به جون خرید. تو پروژه‌های واقعی، صددرصد به همون تابع وفادار بمون؛ دلیل اینکه اینجا با یه ماکرو پیاده‌سازیش کردیم فقط این بود که بهت الگویِ «پیچوندن و کاور کردنِ کدهایِ قبل‌وبعد به دور یه عبارتِ دلخواه (wrap-an-expression pattern)» رو یاد بده، الگویی که خیلی زود تو کریت‌هایی مثلِ `tracing` قراره نمونه‌اش رو تشخیص بدی.
