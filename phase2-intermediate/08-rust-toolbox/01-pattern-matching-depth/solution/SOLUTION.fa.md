# پاسخ تشریحی

guard بخشی از proof exhaustiveness نیست، چون عبارت دلخواه runtime است. حتی دو guard ظاهراً مکمل به شاخه‌ی `_` نیاز دارند. `@` اجازه می‌دهد مقدار کامل range را برای بدنه نگه داری؛ بدون آن یا range را match می‌کنی و مقدار را نداری، یا binding عمومی می‌گیری و شرط را در guard تکرار می‌کنی.

در or-pattern، هر گزینه باید دقیقاً همان bindingها را با نوع یکسان بسازد تا بدنه مستقل از گزینه‌ی matchشده بتواند از آن‌ها استفاده کند. match ergonomics نیز هنگام ورودی reference، bindingهای تو‌در‌تو را borrow می‌کند و مانع move از پشت `&T` می‌شود.

برای slice، سه حالت ریاضی داریم: طول صفر، طول یک و طول دست‌کم دو. `[first, .., last]` حالت سوم را کامل می‌پوشاند. حذف `[only]` خطای non-exhaustive pattern می‌دهد؛ زنجیره‌ی `if` چنین بررسی کامپایلری ندارد.
