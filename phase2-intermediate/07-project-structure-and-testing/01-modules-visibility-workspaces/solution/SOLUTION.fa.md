# راه‌حل

## `Anime::public_rating_band` — یک خواننده‌ی عمومی رویِ یک فیلدِ خصوصی

```rust
pub fn public_rating_band(&self) -> &'static str {
    match self.internal_rating {
        0..=3 => "low",
        4..=7 => "medium",
        _ => "high",
    }
}
```

سه بازو رویِ یک `u8` که از قبل، سرِ ساختنش، به بازه‌یِ `0..=10` محدود شده:
`0..=3`، `4..=7`، و یک بازویِ همه‌گیرِ `_` برایِ `8..=10`. کامپایلر اصلاً
اجازه نمی‌دهد یک `match` رویِ نوعِ عددی نوشته شود مگر صددرصدِ حالت‌های
ممکنش پوشش داده شده باشد — دقیقاً همین است که باعث می‌شود بازوی آخر به‌جایِ
نوشتنِ صریحِ `8..=10`، فقط یک `_` باشد؛ هردو کار می‌کنند، `_` فقط کوتاه‌تر
است وقتی بازه‌هایی که واقعاً برایت مهم بودند از قبل پوشش داده شده‌اند.

## `pricing::discount_percent` — یک سیاستِ `pub(super)`، بیرون از APIِ عمومی

```rust
pub(super) fn discount_percent(internal_rating: u8) -> u8 {
    match internal_rating {
        0..=3 => 0,
        4..=7 => 10,
        _ => 25,
    }
}
```

دقیقاً همان سه‌بازویِ `public_rating_band`، از قصد — همان مقیاسِ زیرین است،
فقط سؤالِ متفاوتی جواب می‌دهد («چقدر تخفیف» به‌جایِ «چطور توصیفش کنم»). نکته‌یِ
جالب همان چیزی است که اینجا *نیست*: هیچ `pub`ی. `pricing` یک زیرماژولِ
`catalog` است، و این تابع فقط لازم است از داخلِ `catalog` دیدنی باشد —
تنها جایی که واقعاً تخفیف را اعمال می‌کند. `pub(super)` دقیقاً همین را
می‌گوید: دیدنی برایِ ماژولِ والد، و هیچ‌جایِ دیگر. `pub` کردنش هم کار
می‌کرد، ولی داشت یک دروغ می‌گفت — که سطح‌بندیِ تخفیف بخشی از سطحِ عمومی و
پایدارِ این کریت است، در حالی که در واقع فقط یک جزئیاتِ پیاده‌سازی از نحوه‌یِ
قیمت‌گذاریِ `Anime` است.

## `Anime::rental_price_cents` — جایی که این دو ماژول به هم می‌رسند

```rust
pub fn rental_price_cents(&self, base_price_cents: u32) -> u32 {
    let discount = pricing::discount_percent(self.internal_rating) as u32;
    base_price_cents * (100 - discount) / 100
}
```

این تنها جایِ کلِ کریت است که واقعاً `pricing::discount_percent` را صدا
می‌زند — و می‌تواند، چون `rental_price_cents` داخلِ `catalog` تعریف شده،
یعنی همان والدِ مستقیمِ `pricing`، دقیقاً همان یک ماژولی که `pub(super)`
درش را برایش باز می‌کند. فرمول کلمه‌به‌کلمه همان چیزی است که کامنتِ
مستنداتِ بالایش گفته بود: اول ضرب، بعد تقسیم، پس
`1000 * (100 - 25) / 100 = 75000 / 100 = 750`، نه یک کسری که زودتر گرد
شده باشد. تقسیمِ اعدادِ صحیح گرد نمی‌کند، قطع می‌کند — دقیقاً برایِ همین
تستِ `rental_price_cents_rounds_down` برایِ یک قیمتِ پایه‌یِ ۹۹۹-سِنتی با
تخفیفِ ۲۵ درصد، انتظارِ `749` را دارد، نه `750`: `999 * 75 = 74925`، و
`74925 / 100 = 749` با باقیمانده‌ای که ساده رها می‌شود.

## این درس واقعاً درباره‌ی چه بود

- **دیدپذیری یک جمله است درباره‌ی اینکه یک تابع *برایِ* چه کسی نوشته شده،
  نه فقط اینکه چه کسی فنی می‌تواند بهش برسد.** `pricing::discount_percent`
  می‌توانست `pub` باشد؛ نبود، چون سیاستِ تخفیف فقط کارِ خودِ `catalog` است.
- **`pub(crate)` و `pub(super)` دو سؤالِ متفاوت را جواب می‌دهند.**
  `internal_rating` لازم بود از هرجایِ این کریت خواندنی باشد (تست‌ها، که
  بیرونِ `catalog` نشسته‌اند)؛ `discount_percent` فقط لازم بود از یک
  والدِ مشخص خواندنی باشد.
- **`mod pricing` تودرتویِ `mod catalog`، همان درختی است که این درس با
  دست ساخت، فقط این‌بار دارد کارِ واقعی انجام می‌دهد.** هیچ‌چیز، نه تست و
  نه صدا زدن، لازم نداشت این ساختارِ تودرتو صاف شود — درخت دقیقاً به
  همان عمقی ماند که لازم داشت.
