# راه‌حل — ۲.۷.۴ تستِ خاصیت‌محور با `proptest`، تستِ عکس‌برداری با `insta`

```rust
pub fn encode_flags(flags: &[bool]) -> String {
    flags.iter().map(|&b| if b { '1' } else { '0' }).collect()
}

pub fn decode_flags(encoded: &str) -> Vec<bool> {
    encoded.chars().map(|c| c == '1').collect()
}

pub fn checklist(items: &[WatchItem]) -> String {
    let mut out = String::new();
    for item in items {
        let mark = if item.watched { "x" } else { " " };
        out.push_str(&format!("[{mark}] {}\n", item.title));
    }
    out
}
```

هیچ‌کدام از این سه چیزی فراتر از آنچه در «مفهوم» دیدی نمی‌خواست — همان دو ابزار، این‌بار رویِ یک دامنه‌ی کمی متفاوت.

## `encode_flags` / `decode_flags` — گراییده به یک خاصیت، نه یک مثال

`encode_flags` هر `bool` را با `.map()` به کاراکترِ متناظرش تبدیل می‌کند و با `.collect()` یک `String` می‌سازد — دقیقاً همان الگویِ تبدیلِ کاراکتر به `String` که از ۲.۲ می‌شناسی. `decode_flags` دقیقاً برعکسش را می‌کند: هر `char` را با `== '1'` مقایسه می‌کند و یک `bool` می‌سازد.

نکته‌ی مهم این نیست که این دو تابع چطور نوشته شده‌اند — نکته این است که تستِ پنهانشان (`flags_round_trip` در `src/lib.rs`) هیچ ورودیِ مشخصی را چک نمی‌کند. فقط این را چک می‌کند: `decode_flags(&encode_flags(&flags)) == flags`، برایِ صدها `Vec<bool>`ِ تصادفی با طولِ بینِ صفر تا پانزده. اگر پیاده‌سازی‌ات این خاصیت را برقرار نگه دارد — هر شکلی که نوشته باشی‌اش — تست سبز می‌شود. proptest اهمیتی نمی‌دهد از `.map()`/`.collect()` استفاده کرده‌ای یا یک حلقه‌ی دستی؛ فقط قرارداد برایش مهم است.

## `checklist` — گراییده به یک عکس

`checklist` هم چیزِ تازه‌ای نیست: همان الگویِ `watch_digest` که در «مفهوم» دیدی، با یک قالبِ خروجیِ متفاوت. تستِ پنهانش (`checklist_snapshot`) اما فرق دارد: یک `insta::assert_snapshot!` است، نه یک `assert_eq!`. فایلِ `src/snapshots/p2_07_04_property_and_snapshot_testing__tests__checklist_snapshot.snap` از قبل با متنِ زیر تأیید شده:

```text
[x] Frieren
[x] Bocchi the Rock!
[ ] Dandadan
```

یعنی هر پیاده‌سازی‌ای که این متنِ *دقیق* را — با همین سه ورودیِ نمونه‌ی داخلِ تست — تولید کند، سبز می‌شود. کامنتِ مستندسازِ بالایِ `checklist` همین قالب را از قبل گفته بود: `[x] title` برایِ دیده‌شده، `[ ] title` برایِ ندیده‌شده، هر خط با یک `\n`.

## چیزی که این درس واقعاً درباره‌اش بود

- **یک خاصیت را طوری بنویس که کدِ پیاده‌سازی‌کننده آزاد باشد.** تستِ `flags_round_trip` هیچ‌جا نمی‌گوید `encode_flags` باید از `.map()` استفاده کند یا از یک حلقه — فقط رفتارِ نهایی برایش مهم است. این دقیقاً همان چیزی است که proptest را از یک تستِ دستیِ سخت‌گیر جدا می‌کند.
- **یک عکسِ تأییدشده، مشخصاتِ خروجی را عوض نمی‌کند، فقط ثبتش می‌کند.** `.snap`ِ بالا همان چیزی است که کامنتِ مستندسازِ `checklist` از قبل گفته بود؛ عکس یک منبعِ حقیقتِ *دوم* نیست، فقط نسخه‌ی ماشین‌خوانِ همان مشخصات است.
- **هر دو تکنیک رویِ کدی کار کردند که هیچ چیزِ خاصی نداشت.** `encode_flags`/`decode_flags`/`checklist` هرکدام چند خط‌اند؛ چیزی که فرق می‌کند نحوه‌ی *تستشان* است، نه پیچیدگیِ خودِ کد. این دقیقاً نکته‌ی درس بود: این دو ابزار را برایِ شکلِ تست انتخاب می‌کنی، نه برایِ اندازه‌ی کد.
