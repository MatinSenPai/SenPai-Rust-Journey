# ۰۱.۲ — `BTreeMap`، `HashSet` و `VecDeque`

درس ۱ نوع‌های `Vec` و `HashMap` رو پوشش داد. این درس، جعبه‌ابزار کالکشن‌های ما رو با اضافه کردن سه تا ساختار دیگه کامل‌تر می‌کنه، و همچنان از همون دامنه‌ی اطلاعات تماشای سریال (watch-data) استفاده می‌کنه: مپ‌های مرتب‌شده (ordered maps)، مجموعه‌ها (sets) و یه صف (queue) که از هر دو طرف سریع کار می‌کنه.

## ساختار `<BTreeMap<K, V` — مثل `HashMap` ئه، اما مرتب‌شده (sorted)

نوع `BTreeMap` تقریباً همون API رو داره که `HashMap` داره (متدهای `insert.` و `get.` و حتی همون entry API دقیقاً همون‌طوری کار می‌کنن)، با این تفاوت که کلیدها رو به صورت داخلی به شکل مرتب‌شده (sorted) نگه می‌داره. این یعنی پیمایشِ (iterating) یه `BTreeMap` همیشه ورودی‌ها (entries) رو بر اساس کلیدشون به صورت صعودی برمی‌گردونه — برخلاف تابع `top_n` از درس اول، اینجا هیچ نیازی به فراخوانی یه sort صریح و دستی نیست. البته این قطعی‌بودن رایگان هم به دست نمیاد: جستجوها (lookups) و درج‌کردن‌ها (inserts) به جای زمانِ به طور میانگین `(O(1` (که تو `HashMap` مستقیماً به یه bucket هش (hash) می‌کنه)، اینجا تو زمان `(O(log n` انجام می‌شه (چون داره یه ساختار درختی رو طی می‌کنه). قانون سرانگشتی اینه: به‌طور پیش‌فرض برو سراغ `HashMap`؛ و فقط وقتی که *مشخصاً* به یه پیمایشِ مرتب‌شده نیاز داشتی (مثل چاپ کردنِ یه گزارش، یا یه «کویری بازه‌ای (range query)» مثل «همه سریال‌های پخش‌شده بین ۲۰۲۰ تا ۲۰۲۳» که `BTreeMap::range` ازش پشتیبانی می‌کنه اما `HashMap` نه)، از `BTreeMap` استفاده کن.

```rust
use std::collections::{BTreeMap, HashMap};

let counts: HashMap<String, u32> = HashMap::from([
    ("naruto".to_string(), 4),
    ("bleach".to_string(), 2),
]);
let sorted: BTreeMap<String, u32> = counts.into_iter().collect();
// حالا اگه رو sorted پیمایش کنی، همیشه کلمه‌ی "bleach" رو قبل از "naruto" بهت می‌ده
```

## ساختار `<HashSet<T` — همون عملیات مجموعه‌ها که از پایتون می‌شناسی

اگه تا حالا از ORMِ فریم‌ورک جنگو یا از همون `set`های معمولیِ پایتون استفاده کرده باشی، این یکی خیلی برات آشنا خواهد بود: `<HashSet<T` مقادیر یکتا رو بدون هیچ دیتای اضافی و وابسته‌ای ذخیره می‌کنه (از نظر مفهومی تو پس‌زمینه فکر کن داری با یه `<() ,HashMap<T` کار می‌کنی)، و دقیقاً همون جبرِ مجموعه‌ها که پایتون داره رو اینجا هم بهت می‌ده:

| پایتون | زبان Rust |
|---|---|
| `a & b` | `(a.intersection(&b` |
| `a \| b` | `(a.union(&b` |
| `a - b` | `(a.difference(&b` |
| `a ^ b` | `(a.symmetric_difference(&b` |

تنها نکته‌اش اینه: متدهایِ set تو زبان Rust مستقیماً یه `HashSet` جدید برنمی‌گردونن، بلکه یه *پیمایشگر (iterator)* از ارجاع‌های قرض‌گرفته‌شده رو بهت می‌دن — در نتیجه اگه بخوای در نهایت یه مجموعه‌ی دارای مالکیت (owned set) داشته باشی، معمولاً باید رو نتیجه‌ی این متدها `()collect.` رو صدا بزنی:

```rust
use std::collections::HashSet;

let a: HashSet<&str> = HashSet::from(["action", "comedy", "isekai"]);
let b: HashSet<&str> = HashSet::from(["comedy", "drama"]);

let shared: HashSet<&str> = a.intersection(&b).copied().collect();
// {"comedy"} == مشترک
```

## ساختار `<VecDeque<T` — از هر دو سر سریع کار می‌کنه

کار با `Vec` وقتی که می‌خوای از **آخرش** چیزی اضافه (push) یا حذف (pop) کنی خیلی سریعه `((O(1)`، اما اگه بخوای چیزی رو از **ابتداش (front)** درج یا حذف کنی سرعتش `(O(n` می‌شه — چون متدهای `(insert(0, x` یا `(remove(0` مجبورن تک‌تک عناصرِ دیگه رو یه دونه ببرن جلوتر تا جا برای عضو جدید باز بشه. اگه لازم داری که با بازدهی و سرعت بالا، چیزی رو از *هر کدوم* از دو سرِ لیست حذف یا اضافه کنی — مثلاً یه «صف تماشا» که هم می‌تونی یه سریال رو بندازی ته صف و هم گهگاهی یکیشون رو بپری بندازی همون اول خط — ساختار `<VecDeque<T` (به معنی «صفِ دو-سَر (double-ended queue)») بهت زمان اجرای `(O(1` رو تو هر دو سرِ صف می‌ده:

```rust
use std::collections::VecDeque;

let mut queue: VecDeque<&str> = VecDeque::new();
queue.push_back("Frieren");   // به آخر صف اضافه می‌شه — O(1)
queue.push_front("Bocchi");   // می‌پره اول صف — O(1)
let next = queue.pop_front(); // خروجی: ("Some("Bocchi — سرعتش O(1)
```

## وظیفه‌ی تو

توابع و ساختار `WatchQueue` رو تو فایل `src/lib.rs` پیاده‌سازی کن:

- تابع `sorted_by_key` — تبدیل یه `HashMap` به یه `BTreeMap` (یه پیمایش مرتب‌شده «به صورت رایگان»).
- تابع `shared_genres` — نقطه‌ی اشتراکِ (intersection) بین دو تا مجموعه‌ی ژانر.
- تابع `exclusive_genres` — تفاوت متقارن (symmetric difference): ژانرهایی که دقیقاً تو یکی از دو تا مجموعه هستن، و نه تو هر دوتاشون.
- ساختار `WatchQueue` — یه پوشش کوچیک (wrapper) دورِ `<VecDeque<String` که داره یه صفِ «برنامه‌ی بعدی چیه» رو مدل‌سازی می‌کنه: متدِ `enqueue` (اضافه کردن به ته صف)، متدِ `watch_next` (برداشتن از اول صف)، و متدِ `watch_next_priority` (انداختنِ یه فیلم به همون جلوی صف).
