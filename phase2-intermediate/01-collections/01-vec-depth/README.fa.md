# ۰۱.۱ — نوع‌های `Vec` و `HashMap`

از فاز ۱ تا حدودی با `<Vec<T` آشنایی داری (آرایه‌ی با قابلیت تغییر سایز تو زبان Rust، که تقریباً همون `list` تو پایتونه). این درس رو دو تا چیز تمرکز می‌کنه: چند تا از متدهای `Vec` که احتمالاً تا حالا بهشون نیاز پیدا نکرده بودی، و همچنین `<HashMap<K, V` — معادل همون `dict` تو Rust، البته با یه ترفند خیلی استاندارد و رایج (یعنی همون **entry API**) که تا زمانی که تو پایتون سراغ `collections.Counter` یا `dict.setdefault` نری، هیچ معادل تمیز دیگه‌ای براش وجود نداره.

مثالی که قراره تو کل این ماژول استفاده کنیم: تحلیل یه لیست از داده‌های مربوط به تماشای انیمه/سریال.

## متدهای `Vec`: مرتب کردن (sorting) و حذف تکراری‌ها (deduping)

```rust
let mut nums = vec![3, 1, 4, 1, 5, 9, 2, 6];
nums.sort();                 // [1, 1, 2, 3, 4, 5, 6, 9] — درجا (in place) مرتب می‌کنه
nums.dedup();                // [1, 2, 3, 4, 5, 6, 9]    — فقط تکراری‌های متوالی (CONSECUTIVE) رو حذف می‌کنه
```

متد `.dedup()` فقط مقادیر تکراری‌ای رو حذف می‌کنه که *کنار هم (adjacent)* باشن — دقیقاً به همین دلیله که تقریباً همیشه بلافاصله قبل از استفاده از اون، از `.sort()` استفاده می‌کنی (تا عناصر برابر، همسایه‌ی هم بشن). اگه لازم داری که حذف تکراری‌ها نه بر اساس خودِ عنصر، بلکه بر اساس یه کلید مشتق‌شده (derived key) انجام بشه، از `(...)sort_by_key(|x|.` استفاده کن:

```rust
let mut shows = vec![("Frieren", 2023), ("Bocchi", 2022), ("Frieren", 2023)];
shows.sort_by_key(|(title, _year)| title.clone());
```

تو پایتون تابع `sorted(list, key=...)` یه لیستِ *جدید* برمی‌گردونه؛ اما متد `.sort_by_key` خودِ متغیر `nums` رو، همونجا (in place) مرتب می‌کنه و خروجیش `()` هست — این یه نمونه‌ی دیگه از ترجیحِ زبان Rust به استفاده از متدهای صریح و تغییردهنده (mutating) به جای متدهای دارای تخصیص حافظه (allocating) تو زماناییه که به حفظ شدنِ ترتیب اصلی نیازی نداری.

## نوعِ `HashMap`: متد entry API

وقتی از دنیای پایتون میای، شمردن تعداد تکرار کلمات به احتمال زیاد برات این شکلیه:

```python
counts = {}
for word in words:
    if word in counts:
        counts[word] += 1
    else:
        counts[word] = 1
# یا با استفاده از: counts = collections.Counter(words)
```

یه ترجمه‌ی مستقیم از همون نسخه‌ی `if/else` به زبان Rust کاملاً کار می‌کنه، اما جستجو تو حافظه (lookup) رو *دو بار* انجام می‌ده (یه بار برای `.contains_key`، یه بار هم برای اون `[]`/`.get_mut` که بلافاصله بعدش میاد). در عوض، نوعِ `HashMap` تو Rust یه ویژگی به اسم **entry API** بهت می‌ده، که جستجو رو فقط یک بار انجام می‌ده و در جواب یه "شکاف (slot)" تغییرپذیر بهت برمی‌گردونه که می‌تونی همون رو تو یه دستور (expression) واحد، یا با یه مقدار پر کنی و یا آپدیتش کنی:

```rust
use std::collections::HashMap;

let mut counts: HashMap<String, usize> = HashMap::new();
for word in words {
    *counts.entry(word).or_insert(0) += 1;
}
```

متد `.entry(word)` یه مقدار از جنس `Entry` برمی‌گردونه — یعنی "جایگاه این کلید، چه وجود داشته باشه چه نه". متد `.or_insert(0)` می‌گه "اگه خالیه، اونجا یه `0` بذار"، و تو هر دو حالت در نهایت یه `&mut usize` برمی‌گردونه که دقیقاً داره به مقدارِ شمارش‌شده اشاره می‌کنه، و دستور `1 =+ ...*` اون مقدار رو درجا یکی زیاد می‌کنه. یک بار جستجو، توی یه خط، بدون هیچ شاخه‌بندی (branch) اضافی. متد `(...)or_insert_with(||.` نسخه‌ی تَنبلِ (lazy) همینه — هر وقت ساختن اون مقدار پیش‌فرض کار هزینه‌بری بود (مثلاً `.or_insert_with(Vec::new)`) از این استفاده کن، چون مقداری که مستقیماً به `or_insert` پاس داده می‌شه حتی اگه اون کلید از قبل وجود هم داشته باشه، همیشه بلافاصله (eagerly) ارزیابی و ساخته می‌شه.

## هیچ تضمینی برای ترتیبِ پیمایش (iteration order) تو `HashMap` وجود نداره

این بزرگ‌ترین چیزیه که برای برنامه‌نویسی که از پایتون +3.7 (که توش یه `dict` معمولی ترتیبِ وارد شدن داده‌ها رو به یاد میاره و پیمایش روش کاملاً قطعی و باثباته) اومده سورپرایزکننده‌ست. نوع `HashMap` تو Rust **هیچ قولی در مورد ترتیب نمی‌ده** — ترتیبی که از `.iter()`، `.keys()`، یا یه `map& (for (k, v` می‌گیری می‌تونه بین دو بار اجرایِ همون *برنامه‌ی ثابت* با هم فرق داشته باشه، چون این ترتیب برای هر فرآیند (process) به صورت تصادفی تعیین می‌شه (که این قضیه یه تدبیر امنیتی عمدی برای مقابله با حملاتِ hash-flooding هست). اگه به یه ترتیب ثابت و قابل‌پیش‌بینی نیاز داری — مثلاً واسه نمایش به کاربر، واسه تست‌ها، یا هر چیزی که قراره توسط یه انسان یا یه assertion چک بشه — تو مجبوری که **به صراحت داده‌ها رو جمع (collect) کنی و خودت مرتبشون (sort) کنی**. دقیقاً به همین دلیله که تابع `top_n` (توی کد پایین) نمی‌تونه خیلی ساده فقط `n` تا آیتم اولی که تصادفاً تو پیمایش بهشون برمی‌خوره رو برداره: بلکه مجبوره جفت‌های (pairs) جمع‌آوری‌شده رو خودش مرتب کنه، اون هم با یه قانون صریح برای رفعِ تساوی (tie-breaker)، وگرنه ممکنه دو بار اجرای برنامه‌ی تو برای آیتم‌هایی که تعدادِ تکرار برابری دارن، دو تا لیست "۵ تای برتر (top 5)" کاملاً متفاوت نشون بده. (درس دوم ساختارِ `BTreeMap` رو معرفی می‌کنه که کلیدها رو به صورت خودکار مرتب نگه می‌داره — البته در ازای یه هزینه‌ی کوچیک برای performance.)

## وظیفه‌ی تو

هر سه تا تابع رو تو فایل `src/lib.rs` پیاده‌سازی کن:

- تابع `word_frequency` — با استفاده از متدِ entry API تعداد تکرار کلمات رو بشمر.
- تابع `top_n` — لیست `n` تا جفت (کلمه، تعداد)ِ برتر رو برگردون که اول بر اساسِ تعداد به شکل نزولی مرتب شدن، و بعد در صورت مساوی بودنِ تعداد، بر اساسِ حروف الفبا به صورت صعودی.
- تابع `dedupe_preserve_order` — آیتم‌های تکراری رو حذف کن اما اون ترتیبی که توش داده‌ها برای اولین بار دیده شدن رو حفظ کن (خودت توجه کن که چرا استفاده‌ی صرف از `.sort().dedup()` اینجا اشتباه درمی‌اومد: چون بی‌سروصدا ترتیبِ اصلیِ ورودی رو به هم می‌ریخت).
