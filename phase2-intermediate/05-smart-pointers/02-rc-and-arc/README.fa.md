# ۰۵.۲ — `Rc` و `Arc`

## شکستن آگاهانه‌ی قانون «یک مالک»

گاهی چند بخش برنامه باید همان داده را تا وقتی هرکدام استفاده می‌کنند نگه دارند و مالک یکتای روشنی وجود ندارد؛ مثلاً config برنامه که handler وب، job پس‌زمینه و logger هم‌زمان می‌خوانند. هیچ‌کدام نباید داده را زیر پای بقیه drop کند.

`Rc<T>` مخفف reference counted است: چند مالک برای یک مقدار heap، و آزادشدن مقدار فقط پس از dropشدن آخرین مالک.

```rust
use std::rc::Rc;
let a = Rc::new(String::from("shared"));
let b = Rc::clone(&a); // مالک دوم همان String، نه یک کپی
let c = a.clone();     // همان کار با syntax متفاوت
```

## `Rc::clone` ارزان است و داده را کپی نمی‌کند

- `some_string.clone()` یک buffer تازه روی heap می‌سازد و همه‌ی byteها را کپی می‌کند.
- `Rc::clone(&some_rc)` فقط شمارنده‌ی داخلی را زیاد می‌کند و pointer دیگری به **همان** تخصیص می‌دهد؛ مستقل از اندازه‌ی `T`.

نوشتن `Rc::clone(&a)` قرارداد رایج Rust است، چون روی call site روشن می‌کند «pointer ارزان clone می‌شود»، نه خود داده.

هر `Rc::clone` شمارنده را زیاد و هر drop آن را کم می‌کند. `T` فقط وقتی آزاد می‌شود که count صفر شود. میان «اصل» و «کپی» تفاوتی نیست؛ همه‌ی handleها مالک معتبرند.

## `Rc` میان threadها کار نمی‌کند؛ `Arc` برای همین است

شمارنده‌ی `Rc` یک integer غیراتمی است. افزایش هم‌زمان آن از دو thread data race می‌سازد، پس `Rc` trait به نام `Send` را پیاده نمی‌کند و انتقالش به `thread::spawn` خطای compile است.

`Arc<T>` مخفف atomically reference counted و نسخه‌ی thread-safe است. API مشابه دارد، اما count را با دستورهای atomic CPU تغییر می‌دهد؛ امن برای چند thread و اندکی کندتر. قاعده: در کد تک‌thread از `Rc` استفاده کن و فقط وقتی داده باید از مرز thread عبور کند سراغ `Arc` برو.

حالت پیش‌فرض همچنان مالکیت معمولی و `&T`/`&mut T` است؛ ساده، بدون هزینه‌ی runtime و کاملاً بررسی‌شده هنگام compile. `Rc`/`Arc` را وقتی انتخاب کن که واقعاً چند مالک بلندعمر داری: config مشترک، node گراف با چند parent یا cache مشترک. خودشان فقط دسترسی خواندنی می‌دهند. برای تغییر داده‌ی مشترک به interior mutability نیاز داری که درس بعد می‌آید.

مثل چند شعبه که به یک نسخه‌ی مرکزی آیین‌نامه اشاره می‌کنند، cloneکردن handle نسخه‌ی تازه‌ای از آیین‌نامه نمی‌سازد. مرز تشبیه: شمارنده خودکار و بخشی از سازوکار حافظه است؛ اگر cycle از `Rc` بسازی، count ممکن است هرگز صفر نشود.
