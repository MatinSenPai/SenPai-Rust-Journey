# ۰۵.۱ — `Box` و تخصیص روی heap

## تفاوت واقعی stack و heap

متین، تا اینجا نام stack و heap را شنیده‌ای؛ این درس جایی است که تفاوتشان واقعاً روی طراحی نوع اثر می‌گذارد:

- **stack** ناحیه‌ای با اندازه‌ی مشخص و ترتیب آخرین‌ورودی/اولین‌خروجی است. افزودن و برداشتن فقط pointer را جابه‌جا می‌کند و بسیار سریع است. اما کامپایلر باید پیش از اجرا دقیقاً بداند هر مقدار چند byte فضا می‌گیرد.
- **heap** ناحیه‌ای بزرگ‌تر و کم‌ساختارتر است. برنامه در runtime قطعه‌ای حافظه تخصیص می‌دهد، pointer آن را می‌گیرد و تا زمان آزادشدن نگهش می‌دارد. از stack کندتر است، ولی مقدارهایی با اندازه‌ی وابسته به runtime یا عمر طولانی‌تر را نگه می‌دارد.

خود مقدارهای `i32`، `bool` و حتی struct روی stack هستند. داده‌ی کاراکتری `String` روی heap است، اما struct کوچک `String` شامل pointer، length و capacity روی stack می‌ماند. `Box` برای قراردادن صریح کل یک مقدار روی heap است.

## `Box<T>`: ساده‌ترین smart pointer

```rust
let boxed: Box<i32> = Box::new(5);
println!("{}", *boxed);
```

smart pointer یک struct شبیه pointer است که مالک داده‌ی مقصد هم هست و رفتار اضافه دارد. `Box<T>` ساده‌ترین نمونه است: یک `T` روی heap و pointer آن روی stack. با خروج `Box` از scope، حافظه‌ی heap خودکار آزاد می‌شود.

معمولاً برای متدها لازم نیست `*boxed` بنویسی. `Box<T>`، `Deref` و `DerefMut` را پیاده می‌کند؛ پس اگر `T` متد `some_method(&self)` داشته باشد، `boxed.some_method()` مستقیم کار می‌کند. این auto-deref یک قاعده‌ی عمومی traitهاست، نه استثنایی مخصوص `Box`.

## کاربرد اصلی: نوع‌های بازگشتی

یک cons list را ببین:

```rust
enum List {
    Cons(i32, List), // compile نمی‌شود
    Nil,
}
```

خطای `error[E0072]: recursive type has infinite size` می‌گیری. اندازه‌ی `List` به variant به نام `Cons` وابسته است؛ آن هم `List` دیگری دارد و این زنجیره بی‌پایان می‌شود. هیچ اندازه‌ی ثابت و متناهی برای layout نوع پیدا نمی‌شود.

راه‌حل، گذاشتن field بازگشتی پشت `Box` است:

```rust
enum List {
    Cons(i32, Box<List>),
    Nil,
}
```

حالا `Cons` یک `i32` و یک `Box<List>` دارد. خود `Box` مستقل از عمق فهرست همیشه به‌اندازه‌ی یک pointer است؛ روی ماشین ۶۴ بیتی ۸ byte. recursion از راه تخصیص heap رخ می‌دهد و layout بیرونی اندازه‌ی ثابت دارد. هزینه‌اش یک تخصیص heap برای هر پیوند است.

کاربرد بزرگ دیگر `Box<dyn Trait>` است. اندازه‌ی خود `dyn Trait` معلوم نیست، چون نوع‌های concrete پیاده‌کننده اندازه‌های متفاوت دارند. `Box` آن‌ها را روی heap می‌گذارد و pointer ثابت را روی stack نگه می‌دارد؛ مثلاً `Vec<Box<dyn Shape>>` می‌تواند circle و square را کنار هم داشته باشد.

تشبیه زنجیر سفارش‌ها مفید است: هر حلقه فقط شماره‌ی سفارش و نشانی حلقه‌ی بعد را نگه می‌دارد، نه کل زنجیره را درون خودش. مرز تشبیه این است که pointer فقط «نشانی مفهومی» نیست؛ تخصیص و dereference واقعی با هزینه‌ی حافظه دارد.
