# راه‌حل

```rust
pub fn from_vec(items: &[i32]) -> List {
    let mut list = List::Nil;
    for &item in items.iter().rev() {
        list = List::Cons(item, Box::new(list));
    }
    list
}
```

بخش جذاب این کد، جهتِ (direction) اجرایِ حلقه‌ست. یه cons list فقط و فقط به سمت «جلو» پوینتر داره — یعنی هر `Cons` به *بقیه‌ی* لیست اشاره می‌کنه، و هیچ راهی هم وجود نداره که بتونی به تهِ یه لیستِ موجود چیزی اضافه (append) کنی مگه اینکه کل مسیر رو تا برسی به `Nil`ِ اون لیست طی کنی و تو مسیر هم تک‌تک گره‌ها (nodes) رو از اول و دوباره بسازی (چون نوع `List` اینجا به صورت درجا (in place) قابل تغییر و میوتیشن نیست). پس به جای اینکه لیست رو از اول به آخر بسازیم، این کد روی `items` به صورت **برعکس (backward)** قدم می‌زنه (`.iter().rev()`) و لیست رو از داخل به بیرون بنا می‌کنه: عنصرِ آخر اول از همه تبدیل می‌شه به `Cons(last, Nil)`، و بعدش هر کدوم از عناصرِ قبلی‌تر میان اون چیزی رو که از قبل ساخته شده بود تو دلِ یه لایه‌ی `Cons`ِ جدید می‌پوشونن (wrap می‌کنن). تا زمانی که حلقه تموم بشه، *اولین* عنصرِ داخلِ `items` در واقع تبدیل شده به همون `Cons`ِ خارجی و روییِ لیست — و این همون چیزیه که عبارت «حفظ کردن ترتیب (preserves order)» برای یه همچین ساختار داده‌ای معنیش می‌ده.

متدِ `sum` همون تیکه‌ی جذابِ دیگه‌ست:

```rust
pub fn sum(&self) -> i32 {
    match self {
        List::Cons(val, rest) => val + rest.sum(),
        List::Nil => 0,
    }
}
```

متغیر `rest` اینجا نوعش `<Box<List>&` هست (چون وقتی روی `&self` عملِ `match` رو انجام می‌دیم، خودبه‌خود این قرض‌گرفتن (borrow) به درونِ الگوها (patterns) هم نفوذ پیدا می‌کنه). صدا زدنِ مستقیمِ `()rest.sum` — بدون نیاز به `(rest**)` یا `(rest*)` و بدون هیچ کار اضافه‌ای — به درستی کار می‌کنه چون نوعِ `<Box<List>` خصیصه‌ی `<Deref<Target = List` رو پیاده‌سازی می‌کنه، و فراخوانی‌های متد به صورت خودکار تا هر تعداد دفعه که لازم باشه عمل نشان‌زدایی (deref) رو واردِ کد می‌کنن تا بتونن بالاخره اون متدی که باهاش سازگاری (matching) داره رو پیدا کنن (به این کار می‌گن "نشان‌زدایی خودکار" یا "auto-deref"، و این کار می‌تونه به صورت زنجیروار از بین لایه‌های مختلف و متعددی از نوع‌هایِ پوینتر-مانند رد بشه، نه فقط از یه لایه).

در مورد سؤال ۳ مرور: اگه متدِ `sum` به جای `&self`، خودِ `self` رو (با ارزش خود مقدارش یا by value) می‌گرفت، اون وقت صدا زدن `()list.sum` کلِ اون لیست رو **مصرف (consume)** می‌کرد — یعنی با هر بار فرو رفتنِ بازگشتیِ تابع به درونِ خودش، تک‌تکِ گره‌های `Cons` به داخل اون تابع منتقل (move) می‌شدن و همونجا هم از بین می‌رفتن (drop می‌شدن). این کار خیلی بیهوده و اسراف‌گرایانه‌ست وقتی که تو در واقع فقط و فقط می‌خوای مقدارِ کل رو *بخونی* (چون برای اینکه بعدش بتونی دوباره از لیستت استفاده کنی مجبور می‌شدی کل لیست رو از اول بسازی)، و از طرفی اصلاً هم نیازی به این کار نیست: واسه جمع زدن هیچ‌وقت نیازی نداریم که بخوایم لیست رو تغییر بدیم یا مالکش بشیم، پس گرفتنِ `&self` کاملاً درست و بهینه‌ترین امضای ممکنه که فقط به حداقل مجوزها (minimal-permission) نیاز داره — یعنی دقیقاً همون اصلِ «فقط همونقدر دسترسی بخواه که واقعاً بهش نیاز داری» که از درسِ ساختارها (structs) با خودمون آوردیمش.
