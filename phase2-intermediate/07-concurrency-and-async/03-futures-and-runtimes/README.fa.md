# ۰۷.۳ — Futureها و runtimeها

ریسمان (Thread) برای اجرای موازی واقعی و کارهای سنگین پردازنده مناسب است. async سراغ مسئله‌های وابسته به ورودی/خروجی می‌رود: وقتی برنامه منتظر شبکه، پایگاه داده یا فایل است، همان ریسمان می‌تواند کار دیگری را جلو ببرد.

## `Future` یک ماشین حالت تنبل است

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

trait Future {
    type Output;
    fn poll(self: Pin<&mut Self>, cx: &mut Context<'_>) -> Poll<Self::Output>;
}
```

`Poll::Ready(T)` یعنی کار تمام شده و `Poll::Pending` یعنی باید بعداً دوباره سراغش برویم. ساختن یک Future بدنه‌ی آن را اجرا نمی‌کند؛ فراخوانی `async fn` تا وقتی Future پیمایش نشود، کاری انجام نمی‌دهد. در JavaScript، یک `Promise` معمولاً همان موقع ساخت شروع به اجرا می‌کند. در Python هم coroutine حاصل از `async def` تا وقتی `await` یا زمان‌بندی نشود اجرا نمی‌شود.

## محیط اجرا چه می‌کند؟

کتابخانه‌ی استاندارد trait مربوط به `Future` را دارد، اما محیط اجرا (Runtime) فراهم نمی‌کند. محیط اجرا کارها را زمان‌بندی می‌کند، آماده‌شدن ورودی/خروجی را زیر نظر می‌گیرد و Future مناسب را دوباره پیمایش می‌کند. `tokio` انتخاب رایجی برای بک‌اند Rust است.

در این درس `Countdown` و ساده‌ترین شکل `block_on` را می‌سازیم. حلقه‌ی آموزشی ما بی‌وقفه وضعیت را می‌پرسد (Busy Polling)؛ یک اجراکننده‌ی واقعی با `Waker` فقط وقتی پیشرفت ممکن باشد، کار را دوباره در صف می‌گذارد. پرس‌وجوی بی‌وقفه هنگام انتظار شبکه، پردازنده را بیهوده درگیر می‌کند.

در صف نانوایی، مسئول سفارش به‌جای ایستادن جلوی فر تا آماده‌شدن یک نان، سفارش بعدی را پیش می‌برد. این تشبیه یک مرز مهم دارد: async محاسبه‌ی پردازنده را سریع‌تر نمی‌کند. کار سنگین پردازنده داخل یک وظیفه‌ی async حتی می‌تواند بقیه‌ی کارهای اجراکننده را معطل کند.

`Pin` جلوی جابه‌جایی Futureای را می‌گیرد که شاید به بخشی از وضعیت خودش ارجاع داشته باشد. `Unpin` یعنی جابه‌جایی مقدار، این تضمین را نمی‌شکند.
