# راه‌حل

```rust
pub fn celsius_to_fahrenheit(c: f64) -> f64 {
    round_to_one_decimal(c * 9.0 / 5.0 + 32.0)
}

fn round_to_one_decimal(x: f64) -> f64 {
    (x * 10.0).round() / 10.0
}
```

هیچ نکته‌ی ظریف یا پیچیده‌ای تو پیاده‌سازی وجود نداره — بخش جذابِ این درس اینه که هر تست کجا *قرار گرفته (lives)*، نه اون ریاضیاتی که انجام می‌ده. سه سطحِ کاملاً متفاوت از تست‌ها دارن یه کریتِ کوچیک و یکسان رو آزمایش می‌کنن:

- بلوک `tests mod [cfg(test)]#` داخل فایل `src/lib.rs` (یعنی همون تست‌های واحد) تابعِ `round_to_one_decimal` رو **به صورت مستقیم** صدا می‌زنه، چون تست‌های واحد به عنوان بخشی از همین کریت کامپایل می‌شن و قوانین مربوط به خصوصی بودن کدها (privacy) برای کدهایی که داخل یه کریت مشترک هستن اعمال نمی‌شه.
- فایل `tests/conversion_test.rs` (یعنی یه تستِ یکپارچگی) فقط و فقط تابعِ `celsius_to_fahrenheit` رو از بیرون وارد (import) می‌کنه — این فایل اصلاً هیچ راهی نداره که حتی *اسمی* از `round_to_one_decimal` ببره، چون از زاویه‌ی دیدِ این فایل، کریت ما یه وابستگیِ خارجی (external dependency) محسوب می‌شه و تابعِ `round_to_one_decimal` هم که هیچ‌وقت `pub` نشده بود.
- بلوک `Examples # ///` که روی تابعِ `celsius_to_fahrenheit` نوشته شده، در واقع یه تستِ مستندات (doc test) هستش — که توسط دستور `cargo test` کامپایل و اجرا می‌شه، و دقیقاً همون لحظه‌ای که رفتار واقعیِ این تابع یه ذره با اون چیزی که تو کامنت قولش داده شده فرق کنه، کلِ فرآیند تست شدنِ پروژه رو با خطا متوقف می‌کنه (fail می‌کنه). این دقیقاً همون چیزیه که نوشتن مستندات رو تو Rust تبدیل می‌کنه به یه ستونِ حمال و «باربر (load-bearing)»، نه فقط یه سری جملات ادبیِ آرمانی که بی‌سروصدا همون گوشه خاک می‌خورن و قدیمی می‌شن.

در مورد سؤال ۴ چک‌پوینت: تست‌های یکپارچگی مچِ یه دسته از باگ‌ها رو می‌گیرن که تست‌های واحد به صورت ساختاری اصلاً از پسش برنمیان — باگ‌هایی که توشون یه API عمومی زمانی که از داخل خود کریت فراخوانی می‌شه *درست کار می‌کنه* (چون هنوز دستش به توابع کمکی خصوصی، قوانین و وضعیت‌های داخلی، و یه سری راه‌های میانبرِ راحت می‌رسه)، اما وقتی که یه مشتریِ خارجیِ واقعی (external consumer) دقیقاً همون استفاده رو ازش می‌کنه، کد می‌شکنه و خراب می‌شه (یا اصلاً از اولش درست تو دسترس قرار نگرفته بوده). یه مثال کلاسیک از این قضیه: وقتی یادت می‌ره یه موجودیت رو به صورت `pub` علامت بزنی، یا یادت می‌ره از ریشه‌ی کریت اونو re-export کنی — تو این حالت، تک‌تکِ تست‌های واحد همچنان با موفقیت پاس می‌شن (چون اونا برای کار کردن هیچ نیازی به عمومی بودن اون موجودیت ندارن)، اما یه تست یکپارچگی (و در نتیجه هر کاربرِ واقعی که داره از کریت تو تو پروژه‌اش استفاده می‌کنه) اصلاً کلاً دستش بهش نمی‌رسه.
