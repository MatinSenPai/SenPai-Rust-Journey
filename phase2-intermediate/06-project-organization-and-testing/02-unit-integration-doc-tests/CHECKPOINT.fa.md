# چک‌پوینت

1. یه خط به فایلِ `tests/conversion_test.rs` اضافه کن که مستقیماً تابعِ `(round_to_one_decimal(1.0` رو صدا می‌زنه. خطای دقیقِ کامپایلر چیه؟ آیا کلمه‌ی "خصوصی (private)" رو میاره، یا یه چیز دیگه — و تو هر دو حالت، این پیامِ خطا واقعاً داره چی بهت می‌فهمونه؟
2. دستورِ `cargo test -p p2-06-02-unit-integration-doc-tests` رو اجرا کن و بخش "Doc-tests" رو تو خروجی پیدا کن. اونجا چند تا تست اجرا شد، و اصلاً این تست‌ها از کجا پیداشون شد در حالی که تو هیچ‌وقت مستقیماً یه تابع با صفتِ `[test]#` برای اینا ننوشتی؟
3. اون علامت `# ` رو که قبل از خطِ `use` تو مثالِ کامنت مستندات (doc comment) بود، پاک کن (طوری که تبدیل بشه به `;use p2_06_02_unit_integration_doc_tests::celsius_to_fahrenheit` بدون اون هش اولش) و مستندات رو با دستورِ `cargo doc -p p2-06-02-unit-integration-doc-tests --open` دوباره تولید کن (یا اگه نمی‌تونی اینجا مرورگر رو باز کنی فقط تصورش کن). الان چیزی که یه خواننده‌ی مستندات تو صفحه‌ی ساخته‌شده می‌بینه چه فرقی کرده؟
4. با وجود اینکه تست‌های واحد (unit tests) همین الانشم می‌تونن همه‌ی توابعِ عمومی (`pub`) رو صدا بزنن، پس تست‌های یکپارچگی (integration tests که می‌رن تو پوشه‌ی `/tests`) *علاوه بر تست‌های واحد* دقیقاً به چه دردی می‌خورن؟ چه دسته باگ‌هایی وجود داره که فقط یه تستِ یکپارچگی می‌تونه مچش رو بگیره اما یه تست واحد از انجامش عاجزه؟
