# ۰۳ — سلام Rust

## در یک نگاه

بعد از این درس می‌توانی:

- یک برنامه‌ی کاملِ Rust بنویسی و اجرا کنی، و بگویی هر خطش چه‌کار می‌کند.
- با `println!` خروجی بسازی و مقدارها را داخلِ متن جا بدهی — با `{}`، با `{name}` و با تنظیمِ عرض.
- بگویی چرا `src/lib.rs` و `src/main.rs` هر دو وجود دارند و کدام‌یک واقعاً اجرا می‌شود.

**زمان:** حدود ۴۵ دقیقه · **پیش‌نیاز:** [۰۲ — نصبِ Rust و زنجیره‌ابزارها](../02-installing-rust-and-toolchains/README.fa.md)

---

## چرا اهمیت دارد

تا اینجا درباره‌ی Rust خوانده‌ای. این اولین درسی است که در آن *Rust می‌نویسی*.

هدفش این نیست که چیزِ چشمگیری بسازی. هدفش این است که شکلِ زبان برایت ملموس شود: یک تابع چه شکلی است، چطور چیزی چاپ می‌کنی، مقدارِ بازگشتی کجاست. این‌ها آن‌قدر تکرار می‌شوند که باید بی‌فکر بشوند، تا وقتی فاز ۱ مفاهیمِ سختِ واقعی را می‌آورد، ذهنت درگیرِ نحو نباشد.

یک چیزِ کوچک هم اینجا یاد می‌گیری که خیلی از تازه‌کارها ماه‌ها بعد کشفش می‌کنند و تا آن موقع اذیت می‌شوند: **در Rust آخرین عبارتِ یک تابع، مقدارِ بازگشتیِ آن است.** یک `;` اضافه کافی است تا این را خراب کند، و خطایش اولین بار گیج‌کننده است. همین درس هم می‌بینی‌اش.

## مفهوم

### `fn main` — جایی که همه‌چیز شروع می‌شود

کوچک‌ترین برنامه‌ی کاملِ Rust:

```rust
fn main() {
    println!("Hello, Rust!");
}
```

```text
Hello, Rust!
```

- `fn` یعنی «یک تابع تعریف می‌کنم». همان `def` در پایتون.
- `main` اسمِ خاصی است. وقتی برنامه اجرا می‌شود، سیستم‌عامل همین را صدا می‌زند. هر باینریِ اجرایی دقیقاً یکی دارد.
- `()` یعنی ورودی نمی‌گیرد.
- `{ ... }` بدنه‌ی تابع است. Rust از آکولاد استفاده می‌کند، نه از تورفتگی — پس تورفتگی برای خواندنِ توست، نه برای کامپایلر. (`cargo fmt` خودش مرتبش می‌کند؛ درسِ ۰۶.)

### `println!` و آن علامتِ تعجب

آن `!` غلطِ املایی نیست. یعنی `println!` یک **ماکرو (macro)** است، نه یک تابع.

فعلاً همین‌قدر بدان: ماکرو چیزی است که *پیش از کامپایل* به کدِ دیگری باز می‌شود. به همین دلیل `println!` می‌تواند هر تعدادی آرگومان بگیرد و رشته‌ی قالب را همان زمانِ کامپایل وارسی کند — کارهایی که یک تابعِ معمولیِ Rust نمی‌تواند بکند.

نتیجه‌ی عملی‌اش را همین حالا می‌بینی: اگر تعدادِ `{}`ها با تعدادِ آرگومان‌ها نخواند، **کامپایل نمی‌شود.** در پایتون `"{} {}".format(1)` یک `IndexError` زمانِ اجراست. اینجا یک خطای کامپایل است.

ماکروها را در فاز ۲ می‌سازی. تا آن موقع، `!` را «این یک ماکروست» بخوان و رد شو.

### قالب‌بندی: از `{}` تا `{name}`

```rust
let language = "Rust";
let day = 1;

println!("Day {} of learning {}", day, language);
println!("Day {day} of learning {language}");
```

```text
Day 1 of learning Rust
Day 1 of learning Rust
```

هر دو یک کار می‌کنند:

- **`{}`** یک جای خالی است که با آرگومانِ بعدی پر می‌شود، به ترتیب.
- **`{name}`** مستقیم اسمِ متغیری را که در دسترس است می‌گیرد. وقتی چهار تا جای خالی داری، این نسخه خیلی خواناتر است — و ترتیبشان را هم نمی‌شود اشتباه کرد.

از `{name}` استفاده کن هر وقت می‌شود. مسیرِ زبان همین است.

عرض و ترازبندی هم دارد:

```rust
println!("[{:>8}] right", "Rust");
println!("[{:<8}] left", "Rust");
println!("debug view: {:?}", "Rust");
```

```text
[    Rust] right
[Rust    ] left
debug view: "Rust"
```

آن `{:?}` نمای **دیباگ (debug)** را می‌خواهد نه نمای نمایشی — برای همین گیومه‌ها را هم نشان می‌دهد. تفاوتِ این دو، دو صفتِ متفاوت به اسمِ `Display` و `Debug` است که در فاز ۲ می‌سازی‌شان. الان فقط این را بدان: **اگر `{}` روی چیزی کار نکرد، `{:?}` را امتحان کن.** این یکی از پرکاربردترین ترفندهای دیباگِ Rust است.

### یک تابع با ورودی و خروجی

```rust
fn banner(title: &str, stars: usize) -> String {
    format!("{title} {}", "*".repeat(stars))
}
```

سه چیزِ جدید:

- **`title: &str`** — نام، بعد دو نقطه، بعد نوع. برخلافِ پایتون، این اختیاری نیست. هر پارامتر نوعش را اعلام می‌کند.
- **`-> String`** — نوعِ چیزی که تابع برمی‌گرداند. اگر تابع چیزی برنمی‌گرداند، این بخش را کلاً نمی‌نویسی.
- **`format!`** — دقیقاً مثلِ `println!` است، فقط به‌جای چاپ کردن، رشته را برمی‌گرداند. همان `f"..."` پایتون.

### آخرین عبارت، مقدارِ بازگشتی است

اینجا را با دقت بخوان، چون از پایتون نمی‌آید.

بدنه‌ی `banner` یک `return` ندارد. آخرین **عبارت (expression)** بدونِ `;` نوشته شده، و همان مقدارِ بازگشتی است.

```rust
fn double(n: u32) -> u32 {
    n * 2          // بدون سمی‌کالن: این مقدارِ بازگشتی است
}
```

اگر `;` بگذاری، معنایش عوض می‌شود:

```rust
fn double(n: u32) -> u32 {
    n * 2;         // با سمی‌کالن: این یک دستور است و مقداری برنمی‌گرداند
}
```

دومی کامپایل **نمی‌شود** — و خطایش را در بخشِ «خطاهایی که خواهی دید» عیناً می‌بینی. این احتمالاً شایع‌ترین اشتباهِ هفته‌ی اولِ همه است.

کلمه‌ی `return` هم وجود دارد و کار می‌کند، ولی در Rust برای **خروجِ زودهنگام** از وسطِ تابع به کار می‌رود، نه برای مقدارِ بازگشتیِ عادی. سبکِ اصطلاحی همان عبارتِ آخر بدونِ سمی‌کالن است.

چرایی‌اش — اینکه در Rust تقریباً همه‌چیز یک عبارت است و مقدار دارد — درسِ [۱.۱.۴ — تابع‌ها و زبانِ عبارت‌ها](../../phase1-fundamentals/01-variables-types-control-flow/03-conditionals-loops-match-intro/README.fa.md) است. الان فقط قاعده را بدان.

### `&str` و `String` — یک نگاهِ اول

در آن امضا دو نوعِ متنیِ متفاوت دیدی و این عمدی است:

- **`&str`** — متنی که **قرض گرفته‌ای**. یک نما به متنی که جای دیگری زندگی می‌کند. `"Rust"` که مستقیم در کد می‌نویسی، همین است.
- **`String`** — متنی که **مالکش هستی**. قابلِ رشد، روی هیپ.

قاعده‌ی سرانگشتی که تا فاز ۱ کافی است: **ورودی را `&str` بگیر، خروجی را `String` بده.**

چرا Rust دو تا دارد و پایتون یکی، و «قرض گرفتن» و «مالکیت» واقعاً یعنی چه — همه‌ی فاز ۱ درباره‌ی همین است. اینجا فقط داری می‌بینی‌شان، نه یاد می‌گیری‌شان. اگر الان کامل جا نیفتاد، درست است؛ قرار هم نیست.

### آن بلوکِ پایینِ `src/lib.rs`

فایلِ `src/lib.rs` را باز کن و برو پایین. این را می‌بینی:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn shouts() {
        assert_eq!(shout("here we go"), "HERE WE GO!");
    }
}
```

سه تکه دارد:

- **`#[cfg(test)]`** — یعنی «آنچه بعدش می‌آید را فقط موقعِ اجرای تست کامپایل کن». باینریِ نهایی‌ات تست‌ها را با خودش حمل نمی‌کند.
- **`#[test]`** — یک تابع را به‌عنوانِ تست علامت می‌زند. `cargo test` همه‌ی این‌ها را پیدا می‌کند و اجرا می‌کند.
- **`assert_eq!`** — یک ماکروی دیگر. اگر دو مقدار برابر نباشند، تست شکست می‌خورد و هر دو را چاپ می‌کند.

در پایتون تست‌هایت در یک پوشه‌ی `tests/` جدا زندگی می‌کنند. در Rust تست‌های کوچک **در همان فایلی که کد را تست می‌کنند** می‌مانند، در انتهایش. این تنبلی نیست — این‌طوری تست می‌تواند به توابعِ خصوصی دست بزند که بیرون نمی‌بیندشان.

خودت در فاز ۲ تست می‌نویسی. فعلاً همین‌قدر بدان که وقتی `cargo test` شکست را گزارش می‌دهد، داری به چه نگاه می‌کنی — و آن assertionی را که چاپ کرده بخوان.

### `src/lib.rs` در برابر `src/main.rs`

این درس هر دو را دارد، و تفاوتشان اهمیت دارد:

| فایل | چیست | چطور اجرا/آزمایش می‌شود |
|---|---|---|
| `src/lib.rs` | یک **کتابخانه (library)**: توابعی که دیگران — از جمله تست‌ها — صدا می‌زنند | `cargo test` |
| `src/main.rs` | یک **باینری (binary)**: برنامه‌ای که واقعاً اجرا می‌شود | `cargo run` |

`main.rs` توابعِ `lib.rs` را با `use` می‌آورد و صدا می‌زند. الگویش این است:

```text
src/lib.rs   →  منطق. تست‌پذیر. چیزی چاپ نمی‌کند.
src/main.rs  →  لبه‌ی نازک. ورودی می‌گیرد، منطق را صدا می‌زند، خروجی چاپ می‌کند.
```

این همان تفکیکی است که تمامِ فازهای بک‌اند رویش سوار می‌شوند: منطقی که می‌شود تستش کرد، جدا از I/O ای که نمی‌شود. الان که برنامه سه خط است بی‌خود به نظر می‌رسد؛ وقتی در فاز ۳ یک API واقعی داری، همین چیزی است که تست‌هایت را ممکن می‌کند.

## دست‌به‌کد

سه برنامه‌ی کوچک. اجرایشان کن، خروجی را با چیزی که بالا نوشته شده مقایسه کن، بعد تغییرشان بده.

> الان قرار است `cargo` را زیاد تایپ کنی بدون اینکه بهت گفته باشیم چیست. این عمدی است — اول باید یک برنامه را اجرا کنی، بعد ابزارِ اجرا کننده‌اش را بخوانی. [۰۴ — مبانی Cargo](../04-cargo-basics/README.fa.md) دقیقاً درسِ بعدی است و تک‌تکِ اجزای این دستورها را توضیح می‌دهد. فعلاً همین‌قدر: `-p` می‌گوید روی کدام کریت کار کن، و `--example` می‌گوید کدام فایلِ داخلِ `examples/` را اجرا کن.


```sh
cargo run -p p0-03-hello-rust --example 01-hello
cargo run -p p0-03-hello-rust --example 02-formatting
cargo run -p p0-03-hello-rust --example 03-a-function
```

بعد این‌ها را امتحان کن و ببین چه می‌شود:

۱. در `02-formatting`، یکی از `{}`ها را پاک کن ولی آرگومانش را نگه دار. چه خطایی می‌گیری؟
۲. در همان فایل، `{:>8}` را بکن `{:>20}`. چه فرقی می‌کند؟
۳. در `03-a-function`، سمی‌کالنِ آخرِ بدنه‌ی `banner` را بگذار. حالا با خطایی روبه‌رو می‌شوی که بخشِ بعد توضیحش می‌دهد — اول خودت بخوانش.

## خطاهایی که خواهی دید

### `E0308` — یک سمی‌کالنِ اضافه

فایلِ `examples/04-wrong-return.rs` دقیقاً همین اشتباه را دارد:

```sh
cargo run -p p0-03-hello-rust --example 04-wrong-return --features broken
```

```text
error[E0308]: mismatched types
  --> phase0-setup\04-hello-rust\examples\04-wrong-return.rs:10:41
   |
10 | fn banner(title: &str, stars: usize) -> String {
   |    ------                               ^^^^^^ expected `String`, found `()`
   |    |
   |    implicitly returns `()` as its body has no tail or `return` expression
11 |     format!("{title} {}", "*".repeat(stars));
   |                                             - help: remove this semicolon to return this value
```

**کامپایلر از چه چیزی شاکی است:** تابع گفته `String` برمی‌گرداند، ولی بدنه‌اش چیزی برنمی‌گرداند. آن `()` — که «یونیت (unit)» خوانده می‌شود — نوعِ «هیچ مقدارِ معناداری» است؛ نزدیک‌ترین معادلش `None` در پایتون است، با این تفاوت که یک نوعِ واقعی است.

آن برچسبِ `----` روی اسمِ تابع دقیقاً می‌گوید چرا: *implicitly returns `()` as its body has no tail or `return` expression*.

**راهِ حل:** سمی‌کالنِ خطِ ۱۱ را بردار.

**چرا این راهِ حل درست است:** با سمی‌کالن، آن خط یک **دستور (statement)** است — کاری انجام می‌شود و مقدارش دور ریخته می‌شود. بدونِ سمی‌کالن یک **عبارت (expression)** است و مقدارش از تابع بیرون می‌آید. کامپایلر آن‌قدر مطمئن است که خودش هم می‌گوید: *remove this semicolon to return this value*.

وقتی این خطا را دیدی، اول از همه دنبالِ یک سمی‌کالنِ اضافه در خطِ آخرِ تابع بگرد. نُه بار از ده بار همان است.

### ماکرویی که وجود ندارد

```sh
cargo run -p p0-03-hello-rust --example 05-unknown-macro --features broken
```

```text
error: cannot find macro `printn` in this scope
  --> phase0-setup\04-hello-rust\examples\05-unknown-macro.rs:7:5
   |
 7 |     printn!("Hello, Rust!");
   |     ^^^^^^
   |
  ::: C:\Users\khmja\.rustup\toolchains\stable-x86_64-pc-windows-msvc\lib/rustlib/src/rust\library\std\src\macros.rs:85:1
   |
85 | macro_rules! print {
   | ------------------ similarly named macro `print` defined here
   |
help: a macro with a similar name exists
   |
 7 -     printn!("Hello, Rust!");
 7 +     print!("Hello, Rust!");
   |
```

**دو نکته‌ی جالب در این یکی:**

**اول: کدِ خطا ندارد.** فقط `error:` است، بدونِ `[E0433]`. همه‌ی خطاهای `rustc` کد ندارند — پس اگر روی چیزی `--explain` نداشتی، اشتباه نکرده‌ای؛ آن خطا فقط کد ندارد.

**دوم: آن `:::` به کتابخانه‌ی استاندارد اشاره می‌کند.** کامپایلر رفته در `library/std/src/macros.rs` گشته و `print!` را پیدا کرده. یعنی برچسب‌ها می‌توانند به فایل‌هایی خارج از پروژه‌ی تو هم اشاره کنند — این بعداً وقتی خطا از داخلِ یک کتابخانه‌ی خارجی می‌آید، خیلی مفید است.

**راهِ حل:** `printn!` را بکن `println!`. (حواست باشد پیشنهادِ کامپایلر `print!` است، نه `println!` — و آن‌ها فرق دارند: `print!` سرِ خط نمی‌رود. کامپایلر نزدیک‌ترین اسم را پیشنهاد می‌دهد، نه لزوماً چیزی که تو می‌خواستی. پیشنهادها را بخوان، کورکورانه قبول نکن.)

## تمرین

### گرم‌کردن

<details>
<summary>این کامپایل می‌شود؟ <code>println!("{} and {}", "a");</code></summary>

نه. دو تا `{}` هست و یک آرگومان. چون `println!` یک ماکروست، رشته‌ی قالب همان زمانِ کامپایل وارسی می‌شود. در پایتون معادلش یک خطای زمانِ اجرا بود.

</details>

<details>
<summary>این تابع چه چیزی برمی‌گرداند؟<br><code>fn f(n: u32) -> u32 { n + 1 }</code></summary>

`n + 1`. آخرین عبارتِ بدونِ سمی‌کالن، مقدارِ بازگشتی است. `return` لازم نیست.

</details>

<details>
<summary>و این یکی؟<br><code>fn f(n: u32) -> u32 { n + 1; }</code></summary>

هیچی — و برای همین کامپایل نمی‌شود. آن سمی‌کالن، عبارت را به دستور تبدیل می‌کند؛ تابع `()` برمی‌گرداند در حالی که `u32` وعده داده بود. خطایش `E0308` است.

</details>

<details>
<summary><code>cargo run</code> کدام فایل را اجرا می‌کند: <code>src/lib.rs</code> یا <code>src/main.rs</code>؟</summary>

`src/main.rs` — چون `fn main` آنجاست. `src/lib.rs` توابع را نگه می‌دارد و `cargo test` آن را می‌آزماید؛ خودش به‌تنهایی اجرا نمی‌شود.

</details>

```sh
cargo test -p p0-03-hello-rust
```

بعد ببین برنامه‌ی واقعی هم کار می‌کند:

```sh
cargo run -p p0-03-hello-rust
```

### بساز

`src/main.rs` را طوری تغییر بده که یک نوارِ پیشرفتِ کوچک برای همین دوره چاپ کند — مثلاً دو درس از هفت درسِ فاز ۰.

بعد فراتر برو: چند خط چاپ کن که با هم یک خروجیِ مرتب بسازند. از تنظیمِ عرض (`{:>8}`) استفاده کن تا ستون‌ها زیرِ هم بیفتند. هدف این است که با `println!` راحت شوی، چون از این به بعد ابزارِ اصلیِ دیباگت است.

### چالش (اختیاری)

`format!` رشته می‌سازد و `println!` چاپ می‌کند. یک سومی هم هست: `eprintln!` که روی **خطای استاندارد (stderr)** می‌نویسد نه خروجیِ استاندارد.

امتحان کن. بعد این را اجرا کن و ببین چه اتفاقی می‌افتد:

```sh
cargo run -p p0-03-hello-rust > out.txt
```

کدام خط‌ها در `out.txt` رفتند و کدام‌ها روی صفحه ماندند؟ همین تفکیک است که در فاز ۴ اجازه می‌دهد لاگ و خروجی را از هم جدا کنی.

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به‌کارت می‌آید |
|---|---|---|
| `fn main` | نقطه‌ی شروعِ برنامه | هر باینریِ اجرایی |
| ماکرو (`println!`) | چیزی که پیش از کامپایل به کد باز می‌شود؛ `!` نشانه‌اش است | چاپ، `format!`، `vec!`، و خیلی چیزهای بعدی |
| `{}` و `{name}` | جای خالی در رشته‌ی قالب | هر خروجی و هر پیامِ خطا |
| `{:?}` | نمای دیباگ به‌جای نمای نمایشی | وقتی `{}` روی یک نوع کار نمی‌کند |
| عبارت در برابر دستور | با سمی‌کالن مقدار دور ریخته می‌شود، بدونش برگردانده می‌شود | هر تابعی که می‌نویسی |
| `()` (یونیت) | نوعِ «هیچ مقدارِ معناداری» | خطای `E0308` روی مقدارِ بازگشتی |
| `&str` / `String` | متنِ قرض‌گرفته / متنِ مالک‌شده | همه‌جا؛ فاز ۱ کامل توضیحش می‌دهد |
| `lib.rs` / `main.rs` | منطقِ تست‌پذیر / لبه‌ی اجرایی | ساختارِ هر پروژه‌ی جدی |

### الان می‌دانی

- یک برنامه‌ی Rust از `fn main` شروع می‌شود.
- `println!` یک ماکروست و رشته‌ی قالبش زمانِ کامپایل وارسی می‌شود.
- `{name}` روشِ ترجیحیِ قالب‌بندی است و `{:?}` وقتی `{}` کار نمی‌کند.
- آخرین عبارتِ بدونِ سمی‌کالن، مقدارِ بازگشتیِ تابع است.
- `&str` را ورودی می‌گیری و `String` را خروجی می‌دهی.
- `lib.rs` منطق است و `main.rs` لبه.

### بعداً کامل‌تر می‌بینی

- **خواندنِ خطاهای کامپایلر** — همان `E0308` بالا، به‌طورِ کامل: [۰۵ — خواندنِ خطاهای کامپایلر](../05-reading-compiler-errors/README.fa.md)
- **عبارت در برابر دستور، و اینکه چرا `if` هم مقدار دارد** — [فاز ۱ — جریانِ کنترل](../../phase1-fundamentals/01-variables-types-control-flow/03-conditionals-loops-match-intro/README.fa.md)
- **`&str` در برابر `String` به‌طورِ واقعی** — [فاز ۱ — رشته و برش](../../phase1-fundamentals/04-strings-and-slices/01-string-vs-str/README.fa.md)
- **`Display` و `Debug` را خودت پیاده‌سازی کنی** — [فاز ۲ — جنریک و صفت‌ها](../../phase2-intermediate/03-generics-and-traits/README.fa.md)
- **ساختنِ ماکروی خودت** — [فاز ۲ — ماکروها](../../phase2-intermediate/08-rust-toolbox/02-macro-rules-basics/README.fa.md)

### می‌توانی توضیح بدهی؟

- `fn main` چه چیزِ خاصی دارد؟
- آن `!` در `println!` یعنی چه، و یک نتیجه‌ی عملی‌اش را بگو.
- بین `println!("{}", x)` و `println!("{x}")` کدام را ترجیح می‌دهی و چرا؟
- یک تابع چطور مقدار برمی‌گرداند، و یک سمی‌کالنِ اضافه چه بلایی سرش می‌آورد؟
- `()` چیست؟
- چرا این درس هم `lib.rs` دارد هم `main.rs`؟
