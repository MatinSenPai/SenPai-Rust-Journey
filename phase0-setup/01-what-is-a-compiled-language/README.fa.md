# ۰۱ — زبان کامپایل‌شده چیست؟

در این درس کدی نمی‌نویسیم. متین، پیش از نصب هر چیزی این صفحه را بخوان؛ وقتی تفاوت اجرا در Python و Rust روشن شود، ادامه‌ی مسیر بسیار منطقی‌تر خواهد شد.

## Python از کجا شروع می‌کند؟

وقتی `python manage.py runserver` را اجرا می‌کنی، برنامه‌ی `python3` فایل‌های `.py` را می‌خواند، آن‌ها را به bytecode تبدیل می‌کند و virtual machine پایتون آن را اجرا می‌کند. جزئیات پیاده‌سازی میان interpreterها فرق دارد، اما نکته‌ی عملی این است که برای تو مرحله‌ی ساخت مستقل و فایل اجرایی بومی وجود ندارد.

- `python foo.py` مستقیماً اجرا می‌شود.
- خطای مسیری که هرگز اجرا نشده ممکن است تا runtime پنهان بماند؛ البته parser و ابزار‌های static analysis بعضی خطا‌ها را زودتر می‌گیرند.
- برای توزیع، معمولاً کد منبع و Python سازگار لازم است یا باید interpreter را با ابزاری مثل PyInstaller بسته‌بندی کنی.

## Rust از کجا شروع می‌کند؟

Rust پیشاپیش کامپایل می‌شود. `cargo build`، کامپایلر یعنی `rustc` را اجرا می‌کند؛ برنامه نوع-check و borrow-check می‌شود و سپس یک فایل اجرایی شامل دستور‌های ماشین ساخته می‌شود.

- خطای نوع، نقض قواعد قرض‌گیری و بسیاری از ایراد‌های حافظه پیش از اجرا متوقف می‌شوند.
- فایل اجرایی روی سیستم‌عامل و معماری سازگار بدون نصب toolchain Rust اجرا می‌شود؛ وابستگی به کتابخانه‌های سیستم و target همچنان مهم است.
- کامپایل زمان واقعی می‌برد. `cargo run` فقط ساخت و اجرا را پشت‌سرهم انجام می‌دهد.

## مثال فارسی روزمره

Python شبیه آشپزی با مترجمی است که دستور را هنگام کار می‌خواند. Rust شبیه ویراستار سخت‌گیری است که کل دستور پخت را پیشاپیش بررسی می‌کند و بعد نسخه‌ای مستقل برای اجرا تحویل می‌دهد.

## قانون دقیق و مرز تشبیه

کامپایلر نمی‌تواند درست‌بودن منطق کسب‌وکار را تضمین کند؛ کدی که سفارش اشتباه را کاملاً نوع-safe ثبت می‌کند ممکن است بدون خطا کامپایل شود. همچنین Python صرفاً «خط‌به‌خط ترجمه» نمی‌شود و معمولاً bytecode دارد؛ تشبیه فقط تفاوت بررسی پیش از اجرا و هنگام اجرا را نشان می‌دهد.

## پل به بک‌اند

در Django ممکن است یک شاخه‌ی کم‌استفاده نخستین‌بار در محیط واقعی خطا بدهد. Rust بسیاری از خطاهای نوع و حافظه‌ی همان شاخه را در CI پیدا می‌کند، اما برای رفتار HTTP و پایگاه داده هنوز آزمون لازم است.
