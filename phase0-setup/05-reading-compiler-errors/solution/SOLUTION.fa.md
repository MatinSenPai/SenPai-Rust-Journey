# راه‌حل — ۰۵ خواندنِ خطاهای کامپایلر

```rust
pub fn total_items(orders: u32, per_order: u32) -> u32 {
    orders * per_order
}

pub fn boxes_needed(items: u32, per_box: u32) -> u32 {
    items.div_ceil(per_box)
}

pub fn title_len(title: &str) -> usize {
    title.len()
}
```

## `total_items`

چیزی برای گفتن ندارد، و همین نکته است: یک تابعِ ضرب باید یک خط باشد. اگر بیشتر نوشتی، احتمالاً `return` گذاشته‌ای یا سمی‌کالنِ اضافه داری — همان دو چیزی که در درسِ ۰۳ دیدی.

## `boxes_needed` — و اینکه چرا `div_ceil` بهترین جواب است

احتمالاً یکی از این‌ها را نوشته‌ای:

```rust
// نسخه‌ی دستی
if items % per_box == 0 {
    items / per_box
} else {
    items / per_box + 1
}

// ترفندِ کلاسیک
(items + per_box - 1) / per_box

// روشِ کتابخانه‌ی استاندارد
items.div_ceil(per_box)
```

**هر سه برای ورودی‌های این تست درست‌اند.** ولی یکسان نیستند:

- نسخه‌ی دستی درست است و خواناست، فقط طولانی. اگر این را نوشته‌ای، هیچ اشکالی ندارد.
- ترفندِ `(items + per_box - 1)` همان چیزی است که در C و جاوا می‌بینی، و **یک تله دارد**: اگر `items` نزدیکِ بیشینه‌ی `u32` باشد، آن جمع سرریز می‌کند. در حالتِ debug برنامه پنیک می‌کند، در حالتِ release بی‌سروصدا عددِ اشتباه می‌دهد. این دقیقاً همان دسته باگی است که [فاز ۱ — انواعِ عددی و سرریز](../../../phase1-fundamentals/01-variables-types-control-flow/02-scalar-and-compound-types/README.fa.md) درباره‌اش است.
- `div_ceil` از سمتِ خودِ کتابخانه‌ی استاندارد می‌آید، سرریز ندارد، و اسمش می‌گوید چه‌کار می‌کند.

**درسِ عمومی‌اش:** پیش از اینکه ریاضیِ عددصحیح را دستی بنویسی، ببین `u32` خودش متدی برایش دارد. معمولاً دارد، و معمولاً حالت‌های لبه را هم درست‌تر از تو مدیریت کرده.

## `title_len` — بایت، نه کاراکتر

`title.len()` تعدادِ **بایت‌ها** را می‌دهد، نه کاراکترها. تست عمداً این را نشان می‌دهد:

```rust
assert_eq!(title_len("Frieren"), 7);   // اسکی: بایت و کاراکتر یکی‌اند
assert_eq!(title_len("سلام"), 8);      // فارسی: چهار کاراکتر، هشت بایت
```

اگر انتظار داشتی `۴` بدهد، بسیار هم منطقی بوده — و همین‌جاست که Rust با پایتون فرق دارد. در پایتون `len("سلام")` می‌شود ۴، چون رشته‌های پایتون دنباله‌ای از کاراکترند. در Rust رشته‌ها UTF-8 هستند و `len()` بایت می‌شمارد، چون این تنها چیزی است که در زمانِ ثابت قابلِ محاسبه است.

اگر کاراکتر می‌خواستی:

```rust
title.chars().count()   // ۴ برای "سلام"
```

که یک پیمایشِ کاملِ رشته است — زمانِ خطی، نه ثابت. Rust این هزینه را از تو پنهان نمی‌کند، و همین است که این دو متد اسم‌های متفاوت دارند.

این موضوع درسِ اختصاصیِ خودش را دارد: [فاز ۱ — یوتی‌اف-۸، بایت، کاراکتر](../../../phase1-fundamentals/04-strings-and-slices/01-string-vs-str/README.fa.md). به‌عنوانِ کسی که با متنِ فارسی کار می‌کند، این یکی از مهم‌ترین درس‌های کلِ فاز ۱ برای توست.
