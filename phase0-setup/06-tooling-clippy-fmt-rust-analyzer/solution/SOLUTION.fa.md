# راه‌حل — ۰۶ ابزارها

هر تغییرِ زیر رفتار را دست‌نخورده نگه می‌دارد. `cargo test` در تمامِ مدت سبز می‌ماند؛ فقط سبک جابه‌جا می‌شود.

| بود | شد | لینت |
|---|---|---|
| `name: &String` | `name: &str` | `ptr_arg` |
| `name.len() == 0` | `name.is_empty()` | `len_zero` |
| `return x * 2;` | `x * 2` | `needless_return` |
| `if flag == true { true } else { false }` | `flag` | `bool_comparison`، `needless_bool` |
| `let counted = ...; counted` | مستقیم برگردانش | `let_and_return` |
| `for i in 0..nums.len() { total += nums[i] }` | `nums.iter().sum()` | `needless_range_loop` |
| `match opt { Some(x) => x, None => 0 }` | `opt.unwrap_or_default()` | `manual_unwrap_or_default` |

## دو تایی که ارزشِ مکث دارند

### `&String` به `&str` آرایشی نیست

```rust
pub fn is_empty_name(name: &str) -> bool
```

این تنها تغییری است که کارِ فراخوانندگان را عوض می‌کند — و آن را *بازتر* می‌کند، پس چیزی نمی‌شکند. پیش از این تغییر، این‌ها خطای کامپایل بودند:

```rust
is_empty_name("");                       // یک &str ثابت، نه &String
is_empty_name(&some_string[0..0]);       // یک برش، نه &String
```

بعدش همه‌شان کار می‌کنند و هیچ‌کدام حافظه نمی‌گیرند. این لینت درباره‌ی شکلِ API توست، نه بهینه‌سازیِ ریز.

هر چیزی که `&String` باشد مجانی به `&str` تبدیل می‌شود — Rust این تبدیل را همان سرِ فراخوانی خودکار انجام می‌دهد. عکسش تخصیصِ حافظه می‌خواهد. پس `&str` همیشه و بی‌استثنا نوعِ پارامترِ مفیدتری است.

### `for i in 0..nums.len()` به `.iter().sum()`

دو بهبودِ جدا که در هم تا شده‌اند:

۱. **پیمایش به‌جای ایندکس‌گذاری.** `nums[i]` هر بار یک بررسیِ محدوده انجام می‌دهد. `nums.iter()` ذاتاً نمی‌تواند از محدوده بیرون بزند، پس چیزی برای بررسی نیست. هم امن‌تر، هم سریع‌تر — یکی از آن موردهای نادر که این دو با هم جور در می‌آیند.
۲. **`sum()` به‌جای یک انباشتگر.** در یک کلمه می‌گوید چه‌کار می‌کند.

اگر `nums.iter().fold(0, |acc, x| acc + x)` نوشته‌ای، آن هم درست است و دقیقاً همان کاری است که `sum()` زیرش می‌کند. نسخه‌ی نام‌دار را ترجیح بده.

## درباره‌ی `cargo clippy --fix`

پنج تا از هفت مورد را خودکار درست می‌کرد. استفاده از آن در کارِ واقعی هیچ اشکالی ندارد.

استفاده از آن **اینجا** نکته‌ی درس را رد می‌کرد. تمرین آن هفت ویرایش نبود — خواندنِ هر هشدار و توانستنِ گفتنِ اینکه چرا درست است بود. همین مهارت است که clippy را از یک غرغروی مزاحم به یک معلم تبدیل می‌کند، و فقط با خواندن ساخته می‌شود.

## کِی با clippy مخالفت کنی

جوابِ واقعی: در سالِ اول، به‌ندرت. تقریباً هر هشداری که می‌گیری درست است، و آن‌هایی که نیستند معمولاً لینت‌های `pedantic`اند که خودت روشنشان کرده‌ای.

ولی وقتی پیش آمد، مکانیزمش مهم است:

```rust
// این درس عمداً این حلقه را غیراصطلاحی نگه می‌دارد: نشان دادنِ همان چیزی که
// clippy ازش بدش می‌آید، کلِ کارِ این مثال است.
#[allow(clippy::needless_range_loop)]
fn sum_verbose(nums: &[i32]) -> i32 {
```

آن کامنت تزئین نیست. شش ماه بعد تنها چیزی است که به خواننده‌ی بعدی — که احتمالاً خودتی — می‌گوید آیا آن `allow` هنوز جایش را حق دارد یا نه.
