# ۰۶ — ابزارها: clippy، fmt، rust-analyzer

## در یک نگاه

بعد از این درس می‌توانی:

- یک هشدارِ `clippy` را بخوانی، بفهمی *چرا* دارد اعتراض می‌کند، و تصمیم بگیری بپذیری‌اش یا نه.
- بگویی `cargo fmt` و `cargo fmt -- --check` چه فرقی دارند و کدام در CI اجرا می‌شود.
- بگویی rust-analyzer چیست و چرا وقتی کار نمی‌کند، Rust نوشتن دو برابر سخت‌تر می‌شود.

**زمان:** حدود ۴۰ دقیقه · **پیش‌نیاز:** [۰۵ — خواندنِ خطاهای کامپایلر](../05-reading-compiler-errors/README.fa.md)

---

## چرا اهمیت دارد

کامپایلر بهت می‌گوید کدت **کار می‌کند یا نه**. این ابزارها بهت می‌گویند کدت **خوب است یا نه**.

و برخلافِ دنیای پایتون که هر تیم `black` یا `yapf` یا هیچی را انتخاب می‌کند و سرِ طولِ خط بحث می‌شود، در Rust عملاً یک سبک وجود دارد و همه‌جا همان است. این خودش یک آزادی است: هیچ‌وقت درباره‌ی فرمت بحث نمی‌کنی.

بخشِ مهم‌تر `clippy` است. `clippy` فقط یک لینتر نیست؛ برای یک تازه‌کارِ Rust یک **معلمِ سبک** است. مدام می‌گوید «کارت درست است، ولی روشِ اصطلاحی این است» — و توضیح می‌دهد چرا. اگر ماهِ اول هر هشدارش را بخوانی، به‌جای اینکه کورکورانه بپذیری، سریع‌تر از هر کتابی Rust اصطلاحی یاد می‌گیری.

این درس با بقیه فرق دارد: **کد از قبل کار می‌کند و تست‌هایش سبزند.** کارِ تو درست کردنش نیست، بهترش کردن است.

## مفهوم

### `rustfmt` — بحثِ سبک تمام شد

```sh
cargo fmt              # همه‌ی فایل‌ها را در جا مرتب کن
cargo fmt -- --check   # چیزی را عوض نکن؛ فقط بگو آیا لازم است
```

دومی همان چیزی است که CI اجرا می‌کند: اگر چیزی فرمت‌نشده باشد، با کدِ خروجیِ غیرصفر شکست می‌خورد و diff را چاپ می‌کند.

نزدیک‌ترین معادلش `black` است، با دو تفاوت:

- **بخشی از خودِ زنجیره‌ابزار است**، نه یک بسته‌ی جانبی. `rustup component add rustfmt` و تمام.
- **یک سبکِ پیش‌فرض دارد که تقریباً هیچ‌کس عوضش نمی‌کند.** `rustfmt.toml` وجود دارد، ولی در پروژه‌های واقعی خیلی کم می‌بینی‌اش.

پیشنهاد: در ویرایشگرت «format on save» را روشن کن و از این به بعد اصلاً بهش فکر نکن.

### `clippy` — فراتر از «کامپایل می‌شود»

```sh
cargo clippy                      # لینت کن
cargo clippy --all-targets        # تست‌ها و مثال‌ها را هم لینت کن
cargo clippy -- -D warnings       # هر هشدار را خطا حساب کن (کارِ CI)
cargo clippy --fix                # پیشنهادهای امن را خودکار اعمال کن
```

`clippy` بیش از ۷۵۰ لینت دارد، دسته‌بندی‌شده:

| دسته | یعنی چه | پیش‌فرض |
|---|---|---|
| `correctness` | تقریباً حتماً یک باگ است | خطا |
| `suspicious` | احتمالاً یک باگ است | هشدار |
| `style` | کار می‌کند، ولی اصطلاحی نیست | هشدار |
| `complexity` | می‌شود ساده‌ترش نوشت | هشدار |
| `perf` | می‌شود سریع‌ترش کرد | هشدار |
| `pedantic` | نظرِ سلیقه‌ای، گاهی مفید | خاموش |
| `nursery` | لینت‌های در حالِ توسعه | خاموش |

آن ردیفِ `correctness` را ببین: `clippy` فقط سلیقه نیست. بعضی لینت‌هایش باگ‌های واقعی می‌گیرند که کامپایلر نمی‌گیرد.

### خواندنِ یک هشدارِ `clippy`

شکلش دقیقاً همان تشخیصِ کامپایلر است که در درسِ ۰۵ یاد گرفتی، به‌علاوه‌ی دو خطِ اضافه:

```text
warning: writing `&String` instead of `&str` involves a new object where a slice will do
 --> phase0-setup\06-tooling-clippy-fmt-rust-analyzer\src\lib.rs:9:28
  |
9 | pub fn is_empty_name(name: &String) -> bool {
  |                            ^^^^^^^
  |
  = help: for further information visit https://rust-lang.github.io/rust-clippy/rust-1.97.0/index.html#ptr_arg
  = note: `#[warn(clippy::ptr_arg)]` on by default
help: change this to
  |
9 - pub fn is_empty_name(name: &String) -> bool {
9 + pub fn is_empty_name(name: &str) -> bool {
  |
```

دو خطِ جدید نسبت به خطاهای کامپایلر:

- **`= help: for further information visit ...#ptr_arg`** — لینکِ صفحه‌ی توضیحِ همین لینت. آن صفحه *چرایی* را با مثال توضیح می‌دهد. بخوانش؛ همان‌جاست که یاد می‌گیری.
- **`= note: #[warn(clippy::ptr_arg)] on by default`** — **اسمِ** لینت. لازمش داری وقتی بخواهی خاموشش کنی.

### وقتی `clippy` اشتباه می‌کند

گاهی درست می‌گوید ولی برای موردِ تو نه. آن‌وقت خاموشش می‌کنی:

```rust
#[allow(clippy::needless_range_loop)]
fn sum_verbose(nums: &[i32]) -> i32 {
    // ...
}
```

**قاعده‌ای که باید به آن پایبند باشی: هر `#[allow(...)]` باید دلیل داشته باشد، نوشته‌شده، درست کنارش.** `allow`ِ بی‌دلیل یعنی «حالش را نداشتم»، و شش ماه بعد کسی — احتمالاً خودت — نمی‌داند آیا هنوز لازم است یا نه.

مثالِ `examples/01-before-and-after.rs` همین درس یکی دارد و دلیلش را هم نوشته: آن تابع عمداً غیراصطلاحی است، چون کارش نشان دادنِ همان چیزی است که clippy از آن بدش می‌آید.

### `rust-analyzer` — کامپایلر، داخلِ ویرایشگر

rust-analyzer یک **سرورِ زبان (language server)** است: در پس‌زمینه کدت را همان‌طور که تایپ می‌کنی تحلیل می‌کند و به ویرایشگرت خبر می‌دهد.

چه چیزی بهت می‌دهد:

- **خطاها همان لحظه**، پیش از اینکه `cargo check` بزنی.
- **راهنمای نوعِ درون‌خطی (inlay hints)** — نوعِ متغیرهایی که خودت ننوشته‌ای را کنارشان نشان می‌دهد. برای یادگیری فوق‌العاده است: می‌بینی کامپایلر چه چیزی استنتاج کرده.
- **پرش به تعریف** — روی هر تابعی از هر کتابخانه‌ای کلیک کنی، منبعش را می‌بینی.
- **اقدامات سریع** — `use` گمشده را اضافه می‌کند، تابعِ ناموجود را می‌سازد، `match` را کامل می‌کند.

اگر ویرایشگرت راهنمای نوع نشان نمی‌دهد، کارِ Rust برایت دو برابر سخت‌تر است و لازم نیست باشد. تنظیماتش در [`docs/setup-guide.fa.md`](../../docs/setup-guide.fa.md) است.

**نکته‌ای که خیلی‌ها نمی‌دانند:** rust-analyzer و `cargo clippy` دو چیزِ جدا هستند. rust-analyzer به‌طور پیش‌فرض `cargo check` را اجرا می‌کند، نه clippy. در VS Code می‌شود عوضش کرد:

```json
"rust-analyzer.check.command": "clippy"
```

از آن به بعد هشدارهای clippy را همان موقعِ تایپ کردن می‌بینی. برای یادگیری، این یکی از پرارزش‌ترین تنظیماتی است که می‌توانی روشن کنی.

### در CI

فایلِ `.github/workflows/ci.yml` همین مخزن این‌ها را اجرا می‌کند:

```sh
cargo fmt --all -- --check
cargo clippy ... -- -D warnings
```

آن `-D warnings` یعنی «هر هشدار را خطا حساب کن». پس CI روی هر هشداری قرمز می‌شود.

**اما فقط روی کدی که تمام است.** اسکلتِ درس‌ها عمداً ناتمام‌اند: بدنه‌های `todo!()` باعث می‌شوند پارامترها استفاده‌نشده بمانند، و clippy درست می‌گوید که هشدار می‌دهد — ولی آن هشدارها همان راهنماییِ درس‌اند، نه خطای CI. برای همین CI فقط `course-ui`، `lesson-lint` و کریت‌های capstone را سخت‌گیرانه لینت می‌کند.

## دست‌به‌کد

اول ببین «قبل و بعد» چه شکلی است:

```sh
cargo run -p p0-06-tooling-clippy-fmt --example 01-before-and-after
```

```text
verbose: 14
idiomatic: 14
```

دقیقاً یک نتیجه، دو سبک. حالا سراغِ کدِ اصلی برو.

**۱. اول ثابت کن چیزی خراب نیست:**

```sh
cargo test -p p0-06-tooling-clippy-fmt
```

```text
test result: ok. 7 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out
```

**۲. حالا `clippy` را بزن:**

```sh
cargo clippy -p p0-06-tooling-clippy-fmt
```

هفت هشدار می‌گیری. **همه‌شان را بخوان** — نه فقط پیشنهادها را، خودِ توضیح‌ها را.

**۳. فرمت را عمداً خراب کن.** یک تابع را بردار و فاصله‌ها و تورفتگی‌اش را به هم بریز. بعد:

```sh
cargo fmt -- --check      # ببین چطور شکایت می‌کند بدونِ اینکه چیزی را عوض کند
cargo fmt                 # حالا بگذار درستش کند
cargo fmt -- --check      # و ساکت شد
```

## خطاهایی که خواهی دید

این‌ها هشدارند نه خطا — کد کامپایل می‌شود و تست‌ها سبزند. ولی هر کدام چیزی یادت می‌دهند.

### `clippy::ptr_arg` — `&String` جایی که `&str` کافی است

```text
warning: writing `&String` instead of `&str` involves a new object where a slice will do
 --> src/lib.rs:9:28
  |
9 | pub fn is_empty_name(name: &String) -> bool {
  |                            ^^^^^^^
  |
help: change this to
  |
9 - pub fn is_empty_name(name: &String) -> bool {
9 + pub fn is_empty_name(name: &str) -> bool {
```

**چرا اهمیت دارد:** تابعی که `&String` می‌گیرد فقط `String` قبول می‌کند. تابعی که `&str` می‌گیرد `String` **و** رشته‌ی ثابت **و** برشی از یک رشته‌ی بزرگ‌تر را قبول می‌کند — و هیچ‌کدام چیزی کپی نمی‌کنند. سخت‌گیریِ بی‌دلیل بود.

همان قاعده‌ی سرانگشتیِ درسِ ۰۳ است: **`&str` بگیر، `String` بده.** clippy دارد همان را با فشار یادت می‌دهد.

### `clippy::len_zero` — `is_empty()` به‌جای `len() == 0`

```text
warning: length comparison to zero
  --> src/lib.rs:10:5
   |
10 |     name.len() == 0
   |     ^^^^^^^^^^^^^^^ help: using `is_empty` is clearer and more explicit: `name.is_empty()`
```

**چرا اهمیت دارد:** خواناتر است، و برای بعضی نوع‌ها `is_empty()` ارزان‌تر از محاسبه‌ی کلِ طول است. یک لینتِ `style` که یک لینتِ `perf` هم هست.

### `clippy::needless_return` — `return`ِ اضافه

```text
warning: unneeded `return` statement
  --> src/lib.rs:15:5
   |
15 |     return x * 2;
   |     ^^^^^^^^^^^^
   |
help: remove `return`
   |
15 -     return x * 2;
15 +     x * 2
```

**چرا اهمیت دارد:** همان قاعده‌ی درسِ ۰۳ — آخرین عبارت مقدارِ بازگشتی است. `return` را برای خروجِ زودهنگام نگه دار، نه برای بازگشتِ عادی. اینجا clippy دارد کمکت می‌کند عادتِ پایتونی را بگذاری کنار.

### `clippy::needless_range_loop` — حلقه با ایندکسِ دستی

```text
warning: the loop variable `i` is only used to index `nums`
  --> src/lib.rs:36:14
   |
36 |     for i in 0..nums.len() {
   |              ^^^^^^^^^^^^^
   |
help: consider using an iterator
   |
36 -     for i in 0..nums.len() {
36 +     for <item> in &nums {
```

**چرا اهمیت دارد:** ایندکس‌گذاریِ دستی همان عادتِ کلاسیکی است که از زبان‌های دیگر می‌آید، و خطای «یکی کم یا زیاد» (off-by-one) از همان‌جا می‌آید. پیمایشِ مستقیم آن دسته را کاملاً حذف می‌کند — و در Rust بررسیِ محدوده هم دیگر لازم نیست انجام شود.

آن `<item>` در پیشنهاد یک جای خالی است؛ خودت اسمِ معنادار بگذار.

### `clippy::manual_unwrap_or_default` — `match`ی که یک متد دارد

```text
warning: match can be simplified with `.unwrap_or_default()`
  --> src/lib.rs:49:5
   |
49 | /     match opt {
50 | |         Some(x) => x,
51 | |         None => 0,
52 | |     }
   | |_____^ help: replace it with: `opt.unwrap_or_default()`
```

**چرا اهمیت دارد:** `Option` ده‌ها متدِ آماده دارد و تقریباً هر `match`ی که رویش می‌نویسی، احتمالاً یکی از آن‌ها هست. این را در [فاز ۱ — Option](../../phase1-fundamentals/06-absence-and-failure/01-option-and-null-safety/README.fa.md) کامل می‌بینی. الان فقط بدان که clippy این‌ها را بلد است و بهت یادشان می‌دهد.

## تمرین

### گرم‌کردن

<details>
<summary><code>cargo fmt</code> و <code>cargo fmt -- --check</code> چه فرقی دارند؟</summary>

اولی فایل‌ها را در جا مرتب می‌کند. دومی چیزی را عوض نمی‌کند و فقط می‌گوید آیا لازم است — با کدِ خروجیِ غیرصفر اگر لازم باشد. CI دومی را می‌زند.

</details>

<details>
<summary><code>clippy</code> فقط سلیقه است؟</summary>

نه. دسته‌ی `correctness` باگ‌های واقعی می‌گیرد که کامپایلر نمی‌گیرد، و به‌طور پیش‌فرض خطاست نه هشدار. `style` و `complexity` سلیقه‌ای‌ترند، ولی سلیقه‌ی جمعیِ کلِ اکوسیستم.

</details>

<details>
<summary>یک هشدار می‌گیری و مطمئنی که برای موردِ تو اشتباه است. چه‌کار می‌کنی؟</summary>

`#[allow(clippy::the_lint_name)]` می‌گذاری **به‌همراهِ یک کامنت که می‌گوید چرا**. اسمِ لینت در خطِ `note:` همان هشدار نوشته شده. `allow`ِ بی‌دلیل، بدهیِ فنی است.

</details>

<details>
<summary>rust-analyzer به‌طور پیش‌فرض clippy را اجرا می‌کند؟</summary>

نه، `cargo check` را. برای اینکه هشدارهای clippy را حینِ تایپ ببینی، `rust-analyzer.check.command` را روی `"clippy"` بگذار.

</details>

### تعمیر

هر هفت هشدار را در `src/lib.rs` برطرف کن، تا اینجا ساکت شود:

```sh
cargo clippy -p p0-06-tooling-clippy-fmt
```

**دو قاعده:**

۱. `cargo test -p p0-06-tooling-clippy-fmt` باید در تمامِ مدت سبز بماند. رفتار عوض نمی‌شود، فقط سبک.
۲. برای هر تغییر، پیش از اینکه انجامش بدهی، بگو **چرا** clippy درست می‌گوید. اگر نمی‌توانی، لینکِ `help:` را باز کن و بخوان.

نکته: `cargo clippy --fix -p p0-06-tooling-clippy-fmt` می‌تواند پنج تا را خودکار درست کند. **اول دستی انجامشان بده**، بعد اگر خواستی با `--fix` روی یک کپی مقایسه کن. اینجا هدف یاد گرفتن است، نه سبز کردنِ خروجی.

### پیاده‌سازی

بعد از اینکه clippy ساکت شد، `is_empty_name` را طوری تغییر بده که با هر سه اینها کار کند:

```rust
is_empty_name("");
is_empty_name(&String::new());
is_empty_name(&some_longer_string[0..0]);
```

اگر امضایش را درست عوض کرده باشی، هر سه بدونِ هیچ تغییرِ دیگری کار می‌کنند. اگر نه، خطای کامپایلر دقیقاً می‌گوید چرا — همان `E0308`ی که در درسِ ۰۵ خواندی.

### بساز

فرمت را در سه فایلِ مختلف عمداً خراب کن، بعد این را بزن:

```sh
cargo fmt --all -- --check
```

خروجی‌اش را بخوان: دقیقاً همان چیزی است که وقتی فرمت‌نشده کامیت کنی روی CI می‌بینی. یاد بگیر آن diff را بخوانی — `-` چیزی است که نوشته‌ای و `+` چیزی که rustfmt می‌خواهد.

بعد در ویرایشگرت «format on save» را روشن کن و دیگر هیچ‌وقت به این فکر نکن.

### چالش (اختیاری)

`clippy` را در حالتِ سخت‌گیرانه اجرا کن:

```sh
cargo clippy -p p0-06-tooling-clippy-fmt -- -W clippy::pedantic
```

هشدارهای خیلی بیشتری می‌گیری، و بعضی‌هایشان اذیت‌کننده‌اند. سه تا را بخوان و برای هر کدام تصمیم بگیر: این را در یک پروژه‌ی واقعی روشن نگه می‌داری یا نه؟

هیچ جوابِ درستی ندارد. تمرین این است که یاد بگیری با یک لینتر **مذاکره** کنی به‌جای اینکه یا کاملاً اطاعتش کنی یا کاملاً نادیده‌اش بگیری.

## جمع‌بندی

| اصطلاح | یعنی چه | کجا به‌کارت می‌آید |
|---|---|---|
| `rustfmt` | قالب‌بندِ استاندارد | `cargo fmt`، پیش از هر کامیت |
| `cargo fmt -- --check` | فقط گزارش بده، عوض نکن | CI |
| `clippy` | بیش از ۷۵۰ لینت برای سبک، پیچیدگی، کارایی و درستی | هر روز |
| دسته‌ی لینت | `correctness` تا `pedantic` | تصمیم به جدی گرفتنِ یک هشدار |
| `#[allow(clippy::x)]` | خاموش کردنِ یک لینت — همیشه با دلیلِ نوشته‌شده | موردهای واقعاً استثنایی |
| `-D warnings` | هر هشدار را خطا حساب کن | CI |
| سرورِ زبان (rust-analyzer) | تحلیلِ درون‌ویرایشگر، حینِ تایپ | تمامِ مدت |
| راهنمای نوعِ درون‌خطی | نمایشِ نوع‌های استنتاج‌شده | یادگیریِ سیستمِ نوع |

### الان می‌دانی

- در Rust یک سبکِ استاندارد هست و `cargo fmt` اعمالش می‌کند.
- `clippy` فقط سلیقه نیست؛ دسته‌ی `correctness` باگ می‌گیرد.
- هر هشدارِ clippy اسمِ لینت و لینکِ توضیحش را همراه دارد.
- `#[allow(...)]` بدونِ دلیلِ نوشته‌شده، بدهیِ فنی است.
- rust-analyzer را می‌شود روی clippy گذاشت، و ارزشش را دارد.
- CI فقط کدِ تمام‌شده را سخت‌گیرانه لینت می‌کند، نه اسکلتِ درس‌ها را.

### می‌توانی توضیح بدهی؟

- `cargo fmt` و `cargo fmt -- --check` چه فرقی دارند و کدام در CI اجرا می‌شود؟
- دو دسته‌ی لینتِ clippy را نام ببر و بگو چه فرقی دارند.
- اسمِ یک لینت را از روی هشدارش از کجا می‌آوری؟
- کِی نوشتنِ `#[allow(...)]` درست است، و چه چیزی باید همراهش باشد؟
- چرا `&str` گرفتن بهتر از `&String` است؟
- rust-analyzer چیست و چرا به‌طورِ پیش‌فرض clippy را اجرا نمی‌کند؟
