# ۰۶ — گردش کار Git و مخزن

اینجا خبری از کد جدید Rust نیست — این درس کاملاً راجع به اینه که تو ماه‌های آینده چطوری از این مخزن استفاده کنی که راهت رو گم نکنی.

## سه تا فایلی که باعث می‌شن این مخزن خودش رو توضیح بده

- **`docs/conventions.md`** — کتابچه‌ی قوانین: اینکه ساختار پوشه‌ی یه درس چطوری چیده شده، سیستم نام‌گذاری، و پیچیدگی‌های مربوط به workspace-glob. یه بار بخونش، و هر وقت چیزی تو ساختار پروژه برات گنگ بود دوباره چکش کن.
- **`PROGRESS.md`** — چک‌لیست اصلی پروژه، برای هر درس یه تیک گذاشته شده و بر اساس فازها دسته‌بندی شدن. وجود عبارت «در حال کار روی» (Currently working on) اون بالا یعنی اینکه می‌تونی این مخزن رو ببندی، سه هفته بعد برگردی و دقیقاً بدونی که از کجا باید ادامه‌اش بدی.
- فایل `README.md` مختص به هر فاز — که در واقع فهرست مطالب همون فازه.

## قرارداد Commitها

برای هر درسی که تموم می‌شه فقط یک commit، و پیام commit باید بر اساس اسم پکیجِ اون درس نوشته بشه:

```
feat(p1-02-01-move-semantics): complete exercise
```

تیک مربوط به اون درس تو فایل `PROGRESS.md` رو دقیقاً تو **همون commit** بزن، اینطوری چک‌لیست و تاریخچه‌ی واقعی git هیچ‌وقت از هم فاصله نمی‌گیرن — اگه یه زمانی شک کردی که «واقعاً این درس رو تموم کرده بودم یا نه؟»، زدنِ `git log --grep` با اسم پکیج بهت جواب قطعی میده.

```sh
git add phase1-fundamentals/02-ownership-and-memory/01-move-semantics PROGRESS.md
git commit -m "feat(p1-02-01-move-semantics): complete exercise"
```

## تگ زدن (Tagging) برای پایان فازها

تیک‌های کوچیک، بی‌هزینه و انگیزه‌بخش برای نشونه‌گذاری مسیر:

```sh
git tag -a phase1-complete -m "Finished Phase 1: Fundamentals"
git push origin phase1-complete   # اگه/وقتی تگ‌ها رو push می‌کنی
```

ماه‌ها بعد، دستور `git log --oneline --tags` یه خط زمانی (timeline) از کل این سفر بهت می‌ده.

## درس‌های صرفاً خوندنی و اینکه چرا بعضی از پوشه‌ها `Cargo.toml` ندارن

چندتا از درس‌ها (مثل همین درسی که توشی) فقط برای مطالعه هستن — نه کدی دارن، نه فایل `Cargo.toml`. این کار از قصد انجام شده، نه اینکه درس ناقص باشه: اگه قرار بود هر درسی رو به یه crate قابل کامپایل مجبور کنیم، باید درس‌هایی که صرفاً مفهومی هستن رو با کدهای بی‌معنی پر می‌کردیم. فایل `Cargo.toml` ریشه‌ی پروژه، دقیقاً بالا سرِ `[workspace.dependencies]` توضیح داده که کدوم درس‌ها به این روش کنار گذاشته شدن.

## کار انفرادی در مقابل تمرین گردش کار PR

تو اینجا تنها کسی هستی که داری روی پروژه کار می‌کنی، پس هیچ اجباری برای استفاده از branchها یا Pull Request (PR) وجود نداره. اما از اونجایی که «آمادگی برای بازار کار» یکی از اهداف واضح این مسیر در نظر گرفته شده: به عنوان یه گزینه‌ی اختیاری، می‌تونی برای هر فاز یه PR به سمت `main` باز کنی، اون هم فقط برای اینکه با جریان کاری PR و بررسیِ کدهای تغییر کرده (diff-review) که تو تیم‌های واقعی استفاده می‌شه، احساس راحتی بیشتری بکنی. این کار هیچ هزینه‌ای نداره، یه تمرین کاملاً واقع‌گرایانه‌ست و به‌شدت هم اختیاریه.
