# ۰۲ — نصب Rust و toolchainها

این درس در مورد *چراییِ* نصب صحبت می‌کنه؛ خود دستورات دقیق تو فایل [`docs/setup-guide.md`](../../docs/setup-guide.md) قرار دارن تا همه تو یه جا جمع باشن و بتونی بعداً دوباره چکشون کنی. الان نصب رو انجام بده، بعد برگرد و خوندن این صفحه رو تموم کن.

## `rustup`: فقط یه نصاب نیست

داری `rustup` رو نصب می‌کنی، نه مستقیماً "Rust" رو. `rustup` یه **مدیر** برای زنجیره‌ابزار (toolchain) هستش — نزدیک‌ترین معادلی که تو پایتون داره `pyenv` ئه (که اجازه می‌ده نسخه‌های پایتون مثل 3.9/3.11/3.13 رو نصب کنی و بینشون سوییچ کنی)، با این تفاوت که `rustup` روش رسمی و کاملاً رایج برای مدیریت نسخه‌های Rust محسوب می‌شه و یه ابزار راحتیِ شخص ثالث نیست.

یه **زنجیره‌ابزار (toolchain)** بسته‌ایه شامل `rustc` (کامپایلر)، `cargo` (ابزار build/مدیریت بسته) و چند تا قطعه‌ی دیگه که همگی با هم نسخه‌گذاری می‌شن.

## کانال‌ها: stable، beta، nightly

زبان Rust با سه تا کانال منتشر می‌شه:
- **stable** — هر ۶ هفته یه نسخه‌ی پایدار جدید میاد. این همونیه که برای همه‌چیز تو این مخزن استفاده می‌کنی و تو تقریباً هر شغلی هم از همین استفاده می‌شه.
- **beta** — نسخه‌ی پایدار بعدی که در حال آزمایشه.
- **nightly** — هر روز از روی جدیدترین کدها ساخته می‌شه و شامل ویژگی‌های آزمایشیه که پشت پرچم‌های `[feature(...)!#]` پنهان شدن. بعضی ابزارها (مثل بعضی از linterهای clippy یا بعضی کتابخونه‌های macro) برای اینکه بهترین تجربه‌شون رو ارائه بدن nightly رو پیشنهاد می‌کنن، اما برای این دوره آموزشی اصلاً بهش نیازی نداری.

فایل `rust-toolchain.toml` تو این مخزن (تو ریشه‌ی مخزن) `channel = "stable"` رو قفل کرده — وقتی هر دستور `cargo`/`rustc` رو *داخل این مخزن* اجرا می‌کنی، `rustup` فارغ از اینکه پیش‌فرض جهانی سیستم چیه، به‌طور خودکار از کانال stable استفاده می‌کنه. این دقیقاً همون ایده‌ی فایل `.python-version` برای `pyenv`، یا تگِ ایمیج پایه‌ی `Dockerfile` ئه — نسخه رو قفل کن، نه اینکه به «هرچی که نصبه» تکیه کنی.

## ویرایش‌ها (Editions)

تو هر فایل `Cargo.toml` این مخزن `edition = "2021"` رو می‌بینی. یه **ویرایش** تو Rust روشیه که هر چند سال یک‌بار تغییراتی رو به زبان معرفی می‌کنه که باعث شکستن کدهای قبلی می‌شن، اما جوری طراحی شدن که نیاز به تایید صریح دارن (تا حالا ویرایش‌های ۲۰۱۵، ۲۰۱۸، ۲۰۲۱ و ۲۰۲۴ منتشر شدن). این کار بدون اینکه تک‌تک crateهای موجود تو crates.io رو خراب کنه انجام می‌شه — ویرایش‌های قدیمی تا ابد کامپایل می‌شن، فقط `cargo` باید بدونه کدوم crate کدوم ویرایش رو هدف قرار داده. این قضیه با مهاجرت پایتون ۲ به ۳ (که یه مهاجرت واقعی و دردناک بود) فرق داره — ویرایش‌ها دقیقاً جوری طراحی شدن که ارتقا دادنشون تقریباً بی‌دردسر باشه و حتی crateهای مختلف تو یه بیلد می‌تونن هم‌زمان از ویرایش‌های متفاوتی استفاده کنن.

## وقتی کار تموم می‌شه «نصب‌شده» باید چه شکلی باشه

بعد از دنبال کردن `docs/setup-guide.md`، این دو تا دستور باید یه شماره نسخه چاپ کنن (نه اینکه بگن "command not found"):

```sh
rustc --version
cargo --version
```

و ویرایشگرت وقتی یه فایل `.rs` باز می‌کنی، باید خط‌های زیگ‌زاگ زیر کدها و راهنمایی‌های نوع‌ها (type-hints) رو از طرف **rust-analyzer** نشون بده — اگه این‌طور نیست، دوباره بخش راه‌اندازی ویرایشگر تو راهنمای نصب رو چک کن.
