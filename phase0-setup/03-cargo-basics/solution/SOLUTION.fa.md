# راه‌حل — مبانی Cargo

```rust
pub fn format_greeting(name: &str, times: u32) -> String {
    (0..times)
        .map(|_| format!("Hello, {name}!"))
        .collect::<Vec<_>>()
        .join("\n")
}
```

چرا این ساختار؟ چرا از یه حلقه‌ی دستی با متغیر `String` که مقادیر رو با `push_str` بهش اضافه کنیم استفاده نکردیم:

- عبارت `(0..times)` تو Rust یه `Range` محسوب می‌شه که می‌تونی مستقیماً روش iterate کنی — اینجا نیازی به نگه‌داشتن دستیِ یه متغیر برای index (مثل `for i in 0..times`) نداریم، چون اصلاً از متغیر `i` تو حلقه استفاده نمی‌کنیم.
- متد `.map(|_| format!("Hello, {name}!"))` تو هر تکرار، یک رشته‌ی احوال‌پرسی جدید تولید می‌کنه. اینجا `format!` دقیقاً همون کاری رو می‌کنه که f-strings تو پایتون (`f"Hello, {name}!"`) انجام میده، فقط به جای اینکه یه سینتکس درونی (built-in) برای رشته‌ها باشه، از جنس macro ئه.
- متدهای `.collect::<Vec<_>>()` و `.join("\n")` در واقع روش استاندارد (idiomatic) تو زبان Rust برای ساختن رشته‌هاییه که الگوی «تعداد N تا آیتم، هر کدوم تو یه خط» رو دنبال می‌کنن — تو فاز دو که کامل وارد بحث iteratorها بشیم، این الگوی `map` ← `collect` ← `join` رو به دفعات خواهی دید. الان خوبه که این الگو رو حتی قبل از درک کامل مکانیزم زیربناییش یه بار ببینی، تا بعداً به‌جای یه مفهوم کاملاً جدید، برات آشنا به نظر برسه.

اگه اون زنجیره‌ی متدهای iterator هنوز برات شبیه جادو می‌مونه، این یه نسخه‌ی کاملاً معتبرِ دیگه‌ست که بیشتر باب میل «تازه‌کارها»ست:

```rust
pub fn format_greeting(name: &str, times: u32) -> String {
    let mut result = String::new();
    for i in 0..times {
        if i > 0 {
            result.push('\n');
        }
        result.push_str(&format!("Hello, {name}!"));
    }
    result
}
```

هر دو کد کامپایل می‌شن و هر دو از تمام تست‌ها سربلند بیرون میان. نسخه‌ی اول (با iterator) بیشتر حس و حال یه کد استاندارد تو Rust رو میده (idiomatic)؛ نسخه‌ی دوم (با حلقه) اگر هنوز داری به زبان اعتماد پیدا می‌کنی، درستی‌اش رو راحت‌تر نشون می‌ده. هیچ‌کدوم «اشتباه» نیستن — فاز دوم باعث می‌شه نسخه‌ی دارای iterator هم به‌جای یه راهکار خیلی هوشمندانه، کاملاً برات طبیعی به نظر برسه.
