# ۰۴ — ابزارها: clippy، fmt، rust-analyzer

برخلاف تمام درس‌های قبلی، فایل `src/lib.rs` تو این درس **از همین الان کامپایل می‌شه و تست‌هاش رو هم پاس می‌کنه**. وظیفه‌ی تو این نیست که کاری کنی کد کار کنه — بلکه باید اون رو به یک کد *استاندارد و اصولی (idiomatic)* تبدیل کنی، اونم با استفاده از دو تا ابزار که تو تقریباً هر شغلی، بخشی از کار روزمره‌ی برنامه‌نویسی Rust به حساب میان:

- **`cargo clippy`** — یه linter با صدها بررسی برای چیزایی که کامپایلر کاملاً معتبر می‌دونه، اما برنامه‌نویس‌های باتجربه‌ی Rust اونا رو استایل بد، ناکارآمد یا یه باگ احتمالی می‌دونن. نزدیک‌ترین معادل پایتونیش می‌تونه `pylint`/`ruff` باشه، با این تفاوت که clippy رو خود پروژه‌ی Rust پشتیبانی می‌کنه و تو اکوسیستم به عنوان یه استاندارد خیلی قوی‌تر پذیرفته شده — اکثر پروژه‌های واقعی Rust اون رو تو CI اجرا می‌کنن (فایل `.github/workflows/ci.yml` این مخزن هم همین کار رو می‌کنه).
- **`cargo fmt`** — برای قالب‌بندی خودکار کد (auto-formatting)، نزدیک‌ترین معادلش تو پایتون ابزار `black` هست. عملاً فقط یک استایل استاندارد تو Rust وجود داره؛ تو یه تیم واقعی Rust کسی سرِ استفاده از tab یا space بحث نمی‌کنه، فقط `cargo fmt` رو اجرا می‌کنی.
- **rust-analyzer** — یه "language server" که ویرایشگرت برای نمایش inline type hints (راهنمای نوع داده‌ها)، تکمیل خودکار کد (autocomplete)، پرش به محل تعریف (jump-to-definition) و (که تو این درس خیلی به درد می‌خوره) خط‌های زیگ‌زاگ هشدار در حین تایپ کردن باهاش در ارتباطه. این هشدارها خیلی وقتا قبل از اینکه حتی clippy رو دستی اجرا کنی بهت نشون داده می‌شن.

## وظیفه‌ی تو

1. دستور `cargo test` رو اجرا کن — مطمئن شو که از همین اول همه‌چیز پاس می‌شه. این درس صرفاً درباره‌ی استایل کده، نه درستیِ اون.
2. دستور `cargo clippy` رو اجرا کن. پیام هشدارهای clippy رو بخون — clippy توضیح می‌ده که *چرا* به هر چیزی گیر داده، و اغلب راه‌حل دقیقش رو هم پیشنهاد می‌ده. پیشنهادها رو کورکورانه اعمال نکن؛ مطمئن شو که دلیلش رو متوجه شدی (این همون چیزیه که تو فایل `CHECKPOINT.md` بررسی می‌شه).
3. تمام توابع تو `src/lib.rs` رو اونقدر اصلاح کن تا زمانی که `cargo clippy` هیچ هشداری (zero warnings) نده، **بدون اینکه مقداری که هر تابع برمی‌گردونه رو تغییر بدی** — `cargo test` باید در تمام این مدت سبز بمونه.
4. فرمت یکی از توابع رو عمداً به هم بریز (فضای خالی اضافی بذار، تو رفتگی‌ها رو اشتباه کن یا هرچی) و بعد `cargo fmt` رو اجرا کن تا ببینی چطوری به‌طور خودکار اصلاح می‌شه. بعدش `cargo fmt -- --check` (همون دستوری که CI اجرا می‌کنه) رو بزن تا ببینی چطور فقط "نیاز به فرمت‌بندی" رو گزارش می‌ده، بدون اینکه چیزی رو تغییر بده.

## چک‌پوینت

وقتی `cargo clippy` تر و تمیز شد و `cargo fmt -- --check` هم بدون خطا پاس شد، به سؤالات `CHECKPOINT.md` جواب بده، بعد استدلال‌های خودت رو با `solution/SOLUTION.md` مقایسه کن (برای رفع بعضی از این هشدارها، بیشتر از یک راه‌حل قابل‌قبول وجود داره).
