# راه‌حل — ابزارها

هر اصلاح و دلیلی که clippy بهش اشاره می‌کرد:

- **تبدیل `is_empty_name(name: &String)` به `&str`**: تابعی که فقط می‌خواد یه رشته رو بخونه، هیچ‌وقت نیازی نداره که به طور خاص یه `String` رو تقاضا کنه — یه `&str` هم یه `&String` که borrow شده رو می‌پذیره (زبان Rust تو محل فراخوانی، خودش به طور خودکار `&String` رو به `&str` تبدیل (deref) می‌کنه) *و هم* یه string literal رو قبول می‌کنه، بنابراین برای پارامتری که نیازی به مالکیت (ownership) نداره، `&str` قطعاً انعطاف‌پذیرتره. مقایسه‌ی `String` با `&str` تو فاز یک یه درس کامل داره — این فقط یه پیش‌نمایش بود.
- **تبدیل `name.len() == 0` به `()name.is_empty`**: نتیجه‌ی یکسانیه، اما `is_empty()` نیازی نداره که خواننده‌ی کد بدونه «طول صفر» به معنی «خالی» بودنشه — مستقیماً منظورت رو می‌رسونه و برای بعضی از collectionها، استفاده از `is_empty()` می‌تونه سریع‌تر از محاسبه‌ی کامل `len()` باشه.
- **تبدیل `return x * 2;` به `x * 2`**: تو زبان Rust، آخرین عبارت (expression) تو یه بلاک کد (بدون سمی‌کالن) *همون* مقدار برگشتیه — این قضیه برای بدنه‌ی توابع (fn)، بلاک‌های `if`، بازوهای `match` و خلاصه همه‌جا صدق می‌کنه. کلمه‌ی کلیدی `return` برای خروج زودهنگام (early exit) از وسطِ تابع در نظر گرفته شده. استفاده از اون برای خط آخر فقط شلوغ‌کاری اضافه است.
- **تبدیل `if flag == true { true } else { false }` به `flag`**: هشدارهای `needless_bool` و `bool_comparison` هر دو از دو زاویه‌ی مختلف دارن به یه مشکل ریشه‌ای اشاره می‌کنن — مقایسه‌ی یه مقدار `bool` با `true`/`false` به صورت صریح همیشه کار اضافه‌ایه (`flag == true` همون `flag` ئه؛ و `flag == false` همون `!flag` هستش). همینطور شاخه‌بندی (branching) فقط برای برگردوندنِ یه عبارتِ `true`/`false` هم همیشه کار اضافه‌ایه (خود شرط در واقع همون جواب ماست).
- **تبدیل `(&char_count(s.to_string` به `char_count(s)`**: متغیر `s` خودش در حال حاضر یه `&str` هست. اینکه بیایم یه `String` جدید که دارای مالکیت (owned) هست با `to_string()` بسازیم فقط برای اینکه بلافاصله دوباره به‌عنوان `&str` برای یه فراخوانی قرضش بدیم (re-borrow)، تو زمان اجرا یه کار بیهوده انجام می‌ده — تخصیص حافظه روی heap و کپی کردن تک‌تک بایت‌ها، اون هم برای هیچ.
- **تبدیل `for i in 0..nums.len() { total += nums[i]; }` به `for &n in nums`**: این همون عادت کلاسیک «ایجاد دستی ایندکس» از بقیه‌ی زبان‌هاست. تو Rust، sliceها مستقیماً قابل تکرار (iterable) هستن؛ عبارت `for &n in nums` تک‌تک مقادیر رو بهت می‌ده، بدون اینکه نیازی به فکر کردن راجع به بررسی محدوده‌ی آرایه (bounds checks) و خطر خطای اختلاف یکی (off-by-one) داشته باشی. (ضمناً دسترسی از طریق `[nums[i]` خودش یه بررسی محدوده در زمان اجرا به همراه داره — ناایمن (unsafe) نیست، اما تو اینجا فقط یه سربار بی‌مورد و یه شلوغ‌کاری اضافه‌ست.)
- **تبدیل `(map(|x| double_it(x.` به `.map(double_it)`**: یه closure (مثل همون تابع‌های ناشناس تو بقیه زبون‌ها) که هیچ کاری نمی‌کنه جز اینکه یه تابع دیگه رو با همون آرگومان و بدون هیچ تغییری صدا بزنه، فقط یه روش طولانی‌تر برای نوشتن همون تابعه. تابع رو مستقیماً پاس بده.
- **تبدیل `match opt { Some(x) => x, None => 0 }` به `()opt.unwrap_or_default`**: نوعِ `Option<T>` دقیقاً همین عملیات «مقدار رو بهم بده، وگرنه یه مقدار پیش‌فرض بده» رو به صورت یه متد ارائه میده، اون هم برای هر نوعِ `T`ای که `Default` رو پیاده‌سازی کرده باشه (برای نوع `i32`، مقدار پیش‌فرض `0` هست). استفاده از متدِ standard-library به‌جای پیاده‌سازی دستی با `match`، هم کوتاه‌تره و هم برای بقیه‌ی کسایی که کدهای Rust رو می‌خونن فوراً قابل تشخیصه.
